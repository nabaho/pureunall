## 남은 순서 (이 순서 그대로)

1. **함수 배포** — PR #3101 + #3099 의 함수: GitHub Actions 「Firebase 배포」를 main 에서 `functions=` 에 이름 10개 이하씩 나눠 실행(`gh workflow run "Firebase 배포" --ref main -f functions=a,b,c`). 규칙(rules)·스위치는 건드리지 않는다. 배포 뒤 확인:
   `curl -s -o /dev/null -D - -X OPTIONS <함수 URL> -H "Origin: https://erp.pureunlabor.co.kr" -H "Access-Control-Request-Method: POST"` → `Access-Control-Allow-Origin: https://erp.pureunlabor.co.kr`.
2. **화면 PR #3102** 병합·Pages 배포 확인(`https://nabaho.github.io/pureunall/index.html`·`enter.html`·`.well-known/assetlinks.json` 200).
3. **전환** — `gh api -X PUT repos/nabaho/pureunall/pages -f cname=erp.pureunlabor.co.kr` → `gh api repos/nabaho/pureunall/pages --jq .https_certificate.state` 가 `approved` 될 때까지(보통 수 분; 안 나오면 cname 을 null 로 뺐다 다시 넣기) → `gh api -X PUT repos/nabaho/pureunall/pages -F https_enforced=true`.
4. **전환 확인** — `https://erp.pureunlabor.co.kr/enter.html` 200, 옛 `https://nabaho.github.io/pureunall/enter.html?x=1` → 301 새 주소(값 유지), manifest·assetlinks 200, 새 출처 예비요청 허용, 콘솔 오류 없음.
5. **카카오 앱 대표 도메인** → `https://erp.pureunlabor.co.kr` (developers.kakao.com › 앱 › 일반).
6. **마무리 PR** — 옛 주소를 박은 서버 링크(index.js newsClick, hosting/index.html, news-friday.js, recruit-digest.js)·docs/storage-cors.json·STATUS.md 배포 주소·docs 주소 갱신, android/portal-twa 값(출시 전이므로 새 주소로). 서버 링크를 바꿨으면 해당 함수 다시 배포.
