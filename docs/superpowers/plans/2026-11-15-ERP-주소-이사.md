# ERP 주소 이사 계획 — `nabaho.github.io/pureunall` → `erp.pureunlabor.co.kr`

> 상태: **계획만** (대표 결정 대기). 2026-11-15 대표 지시 「도메인 여기 주소도 바꿔달라」→「전면 이사 계획부터」.
> 근거: 같은 날 화면 쪽·서버/외부 설정 쪽 전수 조사(읽기 전용) + 홈페이지 이사(pureunlabor.co.kr)에서 실측한 것.
> 이 문서에 비밀값(키·비밀번호)은 적지 않는다.

## 0. 한 줄

ERP 를 `https://erp.pureunlabor.co.kr/` 에서 열리게 한다. 주소창도 새 주소가 된다.
**코드보다 «순서»가 중요하다** — 서버·바깥 설정을 «두 주소 다 받기»로 먼저 바꾸고, 기기 안 자료를 올린 뒤, 마지막에 도메인을 켠다.

## 1. 무엇이 바뀌나

| | 지금 | 이사 뒤 |
|---|---|---|
| 주소 | `https://nabaho.github.io/pureunall/enter.html` | `https://erp.pureunlabor.co.kr/enter.html` |
| 경로 앞머리 | `/pureunall/` | 없음 |
| 브라우저 «출처» | `nabaho.github.io` (홈페이지·한글편집기와 함께 씀) | `erp.pureunlabor.co.kr` (ERP 혼자) |
| 옛 주소로 들어오면 | — | GitHub 이 **301 로 새 주소로 넘김** |

**실측(2026-11-15, 홈페이지로 시험):**
- GitHub 의 301 은 경로 앞머리만 떼고 **뒤의 값(`?t=…&case=…`)은 그대로 넘긴다** → 고객에게 이미 보낸 서명 링크도 이어진다.
- `#k=…`(서명 링크의 복호화 열쇠)는 서버로 안 가고 브라우저가 들고 가는 값이다. 표준상 유지되지만 **카카오톡 안 브라우저는 이사 날 실폰으로 확인** [확인 필요].
- **DNS 를 먼저 걸어 두고** 도메인을 켜면 인증서가 **약 2분** 만에 나왔다. 반대로 DNS 없이 도메인부터 켜면 40분이 지나도 안 나와 «뺐다 다시 넣기»가 필요했다.
- 도메인을 켜는 «순간» 옛 주소는 301 로 바뀐다 — **두 주소를 함께 띄워 두는 기간은 없다.**

## 2. 위험 셋 (이것 때문에 단계를 나눈다)

1. **기기 안에만 있는 자료가 옛 출처에 갇힌다.** 브라우저 저장소(localStorage·IndexedDB)는 출처별이다. 이사 뒤 옛 출처에서는 스크립트가 한 줄도 안 돈다(301).
   - 다시 받으면 되는 것(손실 없음): ERP 업무 표(pu-big-store), 명함·경력 캐시, 포털 타일 — 서버의 사본이다. 첫 접속이 느리고 다운로드량이 잠깐 는다.
   - **잃는 것**: 아직 서버에 안 올라간 변경(ERP `pu_erp_fb_pending_*`·자료보관 업로드 전 줄, 사진첩 업로드 대기열, 정부지원 미전송 표시, 경력 `_fbpending`), 임시저장(메일 초안, 경력 서식 초안, 한글 자동저장, 기금 서식 편집본, 은행 원장 초안, P박스 작업공간), 설정·열쇠(NAS 계정·자동백업 설정, 직원이 넣은 AI 키, **기기 전용 암호화 신분증**), PC 폴더 연결, 카톡 처리표·되돌리기 기록, 화면 취향.
2. **바깥 설정이 «한 주소만» 받는다.** 서버 함수 7곳이 `origin === "https://nabaho.github.io"` 한 값과만 견준다(목록인 곳 없음). 구글 OAuth·캘린더 키 사이트 제한·Storage CORS·카카오 콘솔·NAS 프록시 머리글도 옛 주소다. 하나라도 빠지면 그 기능이 새 주소에서 막힌다.
3. **전원 다시 로그인·다시 설치.** 로그인 상태·«로그인 유지»·저장 아이디·알림 권한·설치한 앱(PWA 11종)이 출처별이다. 첫 로그인은 모두 «새 기기»로 잡혀 새 기기 알림이 쏟아진다.

## 3. 대표님이 정할 것

1. **새 주소 이름** — `erp.pureunlabor.co.kr` (권장. 짧고 뜻이 바로 보인다)
2. **이사 날** — 평일 퇴근 뒤 또는 주말 저녁 (전환 작업 1시간 안팎 + 다음 날 아침 확인)
3. **구출 페이지를 둘지** — 권장. 옛 출처(`nabaho.github.io`)에 남는 작은 저장소(예: `nabaho/pureunall-rescue`)에 «옛 기기 자료 파일로 내려받기» 쪽 하나를 둔다. 같은 출처라 옛 자료를 읽을 수 있다. 직원이 자료 올리기를 빠뜨려도 되살릴 길이 남는다.
4. **플레이스토어 앱(TWA) 순서** — 아직 출시 전이면(assetlinks 지문 비어 있음) **이사를 먼저 하고 새 주소로 처음부터 빌드**하는 것을 권한다. 옛 주소로 냈다가 바꾸면 새 판을 한 번 더 심사받아야 한다.

## 4. 단계

### 1단계 — «두 주소 다 받기» 코드 (PR 2~3개, 직원 영향 없음)

**서버 (함수 배포 필요)**
- 공용 목록 `ERP_ORIGINS = [옛, 새]` 하나를 두고 `===` 비교 7곳을 «목록에 있나»로: `functions/index.js` `MAIL_ORIGIN`·`PORTAL_ORIGIN`(메일 37곳·자동화 8곳이 이것을 씀), `kakao.js`, `passkey.js`(휴면), `gcal-link.js`, `gcal-proxy.js`(gcalEdit), `gcal-eum.js`(backfill).
- 소식지 그림 허용 4곳에 새 주소 «추가»(옛 주소 남김): `mail-send.js` IMG_HOST_OK, `js/pu-news-tpl.js`·`js/pu-news-show.js`(→ sync-news-lib 로 복사), `news-view.js` CSP img-src.
- 웹푸시 링크 8곳(`index.js`·`suggestion-push.js`·`mail-owner.js`·`mail-new-inquiry.js`·`trip-remind.js`·`gcal-proxy.js`·`billing-alert.js`)은 `/pureunall/` 앞머리에 기대지 않게.
- `index.js` newsClick 의 옛 enter.html 넘김, `hosting/index.html`, `news-friday.js`, `recruit-digest.js` 의 옛 주소.

**화면**
- 절대경로 → 상대경로: `enter.html` manifest 줄, `install.html`(6곳).
- manifest 10개: `scope` `./`, `id` 확정, `related_applications` 새 주소. **새 출처에 아무도 설치하기 전에** 확정(나중에 바꾸면 앱이 둘로 깔린다).
- 알림 워커 `firebase-messaging-sw.js`: `/pureunall/` 있는 꼴·없는 꼴 둘 다 받기.
- 뿌리에 `index.html`(→ enter.html), `404.html`(`/pureunall/` 앞머리를 떼고 넘김 — 옛 꼴 즐겨찾기·알림 링크 구제) 추가.
- 배포(`deploy-pages.yml`): `.well-known/` 이 실제로 올라가는지(숨은 폴더 제외 여부) 확인·필수 파일 목록에 추가.
- 검사 60여 파일이 옛 주소를 글자로 박고 있다 → 주소를 한 자리에서 읽게 정리(CLAUDE.md 「검사는 규칙을 못 박는다」).

**도구** — `tools/remember-ext`(확장)·`tools/remember-pull`·`tools/phone-mirror.js` 두 주소 허용.

### 2단계 — 바깥 설정 (대표님 콘솔 작업, 30분~1시간, 이사 전 아무 때나)

| 어디 | 무엇을 더하나 |
|---|---|
| 가비아 DNS (pureunlabor.co.kr) | `erp` CNAME → `nabaho.github.io.` **(이사 하루 전에 미리 — 인증서가 빨리 나온다)** |
| GitHub 계정 Settings → Pages → Verified domains | `pureunlabor.co.kr` (TXT 한 줄, 가로채기 방지) |
| Firebase 콘솔 → Authentication → 승인된 도메인 | `erp.pureunlabor.co.kr` |
| GCP → 사용자 인증 정보 → 캘린더 OAuth 클라이언트 | JS 원본 `https://erp.pureunlabor.co.kr`, 리디렉션 `…/pu-cal.html`·`…/pu-erp.html` |
| GCP → OAuth 동의 화면 | 승인된 도메인 `pureunlabor.co.kr` |
| GCP → API 키 (캘린더 키, Firebase 브라우저 키) | 웹사이트 제한이 걸려 있으면 `https://erp.pureunlabor.co.kr/*` 추가 **(Firebase 키에 제한이 있는데 빠지면 로그인 전체가 멈춘다)** |
| Cloud Shell — Storage 버킷 3개 CORS | 새 주소 추가 (`docs/storage-cors.json` 고친 뒤 `gcloud storage buckets update --cors-file`) |
| Kakao Developers | Redirect URI·로그아웃 Redirect URI `https://erp.pureunlabor.co.kr/enter.html` |
| Cloudflare Worker (AI 프록시) | ALLOW 에 새 주소 |
| Synology DSM 역방향 프록시 | Access-Control-Allow-Origin — **값 하나라 이사 날 바꾼다** |
| (App Check 를 다시 켤 때) reCAPTCHA | 도메인 추가 — 지금은 꺼져 있어 무관 |

### 3단계 — 기기 자료 비우기 (이사 1~3일 전, 직원 공지)

모든 직원·모든 기기(PC·폰)에서 **옛 주소로**:
1. 이알피 「📤 이 기기에만 있는 데이터 서버로 올리기」 (`?fixsync=1`)
2. 사진첩 업로드 대기열 0 확인
3. 임시저장 마무리 — 메일 초안, 경력 서식 초안, 한글 문서, P박스 작업, 은행 원장 초안, 기금 서식 편집본
4. 다시 넣을 것 «목록만» 메모 — NAS 설정, AI 키, 연결한 PC 폴더 (**비밀번호·키 값은 파일에 적지 않는다**)
5. 기기 전용 신분증 자료는 원본이 따로 있는지 확인(이사 뒤 복구 불가)

### 4단계 — 이사 날 (1시간 안팎)

1. GitHub `nabaho/pureunall` → Settings → Pages → Custom domain `erp.pureunlabor.co.kr` → 인증서(수 분) → **Enforce HTTPS**
   - ⚠ 인증서가 나오기 전 몇 분은 http 로만 열린다(http 에서는 암호·알림·서명 복호화가 안 됨) — 그래서 저녁에 한다.
2. 리디렉션 상수 바꿔 함수 배포 — `kakao.js` REDIRECT_URI, `gcal-link.js` (요청 출처에서 고르는 방식이 더 안전)
3. Synology DSM 머리글을 새 주소로
4. **바로 확인** — 비밀번호 로그인·카카오 로그인, 메일 보내기, 달력 연결·Gmail, 사진 받기, 알림 누르기, `manifest.json`·`.well-known/assetlinks.json` 200, 옛 주소 301(값 유지), **고객 서명 링크(카톡 안 브라우저 포함)**, 안드로이드 «공유»로 사진 넣기
5. 문제가 크면 **되돌리기**: Pages 의 Custom domain 을 비우면 그 즉시 옛 주소로 돌아온다(서버는 두 주소 다 받으므로 그대로 둔다). 단 새 주소에서 생긴 기기 자료는 새 출처에 남는다.

### 5단계 — 이사 뒤 (1~2주)

- 직원 공지: 다시 로그인 + «로그인 유지», **설치한 앱 지우고 새로 설치**(옛 앱의 «공유»는 파일이 사라진다), 🔔 알림 다시 켜기, 북마클릿 다시 끌어 놓기, 새 기기 알림은 이번 한 번 무시.
- NAS·AI 키 재입력, 폴더 다시 고르기, **첫 NAS 자동백업이 도는지 확인**.
- 리멤버 확장 다시 불러오기, 폰 미러 확인.
- 플레이스토어 앱: 새 주소로 빌드(versionCode 올림)·assetlinks 지문 넣기·정책 URL 변경.
- 옛 알림 토큰(`fcm_tokens`) 정리 — 옛 워커가 살아 있으면 알림이 두 번 울릴 수 있다.
- 옛 주소 허용(`ERP_ORIGINS` 의 옛 값)은 **이미 나간 링크를 위해 3개월쯤 둔다** → 그 뒤 정리.
- 문서(`STATUS.md` 배포 주소, docs 19개 파일), 낡은 주석(«5MB 공유» 등) 갱신.

## 5. 이사와 함께 좋아지는 것

- 브라우저 저장 공간을 ERP 혼자 쓴다 — `localStorage` 5MB 를 한글편집기·홈페이지와 나눠 쓰던 문제(STATUS 「되풀이된 실수 11」)가 풀린다.
- 기금관리가 «같은 출처라서» 한글편집기(rhwp-studio) 복구본까지 지우던 일이 없어진다.
- 플레이스토어 앱의 주소 확인 파일이 제자리(새 주소 뿌리)에 놓인다.

## 7. 이 계획에 들지 않은 것

- 옛 홈페이지(푸른노무법인.kr) 의존 정리 — 별도 PR 진행 중(ERP 「홈페이지」 화면). 이사 전에 끝나 있어야 한다.
- 패스키 되살리기 — 화면에서 이미 걷혀 있어 이번엔 상수만 둔다. 되살릴 때 전원 재등록.
