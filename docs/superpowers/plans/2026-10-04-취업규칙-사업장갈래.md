# 취업규칙 ③-ⓐⓑ 🏢 사업장 갈래 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 「취업규칙」을 열면 🏢 사업장 목록이 먼저 나오고, 고른 사업장의 취업규칙 이력(회차·판·★최종본)을 보며, 「✏️ 이 사업장 개정 시작」으로 메일의 원본 첨부를 받아(sha256 확인) 검토·개정(rules.html)에 사업장이 정해진 채로 연다.

**Architecture:** 셈은 순수 모듈 `js/rules-v2/lib-sites.js`(「모은 자료」와 같은 `PuRulesV2Order.companyGroups` 를 딛는다), 그리기는 `js/rules-v2/view-sites.js`(view-library 와 같은 «글을 돌려주는 함수 + data-act 손잡이» 꼴). 원본 받기는 공용 모듈 `js/rules-v2/mail-orig.js`(rules.html 이 싣는다). rules-v2.html 은 `#sites`(기본)·`#topics`·`#lib` 셋을 가르고, 두 파일 머리줄 단추가 넷이 된다.

**Tech Stack:** 빌드 없는 브라우저 JS(ES5 꼴 모듈, `window.X` + `module.exports`), Firebase compat 10.13.2, node:test.

**Spec:** `docs/superpowers/specs/2026-10-03-취업규칙-새로짓기-design.md` §7 (7-1~7-6)

## Global Constraints

- 서버 함수·보안규칙·저장 자리·온톨로지 쓰기 선언을 늘리지 않는다. 새 저장은 이미 있는 `S.linkCompany` 뿐.
- 업체는 id 로 고른다. 이름은 거르는 데만 쓴다(이름이 같다고 잇지 않는다).
- 원본은 **sha256 이 문서의 `sha` 와 같을 때만** 연다.
- 회차·판·최종본 셈은 `PuRulesV2Order` 의 것을 그대로 쓴다(두 화면이 다르게 말하지 않게).

- 새 `<script src>` 에 `?v=숫자`, 고친 js 를 싣는 모든 화면의 `?v=` 를 올린다(`node scripts/check-cache-version.js`).
- 검사는 «지금 값»이 아니라 «규칙»을 박는다(CLAUDE.md). 주석을 걷고 본다.

### Task 1: 사업장 줄 셈 — `js/rules-v2/lib-sites.js`

**Files:** Create `js/rules-v2/lib-sites.js`, `tests/rules-v2-sites.test.js`

**Interfaces:**
- Consumes: `PuRulesV2Order.merge(docs, human)` → `[{id, doc, h, kind, name, status, dir, companyId, date, round}]`, `PuRulesV2Order.companyGroups(items, rounds)` → `[{companyId, roundKey, roundId, items, rows:[{item,no}], cand, finalDocId, finalBy, finalAt, hasReport, last}]`, `PuRulesV2Order.mailKey(it)`.
  node 에서는 `require('./lib-order.js')`, 화면에서는 `root.PuRulesV2Order`.
- Produces: `window.PuRulesV2Sites = { band, model, filter, counts, startDoc, normName }`
  - `band(n)` → `'5인 미만'|'5~9인'|'10~29인'|'30인 이상'|''` (n 이 0·없음·숫자 아님이면 `''`)
  - `model(data, companies)` (`data = {docs, human, rounds}`, `companies = [{id,name,bizNo,status,employmentInsuredCount,bizType}]`) → `rows` 배열, 줄 하나:
    ```
    { id, name, bizNo, size /*숫자 또는 0*/, band, bizType, closed /*status==='closed'*/,
      linked /*확정 문서 수*/, cand /*후보 문서 수*/, candIds /*후보 문서 id[]*/, candMails /*후보 메일 수*/,
      last /*확정·후보 문서의 가장 늦은 메일 ms, 없으면 0*/,
      groups /*그 사업장의 companyGroups, last 내림차순*/, 
      fin: { state:'set'|'none'|'', at /*최종본 문서 메일 ms*/, docId } }
    ```
  - `filter(rows, f, q)` — `f`: `'has'`(기본; linked+cand>0) · `'wait'`(cand>0) · `'all'`. `q`: `normName` 포함 또는 (q 의 숫자가 3자 이상이면) 사업자번호 숫자 포함.
  - `counts(rows)` → `{has, wait, all}`
  - `startDoc(row)` → `{docId, roundKey, notFinal:false}` | `{docId, roundKey, notFinal:true, no /*판 번호*/}` | `null`
  - `normName(s)` — 소문자, 띄어쓰기·`㈜`·`(주)`·`주식회사`·`유한회사`·괄호 걷기.

**규칙(테스트가 볼 것):**
1. 대상: `status !== 'closed'` 인 업체 전부 + `closed` 라도 linked+cand>0 인 곳. id 없는 업체는 뺀다.
2. 확정(`linked`): `it.companyId === 업체 id` 이고 `kind !== '기타'`.
3. 후보(`cand`): `it.companyId` 가 없고, `it.h.companyLinkStatus` 가 `'linked'`·`'not_required'` 가 아니며, `kind !== '기타'`, `(it.doc.companyCand||[])` 에 `companyId === 업체 id` 가 있는 문서. 한 문서가 두 업체의 후보면 두 줄 모두에 센다(확정하면 저절로 빠진다).
4. `candMails` = 후보 문서들의 `mailKey` 가짓수.
5. `groups` = `companyGroups(items, rounds)` 중 그 업체 것, `last` 내림차순.
6. `fin`: linked 가 0 이면 `state:''`. 아니면 `rows.length>0` 인 첫 group(가장 최근)에서 `finalDocId` 가 있으면 `{state:'set', docId, at: 그 문서 date}`, 없으면 `{state:'none'}`. 규칙 본문 회차가 하나도 없으면 `state:'none'`.
7. 차례: cand>0 먼저 → `last` 내림 → `name.localeCompare(b.name,'ko')`.
8. `startDoc`: `rows.length>0` 인 첫 group 에서 `finalDocId` → `notFinal:false`; 없으면 그 group 의 `rows` 마지막 줄 → `notFinal:true, no`. 그런 group 이 없으면 `null`. (최근 회차에 규칙 본문이 없으면 그 앞 회차로 간다.)

### Task 2: 메일에서 원본 받기 — `js/rules-v2/mail-orig.js`

**Files:** Create `js/rules-v2/mail-orig.js`, `tests/rules-v2-mail-orig.test.js`

**Interfaces:**
- Produces: `window.PuRulesMailOrig = { fetchOriginal, makeCall, b64ToBytes, sha256Hex }`
  - `makeCall({ base, getToken, fetch })` → `call(fn, body)` : `POST base+fn`, 머리 `Content-Type: application/json`, `Authorization: 'Bearer '+토큰`; 응답 JSON 을 돌려주되 `j.ok !== true` 면 `Error(j.error || '서버가 거절했습니다')` 에 `status` 를 실어 던진다. (화면에서 base = `'https://asia-northeast3-pureun-erp.cloudfunctions.net/'` — pu-cards.html 의 `MB_FN` 과 같음)
  - `sha256Hex(bytes)` → `Promise<hex>` — 화면은 `crypto.subtle.digest('SHA-256', …)`, node 에서는 `globalThis.crypto.subtle`(node 20+ 에 있음).
  - `fetchOriginal({ doc, call, sha256 })` → `Promise<{ok:true, name, bytes:Uint8Array} | {ok:false, why}>`
    - `doc.mail.src === 'imap'`: `call('readMailMessage', {slug: doc.mail.box, uid: String(doc.mail.key)})` → `atts`(각 `{i, part, name, size}`), 이름이 `doc.name` 과 같은 것만 차례로 `call('readMailAttachment', {slug, uid, index: a.i, part: a.part || ''})` → `b64`.
    - `'pop3'`: `call('readOldMail', {key: String(doc.mail.key)})` → `atts`(`{i, part:'', name}`), 같은 이름을 `call('readOldMail', {key, index: a.i})` → `b64`.
    - 받은 바이트의 sha256 이 `doc.sha` 와 같으면 `{ok:true, name: doc.name, bytes}`. 하나도 안 맞으면 `{ok:false, why:'메일의 첨부가 모은 때와 다릅니다 — 📥 에서 가린 파일을 받거나 메일함에서 직접 여세요'}`. 같은 이름이 없으면 `{ok:false, why:'메일에 그 첨부가 없습니다 …'}`.
    - `doc.sha` 가 비었으면(20MB 보류 등) 받지 않고 `{ok:false, why:'원본 지문이 없어 확인할 수 없습니다 …'}`.
    - 호출이 던지면(404·네트워크) `{ok:false, why:'메일에서 원본을 못 받았습니다 — ' + 메시지 + ' (📥 에서 가린 파일을 받거나 메일함에서 직접)'}`.

- [ ] **Step 1: 실패하는 검사** — 가짜 `call` 로(진짜 fetch 없음):
  - IMAP: 같은 이름 첨부 둘 중 «둘째»의 바이트가 sha 와 맞으면 그것을 돌려주고, 부른 차례가 `readMailMessage` → `readMailAttachment(i=첫째)` → `readMailAttachment(i=둘째)` 인지.
  - POP3: `readOldMail{key}` → `readOldMail{key,index}`.
  - sha 가 안 맞으면 ok:false(바이트를 돌려주지 않는다), 이름 없음, sha 빈 것(아무 호출도 안 함), call 이 던지면 ok:false.
  - `makeCall`: 가짜 fetch 가 받은 주소·머리(Bearer 토큰)·몸통, `ok:false` 응답이면 던지는지.
  - sha 값은 검사 안에서 `crypto.createHash('sha256')` 로 셈해 넣는다(박지 않는다).
- [ ] **Step 2:** 실패 확인 → **Step 3:** 구현 → **Step 4:** 통과 + 되돌려 보기(sha 비교를 늘 참으로) → **Step 5:** 경로 지정 커밋 `feat(취업규칙): 메일에서 원본 첨부 받기 — 지문이 같을 때만`
