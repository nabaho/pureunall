# 정부사업신청 ↔ 경력관리 비교 ① 공고 ↔ 지난 수행 이력 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공고·모집 글마다 경력관리의 위촉·실적·근무·지난 지원 서류와 견줘 「동일·유사」를 표시하고, 사람이 「맞음·아님」으로 확인하게 한다.

**Architecture:** 순수 판정기 `js/gov-match.js`(orgKey·sameOrg·topicsOf·words·toRecs·compare·findFor)가 규칙으로 가르고 까닭을 낸다. `gov.html` 은 경력 자료를 «읽기만» 해서(기존 `matPull`) 묶은 줄로 바꾸고, 공고 표·모집 글 표에 「이력」 칸과 팝업을 그린다. 확인 표시는 새 동기화 칸 `recruit_match`.

**Tech Stack:** 바닐라 JS(ES5, 화면) · node:test + vm(검사) · Firebase RTDB(동기화 칸)

**Spec:** `docs/superpowers/specs/2026-10-05-gov-경력비교-design.md` (1·2절)

## Global Constraints
- 정부사업신청은 경력관리 자료를 읽기만 한다 — 읽어 온 경력 자료는 어디에도 담지 않는다(확인 표시만 담는다).
- 자문·고문은 견줄 줄에 넣지 않는다. 화면 글(show)에 고객사·사건 당사자 이름을 넣지 않는다(사건=유형만, 컨설팅=유형·사업·수행기관).
- 「충청남도」≠「충청남도경제진흥원」 — 같은 기관은 열쇠가 같거나 긴 쪽 꼬리가 청·본부·지사·본사·지역본부·지청·사무소일 때만.
- 공인노무사회 게시판(kc) 글은 기관을 게시판으로 정하지 않는다(글을 낸 곳이 아니다) — 제목에서 사전 기관을 찾되 kcplaa 는 뺀다.
- 판정 까닭을 늘 함께 보인다. AI 를 쓰지 않는다.

### Task 1: 판정기 `js/gov-match.js` + 검사

**Files:** Create `js/gov-match.js` · Test `tests/gov-match.test.js`

**Interfaces — Produces:**
- `orgKey(name) → string`, `sameOrg(a,b) → bool`
- `topicsOf(text) → string[]` (TOPICS 의 k), `topicName(k) → string`
- `words(text) → string[]`, `overlap(a,b) → 0..1` (작은 쪽 기준, 둘 다 2낱말 이상일 때만)
- `toRecs(mat, scanOrgs) → [{ id, src:'wiccok'|'perf'|'work'|'scan', srcName, org, orgId?, title, show, topics[], years[], year, count }]` — 같은 (src, show) 를 묶는다
- `compare(target{orgId, orgNames[], title}, rec, matches?) → { level:'same'|'similar'|'', score, why[] }`
  동일 = 기관 같음 + (같은 종류 또는 이름 60%↑) · 유사 = 기관 같음 또는 같은 종류 또는 이름 50%↑
- `findFor(target{key,...}, recs, marks, keyOf(targetKey, recId), matches) → { same[], similar[], no[] }` — 「아님(n)」은 no 로

- [ ] 검사 먼저: 실자료 꼴로 동일·유사·아님(산업일자리전환 공고 ↔ 충남경제진흥원 구조혁신 실적 = 동일 · 괴롭힘 조사 공고 ↔ 괴롭힘 사건 = 유사 · 「충청남도」 위촉 ↔ 「충청남도경제진흥원」 공고 = 기관 다름 · 「컨설팅」만 겹침 = 없음), 묶기(×17, 해 범위), 고객사·사건 이름이 show 에 없음, 자문 제외, 아님 표시 → no.
- [ ] `node --test tests/gov-match.test.js` 실패 확인 → 모듈 → 통과 → 고장넣기.

### Task 2: 화면 — 이력 칸·팝업·확인 (`gov.html`, `js/gov-sync.js`)

**Files:** Modify `gov.html`(싣기 · 「이력」 칸 두 표 · 팝업 · 자료 받기) · `js/gov-sync.js`(FIELDS 에 `recruit_match` map) · Test `tests/gov-recruit-app.test.js`, `tests/gov-app.test.js`, `tests/gov-sync.test.js`

**Interfaces — Consumes:** Task 1 전부 · `GovCareer.build`(이미 `matPull` 이 `_mat` 에 둔다) · `GovRecruit.matches/allOrgs/hitGroup/group`
**Produces (gov.html):**
- `matchRecs() → recs|null` — `_mat`(+ `recGroups().orgs`)로 `GovMatch.toRecs`, 결과를 `_matchRecs` 에 둔다. `_mat` 이 없으면 `matchEnsure()` 가 `matPull()` 을 한 번 부르고 다 받으면 다시 그린다.
- `matchTargetFeed(r)` / `matchTargetHit(x)` → target
- `matchFind(target) → findFor 결과` (캐시 `_matchCache`, 자료·표시가 바뀌면 비움)
- `matchCell(target) → '<td class="mt">…</td>'` — `🟢 동일 n · 🟡 유사 n`(n = 묶음 수), 확인한 것이 있으면 ✓, 누르면 `matchOpen(key)`
- `matchOpen(key)` — 팝업: 동일 → 유사 → 아니라고 한 것(접힘), 줄마다 갈래·보여 줄 글·×건수·해·까닭·「✓ 맞음 / ✗ 아님 / ↩ 되돌리기」
- `matchMark(targetKey, recId, v)` — `recruit_match[safeKey(targetKey+'|'+recId)] = 'y'|'n'|삭제`
- [ ] 검사 먼저(vm): 두 표에 이력 칸 · 배지 수 · 팝업 줄·까닭 · 맞음 ✓ · 아님 → 숨고 「아니라고 한 것」에서 되살림 · 경력 자료를 못 읽으면 칸이 비고 안내 · 고객사 이름 안 보임 · kc 글은 공인노무사회 위촉과 «기관 같음» 아님 · `recruit_match` 가 동기화 칸.
