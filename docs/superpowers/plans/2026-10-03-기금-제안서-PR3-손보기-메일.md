# 기금 제안서 PR 3 — 한글처럼 손보기 · ✉ 메일로 보내기 · 보낸 기록 · 사본 보관

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 채우기 창(양식 하나)에서 채운 한글 문서를 저장소 안 편집기로 손보고, 확인 화면에서 직접 「보내기」를 눌러 회사 메일 서버로 보내며(한글 + 선택 PDF), 보낸 뒤 기업정보함 「보낸 서류」에 기록하고 사본을 기업별 서류에 보관한다.

**Architecture:** 순수 규칙(메일 기본값·기록 열쇠·기록 한 줄)은 `js/pu-form-cardfill.js` 에 두고 node 로 검사한다. db·창고·서버·편집기는 모두 문서관리(`docs-esign.html`) host 함수(`hwpEdit`, `hwpPdf`, `mail.{mode,send,record,keep}`)가 맡는다 — `openFill` 은 db 를 만지지 않는다(tests/form-cardfill.test.js 규칙). 화면은 `js/pu-contract-forms.js` 의 `openFill` 에 단추 둘과 새 창 `openSend` 를 더한다.

**Tech Stack:** ES5, rhwp(`PureunHwp`, `vendor/rhwp-editor` + `vendor/rhwp-studio`), jsPDF(이미 문서관리에 있음), `PuDocFile.putMailFile/sendMail`(명함첩·사진첩과 같은 서버 `sendMaterialMail`), Firebase RTDB, node:test.

**Spec:** `docs/superpowers/specs/2026-09-29-기금-제안서-보내기-design.md` §6, §7, §7.1

## Global Constraints

- ES5. 공용 JS 를 고치면 그 파일을 싣는 모든 html `?v=` 를 같이 올린다: `pu-contract-forms.js` v11→12(docs-esign.html·pu-erp.html), `pu-form-cardfill.js` v6→7(docs-esign.html). `pu-doc-file.js` 는 다른 화면과 **같은 `?v=36`** 으로 싣는다(고치지 않음).
- `PuDocFile.init({ db: db })` — **storage 를 넘기지 않는다**(넘기면 문서관리 창고 `pureun-erp-hrphotos` 로 올라가 서버가 첨부를 못 찾고 조용히 빠진 채 나간다; 기본값 `pureun-erp-photos` 를 써야 한다).
- 편집기는 저장소 안 것만: `import('./vendor/rhwp-editor/index.js')` + `studioUrl: 'vendor/rhwp-studio/index.html'`, `renderer: 'canvas2d'`. `esm.sh`·`edwardkim.github.io`·`PureunHwp.createEditor` 금지.
- 손본 결과는 **원본 형식 그대로** 낸다(.hwp→`exportHwp`, .hwpx→`exportHwpx`).
- 메일은 사람이 「✉ 보내기」를 누를 때만. 보내는 중 단추 잠금. 받는 주소는 기록에 남기지 않는다(`tests/cards-co-sent-write.test.js` 와 같은 원칙).
- 보낸 기록 `pucards/sentDocs/{key}` 한 줄 = `{ at, by(보낸 직원 이메일), kind, names[], card:'', who }`. 열쇠는 사업자번호 10자리 이상이면 그 숫자, 그리고 `'n' + coNorm(회사명)` — 둘 다 쓴다(업무관리 work.html 이 두 열쇠를 다 읽고 `'@'+at` 으로 겹침을 지운다).

### Task 3: 문서관리 host — 편집기(`hwpEdit`) · PDF(`hwpPdf`) · 메일(`mail`)

**Interfaces:**
- Produces (mount host):
  - `hwpEdit(bytes, name) → Promise<Uint8Array|null>` — 전체 화면 편집 창. 「✔ 다 고쳤습니다」→ 원본 형식 바이트, 「취소」→ null. .hwp 는 엔진으로 .hwpx 로 바꿔 연 뒤 `exportHwp` 로 돌려준다.
  - `hwpPdf(bytes, name) → Promise<Uint8Array>` — 화면 밖에서 `PureunHwp.renderPreview` 로 쪽마다 canvas → jsPDF(쪽 방향 그대로).
  - `mail.mode() → Promise<'auto'|'mailto'>` — `pucards/config/matMail/mode` 읽기(실패하면 'mailto').
  - `mail.send(p, files) → Promise<{ok, sent, files}>` — `files=[{name, bytes}]` 를 `PuDocFile.putMailFile(Blob, name)` 로 올리고 `PuDocFile.sendMail({to, cc, subject, body, toName, files:[{name,path}], cardId:''})`.
  - `mail.record(row, V, o) → Promise<number>` — `PuFormCardFill.sentKeys` 의 열쇠마다 `pucards/sentDocs/{key}` 에 `sentRecord({at: Date.now(), by: curUser.email, kind:o.kind, names:o.names, who:o.who})` 를 push. 쓴 수를 돌려줌.
  - `mail.keep(V, file, title) → Promise<{coKey, docId}>` — `PuOfficeStore.putOriginal(file, {kind:'co', coKey: PuOfficeStore.coKey(V.회사명), coName: V.회사명})` → `PuOfficeStore.addCoDoc({coName: V.회사명, fileId, title, date: 오늘, src:'upload'})`.
