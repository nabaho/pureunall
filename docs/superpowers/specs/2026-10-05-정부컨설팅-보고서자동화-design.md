## 0. 한 줄

정부사업일정의 사업장 화면에서 **[📄 보고서 작성]** 을 누르면, 이미 앱에 쌓인 기록(업체정보·회차·메일·보낸 서류)을
모아 **AI 가 기관 양식의 칸을 초안으로 채우고 → 노무사가 검토·확정 → 기관이 보낸 원본 양식(HWPX)에 그대로 채워 저장**한다.
그 뒤 **사업장 서명 → 기관 제출(메일 또는 플랫폼)** 까지 잇는다.

## 1. 대표 지시 (원문)

- 「기술보호컨설팅 충남상공회의소 서산상공회의소 등 모든 정부사업들을 모든 한글 및 ppt 양식을 표준화 하고
  작업시에 보고서에 모두 ai 연결해서 작성 보관후 회사로 보내는 자동화 만들고 싶은것이다.」
- 「컨설팅을 종료할 경우 컨설팅 보고서를 컨설팅을한 회사로 보내서 서명을 받고 이후에 기관에다가 각각 보내야된다.
  이부분도 모두 자동연결시키고 싶은것이다.」
- 「한글보고서이면 한글보고서로 작성해서 송부하고, 플랫폼에 보고서를 넣어야되면 플랫폼에 자동화로 넣고 싶다.」
- 「푸른이알피에서 사업장 컨설팅이 진행되면 업무관리에 진행상황이 메일 캘린더의 내용을 가지고 와서 정리되고
  … 보고서 작성에는 컨설팅 보고서에 앞의 내용을 검토하고 가지고 와서 처리되도록 하고 싶다.」
- 「방문 일정이 기록이 없는경우도 있다 … 본인이 보고서에 입력하면 된다.」

## 2. 정한 것 (대표 결정 2026-10-05)

| 물음 | 결정 |
|---|---|
| 어디에 만드나 | **둘 다** — 작성·검토·보관은 푸른이알피, 양식은 **HWPX** 로. `.hwp` 가 꼭 필요한 기관만 로컬 한글로 변환 |
| 1차 범위 | **기술보호 · 충남북부상의 · 서산상의** 셋을 «제출까지» 끝까지. 나머지 사업은 그 뒤에 붙인다 |

## 5. 양식 서고

### 5-1. 보관
```
Storage  gov_forms/{formKey}/{year}/{파일}.hwpx          ← 토큰 넣은 견본
RTDB     scal_rptForms/{formKey}/{year} = {
           name, agency, files:[{file, role}],            ← role: 'main' | 'visit'(방문확인서) | 'travel'(여비) …
           map:{ 토큰: 자료경로 },                         ← 칸 지도 (§5-2)
           repeat:{ 블록이름: {unit:'round', min, max} },
           sign:[…], photo:false, registeredBy, registeredAt, sourceFile }
```
`formKey` 는 `cci-north`(충남북부상의) · `cci-seosan`(서산상의) · `techguard`(기술보호).

### 5-2. 토큰 규칙 (기존 `pu-hwpx-fill` 에 맞춤)
- 칸: `{{업체명}}` `{{사업자번호}}` `{{대표자}}` `{{업종}}` `{{소재지}}` `{{근로자수}}` `{{담당자}}` `{{담당부서직위}}`
- 회차: `{{회차}}` `{{일자}}` `{{방문체크}}`(■방문 □사무활동) `{{문의}}` `{{진단}}` `{{자문}}` `{{성과}}` `{{향후}}`
- 종합: `{{문의진단종합}}` `{{결과종합_검토}}` `{{결과종합_조치}}` `{{산출물목록}}` `{{기타}}` `{{작성일}}`
- **반복 블록(새로 만듦)**: 견본에 `{{#쪽:회차}}` … `{{/쪽:회차}}` 로 감싼 문단·표·쪽을 회차 수만큼 복제한다.
  표 «줄» 반복은 `kcareer-hwpxfill` 의 `splitRows`·`replaceRowAt` 를 쓴다.
- 모르는 값은 `＿＿＿`(엔진의 BLANK) — **지어내지 않는다.**

### 5-3. 해마다 새 양식 (대표 결정: AI 가 견본 → 사람은 확인)
1. 기관이 보낸 `.hwp` 를 로컬 한글로 `.hwpx` 변환(§8).
2. 이 방에서 AI 가 칸을 찾아 토큰을 넣은 견본을 만들고, **작년 칸 지도와 견주어 바뀐 칸**을 표로 보여 준다.
3. 대표(또는 지정 직원)가 확인 → 서고에 등록. 원본 `.hwp` 는 `sourceFile` 로 함께 남긴다.

## 6. 보고서 작성 흐름

### 6-1. 들어가는 문
정부사업일정 사업장 화면 → **[📄 보고서 작성]**. 그 사업장의 사업 종류로 양식을 고른다.
⚠ 지금 「인사노무 / 상공회의소」 한 종류에 충남북부·서산이 섞여 있다 → 이알피 계약의 사업명
(「인사노무컨설팅충남북부상의」 · 「인사노무컨설팅서산」)으로 자동으로 고르고, **애매하면 사람에게 묻는다.**

### 6-2. 자료 모으기 (출처를 줄마다 붙인다)
| 칸 | 출처 | 비고 |
|---|---|---|
| 기업정보 | `data/companies` → `pucards/coInfo` | 비면 [확인 필요] |
| 근로자수 | `pucards/coInfo.workers`(상시근로자수) | 피보험자수 아님 |
| 회차·일자·방식 | `scal_scheds`(phase≠'pre', 날짜순) | `isField` → ■방문 / □사무활동 |
| 회차 내용 재료 | 그 회차 `memo` + 회차 날짜 ±7일의 업체 메일(`coMail`·메일함)·보낸 서류(`sentDocs`)·캘린더 | AI 초안의 재료 |
| 산출물 목록 | `sentDocs` 중 그 사업장에 보낸 서류 | `#1, #2 …` 번호 |

### 6-3. AI 초안
- 사내 AI 프록시. 보내기 전에 **「데이터 전송 동의」 창**(기금과 같은 것).
- 보내기 전에 **주민번호·전화·계좌 같은 개인정보는 가린다.**
- 규칙: **재료에 없는 사실은 쓰지 않는다** — 재료가 빈 회차는 「기록 없음 — 입력 필요」로 둔다.
  기관 작성기준(예: 충남북부 「진단-처방-결과물 산출 과정을 논리적으로」)을 함께 넘긴다.
- 결과는 **칸마다** 받는다(전문 한 덩어리가 아니라) — 검토 화면에서 칸별로 고치기 위해.

### 6-4. 검토 화면
- 왼쪽: 양식 칸 목록(고칠 수 있는 글상자). 오른쪽: 그 칸의 **출처**(어느 메모·메일·서류에서 왔나).
- **[+ 회차 추가]** — 일정에 없는 방문을 여기서 넣는다. 「보고서에서 추가 — 일정 기록 없음」 딱지. 정부사업일정에는 안 쓴다.
- 회차 수가 기관 기준(충남북부 3회 등)에 못 미치면 [확정] 전에 알린다.
- **[확정]** 은 노무사만. 확정 전에는 어떤 것도 밖으로 나가지 않는다.

### 6-5. 저장
```
RTDB     scal_reports/{coId}/{rid} = { formKey, year, state, data:{…칸…}, src:{칸: 출처}, rounds:[…],
                                       ver, createdBy, confirmedBy, confirmedAt, files:{hwpx, pdf, signed} }
Storage  gov_reports/{coId}/{rid}/v{ver}.hwpx · .pdf · signed.pdf
```
`state`: `초안` → `검토완료(확정)` → `서명대기` → `서명완료` → `제출완료`.
⚠ 규칙(Firebase rules) 자리 둘(`scal_reports`·`scal_rptForms`, Storage `gov_forms`·`gov_reports`)이 새로 필요 — 스크립트로 게시.

## 7. 서명 · 제출 (1차 범위, 윤곽 — 세부는 구현 전 대표 확인)

- **서명**: 확정본 PDF 를 사업장 담당자에게 보낸다 → 서명본 회수 → `files.signed`.
  방식은 아직 미정 — ㉠ 날인 스캔 회신(메일함에서 회신 첨부를 찾아 붙임) ㉡ 전자서명 서비스 ㉢ 자체 서명 페이지. **[대표 결정 대기]**
- **제출**:
  - 충남북부·서산상의 — 메일 제출(받는 사람·제목·첨부를 채운 «초안»까지 자동, **보내기는 사람이 누른다**).
  - 기술보호 — **기술보호울타리 시스템** 업로드. 로그인은 사람이 하고, 입력·첨부는 자동, **최종 제출 단추는 사람이**.
    (매뉴얼: `컨설팅업체\5. 기술보호…\2025 기술보호\기술보호울타리_시스템_사용_매뉴얼(전문가용).pdf`)
- 보내는 메일 계정 **[대표 결정 대기]**.
- 메일은 «자동으로 채우고, 보내기는 한 번 클릭». 사업장 서명 회신은 메일함에서 그 보고서의 «보낸 메일에 대한 회신 + 첨부»로 찾아 `files.signed` 후보로 붙이고, 담당자가 맞는지 확인한다.

### 7-1. 사이트 업로드 — Aside 업로드 대기열 (대표 결정 2026-10-09 「반영」)

대표 지시: 「각 사이트에 자동으로 업로드 정리 하고 싶은데 … 특히 aside 라는 프로그램등을 활용해서 자동으로 처리하고 싶다.」
**Aside** = 로그인된 브라우저를 대신 조작하는 브라우저 에이전트(Claude Code 에 `mcp__aside__exec`·`repl` 로 붙는다).

```
이알피 보고서 [확정]·[서명완료]
   → RTDB scal_uploadQueue/{qid} = { rid, coId, site, files:[…], fields:{…}, state:'대기', owner, createdAt }
   → 지정 PC 의 Aside 가 «하나씩» 꺼내 처리:
        사이트 이동 → (로그인 안 돼 있으면 멈추고 담당자에게 「로그인 필요」) → 입력칸 채우기 → 파일 첨부
        → «제출 직전» 화면 캡처 → state:'확인대기' 로 멈춤
   → 담당자: 캡처를 보고 이알피에서 [제출 확인] → Aside 가 제출 단추 → 접수 화면 캡처 → state:'제출완료'
   → 보고서 state 도 '제출완료', 접수 캡처를 files 에 남긴다
```

| 자동 | 사람 |
|---|---|
| 사이트 이동 · 칸 채우기 · 첨부 · 캡처 · 결과 기록 | **로그인**(공동인증서·OTP·보안문자 — 자동화하지 않는다) |
| 대기열을 차례로 처리, 실패하면 「수동 처리 필요」 + 까닭 | **최종 제출 확인** |

- 사이트마다 «절차서» 하나(`site` 키: `techguard`(기술보호울타리) → 뒤에 일터혁신 상생 등록 · KMAC 업로드 등).
  절차서는 화면 글자(라벨)로 칸을 찾는다 — 좌표에 기대지 않는다(화면이 조금 바뀌어도 버티게).
- **비밀번호·인증서·토큰을 저장하지 않는다.** 대기열에도, 절차서에도, 로그에도.
- **한 번에 하나씩** — 같은 사이트에 겹쳐 붙지 않는다(2026-10-05 푸른메일함 POP3 를 동시에 불러 막힌 일의 교훈).
- 사이트 화면이 바뀌어 칸을 못 찾으면 «추측해서 채우지 않고» 멈춘다.
- 1차 시험: **기술보호울타리** — 대표 PC 에서 Aside 브라우저 실행 + 대표가 직접 로그인한 상태로.
  (2026-10-09 확인: 이 PC 에서 Aside 가 «실행 중이 아니어서» 아직 시험 못 함.)

## 8. 로컬 변환 도구 (대표 PC — 한글 2022 · PowerPoint · Python 확인됨)

- `.hwp → .hwpx`(양식 등록용), `.hwpx → .hwp / .pdf`(기관이 hwp·pdf 를 요구할 때) — `HWPFrame.HwpObject` 자동조종.
- 이알피가 만든 HWPX 를 받아 변환해 같은 자리에 올린다. 웹만으로 못 하는 일만 여기서 한다.

## 9. 지키는 것

- 원본 양식·과거 보고서는 **읽기만**. 결과는 늘 새 파일.
- **AI 초안은 초안이라고 보이게** — 확정 전에는 화면·파일 이름에 「초안」.
- 외부(사업장·기관)로 나가는 것은 **모두 사람이 마지막 단추를 누른다.**
- 개인정보는 필요한 만큼만. 고객사 자료를 섞지 않는다(사업장마다 자리를 가른다).
- 정부사업일정의 «지난 일정»·증빙 사진은 건드리지 않는다.

## 10. 검사 계획

- 반복 블록: 견본에 `{{#쪽:회차}}` 를 넣고 1·3·7회로 채워 **쪽·표 수가 맞는지**, 한글로 열리는지(줄 정보 걷기 포함).
- 칸 지도: 세 양식 각각 «모든 토큰이 채워지거나 ＿＿＿ 로 남는가» — 토큰 글자가 결과에 남으면 실패.
- 출처: AI 를 흉내 낸 응답으로 «재료에 없는 회차는 '기록 없음'» 을 못 박는다.
- 근로자수: 피보험자수 칸을 읽으면 실패하는 검사.
- 보고서에서 추가한 회차가 `scal_scheds` 에 **쓰이지 않는지**.
- 실제 시험: 2025 충남북부·서산·기술보호 확정본 1건씩과 «같은 자료로 다시 만들어» 견준다.

## 11. 만드는 순서 (구현 계획에서 쪼갬)

1. 반복 블록 엔진 + 세 양식 견본(HWPX·토큰) + 칸 지도 등록 ← **여기부터**
2. 자료 모으기(§6-2) + 검토 화면(§6-4) — AI 없이 손으로 채워도 HWPX 가 나오게
3. AI 초안(§6-3) 붙이기
4. 저장·상태(§6-5) + 로컬 변환(§8)
5. 서명·제출(§7) — 대표 결정 뒤
6. Aside 업로드 대기열(§7-1) — 기술보호울타리 절차서부터. ⚠ 5 와 따로 시험할 수 있다(이미 확정된 지난 보고서로 «제출 직전까지만»)
