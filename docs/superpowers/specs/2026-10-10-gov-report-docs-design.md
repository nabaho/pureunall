# 컨설팅보고서 앱 — 서류 관리(왼쪽 패널)·목차 설계

- 작성일: 2026-10-10 · 상위: `2026-10-10-gov-report-app-design.md`(현황판) · 사업별 서류 원자료: 대표 PC `컨설팅보고서_사업별_양식·항목_정리_2026-10-09.md`
- 대표 지시(2026-10-10): 「대시보드 왼쪽에 서류(페이퍼) 관리를 만들고」 · 「푸른이알피 **환경설정 → 컨설팅관리 → 컨설팅 사업**과 연계해 목차를 만든다」 · 「진행」.
- 시안: 왼쪽 = ERP 컨설팅 사업(기관별 묶음) · 오른쪽 = 서류 체크표.

## 1. 범위

한다
- 현황판(`gov-report.html`) **왼쪽 패널**: 푸른이알피 `data/biz_cons_types`(환경설정 → 컨설팅관리 → 컨설팅 사업)를 그대로 읽어 **기관별로 묶은 사업 목록**을 보인다. 사업을 누르면 오른쪽 목록이 그 사업 업체로 걸러진다(다시 누르면 풀림).
- 사업마다 **서류 틀**(= 목차의 뼈대)을 코드에 둔다(§3). 간단형·대형 구분 표시.
- **목차 창**: 업체 한 곳의 목록 줄에서 「목차」를 누르면 그 업체·사업의 목차(계약·기간·담당 머리말 + 번호 매긴 서류 줄 + 회차 펼침 + 상태 딱지)를 보인다. 「복사」로 글로 가져간다.
- 서류 체크표 열 ①초안 ②확정은 지금 있는 자료(`scal_reports`)로 **자동**으로 채운다.

하지 않는다(다음 단계)
- 손으로 체크하는 서류 상태(③ 업체 서명본 · ④ 산출물 별첨 · ⑤ 기관 제출)의 **저장**. 이번에는 칸만 그리고 「—」로 둔다. (저장 자리와 규칙은 서명·제출 단계에서 정한다.)
- 「받은 서류함」(메일 첨부 → 서류 연결) · AI 점검 · 파일 생성.
- 푸른이알피(`data/*`)와 `scal_*` 에 **아무것도 쓰지 않는다**(규칙 변경·게시 없음).

## 2. 자료 · 읽기만 한다

| 읽는 자리 | 쓰임 |
|---|---|
| `data/biz_cons_types` | 컨설팅 사업 목록. 모양 `{u, v:[{code,name,short,agency,sortOrder,hidden?,mergedInto?,…}]}` (`v` 가 목록) |
| `data/consultings` | 업체별 컨설팅 행(`companyName`·`bizNo`·`programName`/`consultingType`·`startDate`·`endDate`·`status`·`managerMain`·`contacts`). 목차 머리말용(없어도 목차는 만든다) |
| `scal_erpTypeMap` | ERP 사업 코드 → 정부사업일정 사업 번호 연결(정부사업일정이 쓰는 그 자리) |
| 이미 읽는 것 | `scal_cos`·`scal_types`·`scal_scheds`·`scal_staff`·`scal_reports`·`scal_rptFormsIndex`·`data/user_dir` |

- 목록에서 **건너뛰는** 사업: `hidden` 이거나 `mergedInto` 가 있는 것(합친 쪽만 쓴다).
- 정렬: `sortOrder` 오름차순(같으면 이름). 기관은 `agency`(빈 값은 「기관 미지정」) 로 묶고, 묶음 순서는 그 기관의 첫 사업 `sortOrder` 순.
- 연결: `scal_erpTypeMap[code]` 가 있으면 그 정부사업일정 사업에 걸린 업체가 그 사업의 업체다. 없으면 「정부사업일정에 사업 없음」 묶음에 모은다(서류 틀이 있어도 업체 수는 0).
- 푸른이알피 행은 «머리말 보조»일 뿐이다. 업체 찾기는 정부사업일정(`scal_cos`)이 기준이고, 같은 업체의 ERP 행은 **사업자번호**(없으면 업체 이름)로 맞춘다. 못 맞추면 머리말에 「[확인 필요] 푸른이알피 계약 못 찾음」을 쓴다.

## 3. 서류 틀 (목차의 뼈대)

코드 상수 `DOC_PLANS`(순수 모듈)에 «ERP 사업 이름 낱말 → 틀» 로 둔다. 코드(`consulting-…`)는 환경마다 다르므로 **이름**(공백 뺀 이름에 낱말이 들어 있는가)으로 맞춘다.

각 틀: `{ key, kind:'간단'|'대형'|'없음', items:[ {id, name, per:'once'|'round'|'month', step:'report'|'sign'|'attach'|'submit'|'plat', note?} ], source }`

| 틀 | 이름 낱말 | kind | 서류 줄 (정리 파일 §2 기준) |
|---|---|---|---|
| `cci-north` | 충남북부 | 간단 | 결과보고서(report) · 업체 서명본(sign) · 산출물 별첨(attach) · 기관 제출(submit) |
| `cci-seosan` | 서산 | 간단 | 방문확인서(round, report) · 상담·자문 결과보고서(report) · 업체 서명본 · 산출물 별첨 · 기관 제출 |
| `techguard` | 기술보호 | 간단 | 별지11 완료보고서(report) · 법률 자문 일지(round) · 보안서약서 · 별지8 여비지급신청서 · 만족도조사 · 기관 제출(기술보호울타리) |
| `clinic` | 현장클리닉 | 간단 | 상담일지(round) · 별지24 성과추적관리결과서 · 기관 제출 — **[확인 필요: 운영지침]** |
| `rural` | 농촌융복합 | 간단 | 사업계획서 · 결과보고서(round) · 수당 영수증·청렴서약서 · 현장 사진 — **[확인 필요: 양식 글자]** |
| `workplace` | 일터혁신 | 대형 | 참여 안내서(서명) · 수행계획서(plat) · 회차별 수행보고서+사진2장+서명지(round, plat) · 착수·중간·최종보고 · 이행관리 등록 · 이행결과표 |
| `industry` | 산업일자리 | 대형 | 착수보고서(PPT) · 수행계획서 · MD별 수행일지(round) · 최종결과보고서 · 최종보고회 · 연계지원사업 등록 · 완료보고서(요약) |
| `industry-cn` | 산업일자리전환컨설팅충남 | 대형 | 수행일지 · 월별 수행실적보고서(month) · 결과보고서 · 사후관리 결과보고서 |
| `none` | (그 밖) | 없음 | 「서류 틀 없음」 — 목차는 머리말만 |

- 대형 틀은 이번에는 **목차(순서·이름)만** 보인다. 단계 상태·기준 점검(MD·방문 횟수 등)은 §14 대형형 설계에서 한다.
- 틀의 내용은 코드 상수라 바꾸려면 PR 이 필요하다(화면에서 고치지 않는다).
- `[확인 필요]` 줄은 목차에 그대로 «[확인 필요]» 딱지로 보인다 — 지어내지 않는다.

## 4. 서류 체크표 · 상태 자동 채움

열: ①초안 ②확정 ③서명본 ④별첨 ⑤제출 (+ 기한). 사업 틀이 «간단형 서식 채우기»(`cci-north`·`cci-seosan`·`techguard`)일 때만 ①② 를 자동으로 채운다 — `buildRows` 결과의 상태를 그대로 쓴다(미작성/초안/검토완료 vN). ③④⑤ 는 「—」.
다른 틀의 사업은 체크표 대신 «서류 목차 보기» 줄만 둔다(표 열을 그릴 근거 자료가 아직 없다).

## 5. 목차 창

- 머리말: 업체 이름 · 사업(ERP 이름·기관) · 계약 기간(`startDate`~`endDate`, 없으면 회차 첫·끝 날짜) · 담당(`managerMain` 없으면 정부사업일정 담당) · 회차 수.
- 본문: `1.` `2.` … 번호가 붙은 서류 줄. `per:'round'` 는 회차 수만큼 «1회차·2회차…» 로 펼친다. 줄마다 상태 딱지(① ② 자동 · 그 밖 「—」) 와 `[확인 필요]` 딱지.
- 「복사」: 같은 내용을 줄바꿈 글로 복사한다(보고서 별첨 목록·메일에 붙이기용).
- 개인정보: 업체 이름·담당 이름·날짜·서류 이름만. 연락처·보고서 본문은 넣지 않는다.

## 6. 오류 · 빈 상태

- `data/biz_cons_types` 를 못 읽으면 왼쪽 패널에 「컨설팅 사업 목록을 불러오지 못했습니다」 + 다시 시도. 오른쪽 목록은 지금처럼 동작한다(왼쪽 없이도 쓸 수 있다).
- 사업 목록이 비면 「환경설정 → 컨설팅관리에 컨설팅 사업이 없습니다」.
- ERP 행을 못 맞추면 목차 머리말에 「[확인 필요]」(목차 자체는 만든다).
