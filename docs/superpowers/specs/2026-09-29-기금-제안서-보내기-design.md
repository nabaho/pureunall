# 기금 제안서·견적서 — 문서관리에 두고, 기업정보함에서 채워 메일로 보내기 (설계)

- 날짜: 2026-09-29
- 지시: 대표 2026-09-28 「첨부서류 문서관리에 지역공동근로복지기금 제안서 등을 넣어서 관리 … 사업장 이름만 바꾸거나 기업정보함에 필요내용만 바꿔서 메일로 보내고 싶다」 → 2026-09-29 「기금관리에 제안서와 견적서를 넣어둘 수 있나, 필요시 기업정보함에서 가지고 와서 수정하고 처리하게」 → 목업 검토 뒤 「추천대로」
- 정한 것: 보내기 창은 **③-A 한 창**(왼쪽 입력 · 오른쪽 A4) + 기업정보함 입구 **③-C**. 보낸 사본은 **기업별 서류에 보관**. v7 원본 손질은 이 기능(바꿀 자리 만들기)으로 Claude 가 로컬에서 해 두고, 결과 파일은 저장소에 넣지 않는다.
- 목업: 세션 scratchpad `mock-proposal.html` (⓪ 검토 · ① 목록 · ② 자리 만들기 · ③-A/B/C · ④ 메일)

## 1. 왜

기금 제안서(v7, 약 6쪽)는 받는 곳마다 **수신자 · 참조 · 송부일자 · 담당 노무사 · 견적 금액 · 호칭**만 바뀌고 나머지(기금 개요·절차·혜택·지원금)는 그대로다(2020년 비츠로셀판과 2025년 경기도판을 견줘 확인). 지금은 한글에서 손으로 고쳐 메일에 손으로 붙인다. 앱에는 이미 ① 한글 원본에 기업정보함 값을 채우는 길(문서관리 「찾아서 채우기」), ② 회사 다음메일로 첨부까지 보내는 서버(명함첩 `sendMaterialMail`), ③ 회사별 「보낸 서류」 기록, ④ 한글처럼 고치는 편집기(경력관리·기금관리, 저장소 안 `vendor/rhwp-editor`)가 있다. **빠진 것은 이것들을 잇는 줄**이다.

## 2. 범위

넣는 것
1. 계약서 양식 › **기금관리** 안의 묶음 「계약서」 / 「제안서·견적서」
2. **바꿀 자리 만들기** — 원본 글자를 찾아 `{{표시}}` 또는 고친 글자로 바꿔 새 원본으로 저장
3. **제안서용 자동 값** — 송부일자·호칭·수신자·참조·담당노무사·연락처·부가세·합계
4. **한글처럼 손보기** — 채운 문서를 저장소 안 편집기로 고침
5. **✉ 메일로 보내기** — 확인 화면 → 직접 「보내기」 → 명함첩과 같은 서버
6. 보낸 뒤 **「보낸 서류」 기록**(종류 「제안서」) + **기업별 서류에 사본 보관**
7. **이알피 계약서 출력**이 「제안서·견적서」 묶음을 자동 체크하지 않게
8. **기업정보함 입구** — 회사 보기에 「📨 제안서 보내기」

넣지 않는 것
- 기금 설립서류 리스트(xlsx) — 기금관리 화면(fund.html) 설립 5단계와 대부분 겹친다. 빠진 항목(막도장사용동의서·막도장파기, 통장 3개·계좌 통보, 신규 참여기업 제출서류 묶음)만 **따로 작은 일**로 한다.
- 여러 곳 한꺼번에 보내기(명함첩 단체메일이 이미 있다), 예약 발송, 글자 살아 있는 PDF(그림 PDF만).
- 제안서 본문 자체를 앱이 새로 짓기(명함첩 「📝 제안서 틀」은 글자 틀이라 별개로 둔다).

## 3. 두는 곳 — 기금관리 안의 두 묶음

- 양식의 `groupName` 을 쓴다(사건계약의 사건유형과 같은 칸). 기금관리 묶음 이름은 `'계약서'`, `'제안서·견적서'` — 상수 `FUND_GROUPS`, 제안서 묶음 이름은 상수 `PROPOSAL_GROUP = '제안서·견적서'`.
- 칩 줄: 지금 사건계약에만 뜨는 묶음 칩을 **기금관리에도** 띄운다(전체 n · 계약서 n · 제안서·견적서 n). 양식 수정 창의 묶음 칸도 기금관리에서 보이고, 고르기 목록은 `FUND_GROUPS`.
- 기존 기본 양식 `fm-5`(공동근로복지기금 설립지원 계약서)는 묶음이 없으면 「계약서」로 본다(저장하지 않고 보이기만 — 시드를 고쳐 쓰지 않는다).
- 제안서 원본은 **시드로 넣지 않는다.** 대표가 「파일 업로드」로 올린다(원본 보관함 영구 보관, 저장소에는 없음). 원본에는 법인 연락처·과거 수신자 같은 실제 내용이 있어 공개 저장소에 둘 수 없다.

### 3.1 이알피 계약서 출력

`pu-erp.html` `formsForKind` 뒤 자동 체크(`initSelMap`)에서 **`groupName === '제안서·견적서'` 인 양식은 뺀다**(목록에는 보이되 체크 안 됨). 한 줄 조건 + 검사. 이알피 쪽 이름은 문자열을 그대로 쓰고, 두 파일이 같은 글자인지 검사가 견준다.

## 4. 바꿀 자리 만들기 (한 번만)

양식 도구줄 「✏ 바꿀 자리 만들기」(원본이 한글 .hwp/.hwpx 일 때만). 창은 목업 ②.

- 왼쪽: ① 찾을 글자 → 「n곳 찾음」 ② 무엇으로 바꿀까 — **표시**(자주 쓰는 자리 칩: 수신자·참조·송부일자·호칭·담당노무사·노무사연락처·견적금액·부가세·비용합계·기간·회사명·대표자) 또는 **글자**(오탈자 고치기) ③ 여러 곳이면 「모두 / 이 곳만(1/3, 2/3 …)」.
- 오른쪽: 원본 미리보기, 찾은 곳 노란 칸.
- 아래: 이번에 바꾼 것 목록(되돌리기), 「새 원본으로 저장」.
- 엔진: rhwp 문서의 `searchAllText`(위치) + `replaceText`(그 한 곳) / `replaceAll`. 바꾼 문단만 줄 다시 나누기(`formHwpFill` 과 같은 방식).
- 저장: 새 파일을 원본 보관함에 올리고 양식의 첨부를 새 것으로 바꾼다. **이전 원본은 보관함에 그대로 남는다**(지우지 않음). 양식 목록은 `changeForms` 거래로만 고친다.
- 한 번 바꾼 자리를 다시 찾으면 `{{…}}` 글자로 찾힌다 — 되돌리기는 이번 창 안에서만.

## 5. 채우기 — ③-A 한 창

지금 「찾아서 채우기」 창(`openFill`)을 넓힌다. 제안서 묶음 양식이거나 아래 자리 중 하나라도 원본에 있으면 **제안서 칸**이 보인다.

| 자리 | 기본값 | 어디서 |
|---|---|---|
| `{{수신자}}` | 기업: 회사명 / 기관: 회사명 + 담당자부서 + 담당자이름 + 직급 + 「님」 | 기업정보함 |
| `{{참조}}` | 기업: 부서 + 이름 + 직급 + 「님」(없으면 「담당자」) / 기관: 「-」 | 기업정보함 |
| `{{호칭}}` | 기업 「귀사」 / 기관 「귀 기관」 | 받는 곳 종류 |
| `{{송부일자}}` | `2026. 9. 29. (화)` | 오늘 |
| `{{담당노무사}}` | 로그인한 직원 이름 | 직원 명부 `data/user_dir`(sid→name) |
| `{{노무사연락처}}` | 이 기기에서 지난번 적은 번호, 없으면 `041-556-0035` | 브라우저 저장(직원 본인 번호 — 고객 자료 아님) |
| `{{견적금액}}` `{{부가세}}` `{{비용합계}}` | 금액 + 「부가세 포함/별도」 → 포함: 부가세 「포함」, 합계 = 금액 / 별도: 부가세 「10% 별도」, 합계 = 금액×1.1 | 손 입력 + 계산 |
| `{{기간}}` | 빈칸 | 손 입력 |

- 받는 곳 종류(기업/기관·지자체)는 창 안 두 칸 토글. 기본은 기업. 기업정보함에 종류 칸을 새로 만들지 않는다(YAGNI).
- 계산·날짜·호칭은 **순수 함수**로 `PuFormCardFill` 에 둔다: `proposalValues(V, { orgType, amount, vat, staffName, staffTel, today })` → 위 자리들. 기존 `valuesFrom` 은 손대지 않는다.
- 모든 값은 창에서 고칠 수 있고, **저장하지 않는다**(연락처 한 칸만 브라우저에 기억).
- 원본에 `{{견적금액}}` 이 있으면 금액 칸 아래에 늘 안내: 「원본의 비용 산출 표와 금액이 다르면 ✏ 손보기에서 고치거나 빼세요」.
- 아래 단추: 「✏ 한글처럼 손보기」 「⬇ 받기」 「✉ 메일로 보내기 →」. 여러 양식 묶음(세트)에서는 메일 단추를 두지 않는다(이번 범위는 제안서 한 벌).

## 6. 한글처럼 손보기

- 채운 파일을 저장소 안 편집기(`vendor/rhwp-editor/index.js`, `studioUrl: 'vendor/rhwp-studio/index.html'`)로 연다 — 경력관리·기금관리와 같은 길. **남의 주소(esm.sh·edwardkim.github.io)로 부르지 않는다**(tests/fund-hwp-no-external-editor.test.js 와 같은 검사를 문서관리에도).
- .hwp 는 편집기가 못 읽으므로 엔진으로 .hwpx 로 바꿔 연다(경력관리 `_rhToHwpx` 와 같은 방식). 손본 뒤 결과는 **.hwpx** 가 되고, 받기·메일 첨부가 그 파일을 쓴다(이름 끝도 .hwpx).
- 편집기를 못 열면 「⬇ 받기로 한글에서 고쳐 주세요」 안내 후 그대로 둔다.
- 손본 것은 이 창을 닫으면 사라진다(원본·양식은 안 바뀜).

## 7. ✉ 메일로 보내기 — ④ 확인 화면

- 보내는 곳: 명함첩 설정(`pucards/config/matMail/from`) 그대로, 답장은 보낸 직원 — 서버가 정한다.
- 받는 사람: 고른 회사의 **담당자 메일 / 대표 메일 / 직접 적기** 중 하나(기본 담당자 메일). 참조 칸(선택). 수 제한은 서버 규칙(각 5명).
- 제목 기본: `[푸른노무법인] {양식 이름} — {회사명}`. 본문 기본 틀(코드 상수, 창에서 고침, 저장 안 함):
  ```
  {참조}, 안녕하십니까.
  푸른노무법인 {담당노무사} 노무사입니다.

  {호칭}의 공동근로복지기금 설립과 관련하여 제안서 및 견적서를 보내드립니다.
  검토하시고 궁금하신 점은 편하게 연락 주십시오.

  푸른노무법인 {담당노무사} 드림 · {노무사연락처}
  ```
  `{참조}` 가 「-」이거나 비면 `{수신자}` 를 쓴다.
- 첨부: 채운(손본) 한글 파일 + **「같은 내용 PDF도 붙이기」**(기본 켬). PDF 는 엔진이 그린 쪽(canvas) → jsPDF(문서관리에 이미 있음), 그림 PDF.
- **「보내기」를 눌러야만** 나간다. 흐름: 첨부를 `pucards/mailout/{uid}/…` 에 올림(`PuDocFile.putMailFile`) → `PuDocFile.sendMail({to, cc, subject, body, toName, files})`. 명함 카드를 모르면 `cardId` 없이 보낸다(서버가 허용함을 확인).
- 서버를 쓸 수 없을 때(`matMail.mode` 가 auto 가 아니거나 서버 오류): 파일을 내려받고 `mailto:` 창을 연다 + 「첨부는 손으로 붙여 주세요」. 오류 글은 화면에 그대로 보인다.
- 두 번 누르기 막기(보내는 중 잠금), 18MB 넘으면 PDF 를 빼자고 묻는다.

### 7.1 보낸 뒤

1. **보낸 서류 기록** — `pucards/sentDocs/{coKey}/{push}` = `{at, by, kind:'제안서', names:[파일 이름], who:참조 이름}`. 받는 주소는 남기지 않는다(기존 원칙). `pu-cards.html` `SENT_KINDS` 에 `'제안서'` 를 넣는다. coKey 는 기업정보함 회사 키(`formCards` 가 쓰는 키와 같은 것), ERP 에만 있는 회사면 기록을 건너뛰고 안내.
2. **사본 보관**(기본 켬) — 보낸 한글 파일을 원본 보관함에 올리고 `PuOfficeStore.addCoDoc` 으로 그 회사 기업별 서류에 연결(분류 「제안서」). 
3. 둘 중 하나가 실패해도 메일은 이미 나갔으니 「보냈습니다 — 기록 저장은 실패(사유)」로 알린다.

## 8. 기업정보함 입구 — ③-C

- `pu-cards.html` 회사 보기(보낸 서류 칸 가까이)에 「📨 제안서 보내기」.
- 누르면 새 탭으로 `docs-esign.html#forms:propose=<coKey>` → 문서관리가 열리며 기금관리 › 제안서·견적서 묶음의 양식을 고르게 하고(하나면 바로), ③-A 창을 **그 회사가 골라진 채** 연다.
- 명함첩은 양식 목록을 읽지 않는다 — 양식은 문서관리 한 곳에만 있다.

## 9. 자료·권한

| 자리 | 누가 | 바뀌는 것 |
|---|---|---|
| `data/contract_forms` | 재직 직원 | 양식 `groupName`, 첨부 원본 교체(거래로만) |
| `pu_docs/originals`, Storage `pu_docs/originals/…` | 재직 직원 | 새 원본·보낸 사본 올리기 |
| `pu_docs/co_docs/{coKey}` | 재직 직원 | 보낸 사본 연결 |
| `pucards/sentDocs/{coKey}` | 메일 권한 직원(`pucards` 규칙) | 보낸 기록 한 줄 |
| Storage `pucards/mailout/{uid}` | 본인 | 첨부 임시(서버가 치움) |

**규칙 변경 없음**(모두 기존 자리). 새 `data/*` 키도 없음.

## 10. 안전

- 원본·채운 파일·v7·v8 은 저장소에 커밋하지 않는다. 검사에는 가짜 회사(가나상사)·가짜 사람만.
- 메일은 사람이 확인 화면에서 누를 때만. 자동·예약 발송 없음.
- 편집기는 저장소 안 것만(외부 주소 금지 검사).
- 받는 주소는 기록에 남기지 않는다.

## 11. 검사

- 순수: `proposalValues` — 송부일자 요일, 호칭, 기관 수신자 모양, 포함/별도 계산(1,000,000 → 1,100,000), 빈 값.
- 구조: 기금관리 묶음 칩, 수정 창 묶음 칸, 이알피 자동 체크 제외, `SENT_KINDS` 에 제안서, 문서관리 편집기 외부 주소 금지, 메일 보내기 전 확인(보내기 단추 누르기 전 `sendMail` 없음), 두 번 누르기 잠금, 실패 시 mailto 폴백.
- 바꿀 자리: 찾기 수·「이 곳만」·되돌리기(엔진은 가짜 문서 객체로).
- 하네스: 가짜 회사로 ① → ② → ③-A → 손보기 → ④ 까지, `sendMail` 은 가짜로 받아 보낸 내용(받는 사람·첨부 2개·기록)을 확인. 실제 발송은 대표가 한 번 시험.
