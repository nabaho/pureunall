# 메일 자료 자동 배달 — 1단계 ① 「급여 칸으로 옮긴 받은메일도 급여데이터함이 받는다」 설계

> 2026-10-17 · 상태: **대표 승인 대기** (구현 전)
> 대표 물음 「메일함에 들어오는 자료를 사업자등록증·명함·사업장 정보, 급여 기본자료 요청,
> 입퇴사 … 제브를 이용해서 자동으로 체크하고 사진첩·기업정보함·계약서 관리·급여정보함 등으로
> 알아서 분류해서 보낼 수 있을까?」 → 검토 의견 → 「네」(1단계 ①부터, 목업 먼저)

## 0. 검토 결론 (요약)

- **가능하다. 다만 제브 혼자가 아니다.** 제브(Jev, TypeSafe)는 «글자만» 읽는 분류기라
  (`functions/typesafe-evaluate.js` — 4,000자 글 하나만 보낸다) 사진·PDF 를 못 본다.
  사업자등록증·명함의 «사진 읽기»는 지금처럼 사진첩 판독(Google Vision → Gemini)이 맡는다.
- 분류·배달 길은 **이미 대부분 있다.** 빠진 것은 «메일 → 각 앱» 마지막 연결뿐이다.

| 자료 | 지금 | 빠진 연결 |
|---|---|---|
| 급여자료 | 「급여」 이름 폴더는 30분마다 서버가 급여데이터함으로 자동 수거(`receivePaydataMail`) | 제브가 받은메일함에서 «급여 칸»으로 옮긴 메일은 실제 폴더가 그대로라 수거 대상이 아니다 |
| 입퇴사 | 급여데이터함이 본 메일은 「📋 입퇴사 할 일」이 자동으로 선다(`js/pu-hr-intake.js`) | 위와 같다 — 수거가 안 본 메일은 할 일도 안 선다 |
| 사업자등록증·명함 | 사진첩에 들어오면 판독 → 가림 → 검산된 사업자번호만 기업정보함 자동 반영 | 메일 → 사진첩이 단추다 |
| 계약서 | 「→ 기업별 계약서」가 회사·종류를 미리 채운 확인 창 | 여러 건 한꺼번에가 없다 |

- 단계: **1단계 = 있는 길 잇기**(제브를 새로 안 쓴다) → 2단계 = 규칙이 못 가른 첨부만 제브에게 묻기.
  이 문서는 1단계 ①만 다룬다. ②(서류 사진 → 사진첩 자동 배달)·③(계약서 후보)은 따로 설계한다.

## 1. 무엇을 바꾸나

`receivePaydataMail`(30분마다)이 폴더를 고를 때(`MR.pickMailboxes`) 지금은
- 이름에 「급여」가 든 폴더 전부
- 받은메일함은 «전부 보기» 스위치(`paydata/mailconf/scanInbox`)를 켰을 때만 — 켜면 자문·산재 메일까지 연다

**새로**: 스위치가 꺼져 있어도, 받은메일함 가운데 **푸른 분류에서 「급여」 칸으로 옮겨진 메일만**
골라서 본다. 받은메일함 전부를 여는 것이 아니다.

- 「급여 칸」 = `pucards/config/mailBins` 의 칸 이름에 「급여」가 든 것(예: `2.급여+사무대행`).
  폴더를 고르는 잣대(`MAILBOX_HINT = '급여'`)와 같은 말을 쓴다 — 두 잣대가 어긋나지 않게.
- 「옮겨진 메일」 = `pucards/config/mailPut/{받은메일함 slug}:{uid}` 가 급여 칸을 가리키는 것.
  사람이 「분류˅」로 옮긴 것과 제브가 옮긴 것(`config/mailPutBy = 'ai'`)이 같은 자리에 적힌다.
- uid 는 같은 다음메일 계정·같은 받은메일함의 IMAP 번호라 수거 서버가 그대로 쓴다.
- 읽는 양: 회차마다 `mailPut` 중 받은메일함 열쇠만(`orderByKey` 범위) + `mailBins`(작다). 전부를 읽지 않는다.
- 지난 14일 것만 본다(지금 수거와 같은 `PAYMAIL_LOOK_DAYS`). 몫(`PAYMAIL_MAX_PER_RUN`)도 함께 센다.

그러면 저절로 따라오는 것:
- 그 메일의 첨부 → 급여데이터함(확인 대기 또는 서랍) — 지금 길(`payMailStoreOne`) 그대로
- 그 메일 → `paydata/maillog` 한 줄 → **「📋 입퇴사 할 일」이 선다** — 화면이 maillog 에서 다시 센다

## 2. 결정할 것 (대표)

**제브가 옮긴 메일을 어디까지 믿을까** — 사람이 옮긴 것은 급여 폴더와 똑같이 대접한다
(대표가 규칙으로 손수 가른 폴더와 같은 무게). 제브가 옮긴 것은 «짐작 위의 짐작»이다.

| | 가 (권장) | 나 |
|---|---|---|
| 업체관리에 없는 주소 | 담지 않고 목록에만 남김(까닭 적음) — «받은메일함 전부 보기»와 같은 잣대 | 급여 폴더처럼 주소 안 가림 |
| 다섯 잣대를 다 통과 | **확인 대기까지만** — 서랍에 바로 넣지 않음 | 급여 폴더처럼 바로 서랍 |
| 입퇴사 할 일 | 선다(할 일은 «처리 완료» 전까지 사람이 본다) | 선다 |

권장 까닭: 제브가 틀려 엉뚱한 메일이 급여 칸에 가도, «가»에서는 확인 대기에 보여서 사람이 잡는다.
«나»에서는 서랍에 조용히 들어가 아무도 모를 수 있다 — 이 저장소가 늘 지켜 온 「잘못 넣느니 안 넣는다」.

## 3. 화면에서 달라지는 것 (목업 — 가짜 자료)

1. 급여데이터함 「마지막 확인」 줄에 한 마디:
   `서버가 마지막으로 본 때 오늘 09:30 · 폴더 2.급여+사무대행 · 새 메일 3통 · 받은메일함에서 급여 칸으로 옮긴 메일 2통`
2. 급여데이터함 「받은 메일」 목록의 그 줄에 작은 꼬리표: `📥 받은메일함 → 급여 칸 (🤖 AI)` 또는 `(사람)`
3. 메일함은 바뀌지 않는다(옮기는 동작·🤖 배지 그대로).

## 4. 지키는 것 (안 바꾸는 것)

- 다음메일 원본은 손대지 않는다. 읽음 표시도 안 바꾼다.
- 판독(AI)을 여기서 돌리지 않는다 — 주민번호 가림을 건너뛰게 된다(지금 원칙 그대로).
- 이름·상호로 업체를 잇지 않는다 — 주소·사업자번호로만(온톨로지).
- 사람이 나중에 그 메일을 급여 칸에서 빼도, 이미 담긴 자료를 자동으로 지우지 않는다(자료는 대기 칸에 보인다).
- 컨설팅 메일 거르기(`MR.consultMail`)·처리 기록(`mailseen`)은 그대로 탄다 — 두 번 담지 않는다.
- 제브가 꺼져 있으면(`config/mailAiClassify.on` 거짓) 사람이 옮긴 것만 남는다 — 그것도 그대로 돈다.

## 6. 검사 (구현 때)

- 스위치 꺼짐 + 급여 칸으로 옮긴 uid 만 받은메일함에서 고른다 / 다른 칸으로 옮긴 것·안 옮긴 것은 안 고른다
- 「급여」 칸 판정이 폴더 잣대(`MAILBOX_HINT`)와 같은 말을 쓴다
- (가) 제브가 옮긴 것은 모르는 주소면 안 담고, 다섯 잣대를 통과해도 서랍에 바로 안 넣는다
- 그 메일이 maillog 에 적혀 입퇴사 할 일이 선다
- mailPut 을 통째로 읽지 않는다(받은메일함 열쇠 범위만)
