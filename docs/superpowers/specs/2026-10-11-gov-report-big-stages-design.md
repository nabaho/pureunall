# 컨설팅보고서 — 대형 사업 단계 체크표 설계 (설계 2-A)

- 작성일: 2026-10-11 · 상위: `2026-10-05-정부컨설팅-보고서자동화-design.md` §14 · `2026-10-10-gov-report-docs-design.md`(서류 틀·체크표) · `2026-10-10-gov-report-track-design.md`(서류 진행 기록) · `2026-10-11-gov-report-sign-submit-design.md`(서명·제출 초안)
- 대표 지시: 「2」(설계 2) → 「추천」(2026-10-11). 순서는 **2-A 단계 체크표 → 2-B 회차 기록·기준 점검 → 2-C 장별 AI 초안**. 이 문서는 **2-A 만** 다룬다.
- 사업 내용 근거: 공개 저장소 밖의 대표 PC 정리본(`컨설팅보고서_사업별_양식·항목_정리_2026-10-09.md` §2-5~2-7). 여기는 구조만 적는다.

## 1. 풀려는 일

대형 사업(일터혁신 상생 · 산업일자리 중진공·KMAC · 산업일자리 충남 지원센터)은 «서식 한 장 채우기»가 아니라 **단계마다 서류와 플랫폼 입력이 따로 있다.** 지금 체크표는 간단형 셋만 ③서명본·④별첨·⑤제출 칸이 열려 있고 대형은 「서류 목차 보기」뿐이라, **어느 사업장이 어느 단계에서 멈췄는지** 현황판에서 안 보인다. 2-A 는 그것만 푼다 — 단계별 상태·날짜·메모·받은 서류 연결을 남기고, 「다음 단계」와 «막힘»을 한눈에 보이게 한다.

이미 있는 것(다시 만들지 않는다)
- `DOC_PLANS` 의 대형 3종 서류 틀(항목 `id·name·per·step`, `step` ∈ `sign|plat|report|attach|submit`).
- 서류 진행 기록 `scal_docs/{업체}/{rid}/items/{키}` 와 칸 창(상태·날짜·메모·연결), 받은 서류함, 설계 1 의 서명 요청 메일 초안.
- **쓰기 규칙이 이미 열려 있다**: 줄 키는 `^[a-z]+(:[0-9]+)?$`·20자 이하이고 대형 서류 틀 항목 `id`(`guide·plan·round·kickoff·mid·final·follow·outcome·mdlog·meeting·link·done·log·monthly·result·after`)는 모두 맞는다 → **새 규칙·게시 없음**(규칙 검사 테스트로 못 박는다).

## 2. 범위

한다
1. **단계 열** — 사업을 고르면(왼쪽 패널) 대형 사업의 체크표 열이 «서류 틀 항목 순서대로 단계 열»이 된다. 칸은 그 업체의 그 단계 칩(없음 ○ · 진행 ◐ · 완료 ● · 막힘 ✕ · 해당없음 —, 여럿이면 `완료/전체`).
2. **칸 창 재사용** — 단계 칸을 누르면 기존 칸 창이 열린다: 상태 · 날짜(「완료일」, 서명 단계는 발송일/회신일) · 메모 · 📥 받은 서류 후보·연결. 회차마다 나오는 서류(`per:'round'`)는 «서류» 고르기로 회차를 고른다(기존 기술보호 ④ 와 같다).
3. **서명 단계**(`step:'sign'`, 예: 일터혁신 «참여 안내서(서명)») 는 설계 1 의 「✉ 서명 요청 메일 쓰기」·보냄 기록·회신 후보를 그대로 쓴다.
4. **플랫폼 단계**(`step:'plat'`) 는 칸 창에 «입력 순서 체크 글» + «증빙 안내»를 보인다(고정 글, 저장 안 함). 로그인과 최종 제출은 사람이 한다. Aside 자동 입력은 하지 않는다.
5. **다음 단계 · 막힘** — 표 끝에 「다음 단계」 열(`done·na` 가 아닌 첫 단계 이름) · 현황판 ⏰ 목록에 **「막힌 단계」** 묶음 추가(`st:'blocked'` 인 줄, 사업장·단계 이름·메모). 「다음 단계」는 **표시일 뿐** — 앞 단계가 안 끝나도 뒤 단계를 기록할 수 있다(현장에서 순서가 뒤집히므로).
6. **월별 서류**(`per:'month'`, 충남 지원센터 «월별 수행실적보고서») 는 계약 기간(없으면 회차 날짜)의 «달 수»만큼 키 `monthly:1`…`monthly:N`(이름 «YYYY-MM 월별 수행실적보고서») 를 만든다. 상한 60.

하지 않는다
- 회차 기록(형태·시간·참석자·사진·서명지)과 **기준 점검**(방문 수·대면 70%·2시간·3명·MD·KPI) — 2-B (새 자료 칸·새 규칙이 필요해 대표 승인 뒤).
- 장별 AI 초안(착수 PPT · 최종결과보고서) — 2-C.
- 기한 계산 — 사업마다 달라 만들지 않는다(노무사가 날짜를 적는다).
- 단계 순서 강제 · 현황판 KPI 숫자 칸(서명·제출)·막대 ③④ 의 대형 확장 · Aside 플랫폼 입력.

## 3. 데이터 · 모듈

기존 `PuGovReportTrack`(`js/pu-gov-report-track.js`) 을 «단계 종류»로 넓힌다. 새 파일 없음, 새 DB 칸 없음.

- `ALLOWED`·`STEP_KO`·`COL_KO` 에 `plat`·`report` 를 더한다.
  - `plat`: `['none','doing','done','blocked','na']`, 글 `{ doing: '입력 중', done: '등록함' }`, 열 이름 «플랫폼 입력».
  - `report`: 같은 상태 집합, 글 `{ doing: '작성 중', done: '작성 완료' }`, 열 이름 «보고서».
  - 간단형의 `report` 항목은 지금처럼 현황판 상태(①②)를 따른다 — **대형 사업 틀에서만** `report` 를 손으로 기록한다.
- `keysForItem(plan, itemId, n, months)` — 항목 하나의 줄 키들(`once` → `[id]`, `round` → `id:1..n`, `month` → `id:1..m`). 기존 `keysFor(plan, step, n)` 은 그대로(간단형).
- `bigCells(plan, rec, n, months, today)` → `[{ id, name, step, chip }, …]` — 칩은 기존 `chipOf` 계열(여럿이면 `완료/전체`).
- `nextStage(plan, rec, n, months)` → 첫 «미완» 단계 `{ id, name } | null`(전부 완료·해당없음이면 `null`).
- `blockedOf(plan, rec, n, months)` → `[{ id, key, name, note }]`.
- `alertsExtra` 에 `blocked` 묶음 추가(대형 사업 줄만). 기존 `waitSign`·`overdue` 는 건드리지 않는다.
- `PuGovReportDocs.docsTable` — `plan.kind === '대형'` 이면 `{ big:true, cols:[단계 이름…, '다음 단계'], lines[].cells:[{id, name, step, chip}], lines[].next }` 를 돌려준다(간단형은 지금 그대로). `months(start,end)` 는 이미 목차에 있다 — 그것을 쓴다.
- `DOC_PLANS` 대형 항목에 선택 필드 `steps`(입력 순서 체크 글)·`note`(증빙·기준 안내 글)를 더한다(코드 상수, 간단형 `how/steps` 와 같은 방식). 글은 **[노무사 확인]** 초안:
  - 일터혁신: 수행계획서 · 회차별 수행보고서(+시작·종료 사진 2장, 참석자 전원 서명지) · 디자인팀·이행관리 등록 · 이행결과표.
  - 산업일자리(중진공·KMAC): 착수보고서(PPT) 업로드 → 수행계획서 승인 → MD별 수행일지 → 최종결과보고서 제출·검수 → 최종보고회 → 연계지원사업 등록 → 완료보고서.
  - 충남 지원센터: 수행일지 · 월별 수행실적보고서 · 결과보고서 · 사후관리 결과보고서.

## 4. 화면 (`gov-report.html`)

- `grRenderDocs` 가 `t.big` 이면 단계 열 표를 그린다: 업체 | 단계 열들(칩 단추 `data-cell` + `data-item`) | 다음 단계 | 기한 | 목차. 단계가 많아(최대 10열) 가로 스크롤을 허용한다.
- `grOpenCell(coId, typeId, step, itemId)` — `itemId` 가 있으면 `keysForItem` 으로 키를 만든다(없으면 지금처럼 `keysFor`). 저장은 **기존 `grSaveCell` 한 곳**(줄 하나 `.set`) — `validate(entry, c.step)` 이 `plat`/`report` 를 받아들이게 된다.
- 칸 창: `plat`·`report` 단계는 상태 · 완료일(`gotAt`) · 메모 · 받은 서류 연결. `plat` 은 `#cwSend` 구역에 체크 글(`item.steps`)과 증빙 안내(`item.note`)를 보인다(글자로만 — `grEsc`).
- ⏰ 알림: 「막힌 단계 N」 묶음(사업장 · 단계 이름 · 메모 — 메모는 이미 있는 사람이 쓴 글이라 `grEsc`).
- 대형 사업 줄에는 기존 «서류 목차 보기» 단추를 그대로 둔다.

## 5. 개인정보 · 쓰는 곳

- 쓰기: **`scal_docs` 줄 하나 `.set`(`grSaveCell`) 한 곳**. 새 필드 없음(`st·gotAt·sentAt·note·link·by·at`). 새 `.set/.update/...` 없음. **규칙 변경·게시 없음.**
- 읽기: 지금과 같다(서류 틀·계약·기록·메일함 거울 머리글). AI 로 보내는 것 없음.
- 메모에 연락처·주민번호를 적지 않도록 칸 창 안내는 그대로.
- 공개 저장소: 검사·문서·상수 글에 고객사·사람 이름·연락처·실제 주소를 쓰지 않는다.

## 6. 오류 · 경계

- 기록을 못 읽었으면(`GR.trackErr`) 단계 칸은 칩 대신 「?」, 칸 창은 열지 않는다(지금과 같다).
- 사업 이름이 서류 틀에 없으면(`NONE`) 단계 열 없이 기존 안내.
- 회차 수·월 수가 0 이면 해당 항목의 칸은 «—»(키 없음).
- `done` 이 아닌 단계가 하나도 없으면 「다음 단계」는 「모두 끝」.
- 규칙에 걸리는 키(소문자 외 글자·20자 초과)는 항목 `id` 검사에서 거른다(`keysForItem` 이 `okKey` 로 걸러 키를 만들지 않는다).

## 7. 검사 계획

- `keysForItem`: `once/round/month` 키 · 상한 60 · 이상한 id(`__proto__`·대문자·21자) 거부 · 기존 `keysFor` 불변.
- `bigCells/nextStage/blockedOf`: 합성 기록으로 — 일부 완료·막힘·해당없음·전부 완료 · 회차 서류의 `완료/전체`.
- 규칙 일치: 대형 3종의 모든 항목 `id`·회차·월 키가 규칙 줄 키 식과 20자 한도를 통과(`tests/gov-report-rules.test.js` 와 같은 식).
- `docsTable` 대형: 열 이름·순서가 `DOC_PLANS` 와 같고 간단형 출력은 그대로(스냅숏 동일).
- `gov-report.html` 정적·동작: 쓰기는 `.set(` 한 곳 · 단계 칸이 `grOpenCell(...,itemId)` 로 열림 · `plat` 체크 글이 이스케이프됨 · 막힘 묶음 표시 · 서명 단계에서 설계 1 단추가 나옴 · 간단형 체크표·칸 창 회귀 없음.
- 실제 확인(대표 PC·로그인): 일터혁신 사업 하나에서 단계 칸 기록·읽기·삭제.
