# 홈페이지 월간 자동 연결 — 설계

- 날짜: 2026-10-05 · 가지: `feat/home-auto-monthly`
- 대표 결정: 「나」(올리기까지 자동) → 「추천대로」(처음 한 번은 홈페이지 관리 화면에서 넣음) →
  「추천대로」(멈춤 장치) → 「1개월에 1번씩만」 → 「가」
- 목업: 대표께 파일로 보냄(저장소에 안 넣음). 결론만 여기와 `status/` 에 적는다.

## 1. 무엇을 하나

매달 1일 아침 8시(서울)에 서버가 스스로 돈다. 푸른ERP 는 **읽기만** 한다.

| ERP 에서 본 것 | 홈페이지에 하는 일 | 단계 |
|---|---|---|
| 직원 `status=retired` | 구성원 소개 글 → 휴지통 | 1 |
| 업체 `status=closed` | 자문사현황 로고 글 → 휴지통 | 1 |
| 새 자문 거래처(자문료 있음·사무대행 아님·아직 표시 안 함) | 로고+공개 동의가 «둘 다» 있으면 올림, 아니면 할 일 | 2 |
| 새 노무사 | 사진+경력이 있으면 올림, 아니면 할 일 | 3 |
| 새·퇴사 일반직원 | 구성원 쪽 본문의 이름 줄 고치기 | 4 |

급할 때는 관리 화면의 「지금 한 번 돌리기」로 같은 일을 부른다. 단계마다 PR 을 따로 낸다.

## 2. 바꾸지 않는 원칙

- **지우지 않는다.** 내리는 것은 언제나 휴지통(`내리는type="trash"` 상수)이다. `delete` 는 보낼 길이 없다.
- **휴직(`leave`)은 내리지 않는다.** 퇴사와 다른 것이다.
- **이름으로 잇지 않는다**(온톨로지 규칙). 자동으로 움직이는 것은 «영구 번호로 이어진» 것뿐이다.
  - 구성원 글 ↔ 직원: `homepage/members/{key}.sid`
  - 로고 글 ↔ 업체: `homepage/partners/{companyId}.boardSrl`
  - 이 연결은 **사람이 한 번 확인해서** 넣는다. 이름이 한 사람과만 맞아도 자동으로 채우지 않는다.
  - 연결이 없는 글은 손대지 않고 할 일 「연결 확인」에 올린다.
- **「남기기」는 지킨다.** 구성원의 `keptOf`와 마찬가지로, 업체에도 «계약은 끝났지만 실적으로 남김» 표시를 둔다. 표시가 있으면 내리지 않는다.
- **글 번호가 겹치면 보내지 않는다**(지금 `srlConflict`와 같은 규칙).
- **홈페이지 수정은 총괄관리자만** 할 수 있다. 화면 단추와 서버 둘 다 `uid_roles/{uid}.isAdmin` 으로 막는다.

## 3. 멈춤 장치

- 한 번 돌 때 내릴 것이 **5건을 넘으면 하나도 내리지 않는다.**
  - 그 목록을 `homepage/auto/runs/{YYYY-MM}` 에 «멈춤»으로 남기고, 할 일 맨 위에 띄운다.
  - 대표가 「모두 내려도 됩니다」를 누르면 **그 목록 그대로만** 내린다. 누르는 순간 서버가 다시 세어서 목록이 달라졌으면 또 멈춘다.
- 끄는 스위치: `homepage/auto/config.off === true` 면 아무것도 하지 않는다(세지도 않는다). 이것은 `monthlyExportLogTidy` 와 같은 꼴이다.
- ERP 를 못 읽었거나 비어 있으면 «0건»이 아니라 **실패**로 남기고 아무것도 하지 않는다. ERP 업체 190건이 «사라진 것처럼» 보였던 일(2026-09-29)과 같은 경우를 막는다.

## 4. 구조

```
functions/homepage-auto.js        순수 로직 — 고르기(ERP·연결·표시) → {내릴것, 할일, 멈춤}
functions/index.js
  monthlyHomepageAuto             pubsub.schedule("0 8 1 * *") Asia/Seoul
  homepageAuto (onRequest)        총괄관리자만 · mode: 보기 | 돌리기 | 승인
  (공용) 홈내리기(그릇, srl, 게시판)  homepageWrite 의 휴지통 길을 꺼내 함께 쓴다
pu-home.html                      «자동 연결» 카드 · 연결 확인 · 멈춤 알림 · 기록
```

- 고르는 규칙은 `homepage-auto.js` **한 곳**에만 둔다. 화면의 「보기」도 서버의 `mode:보기` 를 불러서 같은 답을 받는다(규칙이 두 벌이 되지 않게).
- 자문사현황 글(`partner_board`)은 구성원 글과 생김새가 다르다. 그래서 `막을까`(경력 칸 자물쇠)를 거치는 고치는 길 대신, **문서 관리 화면에서 확인표를 받아 휴지통으로만** 보낸다.
  - 게시판 이름은 허용 목록(`people_board`·`partner_board`) 밖으로 나가지 않는다.
  - 1단계 첫 일은 이 길을 **정찰**하는 것이다(값은 안 보고 칸 이름만 본다).
- 기록: 한 건마다 `homepage/writeLog/{srl}` 에 남긴다(지금과 같은 자리). `by` 는 `"auto"`. 한 번 돈 결과는 `homepage/auto/runs/{YYYY-MM}` 에 남는다.
- 되살리기: 라이믹스 휴지통에서 되살리는 길을 정찰한다. 찾으면 기록 줄의 「되살리기」가 서버를 부르고, 못 찾으면 그 단추가 라이믹스 관리자 휴지통을 연다(있는 그대로 말한다).

## 5. 자료 자리(RTDB)

| 자리 | 쓰는 쪽 | 내용 |
|---|---|---|
| `homepage/auto/config` | 화면(관리자) | `{off}` |
| `homepage/auto/runs/{YYYY-MM}` | 서버 | `{at, 내림[], 멈춤, 할일수, 실패}` — 이름은 안 담고 sid·companyId·srl 만 |
| `homepage/members/{key}.sid` | 화면(관리자) | 연결 확인 |
| `homepage/partners/{companyId}.boardSrl` · `.keep` | 화면(관리자) | 로고 연결 · 남기기 |

- 규칙은 `scripts/make-firebase-rules.js` 에 넣고 바로 올린다(CLAUDE.md 절차). 읽기와 쓰기 모두 `homepage/*` 의 지금 권한(관리자)을 그대로 따른다. 더 넓히지 않는다.
- 새 레코드는 온톨로지 관문(`pu-ontology-write.js` / 서버 `ontology-write-server.js`)을 거친다.

## 6. 화면(목업 그대로)

1. 왼쪽 기둥 «자동 연결» 카드: 마지막·다음 돈 때, 내림·올림 수, 넣어 주셔야 할 것, 「기록 보기」·「지금 한 번 돌리기」.
2. 할 일: 「연결 확인 N건」, (2단계부터) 「로고·동의 넣기」·「사진·경력 넣기」.
3. 멈춤 알림: 무엇을·왜(ERP 근거)·홈페이지 상태 표 + 「모두 내려도 됩니다 / 하나씩 보기 / 이번 달은 그대로 둠」.
4. 기록: 때·한 일·누구/어디·되살리기.

표의 한 칸은 한 줄로 쓰고, 색은 27색 팔레트 안에서만 쓴다.

## 7. 검사

- `homepage-auto.js` 순수 로직을 실제로 돌려 확인한다. 아래 각 규칙을 **되돌렸을 때 검사가 실패하는지**(변이 검증)까지 본다.
  - 연결 없으면 안 내림
  - 휴직은 안 내림
  - 남기기는 안 내림
  - 번호 겹침은 안 내림
  - 5건 초과면 0건
  - ERP 를 못 읽으면 실패
  - 사무대행·종료 업체 규칙
- 보내는 `type` 은 `trash` 뿐이다(지금 검사를 넓힌다).
- 게시판 허용 목록 밖으로는 못 나간다.
- 서버 함수에 관리자 확인이 있다.
- 화면: 카드·멈춤 알림을 상자 안에서 실제로 그려 보고 확인한다.
- 지금 값을 박지 않는다(5건 같은 문턱은 상수 이름으로 확인한다).

## 8. 배포와 남은 위험

- 함수는 이름을 찍어 배포한다: `functions:monthlyHomepageAuto,functions:homepageAuto`.
  - 새 함수는 공개 호출 권한이 없으므로 `homepageAuto` 에 넣어 줘야 한다(안에서 관리자 확인을 한다).
- ⚠ ERP 퇴사 처리가 늦으면 자동도 늦다(김석우 님 사례). 이것은 ERP 쪽 일이다.
- ⚠ 2~4단계는 라이믹스 «새 글 쓰기»와 쪽 본문 고치기 정찰이 먼저다. 정찰 결과에 따라 설계를 다시 여쭙는다.
