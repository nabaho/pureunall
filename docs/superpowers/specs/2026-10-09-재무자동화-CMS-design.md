# 재무 자동화 1단계 — CMS 자동이체 입금 (설계)

- 작성 2026-10-09 · 대표 지시 「사람이 체크해야 하는 항목 제외하고 자동화」 → 가안(서버·예약 작업) 「추천대로」 → 「어사이드로 자동 넣고 확인」 「추천대로」
- 목업(승인): 재무관리 › 🤖 자동 처리 — 흐름 · 확인 상자 · 자동 확정 조건 (목업 파일은 저장소에 넣지 않는다)
- 정한 것: Aside 를 돌릴 PC = **대표 PC(이 PC)** · 읽는 때 = **매일 아침 9시, 지난 7일** · 확인 상자 = **관리자만**

## 1. 왜

2026년 6~9월 입금 699건 중 605건(87%)이 그달에 안 들어가 있다가 10/2(더빌 대조 372)·10/3(엑셀 233)에 뒤늦게 들어갔다.
그동안 미수금·성과급·예상부가세가 틀린 채였다.

- CMS 돈은 통장에 **여러 업체 합계 한 줄**(「더빌이체3572」)로 들어온다. 업체별로 나누려면 더빌 «출금결과»가 있어야 한다.
- 출금결과 파일을 올리는 화면(`CmsMatchModal`)은 있지만 사람이 매달 받아 올려야 해서 거의 안 쓰였다(`cms_ledger` 에 8월 파일 하나).
- 금액만으로 업체를 고르는 추측은 2026-09-15 김보람 노무사 건의로 막혀 있다 — 이 설계도 추측을 쓰지 않는다.

## 2. 시험 결과 (2026-10-09, 읽기만)

- Aside(이 PC)에서 대표가 더빌 «가맹점 관리자»로 로그인 → 2차 인증 → `www.thebill.co.kr:444` 관리자 화면.
- 출금결과조회: 메뉴 `$.loadContent('/cms2/cmsPayList.tb?menucd=CMS5010')`
  - 조회 칸: `searchDateType`(send 출금일) · `startDate` · `endDate` · `statusCd`(T01 대기 · T02 실패 · T03 완료) · `setListPerPage`(100)
  - 표 칸: 구분 · 출금일/최초출금일 · 회원코드 · 회원명 · 연락처/이메일 · 출금정보 · 납부금액/정산(예정)일 · 수수료 · 상태
- 10/2~10/9 12건을 읽었다. 이알피와 견주니 10건 있음 · **1건 빠짐(이레메디컬의원 10/7 88,000)** · 1건 출금 실패.
- 보안 프로그램에 막히지 않았다. 직접 주소 호출은 500 이 나니(10/2 기록) 화면 메뉴 함수로 연다.
- 로그인이 얼마 만에 풀리는지는 아직 모른다 — 첫 주에 잰다.

## 3. 사람 몫 (자동화하지 않는다)

1. **더빌 로그인** — 비밀번호·인증은 사람만. Aside 보관함(Vault)에 더빌 비밀번호를 넣지 않는다.
2. **확인 상자** — 처음 보는 회원 잇기 · 금액 다름 · 그 달 입금이 이미 있음 · 통장 합계 안 맞음 · 마감된 달.
3. 자동 확정 스위치 켜기·끄기, 되돌리기.

## 4. 짜임

```
[이 PC · 작업 스케줄러 09:00]
  scripts/thebill-pull.js ──aside repl──▶ 더빌 출금결과조회 (조회만)
        │  로그인 풀림 → status.needLogin=true (+ 이 PC 알림창)
        ▼
  data/cms_pull/v   ← 받은 줄을 «지문(_k)» 열쇠로만 더한다 (같은 줄 두 번 안 쌓임)
        │
[관리자가 이알피를 켜 둘 때 · 켤 때 + 30분마다]
  erpCmsAutoRun()
        ├─ cms_pull → cms_ledger 합치기 (erpCmsLedgerSave 그대로)
        ├─ 줄마다 판정 → 자동 확정(erpUpsertIncome) 또는 확인 상자
        └─ 통장 「더빌이체」 일괄 줄은 «처리됨»으로만 (입금으로 또 만들지 않는다)
```

### 4-1. 받기 — `scripts/thebill-pull.js` (새 파일, 이 PC 에서만)

- `aside repl` 로 열린 탭 가운데 `thebill.co.kr:444` 를 찾는다. 없거나 로그인 화면이면 → `needLogin`.
- 출금일 기준 «오늘−7일 ~ 오늘», 100건씩, 쪽이 넘으면 다음 쪽까지. 상태는 전부(성공·실패·대기).
- **누를 수 있는 것은 «조회»와 쪽 넘기기뿐** — 「삭제」「출금」「재출금」「회원」 단추는 이름표로 막는다(허용 목록).
- 한 줄 모양은 이미 쓰는 `erpNbSlimRow` 와 같다: `src:'nicebill' · wdate · setdate · name · code(회원코드) · amount · fee · statusRaw · status(ok/fail/pending) · reason · bank`.
  **연락처·이메일·계좌번호는 담지 않는다.**
- 지문 `_k` 는 `_nbRowSig` 와 같은 규칙(출금일·회원·금액·회원코드, 같은 날 같은 줄은 #1·#2).
- 쓰는 곳: `data/cms_pull/v/rows/{_k}` (더하기만) · `data/cms_pull/v/status` `{lastRunAt, lastOkAt, needLogin, read, error}`.
  firebase CLI(이 PC 로그인)로 `database:update` — 표 통째 쓰기는 하지 않는다.
- 실패해도 이알피에는 아무것도 안 바뀐다. 다음 날 7일 창이 겹치므로 하루 빠져도 다시 줍는다.

### 4-2. 업체 잇기 — 업체 기록의 `cmsMemberCodes`

- 더빌 회원코드 ↔ 업체는 **업체 기록에 `cmsMemberCodes: ['2209603282', …]`** 로 적는다(새 최상위 자리를 만들지 않는다).
- 처음 보는 회원은 확인 상자에 «잇기 후보»를 보여 준다 — `erpNicebillMatchCo`(이름·사업자번호·예전 이름)로 찾되 **누르기 전엔 잇지 않는다.**
- 사람이 「이 업체로 잇기」를 누르면 `dbPatch('companies', id, {cmsMemberCodes})` 한 건. 다음 달부터 자동.
- 첫 잇기를 덜어 주려고, 10/2 더빌 대조 469건(이미 사람이 확인한 업체)을 근거로 «잇기 제안 목록»을 한 번 만든다 — 이것도 사람이 한 번에 확인한 뒤에만 적는다.

### 4-3. 처리 — `erpCmsAutoRun()` (pu-erp.html)

관리자 로그인 + 스위치(`app_settings.cmsAutoConfirm`) 켜짐일 때만 확정한다. 꺼져 있으면 «미리보기»만(무엇을 확정했을지 상자에 회색으로).

줄마다:

| 판정 | 조건 | 결과 |
|---|---|---|
| 출금 실패 | status = fail | 「출금 실패」 탭 (입금 안 만듦) |
| 처음 보는 회원 | 회원코드가 어느 업체 `cmsMemberCodes` 에도 없음 | 확인 상자 |
| 금액 다름 | 금액 ≠ 월 자문료 (부가세 별도면 ×1.1 도 인정) | 확인 상자 |
| 그 달 입금 이미 있음 | 받을 달에 그 업체 자문료 입금이 있음 | 확인 상자 |
| 마감된 달 | `isIncomeLocked(받을 달)` | 확인 상자 |
| 이미 넣음 | `finance_income` 에 같은 `cmsKey(_k)` | 건너뜀 |
| **자동 확정** | 위 어느 것에도 안 걸림 | `erpUpsertIncome` |

- 받을 달(advisoryYm) = 그 업체 직전 자문료 입금의 다음 달. 직전이 없으면 출금일의 달. (10/2 대조 때의 규칙 — 말일 출금이 한 달 밀리지 않게)
- 넣는 값: `kind:'자문료' · date:출금일 · amount · companyId · companyName · advisoryYm · cmsKey:_k · autoConfirmed:true · autoBy:'cms-auto' · note:'[나이스빌CMS] 출금일 자동이체 (더빌 출금결과 자동)'`.
  담당·성과 나눔은 `erpUpsertIncome` 이 지금처럼 한다(세후 기준, 마감 달 규칙 그대로).
- 통장 줄: 거래내역의 「더빌이체」 입금은 그날 명세 합계와 `_nbAmtFits` 로 맞으면 `bank_processed` 에 «CMS 명세로 처리됨»만 찍는다.
  **이 줄을 입금으로 따로 만들지 않는다** — 2026-01·02 겹침 43건(「CMS 일괄이체 자동매칭」+「[나이스빌CMS]」 두 줄)이 바로 그것이었다.
  안 맞으면 확인 상자 「통장 합계 안 맞음」.
- 되돌리기: 「자동 확정 기록」에서 한 건씩 → 휴지통(`TrashBin`, 사유 적음). 되돌린 `_k` 는 다시 자동 확정하지 않는다(`cms_pull/v/skip/{_k}`).

### 4-4. 화면 — 재무관리 › 🤖 자동 처리 (관리자만)

목업 그대로: 위 띠(명세 건수 · 자동 확정 · 확인할 것 · 출금 실패 · 마지막으로 읽은 때) · 탭 셋(확인할 것 / 출금 실패 / 자동 확정 기록).
- 줄은 한 줄, 맨 왼쪽 ☐ + 번호. 「고른 것 한 번에」.
- `needLogin` 이면 띠가 빨갛게: 「더빌 로그인이 풀렸습니다 — Aside 에서 로그인해 주세요 (마지막 성공 ○일 전)」.
- 사이드바 재무관리 옆에 확인할 것 건수.

## 5. 지키는 것

- 금액만 맞춘 추측으로 확정하지 않는다. 업체는 회원코드 연결(사람이 확인한 것)로만.
- 이름으로 업체를 만들지 않는다(업체관리 밖 회사 안 넣음).
- 마감된 달을 거슬러 고치지 않는다.
- 비밀번호·인증서·연락처를 저장하지 않는다. 더빌 쪽에서 «조회» 말고는 아무것도 누르지 않는다.
- 색은 27색 팔레트, 표 한 칸 한 줄.

## 6. 검사 (규칙을 박는다, 지금 값을 박지 않는다)

- 판정표 일곱 갈래가 각각 맞게 가는가(가짜 업체 가나상사·다라식품) — 되돌려 보면 우는가.
- 같은 `_k` 를 두 번 받아도 입금이 하나인가 · 되돌린 `_k` 는 다시 안 들어가는가.
- 통장 「더빌이체」 줄이 입금으로 만들어지지 않는가.
- 스위치 꺼짐이면 아무것도 안 쓰는가.
- 받기 스크립트 허용 목록에 「삭제」「출금」이 없는가 · 연락처·이메일 칸을 안 담는가.
- 새 자리 `cms_pull` 의 짝 검사(규칙·백업·온톨로지 등록·배포 제외).

2. 🤖 자동 처리 화면 + 판정 + 업체 잇기(첫 잇기 제안 목록 확인).
3. 대표가 미리보기를 보고 스위치를 켠다.
4. 작업 스케줄러 09:00 등록.
