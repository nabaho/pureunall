# 컨설팅보고서 — 서명 요청 · 서명본 회수 · 기관 제출 초안 설계 (설계 1)

- 작성일: 2026-10-11 · 상위: `2026-10-05-정부컨설팅-보고서자동화-design.md` §7·§9·§14 · `2026-10-10-gov-report-track-design.md`(서류 진행 기록) · `2026-10-11-gov-report-inbox-design.md`(받은 서류함)
- 대표 지시: 「설계먼저」 → 「추천대로」(2026-10-11). 서명 방식·메일 계정은 2026-10-07 대표 결정을 따른다: **서명 = 날인 스캔 회신 · 보내는 메일 = 담당 노무사 본인 메일 · 외부로 나가는 것은 사람이 마지막 단추**.
- 이 문서는 «설계 1(간단형 서명·제출)»만 다룬다. «설계 2(대형 사업 단계 관리)»는 별도 문서로, 이 설계가 합쳐진 뒤 쓴다.

## 1. 풀려는 일

보고서 확정 뒤의 반복 수작업 — ① 업체에 서명 요청 메일 쓰기 ② 날인본 회신을 메일함에서 찾아 붙이기 ③ 기관에 제출 메일 쓰기 — 를 현황판 칸 창에서 «한두 번 누르는 일»로 줄인다. 자동으로 나가는 것은 **없다**(초안까지, 보내기는 사람).

이미 있는 것(다시 만들지 않는다)
- 서류 줄 `scal_docs/{업체}/{rid}/items/{key}` 의 `st`·`sentAt`·`gotAt`·`how`·`link`, 체크표 ③④⑤, 칸 창.
- ⏰ 「서명 회신 기다림」(`WAIT_SIGN_DAYS=7` 넘음) · 「제출 기한 지남」 알림(`T.alertsExtra`).
- 받은 서류함(`PuGovReportInbox`): 업체 «주소» 기준 후보 · 개인 자료 딱지 · 연결 · 열어 보기.
- 푸른메일함은 **받는이·참조·제목·본문을 미리 채워 쓰기 창을 연다**(`pu-cards.html` `puMailComposeTo({to,cc,subject,body})`, URL `?view=mail&to=&subject=&body=&cc=`). **첨부는 미리 채울 수 없다** — 사람이 「💻 내 PC 파일」로 붙인다(8MB 이하).

## 2. 범위

한다
1. **서명 요청 초안** — 서류 틀에 «서명본» 줄(`step:'sign'`)이 있는 사업(지금은 충남북부·서산상의)의 칸 창 ③ 에 「✉ 서명 요청 메일 쓰기」. 누르면 메일 쓰기 창이 받는이(업체 주소)·제목·본문을 채워 열린다.
2. **보냄 기록** — 보낸 메일함 거울에서 그 요청 메일(제목 꼬리표)을 찾으면 「보낸 날 N월 N일 — 기록할까요?」를 제안하고, 사람이 눌러야 `sentAt`=그날·`st`=진행을 쓴다(`how` 는 제출 칸 ⑤ 에서만 쓴다 — 제출 칸은 `gotAt`=제출일·`st`=완료·`how`=메일). 못 찾으면 「보냈음 기록」 단추로 손으로.
3. **회신 후보** — 보낸 날 이후 그 업체 주소에서 온 «첨부 있는» 메일을 후보로 올리고 「회신 도착?」 딱지를 단다(받은 서류함 후보 목록을 «보낸 날부터»로 좁힌 것). 사람이 「서명본으로 연결」을 눌러야 `link`·`gotAt`=회신 날·`st`=완료가 **한 번의 저장**으로 쓰인다.
4. **제출 메일 초안** — 서류 틀의 «기관 제출»(`step:'submit'`)이 메일 제출인 사업(충남북부·서산·현장클리닉[양식 확인 뒤])에 「✉ 제출 메일 쓰기」. 받는이는 **지난 제출 메일에서 따라 온다**(§4-2) — 새 저장 없음. 보낸 뒤 보냄 기록·연결은 2·3 과 같은 길.
5. **플랫폼 제출 체크표** — 기술보호울타리 같은 플랫폼 제출은 칸 창 ⑤ 에 사업별 «제출 순서 체크 글»(고정 글, 로그인·최종 제출은 사람)을 보이고, 접수 완료 메일이 있으면 후보로 연결한다. 자동 업로드(Aside)는 하지 않는다.

하지 않는다(다음 단계)
- 메일 자동 발송 · 첨부 자동 붙이기 · 서명 자동 확정 · 대시보드 전역 «회신 도착» 알림(전 업체 메일 읽기가 무겁다 — 칸 창 안에서만).
- 전자서명 서비스·자체 서명 페이지.
- Aside 업로드 대기열(설계서 §7-1) — 대표 PC 에서 Aside 가 실행될 때 별도.
- 서명 지연 기준(7일) 설정 화면 — 지금 상수 그대로.

## 3. 서명 요청 초안 (순수 함수 `js/pu-gov-report-send.js` 신설)

```
signRequest({ co, biz, reportName, round?, due? }) → { subject, body, tag }
  tag     = '[서명요청:' + rid + ']'       // 보낸 메일을 다시 찾는 꼬리표(rid 전체 = typeId_year, 사람 이름 없음; 제출 메일은 [제출:rid])
  subject = tag + ' ' + biz + ' ' + reportName + ' 서명·날인 요청 (' + co + ')'
  body    = 인사 · 첨부 «확정본(PDF)» 안내 · 날인 후 스캔해 이 메일에 회신해 달라는 부탁 · 회신 희망일(due 있으면)
```
- 본문 문구는 **[노무사 확인]** — 초안 상수로 두고 쓰기 창에서 사람이 고친다.
- 업체 이름은 «화면 실행 중에만» 문안에 들어간다(공개 저장소의 검사·문서에는 합성 이름만).
- 받는이 = `PuGovReportInbox.addrsFor` 가 돌려주는 업체 주소 묶음의 **첫 주소**(업체관리 칸 순서 → 이알피 연락처 순). 나머지 주소는 «참조(cc) 후보»로 화면에 보이고 사람이 고른다. 주소가 하나도 없으면 「업체관리에서 주소를 넣어 주세요」로 막는다.
- 쓰기 창 열기: `window.open('', 'puMailWrite')` 로 떠 있는 창을 잡아 `puMailComposeTo({to,cc,subject,body,card:''})`; 로그인 전이거나 팝업이 막히면 **URL 길**로 되돌아간다. URL 길에는 본문을 싣지 않는다(주소창·기록에 남는 것을 줄인다) — 받는이·제목만 싣고 본문은 클립보드 복사 + 「본문을 붙여 넣으세요」 안내.
- 첨부 안내 줄: 「확정본을 내려받아 💻 내 PC 파일로 붙이세요」 + 보고서 창으로 가는 링크(`gov-consulting.html#rpt=업체|사업`, 기존). 크롬이 이 사이트의 반복 내려받기를 막을 수 있음을 한 줄 안내한다.

## 4. 보냄 · 회신 · 제출 (읽기 → 사람이 누르면 한 줄 쓰기)

### 4-1. 보냄 찾기와 회신 후보
- 읽는 곳은 받은 서류함과 같다(메일함 거울 머리글 — 본문·첨부 바이트는 읽지 않는다).
- `findSent(rows, tag)` — 보낸편지함 줄 가운데 제목에 `tag` 가 든 가장 이른 것 → `{day, key}`. 없으면 null.
- `replyCandidates(rows, {addrs, sentDay})` — 받은 줄(`out:false`)·업체 주소·첨부 있음·`day >= sentDay`·개인 자료 아님을 날짜 순으로. 제목·첨부 이름에 「서명·날인·스캔」이 있으면 앞에 둔다. 기간 끝은 받은 서류함과 같은 규칙(마지막 회차 +90일)을 따르되 `sentDay` 로 시작을 좁힌다.
- 줄마다 「서명본으로 연결」: `linkFrom`(개인 자료 차단 그대로) + `gotAt` + `st:'done'` 을 **한 객체로** 만들어 줄 하나를 `.set` 한다. 기존 `nextLink` 의 이어 받기를 써서 `sentAt`·`note` 를 지우지 않는다.

### 4-2. 제출 받는이 따라 쓰기
- `submitTo(rows, {words})` — 보낸편지함에서 제목에 사업 낱말(`DOC_PLANS[].words`)이 든 가장 최근 메일의 받는이 가운데 **업체 주소가 아닌** 주소를 제안한다(주소는 화면에서만, 어디에도 저장하지 않는다). 못 찾으면 쓰기 창이 받는이 없이는 값 채우기를 못 하므로 **쓰기 창을 빈 채로 열고 제목·본문을 클립보드에 복사**한다 + 「지난 제출 메일을 못 찾았습니다 — 받는 사람을 직접 넣으세요」.
- 제목 꼬리표: `[제출:rid]` — 보냄 기록·접수 메일 찾기에 같은 방식으로 쓴다.
- 제출 메일 본문은 사업별 짧은 상수 문안(**[노무사 확인]**).

### 4-3. 플랫폼 체크 글
- `DOC_PLANS` 항목에 선택 필드 `how`(`'mail'|'platform'`)와 `steps`(체크 글 배열)를 더한다 — 코드 상수이므로 규칙·DB 변경이 없다. 기술보호 `how:'platform'`, 충남북부·서산 `how:'mail'`, 현장클리닉은 `[확인 필요]`(운영지침 대기).
- 칸 창은 `how` 가 `platform` 이면 「✉ 제출 메일 쓰기」 대신 체크 글을 보인다. 체크는 화면에서만(저장 안 함) — 완료는 기존 상태 단추로.

## 5. 쓰는 곳 · 규칙 · 개인정보

- **쓰기는 지금과 똑같이 `scal_docs/{co}/{rid}/items/{key}` 줄 하나의 `.set`** — 필드도 기존 `st·sentAt·gotAt·how·link·note·by·at` 안에서만 쓴다. **새 규칙·게시 없음.**
- 새 파일: `js/pu-gov-report-send.js`(순수) + `tests/gov-report-send.test.js`. 바뀌는 파일: `gov-report.html`(칸 창 단추 3개·후보 목록 재사용), `js/pu-gov-report-docs.js`(`how`·`steps` 상수), `js/pu-ontology.js` 는 바꾸지 않는다(읽는 곳 = 이미 `govreport` 의 `sharedRoots` 에 든 메일함 거울·`data/companies`·`data/consultings`, 쓰는 곳 = `scal_docs` 그대로). 새 `.js` 는 `gov-report.html` 에 `?v` 붙여 싣는다.
- 개인정보: 메일 본문·첨부 바이트는 읽지 않는다. 쓰기 창에 넘기는 문안에는 업체 이름·보고서 이름·날짜만(전화·주민번호·급여 등 없음). 개인 자료 딱지 건은 연결을 막는다. AI 로는 아무것도 보내지 않는다. 비밀번호·인증서를 다루지 않는다.
- 공개 저장소: 검사·문서·상수 문안에 고객사·사람 이름·연락처·메일 주소를 쓰지 않는다(합성 `가나상사`·`example.com`).

## 6. 오류·경계

- 거울을 못 읽음 → 칸 창에 「메일함을 불러오지 못했습니다」 + 다시 시도, 단추는 «손으로» 길로 남는다.
- 같은 꼬리표 메일이 둘 이상 → 가장 이른 것을 제안하고 「N건 있음」 표시(사람이 고른다).
- 이미 `st:'done'` 인 줄에는 「서명 요청」을 숨긴다(다시 보내려면 상태를 되돌려야 한다).
- 저장 거절(권한) → 기존 문구 `SAVE_FAIL`, 값은 그대로.
- 쓰기 창이 다른 사용자 글을 쓰던 중이면 `puMailComposeTo` 가 임시저장에 넘긴다(기존 동작) — 이 설계는 건드리지 않는다.

## 7. 검사 계획

- `signRequest`: 꼬리표 형식 · 제목 길이 · 본문에 개인 정보 형태(숫자 열·주소)가 없음 · 주소 없음 거절.
- `findSent`/`replyCandidates`/`submitTo`: 합성 거울 줄로 — 시작일 이전 제외 · 업체 주소만 · 개인 자료 제외 · 기관 주소는 업체 주소 제외 · 동점 정렬 고정.
- 연결 저장 객체: `sentAt`·`note` 보존 · `gotAt` 이 회신 날 · `__proto__` 키 방어(기존 트랙 모듈 검사와 같은 틀).
- `gov-report.html` 정적 검사: 쓰기 호출이 `scal_docs` 한 곳뿐 · 메일 자동 발송 호출 없음 · 새 `set(`/`update(` 없음.
- 실제 확인(대표 PC·로그인): ① 쓰기 창이 값 채워 열림 ② 보냄 제안 ③ 회신 후보 ④ 연결 저장·읽기 ⑤ 시험 줄 삭제.
