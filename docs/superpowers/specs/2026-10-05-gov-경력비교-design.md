# 정부사업신청 ↔ 경력관리 비교 — 동일·유사 표시와 확인 (설계)

- 날짜: 2026-10-05
- 요청: 대표 「정부사업신청에 들어갈 경우 필요서류 및 신청서 지원서 등이 있는데 이 부분은 경력관리에 이미 수행했던 부분과 비교해서 유사 또는 동일 등을 표시하고 확인하게」
- 대표 결정: 비교 셋 모두(지원서 내용 · 공고 ↔ 이력 · 필요서류 ↔ 갖고 있는 서류) / 경력관리에 없는 줄은 «표시 + 경력관리로 넘기기»(정부사업신청은 읽기만) / 판정은 규칙(AI 아님)

## 0. 짜임

| 순서 | 기능 | 화면 | 바뀌는 곳 |
|---|---|---|---|
| ① | 공고 ↔ 지난 수행 이력 | 공고·모집 글 줄 배지 + 팝업 목록 + 확인 | `js/gov-match.js`(새) · `gov.html` |
| ② | 필요서류 ↔ 갖고 있는 서류 | 서류 준비 창 체크리스트 | `functions/recruit-watch.js`(제출서류 뽑기) · `gov.html` |
| ③ | 지원서 내용 ↔ 경력관리 | 내기 전 점검 결과 | `js/gov-match.js` · `gov.html` · `kcareer.html`(등록 입구 하나) |

셋은 따로 완성·배포한다. ③은 ①의 판정기를 그대로 쓴다.

### 지키는 것
- ⚠ 정부사업신청은 경력관리 자료를 **읽기만** 한다(지금 그대로 — `GovCareer.paths` 창고만, `_secrets`·첨부 조각 안 읽음).
- ⚠ 읽어 온 경력 자료는 **어디에도 담지 않는다**(화면이 열려 있는 동안만). 담는 것은 «확인 표시»뿐이다.
- ⚠ 자문·고문(고객사 이름)은 «동일»을 고르는 데 쓰지 않는다 — 공고 기관은 공공기관이고, 고객사 이름을 공고 옆에 늘어놓을 까닭이 없다. 갈래(유형)만 «유사»에 쓴다.
- ⚠ 판정 까닭을 늘 함께 적는다(「기관 같음 · 사업명 80% 겹침 · 2024」). 까닭 없는 배지는 믿을 수 없다.

## 1. 판정기 `js/gov-match.js` (순수 모듈, 브라우저·Node 겸용)

### 1.1 다듬기
- `orgKey(name)` — 기관 이름 비교 열쇠: 괄호 안·(재)(주)(사)·「재단법인·사단법인·주식회사」·공백·점을 뗀다.
  끝의 「본부·지사·지역본부·센터」는 남긴다(「한국산업인력공단 대전지사」 ≠ 본사로 볼 수 있어야 한다 — 같음 판정은 «한쪽이 다른 쪽을 품음»으로 한다).
- `words(text)` — 낱말: 2글자 이상 한글·영문·숫자 덩어리. 버리는 말(모집·공고·안내·사업·지원·년도·위촉·위원·의 건 …)을 뺀다. 해(2024년)는 따로 뽑는다.

### 1.2 사업 종류 사전 `TOPICS`
경력관리 실적에 실제 적힌 이름에서 만든다(구현 첫 걸음에 대표 자료로 재서 정한다). 첫 판 후보:
일터혁신 · 공정채용 · 노동시간 단축 · NCS(기업활용) · 고용구조 개선(비정규직) · 근로조건 자율개선 · 공공부문 고용개선 · 공무직 노사협력 ·
직장 내 괴롭힘(조사) · 위험성평가·산업안전 · 경영평가 · 인사노무 자문 · 임금체계(직무급) · 노사관계(분쟁·조정) · 퇴직연금 · 청년·일자리 · 강의·교육.
종류마다 찾는 말 정규식 하나. ⚠ 「컨설팅」 같은 넓은 말 하나로는 종류가 되지 않는다.

### 1.3 견주기 `compare(target, rec)` → `{ level: 'same'|'similar'|'', score, why[] }`
- target: 공고 `{ org, title, year }` (나라장터·알리오 feed 줄 / 모집 글 hit — 기관을 모르면 제목의 기관 이름으로 `GovRecruit.matches`)
- rec: 경력 한 줄 `{ src, org, agency, title, type, year }` — src: 위촉(`wiccok`)·실적(`perf`)·근무(`work`)·서류 폴더 7번 제출본(`scan`)
- **동일**: 기관이 같고(`orgKey` 가 같거나 한쪽이 다른 쪽을 품음, 4자 이상) — 실적은 «수행기관(agency)» 을 기관으로 본다
  - 그리고 사업명 낱말이 60% 이상 겹치거나, 같은 사업 종류.
- **유사**: 기관은 달라도 같은 사업 종류(`TOPICS`)거나, 사업명 낱말이 50% 이상 겹침.
- 어디에도 안 맞으면 빈 값(표시 안 함).
- 점수는 줄 세우기용(동일 > 유사, 최근 해 먼저).

### 1.4 확인 `recruit_match` (동기화 칸 — `gov/{uid}/recruit/match`)
- 열쇠 `safeKey(대상열쇠 + '|' + 기록열쇠)`, 값 `'y'`(맞음) · `'n'`(아님).
- 「아님」 표시한 짝은 다시 보이지 않는다(목록 아래 「아니라고 한 것 N」 에서 되살림). 「맞음」은 배지에 ✓ 를 붙인다.
- 기록열쇠: 경력관리 레코드 id 가 있으면 그것, 없으면 `src|org|title|year` 지문.

## 2. ① 공고 ↔ 지난 수행 이력 — 화면

- 경력 자료: 화면을 열면 한 번 받아 온다(`matPull` 을 조용히 — 이미 있으면 다시 안 받는다). 못 받으면 배지를 안 그리고 「경력관리 자료를 못 읽어 비교를 못 했습니다」 한 줄.
- **공고 모아보기 표**와 **모집 글 표(공인노무사회·공공기관)** 에 «이력» 칸: `🟢 동일 3` · `🟡 유사 12` · (없으면 비움).
- 칸을 누르면 팝업: 동일 → 유사 차례로 줄(ㅁ·№·갈래·기관·사업명·해·까닭·✓ 맞음 / ✗ 아님). 위촉은 직책, 실적은 수행기관·고객사 갈래, 7번 폴더 제출본은 파일 이름.
- 「해마다 지원한 곳」 표는 이미 기관별이라 바꾸지 않는다.
- 성능: 공고 수백 × 경력 수백 — 줄마다 한 번 셈하고 `_matchCache`(공고 열쇠 → 결과)에 둔다. 경력 자료나 확인 표시가 바뀌면 비운다.

## 3. ② 필요서류 ↔ 갖고 있는 서류 (뒤에 상세 설계)

- 서버: 본문의 「제출서류·구비서류·제출 서류」 단락에서 서류 종류(`GovSubmit.KINDS` 와 같은 낱말)를 뽑아 `hit.docs`. 기간 읽기와 같은 길(`details`).
- 화면: 서류 준비 창 ③ 의 「요구 서류」 기본값을 `hit.docs` 로. 종류마다 **동일**(이 기관 지난 해 제출본에 같은 종류 파일) · **유사**(다른 기관 제출본·경력관리 서류 보관함에 같은 종류) · **없음**.
- 경력관리 서류 보관함(이력서·프로필·경력증명서)은 «이름·날짜만» 읽는다(파일 알맹이는 안 받는다).

## 4. ③ 지원서 내용 ↔ 경력관리 (뒤에 상세 설계)

- 내기 전 점검에서 읽은 글자(kordoc·pdf.js — 이미 있다)에서 «경력 줄»을 뽑는다: 기간(YYYY.MM ~ YYYY.MM 또는 해) + 기관·직책·사업명이 한 줄에 있는 것.
- 줄마다 ①의 `compare` 로 경력관리 전체와 견줘 동일·유사·없음. 없음 줄에 「경력관리로 넘기기」 →
  `kcareer.html?go=add&store=…&org=…&title=…&from=…&to=…` — 경력관리가 그 창고의 등록 창을 «채운 채» 연다(저장은 사람이).
- 거꾸로: ①에서 이 공고와 동일·유사로 나온 경력 중 지원서에 없는 것 → 「빠진 것 같은 실적 N」.
- ⚠ 지원서 글자는 브라우저 안에서만 읽는다(지금 그대로 — 서버·AI 로 안 보낸다).

## 5. 검사

- `tests/gov-match.test.js`: `orgKey`·`words`·`compare` — 대표 실자료 꼴(위촉 기관·실적 사업명·공고 제목)로 동일·유사·아님을 못박는다. 오탐 미끼(「충청남도」 앞 네 글자만 같은 기관, 「컨설팅」 한 낱말만 겹침).
- `tests/gov-recruit-app.test.js`·`gov-app.test.js`: 배지·팝업·확인 기억·「아님」 숨김·자료 못 읽음 안내 — vm 으로 돌린다.
- 고장넣기로 검사가 실제로 잡는지 확인한다.

## 6. 하지 않는 것
- AI 판정 · 경력관리에 바로 쓰기 · 지원서 파일을 서버로 보내기 · 자문 고객사 이름으로 동일 판정.
