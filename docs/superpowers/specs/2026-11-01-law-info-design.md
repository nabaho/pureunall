# 법령정보 앱 설계서

- 작성일: 2026-11-01
- 대상: 포털 새 앱 «법령정보»(가칭, 키 `law`) + 서울 서버 함수(법제처 자동 수집·찾기·물어보기) + 서버 고정 IP
- 대표 요청: 「법령 관련 프로그램 만든다」 → 「전문가 업무용」 → 「포털 안에 새로」 → 「자동으로 모두 가지고 오게 만들어 달라」 → 「RAG 넣어라」
- 경로: 건축급 — 새 앱 + 새 서버 함수 + 새 저장 자리 + 클라우드 망 설정. 이 설계서 → 대표 승인 → 계획서 순.

## 0. 왜 만드나 — 지금 상태

- 노무사가 의견서·이유서·자문을 쓰며 조문·판례·행정해석을 찾고 원문을 확인하는 일을 포털 안에서 끝내게 한다.
- 지금은 셋 다 막혀 있다(2026-11-01 실측).
  - 개발용 법령 MCP(`korean-law`) — 법제처 키(`LAW_OC`)가 이 PC 어디에도 없다.
  - 뉴스레터 «전문 보기»(`newsFull`, 서울) — 판례 한 건을 부르면 `{"ok":false,"까닭":"빈답"}`.
    서버는 시험용 키 `OC=test` 를 쓰고, 이 PC 에서 같은 키로 부르면 법제처가
    「사용자 정보 검증에 실패 — 서버장비의 IP주소 및 도메인주소를 등록」으로 거절한다. 같은 까닭으로 본다.
  - 대표가 받아 온 외부 묶음(「푸른법령집」 v3 · 「푸른통합시스템 enter 완전결합판」 v7) — 개인 PC 의 127.0.0.1 서버라
    직원 모두·휴대폰이 못 쓰고, 포털 `enter.html` 을 덮어쓰거나 글자로 클릭을 가로채며, `git add .` 후 main 에 바로
    푸시하고, 아무 사이트에서나 부를 수 있게(CORS `*`) 열려 있다. **그대로 붙이지 않는다. 생각만 참고한다**
    (8개 자료 갈래, 조문→판례→해석 체계표, 인용 번호 확인).
- 성공의 모습: 노무사가 PC·휴대폰 포털에서 검색창 하나로 법령·판례·행정해석을 찾아 원문을 읽고,
  AI 에게 물으면 **우리가 쌓아 둔 원문만 근거로** 출처 번호가 붙은 초안 답을 받는다. 법제처가 잠깐 멈춰도 돈다.

## 2. 범위

넣는 것(1판)
- **자동 수집**: 법제처 OPEN API 의 노무 관련 공개 자료(§3)를 처음 한 번 모두 + 매일 새벽 새것·바뀐 것.
  끊겨도 이어 하고, 여러 날에 나눠 돌 수 있게.
- **찾고 읽기**: 검색창 하나(법 이름·조문·사건번호·문서번호·낱말) → 갈래별 결과 → 원문을 앱 안에서.
  법령은 시행일을 늘 함께 보인다.
- **물어보기(RAG)**: 질문 → 쌓아 둔 자료에서 찾기 → 찾은 원문만 AI 에 건넴 → 초안 답 + 근거 목록(누르면 원문).
- **번호 대조**: AI 답에 나온 조문·사건번호·문서번호를 우리 창고와 기계로 대조 → 없으면 «확인 안 됨».
- **법제처 연결 복구**: 고정 IP + 법인 키를 서버 비밀값으로. 뉴스레터가 이것을 빌려 쓰도록 옮기는 일은 따로 작업(§7-1).
- **상태 보이기**: 앱 머리에 마지막 수집 시각·건수·실패(법제처가 막혔으면 막혔다고).

넣지 않는 것(1판 제외)
- 사내 메일·NAS·과거 서면 수집 — 고객 자료라 권한·개인정보 설계가 따로 든다.
- 엘박스·이레이버·HRDB 등 유료·회원 자료 — 약관.
- 의견서 붙여넣기 인용 확인, 체계표, 시점(행위시법) 비교, 한글·엑셀 서류 자동 작성 — 2판 후보(§9).
- 판례 «전체» 미러 — 노무 관련만(§3).
- 업무관리 사건·자문과의 연결(온톨로지 관계) — 2판 후보.

반목표 — 돌아가도 이러면 실패다
- AI 가 **쌓아 둔 자료에 없는** 번호·조문을 근거처럼 내놓는데 «확인 안 됨» 표시가 없다.
- 현행 아닌 조문을 현행처럼 보인다 / 시행일이 빠진다.
- 질문에 든 고객 사실관계·주민번호가 서버 기록에 쌓이거나 동의 없이 밖으로 나간다(§7 결정 필요).
- 수집이 다른 앱을 멈춘다 — AI 하루 몫을 먹어 판독(`readDoc`)이 멎음, 실시간DB 요금 급증, 함수 메모리 초과.
- 조용한 실패 — 법제처가 막혔는데 화면은 아무 말 없이 빈 결과.

## 4. 전체 구조

```
[법제처 OPEN API] ←(고정 IP · 법인 키)─ [서울 서버 함수: 수집]  ─→ [창고(서울): 원문]
                                              │                     [실시간DB: 상태·목록(가벼운 것만)]
                                              └→ [색인 만들기] ─→ [창고: 찾기용 색인]
[포털 앱 법령정보] ─(로그인)→ [서울 서버 함수: 찾기·원문·물어보기] ─→ 색인·원문 읽기
                                                         └→ [AI(Gemini)] ← 찾은 원문만
```

정한 것
- 법제처는 **서버(asia-northeast3)에서만** 부른다(정부 사이트는 바깥 지역을 막는다 — 기억 `gov-sites-need-seoul-region`).
  키는 서버 비밀값으로만 둔다. 브라우저·PC 에 키가 없다.
- 순서: ① 고정 IP 를 단다 → ② 대표가 그 IP 를 적어 키를 신청 → ③ 키를 비밀값으로 넣는다(대표가 직접, 값이 채팅·기록에 안 남게).
- 원문은 **창고(Storage, 서울)** 에 둔다 — 실시간DB 는 GB당 약 $5 라 본문 큰 자료를 두지 않는다. 실시간DB 에는 상태·작은 목록만.
- 법제처는 남의 서버다 — 천천히(초당 몇 번 이하) 부르고, 실패는 기록하고 다음 날 이어 한다.
- 물어보기 답의 모양(조직 지침): 결론 → 근거(법령/판례/행정해석/위원회 결정 구분, 법원·선고일·사건번호 /
  기관·문서번호·회시일) → 적용 조건 → 실무 조치. **검토 기준일**(오늘)과 쓴 자료의 시행일을 함께 보인다.
  맨 위에 «AI 초안 — 담당 노무사 확인 필요».
- AI 에게는 «건넨 원문 밖의 번호·조문을 쓰지 말라»고 하고, 그래도 나온 번호는 기계 대조로 «확인 안 됨» 표시.
  찾은 자료가 없으면 «쌓아 둔 자료에서 근거를 못 찾았다»고 답한다(지어내지 않는다).
- AI 는 지금 쓰는 Gemini 길을 쓴다. 단 **법령 물어보기는 따로 하루 한도**를 두어 판독(`readDoc`)의 회사 전체 몫
  (기억 `ai-quota-shared-one-key`)을 먹지 않게 한다.
- 화면은 코딩 전 시안을 대표에게 먼저 보이고 승인받는다(기억 `mockup-before-coding`). 시안은 저장소에 넣지 않는다.

빌더 몫
- 찾기 방식: 낱말 검색·의미 검색(임베딩)·섞기 중 무엇으로, 색인을 어디에 어떤 모양으로. 단 임베딩은
  **무료 한도·비용을 먼저 세어 보고** 고른다(수만 건 × 조각 수). 사건번호·조문번호는 정확히 맞아야 한다.
- 고정 IP 구성: 1세대 함수 + 서버리스 VPC 커넥터 + Cloud NAT(고정 IP), 또는 법령 함수만 2세대로 — 싼 쪽.
  **실제 월 비용을 견적해 대표에게 먼저 보고**(예산 알림 월 3만 원 — 기억 `blaze-migration-paused`).
- 원문 나누는 단위(법령은 조문 단위 등), 파일·함수 이름, 화면 세부.

## 5. 지켜야 할 집 규칙

- 온톨로지(CLAUDE.md): `PuOntology.PROGRAMS` 에 `law` 를 먼저 등록하고 `READ_ADAPTERS` 도. 법령 자료를 가리킬
  개체 종류(예: 공개 법령 자료)를 `TERMS` 에 먼저 정의. 앱은 Firebase 초기화 전에 `js/pu-ontology-write.js`,
  그리고 `js/pu-active.js`(자리 비움 로그아웃). 쓰는 경로는 `writeContracts` 에 선언(새 프로그램은 기본 `enforce`).
- 새 실시간DB 최상위 자리를 만들면 짝 검사 넷을 함께 고친다(기억 `new-toplevel-rtdb-key-companion-tests`).
  규칙은 `scripts/make-firebase-rules.js` → `node scripts/rules-deploy.js --deploy`, 창고 규칙은
  `docs/firebase-storage-전체(붙여넣기용).txt` → `scripts/storage-rules-deploy.js` (CLAUDE.md).
- 새 함수는 공개 호출 권한이 저절로 안 생긴다(기억 `new-cloud-function-invoker-not-automatic`). 찾기·물어보기 함수는
  로그인 토큰을 확인한다.
- `functions/index.js` 맨 위 `geoip-lite` 가 콜드 스타트마다 실려 256MB 를 넘긴다(`newsFullPage` 실측) — 512MB 이상.
- `newsFull` 의 «갈래 둘(prec·expc)·번호는 숫자만» 안전 규칙은 키를 바꿔도 그대로(아무 주소나 부르는 문 막기).
- 검사는 «지금 값»이 아니라 «규칙»을 박는다(CLAUDE.md, `tests/test-pin-guard.test.js`). 표 한 칸은 한 줄.
- 배포: 개발용 폴더 지우기 목록(`.github/workflows/deploy-pages.yml`)에 새 개발용 폴더가 생기면 넣는다.
  저장소는 **공개**다 — 키·고정 IP 외의 비밀은 코드에 두지 않는다.

## 6. 화면 (시안으로 확정할 것)

- 머리: 검색창 하나 + 갈래 고르기(전체·법령·판례·해석·위원회) + 마지막 수집 시각.
- 결과: 갈래별로 한 줄씩(제목 · 번호 · 날짜 · 법원/기관). 표 한 칸은 한 줄, 넘치면 `…` + 전문은 `title`.
- 원문: 앱 안에서 펼친다. 법령은 조문 단위로 바로 뛰고 시행일 표시.
- 물어보기: 질문 칸 + 답(결론→근거→적용 조건→실무 조치) + 근거 목록(누르면 원문) + «확인 안 됨» 표시.
- 휴대폰: 입력칸 16px(기억 `phone-input-16px`).

## 7-1. 빌더 점검 뒤 Claude 가 정한 것 (대표가 읽으며 확인)

- **키를 기다리는 동안의 법령 출처** — 법령 본문은 저장소가 이미 쓰는 legalize-kr(`functions/rules-lawwatch.js`,

  법제처 원문 주소를 함께 건다. 키가 오면 법제처 원문으로 대조·교체한다. 판례·해석·위원회 결정은 키가 온 뒤 수집한다.

  쓰는 곳(`news-prec.js`·`news-full.js`·`법조문원문`·`브리핑거리모으기`·`weeklyNewsBrief`(us-central1)·
  `engine/simpletax_watch.js`)은 다른 방의 코드라 **따로 작업**으로 옮긴다. 법령 앱의 법제처 부르기를 그쪽도 빌려 쓸 수 있게
  만들어 둔다.
- **고정 IP 구성 우선안** — 커넥터(상시 기계 2대) 대신 «법령 함수만 2세대 + 직접 VPC 나가기 + Cloud NAT + 고정 IP».

  커넥터 방식으로 하고 그 차액을 보고한다.
- **연혁과 시점** — 처음 한 번 수집은 «현행 본문 + 개정 목록(공포일·시행일)»까지. 지난 판 본문은 몽땅 받지 않고
  «그 날짜 조문 보기»를 누를 때 법제처에서 받아 창고에 쌓는다(한 번 받은 것은 다시 안 받음).
