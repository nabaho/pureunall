## 0. 무엇을 하려는가

대표 물음(2026-10-24): 「PC 카톡의 법인 대화방 자료를 받아 따로 보관하고, 대화 진행상황을 업무관리에 자동으로 넣을 수 없나」

- **푸른노무법인 업무채팅방**(참여 11명)에서 오간 이야기를 **사건번호·업체별로 묶어** 업무관리의 «진행 기록»에 한 줄씩 넣는다.
- 방에서 받은 **첨부 파일**을 카톡 보관기간(약 2주)이 끝나기 전에 사건·업체 폴더로 옮겨 둔다.
- **반자동**이다. 주 1회 사람이 PC 카톡에서 «대화 내보내기»와 «서랍 파일 받기»를 하고, 시스템은 그 결과물을 읽어 정리한다.

### 못 박아 두는 것 — 카톡을 읽어 오는 길은 없다
카카오 공식 API는 메시지 보내기뿐이다. **카톡 클라이언트 자동조작·DB 복호화·스크래핑은 하지 않는다**
(`docs/카톡수집기-검토.md` 2026-09-03 결론 그대로 — 약관·읽음처리·개인정보). 사람이 내보낸 `.txt` 를 받는 것이 이 설계의 전부다.

## 1. 왜 급여데이터함이 아니라 업무관리인가

| | 보류 설계(8/16) | 이번 |
|---|---|---|
| 대상 앱 | 급여데이터함 `pu-paydata.html` | **업무관리 `work.html` 💬 카톡정리 안의 탭 하나** |
| 단위 | 한 사업장 = 한 대화방 | **한 방에 사건·업체 여럿** → 사건번호·업체로 묶기 |
| 결과 | 달별 요약·할 일·급여 값 | **진행 기록 한 줄**(업무별·날짜별) |
| 판독 | AI(구글) | **AI 없음**(규칙 요약) |
| 대화 읽기 | 새로 만든다 | 카톡 줄 읽기(안드로이드·아이폰·PC 꼴)를 **가져다 쓴다** |

이미 있는 것을 두 벌로 만들지 않는다: 방 허용목록(`kakaoWork/rooms`)·가리개(`maskSensitive`)·30일 삭제(`purgeOld`)·
총괄관리자 전용 서버 길은 **그대로 쓴다.** 10/9 기록에 «2단계 후보: 대표님 글 채우기(주 1회 내보내기 끌어 놓기)»가 이미 적혀 있다.
알림 길은 대표님이 쓴 글이 안 들어오고(카톡은 내 글에 알림이 없다), 2026-10-19 실측에서는 폰이 서버를 한 번도 부르지 않아 0건이었다.

## 3. 흐름

모든 읽기·묶기·미리보기는 **올리는 사람의 브라우저 안**에서 한다. «반영»을 누르기 전에는 서버로 아무것도 나가지 않는다.

1. **올리기** — `.txt` 한 개 + «카카오톡 받은 파일» 폴더(또는 공유 폴더). 끌어 놓기·고르기 둘 다.
2. **방 확인** — txt 머리글의 방 이름이 받을 방 목록과 **글자 그대로** 같아야 읽는다
   (`PuKakaoWork.roomAllowed`). 다르거나 머리글을 못 찾으면 **거절**한다 — 개인 대화방 파일이 섞이지 않게.
3. **읽기** — 날짜·보낸 사람·내용·첨부 이름. 줄 하나가 안 읽혀도 앱은 멈추지 않고 «못 읽은 줄 N개»로 센다.
4. **묶기·맞추기** — 4장.
5. **미리보기** — ☐ 고르기 칸 + 번호가 맨 왼쪽인 표. 고르기만으로는 아무것도 바뀌지 않는다.
6. **반영** — 건수를 묻고, 원문 30일 보관(서버)과 진행 기록(업무관리)을 한 번에 저장한다(7장 순서).
7. **파일 복사** — 9장.

## 4. 묶기와 맞추기 (규칙으로 못 박는다 — 값이 아니라 규칙)

### 묶는 법
- **사건번호 꼴**: `경기2026부해3347` — 지역(한글 2~4)+연도 4자리+사건부호(한글 1~3)+번호. 공백·하이픈을 지워 견준다.
  업무관리에 없는 번호는 사건부호가 알려진 것(부해·부노·구제·차별·구합·가합 등 — 상수 한 곳)일 때만 «없는 번호»로 보여 준다(잡음 방지).
- **업체명**: 문턱은 메일 잇기가 쓰는 `MLK_MIN_MATCH`(3자)를 **그대로 쓴다.** 같은 숫자를 두 곳에 두지 않는다.
- **이어 붙이기**: 사건번호·업체명이 없는 글은 **같은 날, 직전 묶음에서 30분 안**이면 그 묶음에 붙는다. 아니면 «미분류»(기본 해제).
- **잡담 거르기**: 「네」「확인했습니다」·이모티콘·들어오고 나감 안내는 요약에서 빼고 건수로만 센다.
- **기한**: 글에서 「10월 30일까지」를 찾는 `PuKakaoWork.findDue` 를 그대로 쓴다. 못 찾으면 비운다(지어내지 않는다).

### 기존 업무와 맞추는 법 — 이름으로 id 를 채우지 않는다
| 근거 | 표시 | 기본 |
|---|---|---|
| 사건번호가 업무관리 `no` 와 같음 | **확실**(파랑) | 체크됨 |
| 사건번호가 같은 사건(`ref.id`)의 심급 사건번호와 같음 | **확실**(파랑) | 체크됨 |
| 업체명만 같음(그 업체의 진행 업무 여럿 → 드롭다운으로 고른다) | **짐작**(주황) | 해제 |
| 사건번호는 있는데 업무관리에 없음 | **없는 번호**(빨강) — 「새 업무 창 열기」는 채워서 **열기만**(저장은 사람) | 해제 |
| 아무 근거 없음 | **미분류** | 해제 |

- 연결의 열쇠는 항상 **업무 `id`** 다. 업체명은 후보를 보여 주는 데만 쓰고 `co_id` 를 이름으로 채우지 않는다.
- 이름을 «이름으로» 칼같이 가를 수 없는 경우(여러 업체가 함께 걸림)는 후보 전부를 보여 주고 사람이 고른다.
- 심급 사건번호(`data/cases` 의 `stages[].caseNo`)가 업무관리 화면 메모리에 이미 있는지는 **구현 때 확인** [확인 필요].
  없으면 읽기 전용으로 불러온다. 쓰지는 않는다.

## 5. 진행 기록 한 줄

(업무, 날짜) 당 한 줄. 기존 `addLog` 와 같은 자리·같은 모양이다 — 화면(타임라인·마지막 기록)이 코드 수정 없이 그대로 읽는다.

```
logs/{연도}/{주차}/{업무id}/{lid}   ＝   itemlogs/{업무id}/{lid}(+w)
  d  : '2026-10-23'
  t  : '💬 카톡 · 노무사A·노무사B 외 1명 — 답변서 제출기한 연장 신청, 승인 · 📎 답변서(초안).hwp'   (≤ 280자)
  k  : 'kt'
  by, byName, at : 올린 총괄관리자     ← 말한 사람이 아니다
  kroom, kn, kwho, kck, kh :           방 이름 · 글 수 · 말한 사람 · 줄 열쇠 · 내용 열쇠
```

- **줄 열쇠(`kck`)** = 해시(업무id, 날짜, 방). **내용 열쇠(`kh`)** = 해시(요약 글+첨부). `lid = 'K' + kck + kh`.
- 같은 파일을 다시 올리면 `lid` 가 같아 **건너뛴다**(중복 0). 주 1회 내보내기는 겹치는 기간이 크므로 이것이 핵심이다.
- 같은 (업무, 날짜)인데 내용이 달라졌으면(그날 글이 더 늘었다) **새 줄로 더하고 옛 줄은 그대로** 둔다 — 미리보기에 「보강」으로 표시. **덮어쓰지 않는다.**
- 저장은 **한 번의 다중 경로 `update`** — 반쯤 하다 멈추지 않는다. 배열 한 칸에 이어 쓰지 않으므로 동시 수정으로 소실되지 않는다.
- `items/{id}/last` 는 `addLog` 와 같이 «더 새로우면» 갱신한다 [설계자 판단 — 대표님이 카톡 요약이 마지막 기록이 되는 것을 원치 않으면 끈다].
- **화면 읽기 쪽은 안 고친다.** 글 앞의 💬 가 표식이다.

## 6. 가린 원문 30일 보관 (대표 결정)

- 자리: `kakaoWork/notes/{YYYYMMDD}/{id}` — **기존 알림 길과 같은 자리**다. 규칙이 없어 기본 거부(서버 전용)이고, `purgeOld` 가 30일 지난 날짜 칸을 지운다.
- 길: 새 서버 동작 `kakaoImport`(총괄관리자만) — `hanaMessageBridge` 의 `kakaoIngest` 옆. **브라우저 → 서버**이며 외부 스크립트가 DB에 직접 쓰지 않는다.
- 서버가 하는 일: ① 방 허용목록 재확인(목록 밖은 방 이름도 안 남긴다) ② **가리개를 한 번 더** ③ 30일보다 오래된 글·미래 글은 **건너뜀**(알림 길처럼 «지금»으로 바꾸지 않는다 — 날짜가 틀어지므로)
  ④ 열쇠 `sha(room,sender,time,text)` 로 중복 건너뜀 ⑤ 날짜 칸을 하루 한 번만 읽어 견준다(글마다 읽지 않는다).
- 한 번에 보내는 글은 한도(예: 400건)로 나눠 보낸다. 한 묶음이 실패하면 **이어서 다시 누르면 된다**(중복 안전).
- 레코드: 알림 길과 같은 모양 + `originSystem:'kakaotalk-export'`, `importedBy`, `importedAt`. 개체 종류는 이미 등록된 `Message`.
- 화면 `kakaoList` 는 `src`('alert'|'export')를 함께 준다. 같은 글이 알림과 내보내기 양쪽에 있으면(보낸 사람·글 같고 90초 안) 화면에서 **알림 쪽을 숨긴다**(내보내기가 정확한 시각·실제 말한 사람을 갖는다).
- ⚠ **서버를 배포해야 켜진다.** 합쳐도 `hanaMessageBridge` 는 안 올라간다(손으로 올린다). 배포는 **별도 승인** 뒤에 한다.
  배포 전에 «반영»을 누르면 화면이 「서버가 아직 새 기능을 모릅니다」라고 말하고 **아무것도 저장하지 않는다**(원문 보관이 먼저이므로).

### 저장 순서
① 원문 30일 보관(서버) → ② 진행 기록(업무관리). ①이 실패하면 ②를 하지 않는다(아무것도 안 바뀜).
②가 실패하면 ①은 이미 됐으니 안내하고, **다시 누르면 이어서** 된다(둘 다 중복 안전).

## 7. 개인정보

| 무엇 | 어디에 | 얼마나 | 누가 보나 |
|---|---|---|---|
| 내보내기 `.txt` 원본 | 올리는 사람 PC | 올린 뒤 직접 지운다(안내) | 그 PC 사용자 |
| 가린 원문 | `kakaoWork/notes`(서버 전용) | **30일**(`KEEP_DAYS`, 날짜 칸째 물리 삭제) | **총괄관리자만**(💬 카톡정리) |
| 진행 기록 한 줄(가린 발췌) | `work_erp` 업무 기록 | 업무 기록과 같다 [확인 필요 — 업무 기록 파기 기준] | 업무관리를 여는 재직 직원(기존 규칙) |
| 첨부 파일 | **서버에 없다.** 복사한 폴더 | 그 폴더 규칙 | 그 폴더 권한 |

- **가리개**: `maskSensitive`(주민번호·카드·계좌, 전화번호는 남김)를 브라우저에서 한 번, 서버에서 한 번. 진행 기록은 거기에 **주민번호 지우개**(`PuRrnMask.maskRrnInText`)를 한 번 더 겹친다.
  지우개가 화면에 안 실려 있으면 **저장을 막는다**(옵시디언 내보내기와 같은 규칙 — 조용히 새는 것보다 시끄럽게 멈춘다).
- **AI 없음**: 이번 버전은 어떤 글도 구글·외부 AI 로 보내지 않는다. 그래서 판독 울타리(`rrnScrub` 거절 규칙)·`SENSITIVE_KINDS` 는 해당이 없다.
  AI 요약을 붙이는 날 그 두 가지와 `tests/read-fence-apps.test.js` 를 함께 건다.
- **첨부 이름 민감 의심**: 신분증·주민·통장·계좌·진단서·사본 같은 낱말이 든 이름은 **복사 기본 해제**, 「민감 의심」 표시. 사람이 확인하고 직접 체크한다.
- **총괄관리자만 올린다**: 방 허용목록과 `kakaoImport` 가 총괄관리자(`uid_roles/isAdmin`) 전용이므로 직원 화면에는 이 탭이 없다.

### 「담당 노무사 최종 확인」 항목 (이 문서는 법률 검토를 하지 않는다)
1. 방 참여자(11명)에게 **고지·동의**가 필요한가 — 개인정보 보호법상 수집·이용 근거와 고지 의무 [조문은 노무사가 확인].
2. 대화에 섞이는 **의뢰인·근로자 개인정보**(민감정보 가능)를 가려서 **30일** 서버에 두는 것이 적정한가.
3. **방에 직원이 아닌 사람**(퇴사자·외부인)이 있는가 — 있으면 «진행 기록을 재직 직원이 모두 본다»와 어긋난다.
4. 2026-10-09 직원 안내문의 「30일 뒤 지운다」 문구를 내보내기 방식에 맞게 고칠지(초안은 `docs/카톡-법인방-매주-할-일.md` 끝).
5. 사내 처리 기준 문서(`docs/사진-개인정보-보유기준.md` 꼴)에 «카톡 업무방» 항목을 둘지.

## 8. 매주 하는 일 (한 장 안내는 `docs/카톡-법인방-매주-할-일.md`)
올리기는 총괄관리자만 한다. 내보내기·파일 받기는 방에 있는 누구나 한다 — 총괄관리자가 직접 하면 가장 간단하다.
다른 직원이 하면 `.txt`와 받은 파일을 **공유 폴더**에 두고, 총괄관리자가 그 폴더를 고른다(폴더 고르기는 어느 폴더든 된다).

## 9. 첨부 파일 (서버에 올리지 않는다)

- 대화 txt 에서 «파일: 이름.ext» 꼴과 파일 이름만 있는 줄을 찾는다 [확인 필요 — PC 카톡의 첨부 표기는 실물로 확인].
  사진·동영상 줄은 «이름이 없다» — 이름으로 맞출 수 없으므로 **세기만** 한다(「사진 3장」). 사진은 이 설계의 파일 복사 대상이 아니다.
- **법인방 파일 판별**: 받은 파일 폴더에서 **대화에 적힌 이름과 같은 파일만** 법인방 것으로 본다. 나머지는 건드리지도 목록에 올리지도 않는다.
  카톡이 겹침을 `이름 (1).hwp` 로 바꾸므로, 정확히 같은 이름이 없을 때만 « (숫자)» 를 뗀 이름으로 한 번 더 맞추고 「이름 비슷」으로 표시한다.
- **카톡 만료 D-N**: 보낸 날 + 14일 − 오늘 [확인 필요 — 관찰: 10/23 받은 파일 기한 11/06]. 만료가 임박·지났고 폴더에 없으면 «지금 서랍에서 받으세요».
- **보낼 곳**: `카톡파일/{사건번호 또는 업체명}/{날짜}_{보낸사람}_{원래이름}`. 묶음이 «미분류»이거나 «짐작»이면 `카톡파일/미분류/`.
  File System Access API(크롬·엣지)로 고른 폴더에 **복사만** 한다 — 원본은 지우지 않고, 같은 이름이 이미 있으면 **건너뛴다**(덮어쓰기 없음).
  크롬·엣지가 아니면 이 단계를 막고 안내한다(업무관리의 옵시디언 내보내기와 같은 한계).
- 진행 기록 줄에는 **파일 이름만** 적는다. 보낸 폴더 경로는 PC마다 다르므로 적지 않는다(폴더 규칙은 사무실이 정한다).
- 사진첩에 안 잇는 까닭: 사진첩은 이미지·PDF·한글만 받고 엑셀·워드는 못 받으며, 올리면 서류 자동 판독이 **원본을 AI 로 보낸다**(2026-08-17 대표 «감수» 결정) — 사건 서류에는 맞지 않는다.

## 10. 화면
- 💬 카톡정리 위에 탭 둘: **알림**(지금 화면) · **대화 내보내기 올리기**(새것). 총괄관리자에게만 보인다.
- 표는 **☐ 고르기 칸 + 번호**가 맨 왼쪽(CLAUDE.md 자료 목록 규칙). 번호는 «보는 번호» — 저장하지 않는다. 머리줄 ☐ 는 보이는 줄만 고른다.
- 한 칸은 한 줄(넘치면 `…` + `title` 에 전문). 폰에서는 줄마다 «두 줄 카드»(1줄 ☐·번호·날짜·묶인 곳·근거, 2줄 요약). 입력칸 16px 이상.
- 고른 것은 화면을 떠나면 비운다. 읽은 파일 내용도 탭을 떠나면 메모리에서 버린다.

## 11. 검사 (규칙을 못 박는다 — 「지금 값」을 박지 않는다)
- 세 꼴(PC·안드로이드·아이폰)이 읽히고, 엔터가 든 글이 앞 글에 붙고, 못 읽는 꼴이어도 앱이 멈추지 않는다.
- 방 이름이 목록 밖이면 **읽기 전에 거절**한다.
- 같은 파일을 두 번 올려도 `lid` 가 같아 새 줄이 0이다. 내용이 달라지면 **옛 줄이 그대로**이고 새 줄이 생긴다(덮어쓰기 없음).
- 사건번호 «글자 그대로» 일치만 확실이고, 업체명만이면 기본 해제다. 업체 id 를 이름으로 채우는 코드가 없다.
- 주민번호 지우개가 없으면 저장이 막힌다. 요약·파일명에 주민번호 꼴이 남지 않는다.
- 서버: 목록 밖 방은 방 이름도 안 남고, 30일 밖·미래 글은 건너뛰고, 서버가 가리개를 다시 친다.
- 파일: 대화에 이름이 없는 파일은 복사 목록에 안 오른다. 같은 이름이 있으면 덮어쓰지 않는다. 민감 의심은 기본 해제다.
- 기존 `kakao-work.test.js`·`pu-kakao-work.js` 는 **그대로**다(셈 한 벌을 건드리지 않는다).
