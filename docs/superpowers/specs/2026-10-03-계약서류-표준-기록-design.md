## 2. 표준 양식 — 세 갈래

### 2.1 업체·급여 계약 6종 (엑셀 한 벌) — **만들어 둠**
- `바탕 화면\푸른문서양식\앱용 표준\업체·급여 계약 6종_표지틀.xlsx` (2026-10-03, 저장소 밖).
- 만든 법: 원본에서 업체명단을 **표지 한 줄**(`{{회사명}} {{주담당}} {{계약일}} {{사업자번호}} {{업태}} {{종목}} {{대표자}} {{우편주소}} {{담당자연락처}} {{계약금액}} {{납부일}}`)로 줄이고, 6종 시트의 수식은 그대로 둔다. 시트 고르개 칸은 1, 열 때 다시 계산(`fullCalcOnLoad`).
- 지운 것: 86곳 업체 자료(공유 글자표 739→259), 수식의 지난 계산값(마지막에 고른 업체 이름·주소가 남아 있었다), 일정 메모(댓글), 남의 메일 주소 링크·칸, 손으로 적은 계약 날짜 7칸(→ `{{계약일}}`), 계산 순서 파일(calcChain).
- 고친 오탈자: 「위힘한다」→위임한다, 「전향의 자문수수료」→전항의.
- 검증: 앱의 채우기 코드(`PuFormCardFill.xlsxFillParts`)로 가짜 값을 넣고 실제 엑셀로 열어 6장 모두 계산됨 확인 — 계약기간 EDATE(2026-10-05→2027-10-04), 사업장관리번호 「-0」, CMS 금액·이메일.
- 쓰는 법: 문서관리 › 업체계약 › 「업체·급여 계약 6종 (엑셀 한 벌)」 양식에 원본으로 올린다(대표·직원이 화면에서). 기존 글자 양식 6종(fm-pr-*)은 그대로 둔다(이알피 계약서 출력이 쓰는 중).

### 2.2 사용자측 위임계약서 (사건·컨설팅)
- 틀 하나 + **위임사무 문구 고르기**: 인사노무컨설팅 · 부당해고 대응 · 직장 내 괴롭힘 조사 · 근로감독 대응 · 단체교섭 · 기금 지원금 신청 · 직접 적기.
- 자리: `{{회사명}} {{위임사무}} {{계약금액}} {{부가세처리}} {{계약기간}} {{기간연장}} {{특약}} {{계약일}} {{대표자}} {{주소}} {{대표전화}}`.
- `{{기간연장}}` 두 가지: 「사무가 끝날 때까지 자동 연장」 / 「당사자 합의로 연장」.
- 원본: 최근 실문서 한 벌을 바꿀 자리 만들기(제안서 설계 §4)로 표지화해 「사건계약 › 사용자측」에 올린다. 문구 목록은 코드 상수(`CASE_TASKS`)로 두고 채우기 창에서 고른다.

### 2.3 근로자측 위임계약서 (임금체불·구제신청)
- 별도 틀. 사건계약 › 근로자측(이미 있는 `side: 'worker'`). 체당금 세트(fs-chedang)와 함께 쓴다.

## 3. 기업별 계약 기록 — 「언제 · 어느 회사 · 무슨 서류 · 보냈나」

문서관리 › **기업별 계약서**(이미 있음, `pu_docs/co_docs/{coKey}`) 를 «계약 기록» 으로 넓힌다.

- 한 줄 = `{at(계약일), kind(자문/급여/위임-사건종류/제안서/CMS/EDI…), amount, by, sentAt?, files:[docId…], src}`.
- 들어오는 길
  - **(가) 엑셀 업체명단 가져오기** — 86곳 한 번에(계약체결일·공급대가·지급일·EDI). 회사는 이름·사업자번호로 기업정보함/이알피와 맞추고, 못 맞춘 것은 확인 화면에서 고른다.
  - **(나) PC 폴더 가져오기** — 폴더를 끌어다 놓으면 폴더·파일 이름으로 회사·종류·날짜를 짐작 → 확인 화면 → 올림. 같은 파일(해시)은 두 번 안 올린다(`pu_docs/hash` 이미 있음).
  - **(다) 메일 첨부** — 메일 보기의 첨부 옆 「🏢 기업별 서류로」(급여데이터함 단추와 같은 꼴). 서버가 메일함에서 받아 원본 보관함에 넣고 연결한다(브라우저로 내려받았다 다시 올리지 않음).
  - **(라) 앱에서 보낸 것** — 제안서·계약서 보내기 창이 보낼 때 자동으로 한 줄(제안서 설계 §7.1).
- 화면: 회사를 고르면 계약 기록이 날짜순(최근 위) — 종류 칩 · 금액 · 파일 미리보기 · 「보냄 ✉ 날짜」.

### 3.1 권한 — 서명본은 대표·관리자만 (대표 「추천대로」 2026-10-03)
- 서명본·EDI 위임장에는 대표자 주민번호(일부)·계좌가 들어 있다.
- `co_docs` 항목에 `secret: true` 를 두고, 원본 파일 읽기는 관리자만. 목록 줄(회사·종류·날짜)은 직원도 본다.
- **규칙 바뀜**: `pu_docs/co_docs` 의 `src` 에 `'mail'`·`'import'` 추가, 비밀 원본 읽기 제한. 생성기(`scripts/make-firebase-rules.js`)만 고치고 **콘솔 배포는 대표 승인 뒤**(`--deploy`).

## 4. 자동화 — 이알피 계약에서 한 번에

- 이알피 계약(계약번호·금액·기간·종류)을 고르면 그 종류의 세트(업체 6종 엑셀 / 사용자측 위임계약서 / 근로자측)를 계약 자료 + 기업정보함으로 채운다(서식 묶음 설계의 B단계를 여기에 합친다).
- 채운 뒤: 손보기 → 메일로 보내기 → 기업별 계약 기록 자동 한 줄 — 모두 제안서 설계의 부품.

## 5. 고칠 것 (검증 중 발견)

- `PuFormCardFill.xlsxFillParts` 의 이름표 짐작(「주소」 옆 빈칸에 쓰기)이 **표지가 이미 있는 엑셀에서도** 돈다 — 6종 틀에서 18칸에 값이 더 들어갔다(모두 병합된 이름표 칸 안이라 인쇄엔 안 보였음). → 표지가 하나라도 있으면 이름표 짐작을 하지 않는다 + 병합 칸의 왼쪽 위가 아니면 쓰지 않는다.

## 6. 안전

- 원본·서명본·업체명단·표지틀은 저장소에 넣지 않는다(공개). 검사는 가짜 회사만.
- 메일함 읽기는 머리글 위주, 첨부는 사람이 단추를 누른 것만 옮긴다.
- 규칙 배포는 대표 승인 뒤.
