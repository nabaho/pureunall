# 컨설팅보고서 — 서류 진행 기록(③서명본·④별첨·⑤제출) 설계

- 작성일: 2026-10-10 · 상위: `2026-10-10-gov-report-docs-design.md`(서류 관리) · `2026-10-05-정부컨설팅-보고서자동화-design.md` §7~§8(서명·제출)
- 대표 지시(2026-10-10 「순서대로 모두」): 서류 체크표의 ③④⑤ 를 채운다. 이미 정한 것: 서명은 **날인 스캔 회신**, 메일은 **담당 노무사 본인 계정**(2026-10-07), 플랫폼 로그인·최종 제출은 **사람**.
- 이 기능은 «기록»이다 — 메일을 대신 보내거나 플랫폼에 올리지 않는다. 사람이 한 일(발송·회신·제출)을 한 번 눌러 남기고, 현황판이 그것을 모아 보여 준다.

## 1. 범위

한다
- 서류 체크표 ③ 업체 서명본 · ④ 산출물 별첨 · ⑤ 기관 제출 칸을 **누를 수 있게** 한다. 칸을 누르면 작은 창에서 상태·날짜·메모를 남긴다.
- 상태: `없음`(○) · `진행`(◐) · `완료`(●) · `막힘`(✕) · `해당없음`(—). 칸마다 선택 가능한 값은 단계 종류에 따라 정한다(§3).
- ③ 은 **발송일 → 회신(스캔 받음)일**의 두 날짜를 남긴다. 회신이 안 오면 «회신 N일째» 를 센다.
- ⑤ 는 **제출 방식**(메일/플랫폼/우편 등 자유 선택)·**제출일**·**접수 확인 여부**를 남긴다.
- 현황판 숫자 칸의 「서명」·「제출」(지금은 꺼져 있음)을 켠다: 서명 = ③ 이 진행 이상인 줄 수, 제출 = ⑤ 완료 줄 수. ⏰ 챙길 것에 「서명 회신 기다림」 · 「제출 기한 지남」을 더한다.
- 목차 창에도 ③④⑤ 상태 딱지를 보인다.

하지 않는다(다음 단계)
- 파일 올리기(서명 스캔 PDF 저장): 이번에는 «받았다»는 사실·날짜·메모만 남긴다. 파일은 메일함에 있다. 「받은 서류함」 단계에서 메일 첨부와 연결한다.
- 메일 발송·플랫폼 업로드 자동화(Aside) — 상위 설계서 §7-1 의 별도 단계.
- 대형 사업의 단계별 상태·기준 점검.

## 2. 자료 — 새 자리 `scal_docs`

`scal_docs/{업체번호}/{rid}` (rid = `{사업번호}_{연도}` 로 `scal_reports` 와 같다. 연도·rid 규칙은 보고서 창의 `grpRid` 와 같아야 한다)

```
{ items: { "<서류줄 id>[:회차]": { st:'done'|'doing'|'blocked'|'na'|'none',
                                   sentAt?:'YYYY-MM-DD', gotAt?:'YYYY-MM-DD',
                                   by?:'이름', at: <epoch ms>, note?:'짧은 메모',
                                   how?:'mail'|'platform'|'post'|'other', ack?: true } },
  u: <epoch ms> }
```

- `items` 의 키는 서류 틀(`DOC_PLANS`)의 서류 줄 id(회차마다인 줄은 `id:회차`). 알 수 없는 키는 읽기에서 버린다.
- 한 줄을 고치면 그 키 하나만 쓴다(`update` 로 `items/<키>`). 한 사람이 다른 줄을 쓰는 동안 덮이지 않게 **줄 단위로만** 쓴다.
- 글자수 한도: 메모 200자. 날짜는 `YYYY-MM-DD` 형식만 받는다.
- 개인정보: 이름(`by`)·날짜·짧은 메모뿐. 메모에 연락처·주민번호 등을 쓰지 말라는 안내문을 창에 둔다(검사로 막지는 않는다).

### 2-1. 규칙(새 자리라 게시가 필요하다)

`scal_docs`: 읽기 로그인 · 쓰기 로그인(`scal_reports` 의 본기록과 같은 «직원이 만들고 고치고, 지우기는 관리자만»). 위쪽 칸(루트·`$co`)은 관리자 전용으로 닫아 아래 줄 규칙을 «위에서 뚫지» 못하게 한다(2단계 `scal_reports` 와 같은 이유). 규칙은 생성기(`scripts/make-firebase-rules.js`)에서 만들고 JSON 두 개를 다시 만든다. **게시는 대표 승인 뒤에만** 한다(`scripts/rules-deploy.js`). 게시 전에는 쓰기가 거절되고 화면은 「규칙 게시 필요」 안내를 보인다.
- 등록부: `govreport` 의 `primaryRoots` 에 `scal_docs` 를 더하고 `writeContracts` 에 `scal_docs/{co}/{rid}/items/{key}` 를 더한다(이제 실제로 쓴다). 예약 이름 `activeWriter/gov_report` 는 그대로 둔다.
- 검사: 규칙 생성기 검사에 `scal_docs` 를 더한다. `tests/perf-rules` `allowTop` 과 `photos-staff-share` 의 PENDING 목록에 게시 전까지 올리고, 게시 뒤에 지운다(2단계에서 한 방식).

## 3. 서류 줄마다 가능한 상태

| step(서류 틀) | 칸 | 가능한 상태 | 날짜 |
|---|---|---|---|
| `sign` | ③ 업체 서명본 | 없음 · 진행(발송함) · 완료(회신 받음) · 막힘 | `sentAt` · `gotAt` |
| `attach` | ④ 산출물 별첨 | 없음 · 진행 · 완료 · 해당없음 | — |
| `submit` | ⑤ 기관 제출 | 없음 · 진행(제출 준비) · 완료(제출함) · 막힘 | 제출일 `gotAt`, 방식 `how`, 접수 `ack` |
| `report`(①②) | 자동(변경 없음) | — | — |
| `plat` | 플랫폼 입력(대형) | 이번 범위 밖 | — |

- 서류 틀에 `sign`/`attach`/`submit` 이 없는 사업의 줄은 칸을 그리지 않는다(지금과 같다).
- 상태 판정 순서가 «막힘 > 완료 > 진행 > 없음» 이면 진행 막대(4칸)는 ① ② ③ ⑤ 가 완료일 때 채워진다(④ 는 «해당없음»이면 건너뛴다).
- «기한»: 서류 체크표의 기한(계약 종료일)은 그대로 쓴다. ⏰ 챙길 것의 새 두 줄: ③ `sentAt` 이 있고 `gotAt` 이 없는 채로 7일 넘음 · ⑤ 가 완료가 아닌데 기한이 지남.

## 4. 화면

- 체크표 칸(③④⑤)을 누르면 가운데에 «칸 창»: 서류 이름 · 업체 · 상태 고르기 · 날짜 입력(해당 칸만) · 메모 · [저장] [닫기]. 저장은 그 줄 키 하나만 쓴다.
- 저장 성공 시 체크표와 숫자 칸·챙길 것·목차를 다시 계산한다(읽기를 다시 하지 않고 로컬 값을 갱신한다).
- 쓰기가 거절되면(규칙 미게시·권한 없음) 창에 「저장하지 못했습니다 — 규칙 게시 또는 권한 확인」을 보이고 값은 그대로 둔다.
- 누가 언제 고쳤는지 칸 창 아래 작은 글씨로 보인다(`by`·`at`). 지우기(상태를 「없음」으로 되돌리기)는 누구나 할 수 있다 — 기록은 상태 값만 바뀌고 줄은 남는다(진짜 삭제는 관리자만).
- 권한: 로그인한 직원이면 누구나 기록할 수 있다(2단계 `scal_reports` 와 같은 수준). 「내 담당만」 거르개는 그대로 쓴다.

## 5. 읽기

현황판 읽기(`grLoad`)에 `scal_docs` 한 번 읽기를 더한다(전체 한 번, `once`). 읽기 실패는 서류 체크표만 «기록을 못 불러왔습니다»로 두고 나머지(목록·왼쪽 패널)는 그대로 동작한다. 이름 표(`GR_NODES`)에 넣어 등록부 검사의 «주인 없는 자리» 지적을 피한다(2·3단계와 같은 방식).

- `js/pu-gov-report-track.js`(새, 순수 함수) + `tests/gov-report-track.test.js`: `keyOf(item, round)` · `normalize(raw)`(알 수 없는 키·잘못된 값 버리기) · `stateOf(plan, rec, item)` · `merge(rows, track)` → 체크표 칸 · `kpiExtra(rows)` · `alertsExtra(rows, today)` · `validate(entry)`(날짜·메모 길이) · `patchFor(entry, who, now)`.
- `js/pu-gov-report-docs.js`: 체크표 칸이 `track` 을 받아 ③④⑤ 칸과 목차 딱지를 계산한다(자동 ①② 로직은 그대로).
- `gov-report.html`: 읽기 · 칸 창 · 쓰기(줄 단위 `update`) · 숫자 칸 「서명」·「제출」 켜기 · 챙길 것.
- `scripts/make-firebase-rules.js` + 규칙 JSON 두 개 + `js/pu-ontology.js`(+모든 html 의 `?v`) + 검사 목록(allowTop/PENDING).
- 기록: STATUS.md · `status/2026-10-10-gov-report-track.md`. 규칙 **게시 승인 요청**은 합친 뒤 대표에게 한다.
