# 컨설팅보고서 앱(현황판) 설계

- 작성일: 2026-10-10 · 상위 설계서: `2026-10-05-정부컨설팅-보고서자동화-design.md` (§11 「[F] 현황판」을 앞당김)
- 대표 지시(2026-10-10): 「포털 의뢰인 업무에 별도 앱을 만들어 진행」. 시안 확인 후 「진행」.
- 한 줄: 포털 **의뢰인 업무** 줄에 **📑 컨설팅보고서** 타일을 더하고, 새 화면 `gov-report.html` 에서 모든 사업장·사업의 보고서 상태를 한눈에 본다. 쓰는 일은 정부사업일정의 기존 보고서 창(초안·AI·HWPX·확정)을 그대로 쓴다.

## 1. 범위

한다
- 포털 타일 + 앱 막대 + 앱 등록(온톨로지) — 기존 «모든 앱이 갖춰야 하는 것» 검사를 통과한다.
- `gov-report.html`: 숫자 칸(전체·미작성·초안·검토완료·서명·제출) · 찾기 조건(연도·사업·담당·상태·업체) · 보고서 목록 · 양식 서고 현황(읽기) · ⏰ 챙길 것.
- 목록 한 줄의 「📄 작성/이어 쓰기/⬇ HWPX/보기」 단추 → `gov-consulting.html#rpt=<업체번호>|<사업번호>` 로 건너가 그 업체 보고서 창을 연다.
- 정부사업일정이 `#rpt=` 를 읽어 보고서 창을 연다(기존 `#sc=` 와 같은 기다리기 방식).
- 순수 함수 모듈 `js/pu-gov-report-list.js`: 줄 만들기 · 상태 가르기 · 숫자 · 거르기 · 챙길 것.

하지 않는다
- 보고서 창을 새 화면으로 옮기지 않는다(정부사업일정 안에 그대로 둔다).
- 서명(③)·기관 제출(④) 기능은 이번 범위 밖이다. 진행 막대 4칸 중 ③④ 는 «비어 있음»으로만 그린다(다음 단계 [D]·[E] 에서 채움).
- 양식 등록은 이 화면에서 하지 않는다. 서고 현황은 읽기만 하고 「등록·바꾸기」 는 정부사업일정의 ⚙ 양식 서고로 건너간다(`#forms`).
- 대형 사업(일터혁신·산업일자리 등)은 줄에 넣지 않는다(§14 대형형은 별도 설계). 간단형 양식(`PuGovReport.FORMS` 로 가려지는 사업)만 줄이 생긴다.

## 2. 자료 · 읽기만 한다

이 화면은 **아무것도 쓰지 않는다**(규칙·DB 변경 없음).

| 읽는 자리 | 쓰임 |
|---|---|
| `scal_cos` · `scal_types` · `scal_scheds` · `scal_staff` | 업체·사업·회차·담당 (정부사업일정이 쓰는 그 자리) |
| `scal_reports/{업체}/{사업}_{연도}` | 보고서 상태 `state`(초안/검토완료)·`ver`·`updatedAt`·`updatedBy`·AI 칸 표시 `aiFields` |
| `scal_rptFormsIndex` | 양식 서고 현황(사업·파일·연도) |

줄이 생기는 조건: 업체가 그 사업(간단형)에 걸려 있고, 올해(또는 고른 연도) 그 사업의 회차가 하나라도 있다.

상태 가르기(위에서부터 먼저 맞는 것)
1. `scal_reports` 에 `state==='검토완료'` → **검토완료 vN**
2. `scal_reports` 가 있고 `state==='초안'` → **초안**(`aiFields` 가 있으면 「AI 초안」 딱지)
3. 보고서가 없고 회차가 **모두 종료** → **미작성**(종료일부터 지난 날수를 센다)
4. 보고서가 없고 회차가 남아 있다 → **작성 전**(단추 비활성, 「회차가 남았습니다」)

진행 막대 4칸: ① 초안이 있다 ② 검토완료다 ③ ④ 이번에는 항상 비어 있다.

챙길 것(⏰): 종료 후 14일 넘은 미작성 · 초안 7일 넘음 · (서명 기다림은 ③ 이 생기면 센다 — 이번에는 0 으로 두되 칸은 그린다).

## 3. 화면

시안(2026-10-10 대표 확인) 그대로다. 왼쪽 큰 칸에 숫자 칸·찾기 조건·목록, 오른쪽에 ⚙ 양식 서고 현황과 ⏰ 챙길 것. 폭이 좁으면 한 줄로 쌓는다.
- 숫자 칸을 누르면 그 상태로 거른다(다시 누르면 풀림).
- 「내 담당만」 = 로그인한 사람이 그 사업장 담당·부담당인 줄(정부사업일정의 `getCoAtts` 와 같은 뜻).
- 단추: 미작성 → 📄 작성 · 초안 → 이어 쓰기 · 검토완료 → ⬇ HWPX(보고서 창을 열어 내려받기) · 작성 전 → 비활성.
- 색은 저장소 팔레트(`tests/color-palette-apps.test.js`) 안에서만 쓴다.

## 4. 권한 · 개인정보

- 로그인한 직원만 본다(포털 앱과 같은 문). 목록에는 업체 이름·담당 이름·상태만 나온다 — 보고서 본문은 나오지 않는다.
- 기술보호 보고서 줄도 이름·상태만 나온다.
- `#rpt=` 로 건너간 뒤의 권한(확정은 담당·부담당·관리자만 등)은 기존 보고서 창 규칙 그대로다.

## 5. 오류 · 빈 상태

- 클라우드에서 못 읽으면 「불러오지 못했습니다 — 연결을 확인해 주세요」와 다시 시도 단추.
- 줄이 없으면 「올해 걸린 보고서가 없습니다 — 사업 걸기는 정부사업일정에서」.
- `#rpt=` 가 가리키는 업체·사업이 15초 안에 안 나타나면 「그 보고서를 찾지 못했습니다」 알림(기존 `#sc=` 와 같다).

## 6. 만들 것

- `gov-report.html` (새) — 화면 + 읽기. 기존 앱 페이지(`gov.html`)의 공통 머리(Firebase·로그인 문·앱 막대·뒤로가기·누구인지)를 따른다.
- `js/pu-gov-report-list.js` (새, 순수 함수) + `tests/gov-report-list.test.js`.
- `enter.html` 의 `APPS` 와 `js/pu-appbar.js` 의 `APPS` 에 같은 줄(consult 바로 뒤, 행 `client`).
- `js/pu-ontology.js` PROGRAMS 에 새 앱(읽기 자리는 sharedRoots — `scal_reports`·`scal_rptForms*` 는 정부사업일정 소유 그대로).
- `gov-consulting.html`: `#rpt=` 읽기(`openFromReportLink`) · `#forms` 로 양식 서고 열기.
- 기록: STATUS.md · `status/2026-10-10-gov-report-app.md`.
