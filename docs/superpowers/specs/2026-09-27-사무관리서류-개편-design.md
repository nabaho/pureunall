## 1. 목표와 범위

| # | 할 일 | 끝났다고 보는 기준 |
|---|---|---|
| A | 계약서 양식 화면 개편 | 양식을 왼쪽 트리에서 고르면 오른쪽에 A4 종이 한 장이 **높이 제한 없이** 뜬다. 가로 탭·목록 표·마우스 올림 미리보기는 없어진다 |
| B | 원본 보관함 | 파일을 올리면 창고에 **지울 수 없는 사본**이 남는다. 양식을 지우거나 첨부를 빼도 보관함에서 내려받을 수 있다 |
| C | 기업별 계약서 | 회사를 고르면 그 회사 계약서(사진첩에서 가져온 것과 직접 올린 것)가 한곳에 모인다 |

**범위 밖**: 이알피 「📄 계약서 출력」 동작 변경, 사진첩(pu-photos.html) 수정, 서식집(`claude/forms-library`) 연동,
이알피 업체관리와의 회사 자동 연결(§8 후속).

## 2. 지켜야 할 것 (기존 계약)

1. **양식 자료 자리와 저장 방식은 그대로다.** `data/contract_forms`(통표 `{v:[…], u}`) · `data/contract_forms_removed`,
   저장은 반드시 `changeForms`/`changeRemoved` 거래 한 길. `mount()` 안에 `.set(` 금지.
   (tests/docs-office-forms.test.js ⓓⓔ 가 지킨다 — 이번에 **한 줄도 느슨하게 하지 않는다**.)
2. **첨부(base64 `attachments[].data`)는 그대로 둔다.** 이알피 계약서 출력이 `att.data` 로 한글을 연다
   (pu-erp.html `openContractHwpAttachment`). 창고로 «옮기면» 이알피가 깨진다. 보관함은 «옮기기»가 아니라 «사본»이다.
3. 양식 화면은 **처음 열 때 한 번만** 싣는다(`!formsMounted`). 뒤로가기는 `__puBackNav = true` 로 알린다.
4. 사진첩은 **사람별 잠금**(본인 것만 읽기)이다. 남의 사진첩을 모아 보는 길은 만들지 않는다.

## 3. 화면

### 3-1. 왼쪽 트리 (docs-esign.html `<nav class="side">`)

```
📤 집단체불 전자송부                 data-pane="esign"   (#)
🗂 사무관리서류
   📄 계약서 양식                     data-pane="forms"   (#forms)
      <div id="formsTree">           ← 양식 화면이 처음 열릴 때 PuContractForms 가 채운다
        ▸ 상담사항 1
        ▾ 업체계약 7
            자문계약서 (푸른 표준)     (#forms:fm-pr-advisory)
            …
   🏢 기업별 계약서                   data-pane="co"      (#co)
   🗄 원본 보관함                     data-pane="arc"     (#arc)
```

- 사이드바 폭 196px → 250px. 양식 이름이 길면 말줄임(`title` 에 전체 이름).
- 계약유형 6종은 접이식. 처음엔 **고른 양식이 속한 유형만** 펼친다. 접힘 상태는 localStorage(편의용, 실패해도 무방).
- 사건계약은 지금처럼 `groupName`(체당금/해고/…)으로 한 단계 더 묶는다.
- 트리 맨 아래 유형마다 `+ 새 양식` 한 줄(그 유형으로 추가 창을 연다).
- **휴대폰(≤700px)**: 사이드바는 지금처럼 위쪽 가로줄이 되고 트리는 숨긴다. 대신 양식 화면 맨 위에
  `유형 ▾` `양식 ▾` 두 개의 고르기 칸을 띄운다.

### 3-2. 양식 보기 (오른쪽)

```
[업체계약 · 자문계약서 (푸른 표준)]            [수정] [복제] [🗑]
[📎 원본: 자문계약서_2026.hwp  ✓보관함에 사본]   [🔍 한글 원본] [📎 파일 업로드] [rhwp v…]
┌──────────────── A4 종이 (최대 폭 820px, 높이 제한 없음) ────────────────┐
│  본문 pre-wrap · 칸 {{회사명}} 은 파란 딱지로 강조                         │
└─────────────────────────────────────────────────────────────────────────┘
```

- 글자 크기는 13px 고정(지금의 「분할 비율에 따라 9~15px」 계산 삭제 — 분할이 없어졌다).
- 칸 강조: 본문을 `textContent` 로 넣은 뒤 `{{…}}` 부분만 `<span class="pcf-v">` 로 감싼다(HTML 문자열 조립 금지 — 본문은 사용자 입력).
- 비활성 양식은 종이 위에 「사용 안 함」 띠.
- 양식을 아직 안 골랐으면 「왼쪽에서 양식을 고르세요」 빈 화면 + 유형별 개수 요약.
- 수정 창(openModal)·한글 미리보기(openHwpPreview)·rhwp 판 올리기는 **지금 것을 그대로** 쓴다.

### 3-3. 원본 보관함 (#arc)

- 표: 파일 · 연결(양식 이름 / 기업 이름 / 「양식 삭제됨 · 사본만 남음」) · 크기 · 올린 날 · 올린 사람 · [내려받기].
  (한글 미리보기는 계약서 양식 화면·기업별 큰 보기에서 한다 — 보관함은 목록과 내려받기에 집중한다.)
- 위에 검색 한 칸(파일명·연결 이름). 최신순. **삭제 단추 없음.**
- 맨 위 한 번만 뜨는 줄: 「기존 첨부 N개가 아직 보관함에 없습니다 [보관함에 담기]」(§5-4).

### 3-4. 기업별 계약서 (#co)

- 왼쪽: 회사 목록(이름 · 건수, 검색). 오른쪽: 고른 회사의 계약서 카드 격자(미리보기 · 제목 · 계약일 · 출처 딱지 「사진첩」/「업로드」).
- 카드를 누르면 큰 보기(이미지면 그림, PDF·한글이면 미리보기 창) + [내려받기] [제목·날짜 고치기] [이 회사에서 빼기].
  「빼기」는 연결만 지운다 — **파일은 보관함에 남는다.**
- 위 단추 둘:
  - **[사진첩에서 가져오기]**: 내 사진첩에서 `read.kind === 'contract'` 사진을 격자로 보여 준다(판독된 회사명 표시).
    골라서 회사를 정하면(판독된 회사명이 기본값, 기존 회사 자동완성) 사본이 보관함으로 복사되고 그 회사에 붙는다.
    이미 가져온 사진은 「가져옴」 딱지(같은 파일 해시 → 두 번 담지 않는다).
  - **[업로드]**: 파일을 고르고 회사·제목·계약일을 정해 올린다.
- 회사가 하나도 없으면: 「사진첩의 계약서를 가져오거나 파일을 올리면 회사별로 모입니다」 + 두 단추.

## 4. 자료

### 4-1. 자리

| 자리 | 무엇 | 쓰기 규칙 |
|---|---|---|
| 창고 `pu_docs/originals/{fileId}/{파일명}` (pureun-erp-hrphotos) | 원본 파일 | 직원 **새로 쓰기만**. 덮어쓰기·지우기 불가 |
| RTDB `pu_docs/originals/{fileId}` | 원본 색인 | 직원 **새로 쓰기만**(`!data.exists()`) |
| RTDB `pu_docs/hash/{sha256}` | 같은 파일 찾기 → fileId | 직원 새로 쓰기만 |
| RTDB `pu_docs/co/{coKey}` | 회사 | 직원 읽기·쓰기 |
| RTDB `pu_docs/co_docs/{coKey}/{docId}` | 회사↔파일 연결 | 직원 읽기·쓰기(지우기 = 연결만 끊기) |

창고는 서면함·서고 원본과 같은 **pureun-erp-hrphotos**(서울). 읽기는 서고처럼 **직원 전체**(계약서는 법인 업무기록).

### 4-2. 모양

```js
// pu_docs/originals/{fileId}
{ name, size, type, sha256, path,            // path = 창고 경로
  at, by /*uid*/, byName,
  from: { kind:'form', formId, formName, formKind }     // 양식에 올린 것
      | { kind:'co',   coKey, coName }                  // 기업별에 올린 것
      | { kind:'photo', owner, year, photoId, coKey } } // 사진첩에서 가져온 것

// pu_docs/co/{coKey}
{ name, n /*건수*/, lastAt }
// pu_docs/co_docs/{coKey}/{docId}
{ fileId, title, date /*YYYY-MM-DD 계약일*/, src:'photo'|'upload', at, by, byName }
```

- `coKey` = 회사명 정규화(공백·「(주)」「주식회사」「㈜」 제거, 소문자) → RTDB 키 금지 문자(`.#$[]/`) 치환.
  같은 회사가 표기만 달라 두 칸이 되는 것을 막는 최소한. (사업자번호 연결은 §8.)
- `fileId` = RTDB push 키. 양식에는 새 필드 `originals: [{fileId, name, size}]` 를 더한다 — 이알피는 모르는 필드라 무시한다.
- `from` 은 **올린 순간의 기록**이다. 양식이 나중에 지워지면 보관함은 양식 목록과 견주어 「양식 삭제됨」으로 보여 준다.

### 4-3. 크기·종류

- 창고: 파일당 **25MB**(서면함·서고와 같음), 종류 검사는 앱에서(한글은 브라우저가 종류를 안 알려 줘 규칙으로 못 묶는다 — 서고와 같은 까닭).
  허용: hwp·hwpx·pdf·doc·docx·jpg·jpeg·png·heic. 거절: 그 밖 전부(exe·js·html…).
- 양식 첨부(base64)는 지금처럼 **1MB 이하만**. 1MB 초과는 보관함에만 담고 양식에는 `originals` 로만 연결한다
  (지금은 1MB 초과를 거절하고 끝이다 — 이것이 나아지는 점).

## 5. 흐름

### 5-1. 양식에 파일 올리기 (quickUpload · 수정 창 첨부)

1. 앱에서 종류·크기 검사.
2. **보관함에 먼저**: sha256 → `pu_docs/hash/{h}` 있으면 그 fileId 재사용, 없으면 창고 올리기 → 색인 → 해시 순으로 쓴다.
3. 그다음 지금처럼 양식에 반영(`changeForms`) — 1MB 이하면 `attachments` 에도, 언제나 `originals` 에 fileId.
4. **보관함이 실패하면**(규칙 미게시·네트워크): 양식 반영은 그대로 하고 「⚠ 보관함 사본을 못 남겼습니다 — {까닭}」을 띄운다.
   1MB 초과 파일은 보관함 없이는 담을 곳이 없으므로 그 경우만 거절한다.

### 5-2. 사진첩에서 가져오기

1. docs-esign 이 `PuPhotoStore.init({db, storage: hrphotos, auth, uid})`.
2. `listYears()` → 해마다 `listYear(y)` → `meta.read.kind === 'contract'` 만 → 미리보기는 `loadThumb`.
3. 고르면 `loadFull` 로 원본(dataURL) → 보관함 올리기(§5-1 ②, `from.kind='photo'`) → `co`·`co_docs` 쓰기.
4. 사진첩 원본은 **건드리지 않는다**(읽기만).

### 5-3. 기업별 업로드

§5-1 ②로 보관함에 담고 `co`(없으면 만들고 `n`+1)·`co_docs` 쓰기. `n` 은 거래로 올린다.

### 5-4. 기존 첨부 보관함에 담기 (한 번)

양식들의 `attachments` 중 `originals` 에 없는 것 → base64 를 바이트로 → §5-1 ② → 양식의 `originals` 에 fileId 추가(`changeForms` 로 한 건씩).
해시 재사용 덕에 두 번 눌러도 두 벌이 안 생긴다.

## 6. 규칙 (대표님 승인 후 배포)

- **RTDB**: `scripts/make-firebase-rules.js` 에 `rules.pu_docs` 추가(읽기 `LOGIN`, originals·hash 는 `LOGIN && !data.exists()` + 필드 검사).
  `node scripts/make-firebase-rules.js > docs/firebase-rules-전체-적용본.json` → `node scripts/rules-deploy.js`(미리보기) → 승인 후 `--deploy`.
- **창고**: `docs/firebase-storage-전체(붙여넣기용).txt` 에 한 칸:
  ```
  match /pu_docs/originals/{fileId}/{file} {
    allow read:   if isStaff();
    allow create: if isStaff() && request.resource.size < 25 * 1024 * 1024;
    allow update, delete: if false;   // 영구 보관
  }
  ```
  `node scripts/storage-rules-deploy.js` → 승인 후 `--deploy`.
- 규칙이 없을 때: 양식 화면(A)은 **그대로 된다**. 보관함·기업별 화면은 「파일 창고 규칙 게시 대기 중」 안내를 띄운다(첫 읽기 PERMISSION_DENIED 로 판정).

## 8. 후속 (이번에 안 함)

- 회사를 이알피 업체관리(`companies`)·사업자번호와 잇기 — 지금은 이름 정규화만. 합치기 단추는 연결이 생긴 뒤에.
- 서식집(`claude/forms-library`)의 검토 끝난 서식을 이 트리에 「서식」 유형으로 싣기.
- 보관함 용량이 커지면 연도별 색인 분할(사진첩과 같은 방식).

## 9. 검사

- 순수 함수: coKey 표기 변형(㈜/주식회사/공백) 한 칸으로, okDocFile 허용·거절, originalRecord 모양.
- 저장 층(가짜 db·가짜 창고): 같은 해시 두 번 → 창고 올리기 1번, 색인 1개 / 창고 실패 시 색인·해시 안 씀 /
  해시는 **맨 마지막**에 쓴다 — 창고 성공·색인 실패면 해시가 없어 다음 시도가 새 fileId 로 다시 담는다
  (창고에 고아 파일 하나가 남는 것은 감수한다. 창고는 덮어쓰기가 막혀 있어 같은 자리에 이어 쓸 수 없다).
- 양식 화면: 기존 ⓐ~ⓔ 전부 통과, `mount()` 에 `.set(` 없음, 본문을 innerHTML 로 안 넣음, 보관함 실패해도 양식 저장은 된다.
- 문서관리 뼈대: 트리 칸이 「사무관리서류」 아래, 세 칸 모두 처음 한 번만 싣기, 뒤로가기 `__puBackNav`.
- 규칙: 생성된 RTDB 규칙에 `pu_docs/originals/$id/.write` 가 `!data.exists()` 포함, 창고 규칙에 `allow update, delete: if false`.
- 눈으로: 가짜 db 로 띄운 로컬 시험 화면(커밋 안 함)에서 데스크톱·휴대폰 폭 스크린샷.

## 10. 변경 — C안 (2026-09-27 대표 결정 「c」)

대표 지적: 「왜 대시보드를 왼쪽끝으로 정리 안했나?」 · 「사건 계약에는 근로자측과 사용자측이 있다」.
목업 네 가지(A 3단 · B 메뉴에 전부 · C 거르기 칩 · D 카드 격자) 중 **C** 로 정했다.

- **메뉴는 왼쪽 끝에 붙는다.** `.shell` 의 1360px 가운데 정렬을 없앴다(넓은 화면에서 250px 떠 있었다).
  메뉴는 흰 바탕·오른쪽 선·세로 전체 높이로 고정.
- **메뉴는 3단까지** — 「전자송부 › 집단체불 위임장」, 「사무관리서류 › 계약서 양식(계약유형 6종) · 서식집(검토 후, 누를 수 없음) · 기업별 계약서 · 원본 보관함」.
  양식 이름은 메뉴에서 빼고 본문 목록으로 옮겼다(서식집 1,026종이 와도 메뉴가 안 길어진다). §3-1 의 트리 설계를 대신한다.
- **본문**: 도구줄 → 칩 줄(사건계약만: 측 칩 전체·근로자측·사용자측·공통 / 사건유형 칩, 모든 종류: 이름 찾기 · 목록/카드) → 목록 + A4 종이, 또는 카드 격자.
- **측(`side`)** — 양식에 새 칸 하나: `worker` | `employer` | `both`. 사건계약에만. 적힌 값이 먼저, 없으면 본문 칸으로 짐작
  (`{{근로자…}}` → 근로자측, `{{회사명}}`·`{{대표자}}` → 사용자측, 둘 다 없으면 공통). 수정 창에서 고른다.
- **사건유형** — 새 칸을 만들지 않고 기존 **그룹명**을 이알피 사건유형 13종(`BIZ_CASE_SEED` 이름·순서) 중에서 고르게 했다.
  이알피 「계약서 출력」이 그룹명을 계약의 사건유형 이름과 맞춰 자동 체크하기 때문이다(옛 값은 그대로 두고 직접 입력도 된다).
- **범위 밖(결정)**: 근로자측 서명본은 「기업별 계약서」에 넣지 않는다(상대 회사 밑에 근로자 개인정보가 묶인다) — 이알피 사건에 붙이는 일은 이알피 쪽.
  이알피 「계약서 출력」이 계약의 의뢰인 구분(회사·근로자)으로 측을 거르는 일은 다음 단계.
