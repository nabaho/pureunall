# 법인 서식집 — 설계 문서

- 작성일: 2026-08-06
- 대상 시스템: 푸른노무법인 ERP(`nabaho/pureunall`, GitHub Pages + Firebase `pureun-erp`)
- 담당: 대표노무사(권형하) 요청
- 관련 문서: `2026-07-21-group-arrears-esign-design.md`(집단체불 전자송부), `fund-erp/tools/README.md`(기금 서식 변환기)

## 1. 목적 (무엇을 / 왜)

법인 전체 업무에서 쓰는 서식을 **한 곳에 모아 종류별·사건별로 분류한 서식집**을 만든다.
서식집은 두 가지 역할을 한다.

1. **전자서명 템플릿 소스** — `docs-esign.html` / `sign.html`이 소비. 지금 `js/esign-docs.js`에
   하드코딩된 `ESIGN_FORMS` 3종을 대체한다.
2. **법인 전사 서식 자료실** — 전자서명 대상이 아닌 서식(취업규칙·급여대장·기금 설립서류 등)도
   분류·검색해 열람한다.

### 왜 지금 필요한가

- `js/esign-docs.js`는 **서식마다 전용 빌더 함수**(`buildDelegationHtml`, `buildConsentHtml`)를 둔다.
  서식이 수백 종이 되면 빌더 함수도 수백 개가 된다. 데이터 주도로 바꿔야 한다.
- 서식 원본이 바탕화면 17,483개 문서에 흩어져 있어 **어떤 게 최신인지 아무도 모른다**.
  실제로 현행 「별지 제3호의2서식 간이대지급금 지급청구서」는 `2. 임금체불` 폴더가 아니라
  `푸른노무법인/…/공영건설/간이대지급금/`이라는 사건 폴더에 묻혀 있었다(§3.2).

## 2. 범위 (Scope)

### 포함 — 전 도메인

| 도메인 | 서식 후보 | 파일명 고유 |
|---|---:|---:|
| 임금체불 (진정·대지급금·민사집행·위임·동의) | 857 | 552 |
| 컨설팅·근로계약 | 2,035 | 1,035 |
| 기금 | 1,447 | 733 |
| 산재 | 324 | 228 |
| 노동위원회 | 267 | 131 |
| 교섭·노조 | 255 | 199 |

전 도메인을 서식집에 담되, **전자서명 대상 여부는 서식 속성 `esign`으로 구분**한다.
`docs-esign` / `sign.html`은 `esign: true`인 서식만 소비한다.

### 제외 (YAGNI)

- 서식 **작성 UI**(화면에서 새 서식을 만드는 편집기) — 원본 HWP를 고쳐 재변환한다
- 원본 `.hwp` 파일의 저장소 커밋 — 로컬 전용 정책 유지(§7)
- 승인 워크플로(결재선·알림) — `review.status` 필드 하나로 시작
- 서식 버전 이력 UI — git 이력으로 갈음
- 기금 서식(`fund_forms.js`)의 즉시 통합 — 이미 동작 중이므로 유지하고, 서식집 스키마가
  안정된 뒤 Phase 5에서 흡수

## 3. 조사 결과 (설계 근거)

### 3.1 파일 ≠ 서식

`2. 임금체불` 폴더 HWP 70개를 전수 파싱(성공률 100%)한 결과, **한 HWP에 여러 서식이 연달아**
들어 있다. 예: `위임장-노동부위임장-진정취하서- cms-개인정보동의서.hwp`(6,552자)는
위임약정서 / 위임장 / 진정취하서 및 반의사불벌고지확인서 / 개인정보 제공 동의서 / CMS 5종을 담는다.

→ 파싱은 파일 단위가 아니라 **중앙 제목줄 기준 서식 단위 분할**이어야 한다.
70개 파일이 32종으로 접혔다(약 2:1).

### 3.2 최신 서식이 사건 폴더에 묻혀 있다

임금체불 서식 후보 857건의 소재:

```
313  10. 자문사관리      114  컨설팅업체        96  권형하 개인 이력등
 64  2. 임금체불          55  9. 강의 회의       49  1. 컨설팅자료
 45  푸른노무법인
```

`2. 임금체불` 폴더는 전체의 **7.5%**에 불과하다. 그리고 그 폴더의 서식은 전부 구법(소액체당금)
시절 자료다. 현행 서식은 `푸른노무법인/…/2025 박성수 인수인계등/인수인계/박한별/공영건설/`
같은 최근 사건 폴더에 있다.

→ **사건본을 버리면 안 된다.** 사건본이 현행 서식의 유일한 소스인 경우가 많다.
익명화해서 서식으로 승격하는 경로가 필요하다.

### 3.3 그대로 쓰면 안 되는 것

- **구법 용어**: 2021.10.14 임금채권보장법 개정으로 체당금 → **대지급금**,
  소액체당금 → **간이대지급금**, 일반체당금 → **도산대지급금**. `2. 임금체불`의 서식은 전부 구 용어.
  단, 「별지 제3호서식」처럼 관서 제출 서식은 **관서 서식 원문을 따라야** 하므로 일괄 치환하면 안 된다.
  서식별 판단이 필요하다.
- **개인정보 제공 동의서 내용 부적합**: 본문이 "회원서비스의 기초자료 / 회비산출의 근거자료 /
  회원에 대한 추천 등 실적증명자료"로, **한국공인노무사회 회원가입용 동의서**다.
  근로자 사건 수임 동의서로는 수집목적이 맞지 않는다(개인정보보호법 §15).
- **관할 변형**: 진정취하서가 천안·평택·보령본으로 갈린다. 병합하지 말고 `jurisdiction`으로 구분한다.

### 3.4 중복

`2. 임금체불` 안에서만 내용 완전동일 3그룹(체불확인서 발급신청서 ×3, 722-지급명령신청서 ×2,
일반체당금 지급청구서 ×2). 전 디스크로 넓히면 파일명 기준으로도 중복 복사본 2,150개가
748종으로 접힌다.

## 4. 기존 자산 (재사용)

이 설계는 **기금 서식 파이프라인의 일반화**다. 새로 만드는 게 아니다.

| 자산 | 위치 | 역할 | 서식집에서 |
|---|---|---|---|
| `hwp2html.py` | `fund-erp/tools/` | HWP 5.0 → HTML, **표 격자·열 너비 복원** | **그대로 재사용** |
| `build_forms.py` | `fund-erp/tools/` | 서식 목록 → JS 생성 + 실데이터 혼입 검사 | 패턴 계승, 자동 발견으로 확장 |
| `pii_scan.js` | `fund-erp/tools/` | 생성물 전수 PII 스캔(7패턴) | **확장 재사용** |
| `hwp_extract.js` | 루트 | HWP → 평문(브라우저/Node 공용) | 분류·군집용 텍스트 |
| `xlsx_gen.js` | 루트 | A4 인쇄 규격 xlsx 생성 | Phase 0 검토표 |
| `htmlPagesToPdf` | `js/esign-docs.js` | HTML → PDF | 서식 출력 |
| `fillVars` | `js/esign-docs.js` | `{{변수}}` 치환 | 렌더러 |

**중요**: `hwp_extract.js`는 평문만 뽑아 표가 사라진다. 서식 상당수가 표 기반(진정서·지급청구서·
배당요구신청서)이므로 **본문 변환은 `hwp2html.py`를 쓴다.** `hwp_extract.js`는 군집·분류용
텍스트 추출에만 쓴다.

### 기금 파이프라인과 다른 점

| | 기금(기존) | 서식집(신규) |
|---|---|---|
| 서식 발견 | `FORMS` 배열에 경로 32개 수작업 | **자동 발견** — 전 디스크 스캔 |
| 대표본 선정 | 사람이 지정 | **자동 군집 + 규칙 선정** |
| 실데이터 치환 | `REAL_NAMES` 상호 14개 하드코딩 | **인명·상호 자동 추출** |
| 출력 | `fund_forms.js` 단일 (`window.HWP_FORMS`) | 도메인 분할 JSON + index |

## 5. 아키텍처

### 5.1 저장 구조

```
forms/index.json               목록·분류·메타만 (본문 제외) — 전체 로드
forms/wage-arrears.json        도메인별 본문 — 필요할 때 fetch
forms/labor-commission.json
forms/industrial-accident.json
forms/consulting.json
forms/bargaining.json
forms/fund.json                ← Phase 5에서 생성 (그때까지는 fund_forms.js 유지)
```

**경로 주의**: `.gitignore`가 `data/`를 통째로 차단하므로(급여 실데이터 보호 규칙)
`data/forms/`는 쓸 수 없다 — 커밋 자체가 안 된다. 루트 `forms/`를 쓴다.
같은 이유로 `*.xlsx`도 차단되어 있어 Phase 0 검토표는 **저장소에 커밋되지 않는 로컬 산출물**이다.

서식 수백 종 × 본문 2KB면 1MB를 넘는다. 단일 파일이면 초기 로딩을 다 잡아먹으므로 분할한다.
`index.json`으로 목록·검색·필터를 즉시 그리고, 서식을 고를 때 해당 도메인 파일만 지연 로딩한다.

**왜 Firebase가 아니라 레포인가**: 위임약정서·동의서는 법적 문구다. "누가 언제 왜 고쳤나"가
남아야 하고 git이 그걸 공짜로 준다. 자주 바뀌는 건 사건 데이터인데 그건 이미 RTDB
(`esign/cases/…`)에 있다. GitHub Pages 정적 호스팅이라 배포도 push 하나로 끝난다.

### 5.2 서식 레코드 스키마

```js
{
  id: 'wa-mandate-agreement',
  title: '위임약정서(임금체불)',
  domain: 'wageArrears',            // wageArrears|laborCommission|industrialAccident|consulting|fund|bargaining
  track: ['임금체불·진정', '대지급금'],  // 사건유형(복수 가능)
  category: 'mandate',              // mandate|consent|complaint|wageGuarantee|civil|settlement|internal
  esign: true,                      // 전자서명 대상 여부
  signer: 'worker',                 // worker|attorney|employer|both
  jurisdiction: null,               // '천안'|'평택'|'보령' 등 관할 변형
  vars: [
    { key:'이름', label:'성명', type:'text', required:true, source:'submission.name' }
  ],
  signFields: [{ role:'worker', label:'위임인', type:'sign' }],
  body: '<p>위 임 약 정 서</p>…',    // hwp2html.py 산출 HTML (표 격자 보존)
  source: {
    file: '…/공영건설/간이대지급금/[별지 제3호의2서식]….hwp',
    mtime: '2023-11-28', segment: 0, hash: '…',
    pickedBy: 'anonymized-latest',  // 'blank' | 'anonymized-latest'
    cluster: ['…동일 서식으로 판정된 다른 경로들…']
  },
  review: { status:'pending', flags:['구법용어'], reviewedBy:'', reviewedAt:'' }
}
```

- `pickedBy: 'anonymized-latest'` — 사건본을 익명화해 승격한 서식. **육안 검증 필수 대상**으로
  자동 표시된다.
- `review.status !== 'approved'`인 서식은 `sign.html`에 노출되지 않는다. 내부 열람은 가능.

### 5.3 파이프라인

```
전 디스크 스캔 (17,483)
  └─ ① 파일명 1차 선별 ────────────▶ 서식 후보 4,783 / 고유 2,633종
      └─ ② 본문 변환 (hwp2html.py) ─▶ HTML (표 보존)
          └─ ③ 제목줄 세그먼트 분할 ─▶ 서식 단위
              └─ ④ 정규화 해시 + 유사도 군집
                  └─ ⑤ 대표본 선정
                      ├─ 빈 양식이 있으면 그것 (pickedBy:'blank')
                      └─ 없으면 mtime 최신 사건본 (pickedBy:'anonymized-latest')
                          └─ ⑥ 익명화 (인명·상호·주민번호·계좌 → {{변수}})
                              └─ ⑦ 변수 추출 (`주민등록번호 : ____` → {{주민등록번호}})
                                  └─ ⑧ 검토 산출물 2종
```

①은 파싱 0건으로 17,483 → 4,783까지 줄인다(실측). ②~⑦은 전부 자동이다.
**사람 손이 필요한 지점은 두 곳뿐** — 군집별 대표본 확정, 노무사 문구 승인.

파이프라인 스크립트는 저장소 루트의 **`tools/`** 에 둔다. `fund-erp/tools/`는 기금 전용이고
서식집은 전 도메인 공용이기 때문이다. `hwp2html.py`는 `fund-erp/tools/`에서 import 해 쓰되,
Phase 5에서 기금을 흡수할 때 `tools/`로 옮기고 기금 쪽이 그걸 참조하도록 뒤집는다.

### 5.4 렌더러 — 빌더 N개 대신 1개

`renderForm(form, data)` 하나가 `buildDelegationHtml` · `buildConsentHtml`을 대체한다.
`form.body`의 `{{변수}}`를 `fillVars`로 치환하고 `signFields`를 서명란으로 렌더한다.
출력은 지금과 같은 HTML 페이지 → 기존 `htmlPagesToPdf`로 그대로 흘러간다.

### 승인 순서

범위는 전 도메인이지만 노무사 검토를 한 번에 다 할 수는 없다.
**임금체불 → 노동위 → 산재 → 컨설팅 → 기금 → 교섭** 순으로 승인해 나간다.
미승인 서식도 서식집에는 들어가 있어 내부 열람은 가능하다.

## 7. 개인정보 — 최대 리스크

17,483건 안에는 **실제 주민번호·계좌번호·실명**이 대량으로 있다.
서식집은 GitHub Pages로 **공개 배포**되는 정적 파일이므로 익명화 실패는 곧 개인정보 유출이다.

기금 파이프라인이 확립한 정책을 그대로 승계하고 강화한다.

1. **원본 `.hwp`는 저장소에 커밋하지 않는다** (로컬 전용). 생성물만 커밋한다.
2. **자동 검사** — `pii_scan.js`의 7패턴(전화·휴대폰·주민번호·상세주소·사업자번호·법인등록번호·
