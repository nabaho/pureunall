# 컨설팅보고서 — 회차 기록 · 기준 점검 설계 (설계 2-B)

- 작성일: 2026-10-12 · 상위: `2026-10-11-gov-report-big-stages-design.md`(2-A) · `2026-10-05-정부컨설팅-보고서자동화-design.md` §14
- 대표 지시(2026-10-12): 「묻지말고 우선 끝까지 해라」. 2-B 의 열린 결정(회차 «형태·시간·참석자»를 어디에 둘지)은 **제가 정했다** — 아래 §3. 틀리면 알려 주세요.
- 근거: 공개 저장소 밖의 대표 PC 정리본 §2-6·§2-7(기준 수치). 여기는 구조·수치만 적는다. 수치는 정리본 기준 초안 **[노무사 확인]**.

## 1. 풀려는 일

일터혁신 상생·산업일자리(중진공·KMAC)는 회차마다 «증빙과 기준»을 맞춰야 인정된다(일터혁신: 회의 2시간 이상·기업 참여 3명 이상·대면 70% 이상·시작/종료 사진과 서명지, 산업일자리: MD 수·비대면 한도). 지금은 회차 날짜·방문 여부만 있고 이 자료가 없어서 **기준 미달을 제출 전에 알 수 없다.** 2-B 는 회차 기록을 남기고 «인정/미달»을 보여 준다.

## 2. 범위

한다
1. **회차 기록**(대형 중 일터혁신 «회차별 수행보고서» · 산업일자리 «MD별 수행일지» 칸 창에서): 형태(대면/비대면) · 회의 시간(분) · 참석 인원 · 시작·종료 사진 확보(✓) · 참석자 서명지 확보(✓) · (산업일자리만) MD(0.5 단위) · 종류(방문/보고서/자료조사). **파일은 저장하지 않는다** — 확보했는지만 체크한다.
2. **기준 점검**(칸 창 안 «기준» 구역, 읽기만): 회차별 인정/미달 + 미달 사유 목록, 그 업체 합계 — 일터혁신: 기록한 회차 · 인정 회차 · 대면 비율(70% 기준) · 계획 회차 대비. 산업일자리: MD 합계 · 비대면 보고서 MD(4 이하)·자료조사 MD(2 이하).
3. 회차 기록은 기존 서류 줄(`items/round:N`)의 **새 자식 `rd`** 로 같은 `.set` 안에 실린다.

하지 않는다
- 사진·서명지 파일 보관/업로드, AI 가 점검하는 일, 정부사업일정 회차 입력 화면 변경, 방문 인정 회수의 유형별 목표(자문 2·4회 / 전문 4·8·12회 / 심화 8·12·16회) 계산 — 유형 입력이 없다(계획 회차 수와 견주어 보여 주기만).
- 산업일자리 충남 지원센터·간단형 사업의 점검(기준이 다르거나 없다).
- 제출 막기 — 점검은 «알림»이다(막지 않는다).

## 3. 결정 (제가 정한 것)
- 저장 자리 = **컨설팅보고서 앱의 서류 줄 `rd`**(정부사업일정 회차 입력은 건드리지 않는다 — 다른 방·화면 소관, 대면 여부와 시간은 «보고서용 기록»이라 앱에 둔다).
- **새 규칙이 필요하다**: `scal_docs/$co/$rid/items/$key` 아래 `rd` 자식(`mode` 필수, `mins`·`people`·`photo`·`sign`·`md`·`kind` 선택, `$other:false`). 게시는 대표가 이미 「묻지말고 끝까지」 라고 지시했으므로 합쳐진 뒤 `scripts/rules-deploy.js` 로 한다(새로 늘리기만 — 기존 줄·권한은 안 바꾼다. 게시 전에는 `rd` 가 든 저장만 거절되고 다른 저장은 그대로).

## 4. 데이터 · 모듈

`rd` = `{ mode:'face'|'remote', mins:0..600 정수, people:0..99 정수, photo:bool, sign:bool, md:0..5(0.5 단위), kind:'visit'|'report'|'research' }`.

- `js/pu-gov-report-track.js`: `normRd(rd)`(틀리면 null·값 자르기) · `nextRd(prev, op)`(`op.rd` 가 올바르면 그것, 아니면 옛 줄 것 이어받기 — 지우기 없음) · `normalize`/`patchFor`/`validate` 에 `rd` 가지 · 상수 `RD_MINS_MAX=600`·`RD_PEOPLE_MAX=99`·`RD_MD_MAX=5`·`RD_MODE`·`RD_KIND`.
- `js/pu-gov-report-criteria.js`(신설, 순수): `roundCheck(planKey, rd)` → `{state:'none'|'ok'|'miss', miss:[글]}` · `summary(planKey, list, planned)` → 합계/비율/경고. 상수 `WP_MIN_MINS=120`·`WP_MIN_PEOPLE=3`·`WP_FACE_PCT=70`·`IND_REMOTE_REPORT_MD=4`·`IND_REMOTE_RESEARCH_MD=2`.
- `js/pu-gov-report-docs.js`: 항목 플래그 `rd:true`(일터혁신 `round`, 산업일자리 `mdlog`)와 `criteriaKey`.
- `scripts/make-firebase-rules.js` + 규칙 JSON 두 개 + `tests/gov-report-rules.test.js`(모듈 한계와 같음).

## 5. 화면 (`gov-report.html`)
칸 창에서 `rd` 항목이면 «회차 기록» 입력(형태·시간·인원·사진✓·서명지✓·(MD·종류))과 «기준» 구역. 저장은 **기존 `grSaveCell` 한 곳**(입력값을 `entry.rd` 로 실어 보낸다 — 새 `.set` 없음). 기준 구역은 저장된 기록 + 지금 입력 중인 값을 함께 본다(미리 보기).

## 6. 개인정보 · 오류
- 참석자 이름·서명 이미지는 저장하지 않는다(인원 수·확보 여부만). 메모 안내 그대로.
- 숫자가 범위 밖이면 저장 전에 안내(`validate`). 게시 전 저장 거절은 기존 `SAVE_FAIL` 문구.

## 7. 검사
`normRd`/`nextRd` 경계(범위·소수·이상한 키·`__proto__`)·`roundCheck`/`summary` 경계(미달 사유·70% 경계 69/70·기록 0)·규칙 JSON 이 모듈 한계와 같음·화면(입력 → `entry.rd` → 한 줄 `.set`, 기존 `link`·`note` 보존, 기준 구역 이스케이프, 기록 못 읽음) · 간단형·기존 칸 창 회귀 없음.
