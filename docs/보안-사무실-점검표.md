# 사무실 보안 점검표 — PC·계정·메일·NAS·퇴사자

2026-10-14 작성 · 분기마다 이 표를 다시 채운다(`docs/보안-현황-*.md` 와 짝).
근거: 개인정보 보호법 제29조(안전조치의무)와 「개인정보의 안전성 확보조치 기준」(개인정보보호위원회 고시).
고시의 세부 조항은 원문을 대조해야 한다 **[확인 필요]**. 이 표는 그 취지를 사무실 실정에 맞춰 옮긴 **실무 점검표**이며, 법령 해석이 아니다.

칸 표시: ✅ 됨 · ❌ 안 됨 · ❓ 모름(확인 필요) · — 해당 없음

## 1. PC (한 대마다)

| # | 점검 | 왜 | 확인 방법 |
|---|---|---|---|
| 1-1 | 윈도 **보안 업데이트를 받는 판**인가 | 지원이 끝난 판은 새 구멍이 나도 막아 주지 않는다 | 설정 › 시스템 › 정보 › 「버전」. 윈도 11 은 **21H2(빌드 22000) 지원이 2023-10 에 끝났다** |
| 1-2 | 백신이 켜져 있고 오늘 갱신됐나 | 랜섬웨어·키로거 | V3 창의 「최신 엔진」 날짜 |
| 1-3 | **자리를 비우면 화면이 잠기나**(5~10분) | 켜 둔 PC 에는 이알피·메일·파이어베이스가 «로그인된 채» 있다 | 설정 › 개인 설정 › 잠금 화면 › 화면 보호기 「다시 시작할 때 로그온 화면 표시」 + 대기 시간 |
| 1-4 | 디스크 암호화(BitLocker) | 노트북·PC 를 들고 가면 주민번호 서류가 그대로 읽힌다 | 제어판 › BitLocker. **복구 키는 PC 밖에** 보관 |
| 1-5 | 윈도 로그인에 비밀번호/PIN | 1-3 이 소용 있으려면 | — |
| 1-6 | 브라우저 «비밀번호 저장» 정리 | 저장된 비밀번호는 그 PC 를 연 사람 누구나 꺼낼 수 있다 | 크롬 › 설정 › 자동완성 › 비밀번호 관리자 |
| 1-7 | 공용 PC 는 이알피 «로그인 유지» 끄기 | 유지 켠 기기는 자동 로그아웃이 없다 | 포털 로그인 화면의 「로그인 유지」 |
| 1-8 | 원격 접속 도구 목록(Tailscale·원격데스크톱·애니데스크 등) | 쓰는 것만 남긴다. 모르는 원격 도구는 사고의 흔한 입구 | 설정 › 앱 |

## 2. 계정

| # | 점검 | 왜 |
|---|---|---|
| 2-1 | 대표 구글 계정(파이어베이스 콘솔)·깃허브 **2단계 인증** | 2026-08-04 둘 다 켬 ✅ — 복구 코드 보관 위치 확인 |
| 2-2 | **다음메일 계정** 2단계 인증·비밀번호 공유 여부 | 메일함이 이알피로 거울처럼 들어온다. 메일 비밀번호가 새면 의뢰인 자료 전체가 샌다 |
| 2-3 | 이알피(포털) 비밀번호 — 처음 받은 비밀번호를 그대로 쓰는 직원 | 처음 비밀번호는 여러 사람이 안다. 바꾸지 않으면 감시가 있어도 들어온다 |
| 2-4 | 카카오 로그인 연결 계정 | 개인 카카오가 털리면 포털도 열린다 |
| 2-5 | 공용 계정(대표 메일·홈택스·4대보험 EDI 등) 비밀번호를 누가 아나 | 퇴사자 회수 때 바꿀 목록이 된다 |

## PC 별 실측 결과는 «여기 두지 않는다»

이 저장소는 공개다. 「어느 PC 가 업데이트가 끊겼고 잠금이 없는지」는 그대로 공격 안내서가 된다.
실측 결과는 사무실 PC 의 `pureunall/data/보안검토/`(git 이 무시하는 자리)에 둔다.
