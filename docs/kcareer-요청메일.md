# 경력관리 «요청 메일» — 법인 메일함에 온 요청을 알아보고, 정리하고, 알린다 (2026-11-09)

대표 지시: 「법인메일로 경력요청 및 동의서 등 기타 메일로 요청사항이 있을경우 자동으로 감지하고 경력관리에 정리하면서 알람으로 정리해달라」
알아보는 일은 `js/kcareer-mailreq.js` 한 곳이 한다 — 경력관리(`kcareer.html`)와 포털(`enter.html`)이 같은 모듈을 쓴다.
아래 표·숫자는 `tests/kcareer-mailreq-doc.test.js` 가 코드와 견준다.

## 한 줄 원칙
**알아보고 알릴 뿐, 보내거나 채우지 않는다. 확실한 것만 올리고, 못 찾은 것은 «모름»이라고 한다.**
답장·서식 채우기·첨부 받기는 사람이 푸른메일함·서식 채우기에서 한다(도장·주민번호가 든 서류라 자동으로 나가면 되돌릴 수 없다).

## 무엇을 «요청»으로 보나

| 종류 | 제목·첨부 이름에 이런 말 | 이름 |
|---|---|---|
| consent | `동의서` `서약서` `확약서` `위임장` `개인정보 수집·이용 동의` | 📝 동의서 |
| career | `경력증명` `경력확인서` `이력서` `프로필` `강사 이력` `약력` `수행실적` `재직증명` `자격증 사본` | 📇 경력 요청 |
| other | `서류` `증빙` `신청서` `양식` `서식` `통장 사본` `사업자등록증` | 📨 기타 요청 |

- **동의서·경력 요청**: 제목·첨부 이름에 위 말이 있고, 아래 셋 중 하나가 겹치면 올린다 — 요청 말투(`제출` `회신` `작성` `서명` `송부` `부탁` …) · 양식 파일 첨부(한글·워드·엑셀·PDF) · 본문의 기한.
- **본문에만 단서가 있으면** 말만 스쳐서는 안 된다 — 요청 말투 + (양식 첨부 또는 기한)까지 겹쳐야 한다.
- **기타 요청**: 위 둘에 안 걸리고, 서류 말 + 요청 말투 + (기한 또는 양식 첨부 또는 제목의 요청 말투)가 겹칠 때.
- **«첨부하여»는 요청 말투가 아니다** — 첨부가 있는 메일마다 들어 있는 말이라 넣지 않았다. 첨부가 «있기만» 해서도 안 된다(양식 파일 이름이어야 한다).
- **답장(`RE:` · `회신:` · `답장:`)은** 요청 말투나 새 기한이 없으면 요청이 아니다 — 서명해 돌려보낸 사본이 «새 요청»으로 울리면 안 된다.
- **올리지 않는 것**: 광고·소식지(`(광고)` `수신거부` `뉴스레터` …), 우리 주소(`@pureun.kr`)에서 온 것, 보낸·보관·임시·스팸·휴지통 폴더.
- 올린 **까닭(why)** 을 늘 적는다 — 목록에서 제목에 올려 보면 «제목에 「동의서」 · 양식 첨부 …» 처럼 나온다. 틀리면 «🚫 아님»으로 치운다.

## 기한은 어떻게 읽나
- 본문(답장·전달 꼬리는 잘라 냄)에서 **«기한 말 가까이 있는» 날짜만** 기한으로 본다: `제출기한 : 2026년 11월 16일 월요일 18시까지` → 2026-11-16 18:00.
  `2026.11.16` · `2026-11-16` · `11월 16일` · `오후 6시` · `18:00` 도 읽는다. 범위(`11월 10일 ~ 11월 16일까지`)는 끝 날짜.
- 연도가 없으면 «받은 날 이후 가장 가까운» 해로 짐작하고 `*` 로 표시한다.
- **기한 말이 가까이 없는 날짜(행사일·옛 일정)는 잡지 않는다** — 틀린 기한으로 알리느니 «기한 모름»이다. 첨부 문서(한글 파일) 안의 기한은 읽지 않는다.
- 메일함 거울에는 본문 앞 140자뿐이라, 올린 건마다 **본문을 한 번 열어**(푸른메일함과 같은 서버 함수 `readMailMessage`, 읽음 표시 안 함) 기한·회신 주소를 채운다. 한 번에 몇 건만 열고, 못 열면 몇 번 다시 해 보다 그만둔다.

## 어디에 정리되고, 어디서 알리나
- **경력관리 › 📬 요청 메일** — 진행 중 / 처리 완료 / 요청 아님 / 전체 탭. 기한 지난 것 → 임박 → 새 요청 → 확인함 순.
  상태: **새 요청 → 확인함(처리 중) → 처리 완료**, 틀린 것은 **요청 아님**(모두 되돌릴 수 있다). 이미 답장한 메일(메일함 «답장함» 표시)은 «새 요청»이 아니라 처리 중으로 시작한다.
  ☐ 로 여러 건을 골라 한 번에 바꿀 수 있다(건수를 묻고, 저장은 한 번).
- **알림 띠** — 경력관리 맨 위: 「📬 확인할 요청 메일 N건 · 새 · 기한 임박 · 기한 지남」. «나중에»는 그때 알린 건들을 기억해 두었다가 **새 건이 오거나 기한이 임박해 알릴 건이 바뀌면 다시** 뜬다.
- **옆줄 「요청 메일」 숫자**(진행 중 건수, 알릴 것이 있으면 붉게) · **탭 제목 「(N) 경력관리」**.
- **브라우저 알림(선택)** — 버튼으로 켜면, 다른 탭을 보고 있을 때 새 요청이 오면 알림 창을 띄운다(이 탭을 열어 둔 동안).
- **포털 «경력관리» 타일 딱지 「요청 N」** — 경력관리를 열어 두지 않아도 포털을 열어 두면 알린다. 창이 저절로 뜨지는 않는다(하던 일을 끊지 않는다 — 입금 딱지와 같은 약속). 누르면 이 화면으로 간다.
- 기한이 **3일 안**이면 «임박», 지나면 «기한 지남» — 확인함으로 두어도 계속 알린다.

## 얼마나 자주 확인하나
- 로그인하면 바로, 그 뒤 **화면을 켜 둔 동안 5분마다**(메일함 거울이 3분마다 갱신된다). 처음에는 **최근 21일** 안의 메일을 훑는다(그보다 옛 메일은 알리지 않는다).
- 폴더마다 «어디까지 봤는지»를 적어 두어 다음부터는 **새로 온 몇 통만** 읽는다. 하루에 많이 온 날은 한 번 크게 다시 본다.

## 저장 자리와 보안
- `kcareer/{uid}/mailreq/items/<폴더>~<번호>` (건마다 한 줄) · `kcareer/{uid}/mailreq/cur/<폴더>` (어디까지 봤나).
  **경력관리 자료 통(`ls`)·`at` 과 따로**다 — 통은 `at` 이 바뀌면 다른 기기에 «새 저장» 띠가 뜨는데, 이 칸은 안 건드린다. 보안규칙은 `kcareer/$uid` 본인 읽기·쓰기 그대로(바꾸지 않았다).
- **본문은 저장하지 않는다.** 제목·보낸이·첨부 이름(최대 3개)·기한·회신 주소·까닭만. 원본은 메일함에 있다.
- 새 건은 «없을 때만» 쓴다(transaction) — 포털과 경력관리가 동시에 훑어도 겹치지 않고, **사람이 바꾼 상태를 되돌리지 않는다.** 기한을 채울 때도 상태 칸은 건드리지 않는다.
- **대표 본인으로 확인된 때만** 훑는다 — 직원 보기(사본)·안전 모드·확인 전에는 읽지도 쓰지도 않는다.
- 이 설정(알림 켬·띠 닫음)은 이 기기 `localStorage` 에만 둔다 — 자료 통(`cm3_*`)에 두면 클라우드로 간다.

## 안 하는 것 (일부러)
- 자동으로 **답장을 보내거나 서식을 채우지 않는다.** «발송 대기»(`docs/kcareer-발송대기-비슷한서류.md`)로 넘기는 길도 아직 사람이 누른다.
- **폰 푸시 알림은 건드리지 않았다.** 받은 메일 폰 알림은 2026-10-20 대표 지시로 «전체 꺼짐»이다(`status/2026-10-20-mail-push-master.md`) — 이 기능은 화면 안 알림뿐이다.

## 아직 안 되는 것 (숨기지 않는다)
1. **알림은 경력관리나 포털을 «켜 둔 동안»만 뜬다.** 서버가 24시간 감지해 폰으로 알리려면 메일 동기화 함수(`syncMailbox`)에 붙여야 하고, 함수 배포와 «폰 알림 전체 스위치» 결정이 필요하다 — 대표 결정 사항이다.
2. **알아보는 말은 손으로 정한 목록**이다 — 놓치거나(목록에 없는 말) 잘못 올릴 수 있다. 실제 메일로 정확도를 재 보지는 못했다. [확인 필요] 틀린 것은 «🚫 아님»으로 치우고, 놓친 것은 알려 주면 말을 더한다.
3. 같은 보낸 곳이 되풀이해 보내는 소식지를 «보낸 곳 단위로 끄는» 기능은 없다(메일마다 «🚫 아님»).
4. 본문 앞쪽만 읽고(8천 자), **지난 메일(POP3) 칸**·**첨부 문서 안의 글**은 읽지 않는다.
5. 메일함에서 그 메일을 **바로 여는 주소**는 없다 — «📬 메일함 열기»는 푸른메일함을 새 창으로 열 뿐이니 제목으로 찾는다.
