# 사업자번호·담당 «근거로 채우기» — 한 장 요약

> 대표 지시 2026-11-28: 「ERP 안에 사업자 등록번호가 제대로 안 들어가거나 담당자가 없는 경우도 종종 있다. 최근 계산서나 이런 데를 찾아서 다 자동으로 들어갈 수 있게 해라. 이미 메일하면서 받은 세금 계산서 등이 다 있다. 메일함 또는 세금 계산서 발급했던 재무관리 등을 전체 확인해서 **항상 동일성이 유지된다고 판단되면** 자동으로 끌고 와서 연결하는 기능을 만들어라.」
>
> 판정 한 곳: `js/pu-biz-evidence.js` (브라우저 `window.PuBizEvidence` · Node 겸용) · 화면·저장: `pu-erp.html` 의 `BizFillModal`·`bfApply`·`bfUndo` · 지킴: `tests/biz-evidence.test.js`

## 1. 무엇을 하나

업체관리·컨설팅·기금·기타사업·사건에서 **사업자번호 칸이 비었거나 표기가 다른 곳**을 찾아, 이미 있는 근거에서 «꼭 같은 업체»라고 믿을 수 있을 때만 번호를 채운다. 입구는 두 곳이다.

- 업체관리 › 정리 도구 「🧾 번호·담당 채우기」
- 컨설팅·기금·기타 목록의 「🧾 번호 채우기」(폰은 「⋯ 더보기」 안)

창은 여섯 갈래로 보여 준다 — ✅ 자동 채움 · 🔎 후보 제안 · ⚠ 확인 필요 · ⛔ 충돌 · 👤 담당 제안 · ↩ 채운 것(되돌리기). 고르기만으로는 아무것도 바뀌지 않고, 「선택 채우기」를 누르면 건수를 한 번 묻고 쓴다.

| 갈래(kind) | 자료 | 믿음 | 비고 |
|---|---|---|---|
| `hometax` | 홈택스에서 올린 매출 세금계산서 아카이브(`invoice_history`·서버 `invoice_arc`) | 바깥(공문서) | 재무 권한이 있는 PC 만 서버 줄까지 받는다 |
| `regcert` | 기업정보함 사업자등록증 판독(`pucardsIdx` 의 `k:'biz'`) | 바깥(공문서) | |

## 3. «같은 업체다»라고 자동으로 믿는 기준 (코드로 못 박음)

자동 채움(`level:'auto'`)은 **아래를 전부** 통과한 것만이다.

1. 채울 번호가 **검증숫자(국세청 규칙)를 통과**한다. 틀린 번호는 근거로 색인에 들이지 않는다. 모두 같은 숫자(0000000000 …)는 검증숫자를 «통과»하지만 번호가 아니라 뺀다.
2. **꼭 같은 이름**이다 — 법인 표기를 이름 «앞·뒤»에서만 걷고 공백·기호를 걷은 `nameKey`(앞·뒤 표기는 `erpNormName` 과 같은 답 — 검사가 견준다. `erpNormName` 은 가운데 낀 표기도 걷지만 이쪽은 걷지 않는다: 서로 다른 상호가 같아지지 않게). 부분 일치·별칭 추정·비슷한 이름은 후보로도 안 올린다. 괄호 안의 지점 이름은 남긴다(「○○(서울점)」≠「○○」). 한 글자 이름은 쓰지 않는다.
3. **서로 다른 근거(kind)가 둘 이상** 같은 번호를 말하고, 그 가운데 **바깥 자료(공문서·재무 장부) 하나**가 있다. 같은 곳에서 여러 줄이어도, 업체관리 + 다른 업무 건처럼 **안쪽 기록끼리만** 짝이면 «독립된 두 곳»이 아니라 **제안**이다.
4. **같은 이름에 다른 번호가 하나라도** 나오면 **충돌** — 채우지 않는다. 대표자는 근거 «줄마다» 견준다 — 대표자를 적은 줄이 하나라도 이 건의 대표자와 겹치지 않으면 충돌.
5. **끝난 건**(`closed`·`cancelled`·`transferred`·`done`·`end`·`closedAt`·`permanentArchived`·`transferredTo`)과 삭제 건은 건드리지 않는다. 표기 정리도 하지 않는다.
6. **이미 값이 있으면 덮지 않는다.** 근거가 다른 번호를 말하면 «확인 필요»로만 알린다. 검증숫자가 틀린 값·글자가 섞인 값·모자란 값도 후보만 보여 주고 쓰지 않는다. 표기만 다른 같은 번호(하이픈 없음)는 `000-00-00000` 로 정리한다(자동).
7. **자동으로 채운 값**(`bizAuto` 표시)은 다음 계획에서 **근거로 쓰지 않는다** — 짐작이 짐작을 낳지 않게. (표기만 고친 줄은 사람이 적은 번호라 그대로 근거.)

예외: **업체 번호(`companyId`)로 이어진 업체관리의 번호**는 이름 짐작이 아니라 번호표 연결이라 근거 하나로 채운다(`via:'link'`). 다만 번호표 길도 먼저 본다 — 바깥 자료가 이 이름에 다른 번호를 말하면 **충돌**, 대표자가 겹치지 않으면 **충돌**, 업체의 번호가 **자동으로 채운 값**(`bizAuto`)이면 다시 퍼뜨리지 않고 **제안**으로만 둔다. 업체가 다른 번호를 갖고 있으면 확인 필요.

열한 자리 이상인 값은 앞 열 자리가 검증을 통과하면 «사업자번호 + 종사업장 번호»라 **정상으로 둔다**(`has-suffix`, `js/pu-cokey.js` 가 앞 열 자리로 자르는 그 꼴). 통과 못 하면 공단 관리번호로 의심해 «확인 필요».

## 4. 주담당·거래처 담당자 — «제안만»

둘 다 **자동으로 쓰지 않는다**(제안만, 창에서 사람이 담당 변경 화면으로 간다).

- 까닭: 주담당은 성과 분배·권한에 걸리고 변경 때 업체에 `mgrHistory`(담당 이력)를 남기는 길이 따로 있다. 거래처 담당자는 연락처(개인정보)다. 이 창이 번호 칸 밖을 쓰면 그 길들을 건너뛴다.
- 기준: 비어 있는 건에서, **같은 업체**(번호표 `companyId` 또는 **검증을 통과한 사업자번호**로만 이은 — 이름으로는 잇지 않는다)의 다른 건·업체관리가 **한 사람으로 일관**될 때만 제안. 업체관리 값 하나 또는 다른 건 둘 이상이어야 하고, 끝난·지운 건의 옛 담당은 근거가 아니며, 퇴사·휴직·담당배제는 제안하지 않고, 다른 사람이 섞이면 충돌.
- 부담당은 선택 사항이라(비어 있는 것이 정상) 건수에도 세지 않는다.

## 5. 쓰는 방식 (CLAUDE.md 규칙과의 양립)

| 규칙 | 이 기능에서 |
|---|---|
| 온톨로지 — 이름으로 추정한 관계를 저장하지 않는다 · 자동 ID 대입 금지 · `sourceMutation:'never'` | 저장하는 것은 **번호 칸(속성) 하나**와 `bizAuto` 표시뿐. **`companyId`(관계)는 쓰지 않는다** — 번호가 채워지면 기존 「🔗 업체 연결」이 «사업자번호 일치 — 확실» 갈래로 잇는다(사람이 누른다). 계약 표는 `validateCompanyLink` 관문이 따로 있어 **제안만** 하고 쓰지 않는다. |
| 종료·삭제·되돌림 불변 | 끝난·삭제 건은 계획에서 빼고, 쓰는 «지금» 다시 한 번 확인한다. 최소 경로 패치(`dbPatch` 의 칸 단위)만 쓴다 — 표 통째 쓰기 없음. 물리 삭제 없음. |
| 입금 명의 | 이 기능은 입금을 만들거나 확정하지 않는다. |
| 살아 있는 자료 일괄 쓰기 | 버튼 눌러 사람이 고른 줄만(화면에 그린 줄 범위 안에서만), 건수를 묻고 쓴다. 창을 연 뒤 자료가 바뀌었으면(번호가 들어옴·답이 바뀜·근거 약해짐) **건너뛴다**. 쓰기 직전에 **서버의 지금 값**(상태·끝남·지움·번호 칸)을 줄마다 다시 읽어, 이 PC 사본이 낡아 다른 PC 의 입력·종결을 덮을 수 있으면 건너뛰고, **서버에 못 닿으면 쓰지 않는다**. |

`bizAuto` = `{ at, by, via('evidence'|'link'|'format'), reason, before, after, kinds[], rows, last, pick('auto'|'person') }`. 「↩ 채운 것」 탭이 이 표시가 남은 줄을 모아 보여 주고, **«채울 때 남긴 표시와 똑같고(시각·이전 값·채운 값) 값이 그대로일 때만»** 이전 값으로 되돌린다 — 서버의 지금 값도 같아야 한다. 그 뒤 끝난 건·사람이 고친 값·같은 번호로 새로 처리된 건은 건드리지 않는다. 되돌리면 표시도 지운다.

## 6. 하지 않는 것 · 알려 둔 한계

- **메일 세금계산서는 자동으로 못 읽는다.** 메일 거울(`mailbox/msgs`)에는 머리글(보낸 사람·제목·날짜·첨부 유무)과 140자 미리보기뿐이라 사업자번호가 없다. 본문은 메일을 열 때만 받는다. 홈택스 세금계산서는 이미 `hometax` 근거로 들어 있다(같은 내용). 메일 본문을 근거로 쓰려면 사람이 한 통을 고르는 길(`pu-case-jur-mail` 방식) 또는 서버가 본문을 받아 읽는 별도 함수가 필요하다 — 대표가 정할 일.
- 근거가 «없는» 업체(아직 계산서를 끊지 않은 상담접수 단계·사건 상대방 등)는 채울 수 없다. 건수로만 알린다.
- 계약 표·종료 건은 쓰지 않는다.
- **쓰기는 «서버 조건부 트랜잭션»이 아니다.** 앱의 공용 저장 길(`dbPatch` — 칸 단위 최소 경로 패치, 업체 연결 `coLinkApply` 와 같은 길)을 쓰므로, 쓰기 직전에 서버의 지금 값(그 건이 있는가·끝났나·지웠나·번호 칸·표시)을 줄마다 다시 읽어 «확인한 뒤» 쓴다. 확인과 쓰기 사이의 아주 짧은 틈(밀리초)에 다른 PC 가 같은 칸을 고치는 경쟁은 이 길에서 막지 못한다 — 번호 칸과 표시 둘만 쓰고, 채운 값은 표시(시각·이전 값·채운 값)가 같을 때만 되돌릴 수 있게 한 까닭이다. 완전한 원자성이 필요하면 공용 저장 길에 조건부 쓰기를 넣는 별도 일이다.
- 일괄 쓰기는 «누르는 지금» 한 번 계획을 다시 세우고, 홈택스 줄은 창을 열 때 받아 둔 것을 쓴다(그 뒤 올라온 줄은 다음에 열 때 반영). 줄마다 서버 확인을 하므로 이 사이에 번호·종결이 바뀐 건은 건너뛴다.
- 공개 저장소다 — 이 문서·검사에 실제 업체 이름·사업자번호를 쓰지 않는다(`tests/no-real-client-data.test.js`).
