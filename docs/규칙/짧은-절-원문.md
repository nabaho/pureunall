## 작업이 끝나면 PR 은 **묻지 않고 만든다** (대표 지시 2026-10-17)

> 「네 묻지말고 항상 만들어라」

고친 것을 가지에 올린 뒤 「PR 을 만들까요?」를 묻지 않는다. **검사를 돌려 통과하면 바로 PR 을 만들고 보고한다.**
합치기는 저장소의 자동 병합(`auto-merge.yml` — Quality Gate 통과 뒤)이 한다.

- ⚠ **묻지 않는 것은 «PR 만들기»뿐이다.** 검사가 빨가면 PR 을 만들지 말고 먼저 고친다.
- ⚠ 사람이 보고 합치고 싶으면 제목에 `[보류]` 를 붙인다 — 자동 병합이 멈추는 브레이크다.
- 보고에는 PR 주소, 그리고 «합쳐졌는지·배포됐는지»를 확인한 만큼만 적는다.

## 만들기 전에 «이미 있는 것»부터 찾는다 (대표 승인 2026-10-18)

- 새 함수·화면·검사·스크립트를 만들기 전에 **저장소 안에 같은 일을 하는 것이 있는지** 먼저 찾는다
  (`rg`, `STATUS.md` 「4. 이 저장소에서 되풀이된 실수」, `status/`). 있으면 그 길을 그대로 탄다 —
  같은 일을 두 벌로 만들면 한쪽만 고쳐져 어긋난다.
- ⚠ **찾지 못한 곳은 «못 찾았다»고 밝힌다.** 검색 길이 막혔는데(도구 없음·로그인 풀림)
  「없습니다」라고 보고하지 않는다 — 안 본 것과 없는 것은 다르다.

## 기금 시스템(fund.html) 작업 규칙 — 계정·PC 간 이어가기
근로복지기금 관리(`fund.html`, Firebase RTDB)는 여러 로그인/PC에서 이어서 개발한다.
AI 개인 메모리는 계정마다 다르므로 **공용 상태 파일이 유일한 기준**이다.

- **세션 시작 시**: `fund-erp/STATUS.md`를 읽고 `git log --oneline -20`으로 최근 변경을 확인한 뒤 이어간다.
- **세션 종료 시**: 바뀐 내용을 `fund-erp/STATUS.md`(진행률·다음 할 일·변경 로그)에 반영하고 commit/push 한다.
- **push 전 반드시** `git pull --rebase origin main` (원격에 급여·명함첩·달력 등 다른 작업이 자주 올라옴).
- 실데이터(fund.db·사업장 실데이터·templates 서식엑셀·backups)는 저장소에 올리지 않는다.
