## 파이어베이스 보안규칙 — **묻지 않고 내가 콘솔까지 고친다** (대표 지시 2026-09-03)

「곤솔을 니가 직접 고쳐라」
(앞선 지시: 「앞으로 여기서 만드는 푸른통합시스템에서는 콘솔 자동등록여부 질문하고
답하면 니가 알아서 수정해라」 → 이제 그 질문조차 생략한다)

**사람은 콘솔에 들어가지 않는다.** 어느 연장이든(경력관리·명함첩·급여·사진첩 …)
새 기능이 규칙을 필요로 하면 내가 만들개에 넣고 **바로 올린 뒤 무엇이 바뀌었는지 보고한다.**

```
① scripts/make-firebase-rules.js         ← 규칙은 여기만 고친다
② node scripts/rules-deploy.js --deploy  ← 바로 올린다 (묻지 않는다)
③ 무엇이 새로 생기고 바뀌었는지 보고한다
```

- ⚠ **안전 장치를 빼지 말 것 — 이것이 있어서 묻지 않아도 된다.**
  `rules-deploy.js` 는 올리기 전에 「마지막으로 확인한 콘솔 규칙」과 견주어
  **사라질 규칙이 하나라도 있으면 올리지 않고 멈춘다**(종료코드 2).
  기준은 `docs/firebase-rules-콘솔원문-YYYY-MM-DD.json` 중 가장 최신 것이다.
  내 파일이 콘솔보다 낡으면 단 한 번에 남의 규칙을 지운다 — 그것 하나를 막는 장치다.
- ⚠ **멈추면 그때는 사람에게 알린다.** 무엇이 사라지려 했는지 그대로 보이고,
  만들개에 그 규칙을 넣은 뒤 다시 돌린다. 임의로 `--force` 같은 길을 만들지 말 것.
- ⚠ **고칠 곳은 만들개 하나다.** JSON 을 손으로 고치면 다음에 만들 때 조용히 사라진다
  (`tests/firebase-rules-apply.test.js` 가 막는다). `rules-deploy.js` 도 만들개를 돌려
  나온 것만 올리고, `JSON.parse` 로 한 번 걸러 깨진 것을 올리지 않는다.
- ⚠ **루트 `firebase.json` 에 `database` 를 넣지 말 것** — 넣으면 다른 세션이
  `firebase deploy` 할 때 규칙이 함께 나간다. 규칙 전용 설정은 `firebase.database.json` 이다.
- ⚠ **읽기 권한도 내가 판단해 바로 올린다**(대표 지시 2026-09-03 「읽기권한도 알아서 해라」).
  단, 더 많은 사람이 보게 되는 변경이면 **보고에 «어느 칸이 누구에게 보이게 됐는지»를 반드시 적는다** —
  묻지 않는 대신 조용하게 넘어가지는 않는다. 이 집에는 주민번호·도장·계좌가 있다.
- ⚠★ **기준은 «살아 있는 콘솔» 이다** — `firebase database:get /.settings/rules` 로 지금 규칙을
  그대로 읽어 견준다. 그래서 「콘솔에서 손으로 고쳤으니 알려 주십시오」가 **필요 없다** —
  누가 콘솔을 고쳐도 스크립트가 스스로 알아내고, 그 손질이 사라질 판이면 멈춘다.
  ⚠ 콘솔을 못 읽으면(로그인이 풀렸을 때 등) 사본으로 물러선다 — 그럴 땐 그렇다고 밝힌다.
- 올린 뒤엔 올린 내용이 새 기준으로 자동 저장된다 — 다음에 견줄 자리다.
- firebase CLI 는 이 PC 에 로그인돼 있다(현재 프로젝트 `pureun-erp`).
  로그인이 풀렸거나 CLI 가 없으면 자동 배포가 안 된다 — 그때만 `docs/rules-paste.json`
  을 사람에게 건네 붙여넣게 한다.
- ★ **클라우드 방(대표 PC 가 아닌 곳)에서는 GitHub 작업 「Firebase 배포」를 부른다**(대표 지시 2026-10-31 「니가 직접 하면 안되나 … 한번에 하게」) —
  `.github/workflows/firebase-deploy.yml`(수동 실행·main 만). 그 안에서도 규칙은 `rules-deploy.js --deploy` 로만, 함수는 이름을 찍어서만,
  열쇠는 GitHub 비밀(`FIREBASE_SERVICE_ACCOUNT`)에만. 올린 뒤 새 기준 파일·PENDING 정리 PR 은 부른 쪽이 만든다. 쓰는 법 `docs/배포-클라우드에서.md`
  (`tests/firebase-deploy-workflow.test.js` 가 울타리를 지킨다).
- 읽을 문서: `docs/firebase-rules-적용안내.md` · `docs/firebase-rules-읽어보세요.md`.

**예전 방식을 되살리지 말 것** — 채팅에 규칙 전문을 통째 부어 대표가 붙여넣게 하는 것은
2026-09-03 부터 하지 않는다. 자동 배포가 막힐 때만 그 길을 쓴다.

### 창고(Storage) 규칙도 이제 내가 올린다 (2026-09-08)

```
① docs/firebase-storage-전체(붙여넣기용).txt      ← 규칙은 여기만 고친다
② node scripts/storage-rules-deploy.js           ← 먼저 «보여만» 준다
③ node scripts/storage-rules-deploy.js --deploy  ← 창고 세 곳에 올린다
```

- ⚠⚠ **실시간DB 와 다르다 — 창고 규칙은 «CLI 로 읽을 수 없다».**
  `firebase deploy --only storage` 는 있는데 「지금 규칙 보기」가 없다. 그래서 기준은
  **대표님이 콘솔에서 옮겨 주신 파일**(`docs/firebase-storage-콘솔원문-YYYY-MM-DD.txt`
  중 최신)이다 — 살아 있는 콘솔이 아니다. **약한 안전장치임을 보고에서 숨기지 말 것.**
- 안전장치 둘이 있고, 둘 중 하나라도 걸리면 **올리지 않고 멈춘다**(종료코드 2):
  ① 기준에 있던 칸·허락·보조함수가 하나라도 사라지면
  ② 앱이 실제로 쓰는 창고 자리가 안 덮이면 (밑줄 하나가 달라도 사진첩이 통째로 멎는다)
  ⚠ `--force` 같은 길을 만들지 말 것 — 이 멈춤 하나가 창고의 안전장치 «전부»다
  (`tests/storage-rules-deploy.test.js` 가 기계로 지킨다).
- ⚠ **루트 `firebase.json` 에 `storage` 를 넣지 말 것** — `database` 와 같은 까닭이다.
  올리개가 임시 설정을 만들어 `--config` 로 넘긴다.
- 창고가 **셋**이다: `pureun-erp-hrphotos`(사진첩·서고·자문 증빙) ·
  `pureun-erp-photos`(명함·메일 첨부) · `pureun-erp.firebasestorage.app`(급여데이터함).
  한 벌을 세 곳에 다 올린다 — 그 창고에 없는 자리는 규칙만 있고 아무 일도 안 한다.
- **대표님이 콘솔을 손으로 고치시면 그 내용을 새 날짜 파일로 남겨야 한다** —
  실시간DB 처럼 스스로 알아낼 길이 없다. 이것만은 사람이 알려 주셔야 한다.
