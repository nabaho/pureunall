## 폰 화면 — 모든 앱은 폰에서 «한 화면에 보이게» (대표 지시 2026-10-18 「폰화면관리」)

대표는 주로 **폰으로** 쓴다. 그런데 폰 정리를 앱마다 따로 해 와서(10/17 하루에만 여섯 앱)
같은 흠이 앱마다 다시 나왔고, «어느 앱이 폰에서 어떤지»를 한 번에 볼 길이 없었다.

| ✗ 이렇게 하지 말 것 | ✓ 이렇게 한다 |
|---|---|
| 넓은 표를 그대로 두고 옆으로 밀게 한다 | 폰에서는 줄마다 **«두 줄 카드»** — 1줄 ☐·№·이름·핵심값(금액·기한·남은 날), 2줄 «말을 하는» 값만 |
| 좁은 칸에 글자가 한 글자씩 세로로 쌓인다 | 칸 너비를 못박은 표를 폰에서 풀고 줄을 `flex` 로 편다 |
| 탭·단추 글자가 두 줄로 접힌다 | 탭은 한 줄(`nowrap` + 넘치면 옆으로 민다), 단추는 그림만 + `title` |
| 머리·거르개·안내문이 첫 화면을 다 먹는다 | 머리 한 줄(부제 숨김), 거르개는 줄 수를 줄이고 긴 설명은 접는다 |
| 앱마다 새 «떠 있는 단추»를 만든다 | 떠 있는 것은 공용 손잡이 하나 — 자주 안 쓰는 일은 손잡이 목록이나 앱의 ⋯ 안으로 |
| 입력칸 글씨 16px 미만 · 확대 막기 | 16px 이상(아이폰이 누를 때마다 화면을 키운다) · `user-scalable` 은 막지 않는다 |
| 겉 여백 + 카드 여백 + 안쪽 상자 여백이 겹겹이 쌓여 양옆이 비어 있다 | 폰에서 글·단추는 화면 양 끝 **8~14px 안**에서 시작·끝, 상자는 **한 겹**(안쪽 상자의 여백·테두리를 걷는다) — 대표 지시 2026-10-18 「좌우 옆공간 모두 채워서」 |

- ⚠ **폰 구간(`@media (max-width:…)`)에서만 바꾼다 — PC 는 그대로.** 고친 뒤 1366px 로도 그려 전후가 같은지 본다.
- ⚠ «☐ 고르기 칸 + 번호»(위 절)와 «한 칸은 한 줄»은 폰에서도 그대로다. 카드로 바꿔도 ☐·№ 는 왼쪽 끝에 둔다.
- ⚠ **「열렸는데 안 보인다」** — `overflow:hidden` 이나 `backdrop-filter` 가 있는 조상 안의 `fixed` 창은
  폰에서 통째로 잘린다(STATUS.md 「열려 있는데 안 보인다」). `display` 만 재지 말고 `elementFromPoint` 로 그 자리에 진짜 있는지 본다.
- ★ **떠 있는 단추는 공용 앱바가 정리한다** — 폰에서 「즐겨찾기」 손잡이는 가늘게, 「최신」(평소일 때)·「백업·복구」는
  숨기고 손잡이 목록 맨 아래 «🔄 새 버전 확인 · 🗄 백업·복구» 줄로 옮겼다(`js/pu-appbar.js` 의 `phoneRows`).
  새 버전이 «있을 때»·확인 중·결과는 숨기지 않는다. 앱에서 따로 숨기지 말 것 — 숨기면 그 일을 할 길이 없어진다.
  ⚠ 예외 하나 — 앱 머리줄에 **같은 목록을 여는 길**(⭐ 단추 또는 ⋯ 안의 줄, `PuAppBar.open`)이 있을 때만 「즐겨찾기」 손잡이를 숨길 수 있다.
  화면 끝까지 편 목록의 줄 끝(금액·날짜)을 손잡이가 덮어서다 — 정부지원금(⭐)·정부사업일정(⋯)·이알피·인사·재무(⭐)가 이 길이다.
  그 길이 «있을 때만» 숨긴다(이알피는 `body:has(.hd-fav)`) — 없이 숨기면 다른 앱으로 건너갈 길이 없어진다.
  그때 「새 버전 있음 · 누르기」는 폰에서 **바닥 가까이** 앉고, 그 자리에 바닥에 붙은 막대(쪽 막대·저장 막대)가 있으면
  **막대 높이를 재서 그 위로** 올라간다(`fabLift`, 대표 지시 2026-10-18 「너무 위에 있다 … 조금 낮게」).
  ⚠ 앱에서 이 단추 자리(`bottom`)를 따로 박지 말 것 — 한때 취업규칙만 박았다가 쪽 막대를 덮었다(`tests/version-fab-phone-low.test.js`).

**확인하는 법 — 눈대중 말고 잰다**

```
node tools/phone-audit/run.mjs <앱 key> [--full]     # 360·411px, 로그인한 채, 지어낸 자료로
```

가짜 파이어베이스를 끼워 «로그인된 대표 계정»으로 그린다(비밀번호를 안 친다, 진짜 서버에 안 쓴다).
옆넘침·화면 밖·세로로 깨진 글자·두 줄 단추·작은 단추·작은 입력칸과 **양옆 빈자리(L/R px·상자 겹)**를 세고 갈무리를 남긴다 — 숫자는 그물이고 판단은 갈무리로 한다.

- ★ **갈무리를 볼 때 먼저 묻는다 — 「처음 보는 사람의 눈이 이 화면 한 장에서 어디에 먼저 가는가, 그것이 이 화면의 결과(금액·기한·남은 건수)인가」.**
  아니라면(머리·거르개·안내문·빈 띠가 먼저 보이면) 그것이 가장 큰 흠이다 — 숫자가 다 초록이어도 고칠 차례는 그것부터다.
  (대표 지시 2026-11-08 「추천대로」 — benjitaylor/skills 의 Stageshow 검토에서 들인 점검 질문 하나. 스킬 자체는 홍보용 그림 도구라 붙이지 않았다.)

- ⚠ **새 앱은 `tools/phone-audit/seeds/<key>.js`(지어낸 자료)를 함께 만든다.** 빈 화면으로는 표가 폰에서 깨지는지 알 수 없다.
  자료는 «지어낸 것만» — 실제 고객·직원 이름·주민번호·연락처 금지.
- 앱별 상태와 남은 일: `docs/폰화면-현황.md`.

`tests/phone-screen-rules.test.js` 가 기계로 지킨다(점검 도구가 앱을 안 빠뜨리는가 · 앱마다 점검 자료가 있는가 ·
폰에서 숨긴 단추에 다른 길이 있는가). 입력칸 16px 은 `tests/phone-input-zoom.test.js`.
⚠ 화면을 «그려서» 재는 일은 CI 에서 못 한다(브라우저가 없다) — 앱을 손댈 때 위 도구를 직접 돌린다.

### 진짜 폰으로 보기 — 폰 미러 (대표 지시 2026-10-24 「폰을 미러링으로 연결하고 UI 고칠 수 있게」)

지어낸 자료로 재는 위 도구와 짝이다 — 대표 폰(글자 크게·실제 자료)에서만 깨지는 것을 **대표 PC 의 Claude** 가 직접 본다.
USB 로 꽂고 `폰미러-켜기.bat`(→ `tools/phone-mirror.js`): ① 미러 창(scrcpy) ② `--shot` 폰 갈무리 ③ `--measure` 폰 크롬의 푸른 화면을
phone-audit 와 같은 자(`measure.js`)로 잰다. 고치는 순서: 갈무리를 읽고 → 재고 → 코드 고침 → `phone-audit --font=1.4` 로 다시 재고 → PR.

- ⚠ **폰을 누르지도 치지도 않는다** — 누르고 넘기는 것은 미러 창에서 사람이 한다. 폰 크롬은 «진짜 로그인»이라 위 「화면 같이 보기」 표가 그대로다.
- ⚠ 재기는 푸른 화면(nabaho.github.io/pureunall · localhost)만, 돌리는 코드는 `measure.js` 뿐이다.
- ⚠ 갈무리(`tools/phone-mirror/out/`)에는 고객 이름·금액이 찍힌다 — 저장소에 안 올라가고(.gitignore), 채팅·PR 에 붙이지 않는다.
- 클라우드 방에서는 폰이 안 닿는다 — 이 도구는 대표 PC 에서 연 방(로컬·폰연결)에서 쓴다.
`tests/phone-mirror.test.js` 가 지킨다. 쓰는 법: `docs/폰-미러.md`.
