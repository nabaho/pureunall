# 보안 점검 · 미토스(Claude Mythos) 연결 준비 (대표 지시 2026-11-15)

> 「푸른노무법인의 보안 관련된 전체 검토하고 문제되는 걸 확인하고 싶다 … 외부 해킹을 방어하기 위한 시스템을 구축하고 싶다」
> 「모두 실행하고 미토스 연결도 준비해」

## 0. 지킬 것 — 이 저장소는 «공개»다

- ⚠★ **점검 결과(어디가 뚫려 있나)는 이 저장소에 적지 않는다.** 깃허브에서 누구나 읽는다 — 고치기 전의 약점 목록은 공격 안내서가 된다.
  결과 보고서는 대표에게만 따로 건넨다(채팅 파일·비공개 문서). 저장소에는 «고친 뒤»의 PR 과 검사만 남는다.
- PR 설명에도 «무엇을 막았나»만 짧게 — 공격 순서를 자세히 쓰지 않는다.
- 점검에 고객 자료(주민번호·임금·계좌·메일 본문)를 쓰지 않는다. 코드·규칙·설정만 본다. 살아 있는 DB·서버를 «찔러 보는» 시험은 하지 않는다.

## 1. 점검 범위 (1단계 — 찾기)

| 갈래 | 보는 것 |
|---|---|
| DB·창고 규칙 | `scripts/make-firebase-rules.js` · `docs/firebase-storage-전체(붙여넣기용).txt` — 민감 자리를 누가 읽고 쓰나, 권한 올리기, 크기 제한 |
| 서버 함수 | `functions/` — 로그인 없이 부르는 함수, 관리자 검사, CORS, 경로 조작, 외부 주소 부르기(SSRF), 메일 머리 주입, 요금 폭탄 |
| 공개 저장소·자동 작업 | 비밀·개인정보가 기록(history)에 남았나, 배포본에 내부 문서가 새나, 깃허브 작업의 입력 주입·자동 병합 |
| 화면·로그인 | 남이 심은 글이 관리자 화면에서 실행되나(XSS), 화면만 가린 권한, 가입·세션, 외부 스크립트 무결성(SRI)·CSP |

## 2. 방어 체계 (2단계 — 막기, 1단계 결과로 정함)

후보: 서버 함수 «우리 앱에서만» 잠금(App Check) · 부르는 횟수 제한 · 이상 접속·관리자 권한 변경 폰 알림 ·
관리자 계정 보안 키(패스키) · 외부 스크립트 SRI·CSP · 백업 복구 연습. 고치기는 위험한 것부터 한 건씩 PR.
보안규칙은 늘 `rules-deploy.js` 의 안전장치(사라질 규칙이 있으면 멈춤)를 거친다.

## 3. 미토스 — 무엇이고 어떻게 연결하나

- Anthropic 의 보안 전용 모델. **사이버 검증 프로그램(CVP)** 심사를 통과한 «방어 목적» 사용자에게만 열린다.
- 푸른은 Claude Team(유료)이라 **방어용(Defense Access)** 을 신청할 수 있는 것으로 보인다 [확인 필요 — 신청 화면에서].

**신청(대표가 직접 — 법인 계정 관리자)**
1. portal.anthropic.com 로그인(법인 Claude 계정) → Cyber Verification Program → Apply
2. 쓰임새: 「우리 법인이 만든 업무 시스템(공개 저장소 nabaho/pureunall)의 방어 목적 보안 점검」. 남의 시스템을 공격하는 용도가 아님을 적는다.
3. 승인 뒤 «관리자 켜기(activation)»가 따로 있을 수 있다 — Team 관리 화면에서 켠다.

**요구 조건(신청 전에 갖출 것)**
- 법인 Claude 계정 전원 2단계 로그인(MFA). ⚠ **2026-12-15 부터 «피싱에 강한» 2단계(패스키·보안 키) 요구** — 대표 계정부터 패스키로 바꾼다.
- API 키를 쓰면 7일마다 바꾸기(12-15 부터는 고정 키 금지). 지금 푸른은 Claude API 키를 쓰지 않는다(외부 «AI 프록시» 확인 필요).
- ⚠ **CVP 에 들면 대화 내용이 Anthropic 에 보관된다.** 그래서 미토스 방에는 코드·규칙·설정만 넣고 고객 자료는 절대 넣지 않는다.

**연결되면 쓰는 법**
- 같은 저장소를 미토스 모델로 연 방에서 위 1절 네 갈래를 한 번 더 돌린다 — 1단계 결과와 견줘 «새로 찾은 것만» 추린다(두 번째 눈).
- 결과는 0절대로 저장소 밖으로만 건넨다. 고치기는 이 저장소의 보통 길(가지 → 검사 → PR)로.
