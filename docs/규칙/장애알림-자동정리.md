# 시스템 장애 알림 — 화면에 띄우지 않고 저절로 «처리 완료»로 정리한다

> 대표 지시 2026-11-22: 「시스템 장애 알림 관련 모두 처리 완료 버튼 안 눌러도 자동으로 정리되게,
> 앞으로 다른 전체 프로그램에 이 창 안 뜨게 다 만들어 달라.」
> CLAUDE.md·AGENTS.md 의 짧은 절이 «지킬 것»이고, 여기는 까닭·동작·되돌리는 길이다. 어긋나면 CLAUDE.md 가 이긴다.

## 무엇이 어떻게 바뀌었나

| 예전 | 지금 |
|---|---|
| 오류가 한 번 나면 왼쪽 아래에 빨간 「⚠ 장애 알림 N」 단추가 뜸 | 어느 화면에도 단추를 «스스로» 만들지 않는다 |
| 단추를 누르면 「시스템 장애 알림」 창이 열려 건마다 「처리 완료」를 눌러야 함 | 이 화면의 오류는 서버에 «처음부터 처리 완료»로 적는다 |
| 서버가 적은 알림(새 기기 로그인 등)도 눌러 줘야 함 | 총괄관리자 화면이 열릴 때 «열린 것 전부»를 조용히 처리 완료로 바꾼다 |

- 창은 포털 [⚙ 설정] 「시스템 장애 알림 · 열어보기」를 **사람이** 눌렀을 때만 뜬다(남은 «손으로 하는 길»).
- 코드는 `js/pu-health.js` 한 벌이고 21개 화면이 같은 파일을 `?v=` 로 부른다. 화면마다 따로 만든 곳은 없다.

## 기록은 지우지 않는다

- 서버 `systemAlerts/{uid}/{id}` 는 그대로 남고 `status: 'resolved'` · `resolvedAt` · `resolvedBy: 'auto'` 세 칸만 바뀐다.
  손으로 누른 것은 `resolvedBy` 가 사람의 uid 라서 «자동 정리»와 구별된다.
- 값을 `null` 로 쓰지 않는다(그러면 지워진다). 검사가 이것을 잡는다.
- 서버 규칙(`systemAlerts`)은 바꾸지 않았다 — 본인 알림을 새로 쓰는 것을 이미 허락하고 `status` 는 `new|resolved` 만 본다.

## 정리가 도는 방식 (`settleOpen`)

- 대상: 총괄관리자(`uid_roles/{uid}.isAdmin`)로 확인된 화면만. 그 밖의 사람은 서버 알림을 읽지도 쓰지도 않는다.
- 빈도: 잘 끝났으면 6시간에 한 번, 못 했으면 30분 뒤에 다시(브라우저 저장칸 `pu_health_settle_v1`).
  장애 이력 전체를 한 번 읽는 일이라 화면을 열 때마다 하면 읽는 양만 는다(`tests/rtdb-cost-guards.test.js` 의 뜻).
- 100건씩 묶어서 쓰고, 한 묶음이 거절되면 건별로 다시 쓴다 — 한 건이 막혀도 나머지는 정리된다.
- 실패는 삼킨다 — 실패를 새 장애로 다시 적으면 알림이 늘어나는 순환이 된다.

## 하지 않은 것 · 알아 둘 것

- 서버 함수(`functions/`)가 `status: 'new'` 로 적는 알림(새 기기 로그인·카카오 실패·뉴스레터·취업규칙 모으기·리멤버 연결·저장 공간 미리 알림)은
  «적는 것»은 그대로이고, 총괄관리자 화면이 열릴 때 정리된다. 서버 함수는 고치지 않았다(배포가 따로 필요하다).
- 이 알림판은 «대표에게 알리는 길»이기도 했다. 이제 화면에 안 뜨므로, 알려야 하는 것(보안·저장 공간 등)을 어디서 볼지는
  대표가 정한다(PR 보고의 「정하실 것」).
- 되돌리려면 `js/pu-health.js` 를 이전 버전으로 되돌리고 `?v=` 를 올린다 — 단, 새 규칙을 못 박은 검사도 함께 바꿔야 한다(대표 결정이 먼저).
