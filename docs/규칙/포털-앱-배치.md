# 포털 앱 배치 — 관리자만 옮기고 모두가 같게 본다

> 대표 지시 2026-11-08. 지킬 것의 핵심만 여기 있다. 변경 기록: `status/2026-11-08-portal-layout-admin.md`.

- **저장**: `data/app_config/portalLayout` = `{ v, order:[앱 key…], rows:{앱 key:영역 id}, frozen:{앱 key:true}, updatedAt }`.
  이 자리는 규칙 `app_config` 가 «읽기 직원 · 쓰기 관리자만(isAdmin)» 으로 이미 잠가 둔 곳이다 — **새 규칙을 만들지도 넓히지도 않는다.**
  위임관리인은 쓸 수 없다(화면은 `role === 'admin'` 만 편집을 켠다).
- **누가**: 편집 단추·편집 줄·📌·내 메뉴 항목은 관리자 화면에만 «만든다». 직원 화면에는 아예 없다. 서버 쓰기는 `layoutPublish` 한 곳이고 관리자가 아니면 서버를 부르지 않는다.
- **틀 고정(📌)**: 앱이 지금 있는 영역 안에서만 움직인다 — 끌기(`onTileDragOver`)·▲▼·영역 고르개·일괄 옮기기(`layMove`·`layBulk`) 모두 같은 규칙. 순서 바꾸기는 된다.
- **없을 때**: 공용 배치가 «없으면» 예전처럼 개인 저장값(`tilePrefs.order`·`rows`)을 따른다. 있으면 모두 공용 배치만 따른다.
  「처음 자리로」는 저장값을 지우지 않고 기본 배치를 새로 저장한다.
- ⚠ **`cfgSave` 는 `data/app_config` 를 통째로 바꾼다(set).** 같은 자리에 둔 `portalLayout` 을 저장할 때 다시 얹는다 — 이 자리에 새 칸을 더 두려면 같은 주의가 필요하다.
- ⚠ 계산 함수(`lay…`)는 화면을 안 만지는 순수 함수다 — 새 규칙은 거기에 넣고 검사가 «돌려» 본다.
- ⚠ `APPS` 를 `for` 로 읽으면 가운데 빈 칸(쉼표만 있는 자리)에서 죽는다 — `forEach` 를 쓰거나 `APPS[i] &&` 로 거른다.
