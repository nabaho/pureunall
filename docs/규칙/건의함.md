## 건의함 세 자리의 보안규칙 — 번호 모양 · 알려진 칸 · 길이 한도 (2026-11-12 「건의함 보안규칙: 키 모양·크기 검사 추가」)

건의함 세 자리(`suggestions_private` · `suggestions_meta_private` · `suggestions_resolved_private/{uid}`)는 «직원이 쓸 수 있는 자리» 다.
예전 규칙은 키 모양도 칸도 크기도 안 봐서 **번호에 `& | ^ %` 따옴표를 넣을 수 있었고**(대표 PC 의 감시 도구가 윈도우에서 firebase 를 cmd.exe 로 부르므로 명령으로 읽힐 수 있다 — 도구는 PR #3008 에서도 막았다, 이것은 «두 번째 겹»),
**아무 이름의 칸에 큰 글을 숨기면 대표가 건의함 목록을 열 때마다 내려받았다.** 진짜 엔진(에뮬레이터)에서 예전 규칙은 나쁜 쓰기 36개를 그대로 받았다.

- **번호(키)**: 건의·메타·진행함 번호는 `^[A-Za-z0-9_-]{1,64}$`(푸시 번호 모양), 진행함 uid 칸은 `{1,128}`. 화면 `_chatImpValidId` 와 «같은 모양» 이어야 한다(검사가 묶는다).
- **알려진 칸만**(`$other:false`): 건의 원문 14칸 · 메타 7칸 · 진행함 13칸. 서버가 쓰는 칸(AI 접수 초안 `assist`·감시 알림 칸)은 일부러 규칙에 없다 —
  서버(Cloud Functions · 감시 도구 = firebase CLI)는 관리자 권한이라 규칙을 안 타고, 브라우저에서 직원이 그 칸에 못 쓰게 된다.
- **칸마다 종류·길이**: 그림은 한 장 100만 자·최대 3장·0번부터 빈틈 없이(줄여 담은 그림이 운영 실측 최대 약 33만 자), 답변 2만 자, 피드백 2천 자, 제목 200자, `relatedId`·`source` 모양, `resolvedOk`·`seen` 은 참/거짓만.
- ⚠ **이 자리에 새 칸을 쓰려면 `scripts/make-firebase-rules.js` 의 건의함 절과 화면을 «같이» 고친다** — 모르는 칸은 거절되므로 규칙을 안 고치면 건의 접수·답변이 막힌다.
- `.validate` 는 «새로 쓰는 값» 만 본다 — 이미 있는 자료(서버 칸이 붙은 옛 건의 포함)는 그대로 두고, 지우기는 번호가 이상해도 된다. 읽기·쓰기 권한은 바꾸지 않았다.
- 지킴: `tests/suggestion-rules.test.js`(모의 평가기 — 평소 전체 검사에 돈다) · **진짜 엔진 확인** `tests/suggestion-rules.emulator.mjs`(수동 — 방법은 파일 머리. 자바 필요, 에뮬레이터 파일은 처음 한 번 내려받는다).

## 건의함(포털 💬)의 고칠 일은 «점수와 상관없이» 내가 검토하고 직접 고친다 (대표 지시 2026-10-18)

> 「점수와 상관없이 니가 검토하고 수정해라. 푸른 모든 직원이 앞으로 사용할 것이다」
> (2026-10-15 의 「난이도 60점 미만만 직접」은 이 말씀으로 거두었다 — 점수 문턱은 없다.)

건의 중 **코드를 고쳐야 하는 건**은 대표에게 넘기지 않고 내가 읽고·고치고·검사하고·PR 로 올린 뒤 **답변까지** 넣는다.

- **읽는 법**: `firebase database:get /suggestions_private --project pureun-erp` (Bash 에서는 `MSYS_NO_PATHCONV=1` 을 앞에).
  한 판이 5MB 가까이 된다(사진이 글자로 들어 있다) — 파일로 받아 본문만 뽑아 본다. `-o` 는 쓰지 말고 표준출력을 파일로 돌린다.
- **나누기**: ① 코드를 고칠 일 → 고친다 ② 설명·확인만 필요한 일 → 답만 쓰고 `ing`(검토중) ③ 돈·정책 결정 → 대표에게 묻고 `ing`.
  고치지 않은 것을 `done` 으로 두지 않는다 — 거짓 완료가 가장 나쁘다.
- **답변은 세 자리에 함께** 쓴다(하나만 쓰면 답은 들어갔는데 미처리로 남는다):
  `suggestions_private/{id}` · `suggestions_meta_private/{id}` · `suggestions_resolved_private/{authorUid}/{id}`(`seen:false` 일 때만 본인에게 팝업).
  담을 것: **왜 그랬나 · 어떻게 고쳤나 · 건의자가 할 일**(특히 파일을 다시 올려야 하는지). 「처리함」 같은 2~3글자 답은 쓰지 않는다.
  건의한 직원은 대표 화면을 안 본다 — 건의함이 유일한 답이다.
- **같은 모양이 되풀이되면 뿌리를 찾는다.** 2026-10-18 에 34건을 분석했더니 재무 거래내역 매칭 · 계약·사건 입력 · 사진첩이 79% 였고,
  뿌리는 넷이었다 — ① 이름으로 회사를 맞추는 구조 ② 이관할 때 값이 한 칸 빠짐 ③ **내 고침이 다른 곳을 깸**(9/19 의 한 줄 누락으로 계약 추가가 12일간 멈췄고 직원이 건의해서야 알았다) ④ 사진 화면과 저장 자리 어긋남.
  ③ 때문에 **고친 뒤 «같은 화면의 다른 길»을 한 번 더 본다** — 건의자가 오류의 첫 발견자가 되게 두지 않는다.
- ⚠ **직접 고친다고 안전장치를 푸는 것은 아니다.** 돈·금액을 자동으로 바꾸는 일, 보안규칙(위 절차), 살아 있는 자료 쓰기, 되돌리기 어려운 외부 발송은 그대로다.
- **도구가 있다 — 손으로 세 번 쓰지 말 것**: `node scripts/suggestion-watch.js pending`(미처리 목록, 읽기만) ·
  `show <id> [--out 폴더]`(글 + 캡처를 그림 파일로) · `reply <id> --status ing|done --file 답변.txt [--seen true|false] [--again]`
  (세 자리에 한 번에 쓰고 다시 읽어 확인). 짧은 완료 답(40자 미만)·이미 done 인 건 덮기·new 로 되돌리기는 도구가 거절한다.
  재요청(`relatedId`)은 먼저 원본의 `resolvedAt` 과 재요청 시각을 비교한다 — 건의자가 이미 「해결됐어요」로 확인했으면 재요청은 풀린 것이다.
- **자동 감시(2026-10-30 「건의함 자동감시」)**: 예약 작업 `suggestion-watch` 가 **평일 09:00~20:00 에 30분마다** 미처리를 훑는다 — **주말·공휴일은 쉰다**(대표 지시 2026-11-08).
  공휴일은 서버가 매달 받아 두는 `pubdata/common/holidays/{해}`(한국천문연구원 특일 정보 — 대체·임시공휴일·선거일 포함)로 가린다. 못 읽으면 감시는 그대로 한다.
  새 건이면 ① 「접수했습니다」(ing) ② 코드를 고칠 일이면 새 작업폴더에서 고쳐 검사·PR(**제목 맨 앞 `[보류]` — 자동 병합 브레이크, 대표가 보고 합친다**)
  ③ 합쳐지고 배포되면 완료 답. 돈·정책·권한 판단은 ing 로 두고 대표에게 알린다.
  **알림은 `node scripts/suggestion-watch.js notify <id> --kind pr|decide|human|done --text "한 줄"`** — `suggestions_private/{id}/watchNotice` 에 쓰면
  서버 함수 `notifySuggestionWatch` 가 대표 폰으로 보낸다(앱의 알림 도구가 없는 무인 실행에서도 닿는다). 새 건의 자체의 폰 알림은 예전부터 있는 `notifySuggestion`.
  건의함 머리의 **[🔔 테스트]** 는 `pucards/config/pushTest/{내 uid}` 요청 → `pushSelfTest` 가 등록 기기 모두로 시험 알림 + 결과를 done 에 적는다.
  ⚠ 두 함수 모두 «쓴 사람»을 본다(관리자·관리 도구만) — 직원도 쓸 수 있는 자리라서. 규칙·최상위 자리를 새로 만들지 않았다(함수만 올린다: `--only functions:notifySuggestionWatch,functions:pushSelfTest`). 한 건 2번 시도해도 안 되면 사람 확인으로 넘긴다.
  PC 와 데스크톱 앱이 켜져 있어야 돈다. 끄려면 예약 작업 `suggestion-watch` 를 비활성화한다.
  ⚠ 예약 작업의 지시문은 저장소가 아니라 «이 PC» 의 `%USERPROFILE%\.claude\scheduled-tasks\suggestion-watch\SKILL.md` 에만 있다 —
  2026-11-07 윈도우 재설치로 사라져 11-08 이 문서와 도구를 보고 다시 썼다. 건마다 어디까지 했는지는 같은 폴더 `state.md` 에 쌓인다.
