# 로그인 유지 — 「내 기기에서 30일간 로그인 유지」

대표 요청(2026-11-10): 「로그인 할 경우 30일 피시에서 본인 컴퓨터인 경우 로그인 연속가능기능 및 체크기능 만들어줘」

## 어떻게 돌아가나

| | 체크함 (내 기기) | 체크 안 함 (공용 PC) |
|---|---|---|
| 파이어베이스 지속 | LOCAL (창을 닫아도 남음) | SESSION (창·브라우저를 닫으면 끝) |
| 상한 | **30일** — 마지막 «진짜 로그인» 부터. 넘으면 스스로 로그아웃 | 해당 없음 |
| 로그인한 때 | `pu_keep_login_at` 에 시각(숫자) 하나 | 적지 않는다(있던 것도 지운다) |
| 자리비움 자동 로그아웃 | 안 한다(대표 2026-10-04) | 60분(기존 그대로) |

- 체크칸은 포털(`enter.html`)의 `#autoLogin` — 카카오·비밀번호 로그인이 같은 칸을 따른다. 마지막에 고른 값은 `pu_portal_auto`('1'/'0')에 남는다(처음 쓰는 PC 는 꺼짐·폰은 켬 — 2026-09-29 결정 그대로).
- **비밀번호·토큰은 저장하지 않는다.** 시각 하나와 0/1 만 적는다. 로그인이 남는 것은 파이어베이스 몫이다.
- 30일은 «마지막 로그인» 기준이다 — 쓸 때마다 미뤄 주지 않는다(앱을 열거나 토큰이 새로 고쳐져도 그대로). 30일마다 한 번은 다시 로그인한다.
- 로그인 시각 기록이 없는 로그인 — 이 기능 이전에 «유지»로 로그인한 기기, 포털을 안 거치고 앱의 자체 로그인 칸으로 들어온 기기(파이어베이스 기본이 LOCAL 이라 «영원히 남는» 로그인이다) — 은 **처음 본 날부터** 30일을 센다. 시각을 안 보는 것은 「유지 끔」(`pu_portal_auto='0'`)을 골라 둔 기기뿐이다.

## 코드 — `js/pu-keep-login.js` (로그인이 필요한 모든 화면이 싣는다)

1. **30일 검사** — 사람이 보일 때·창이 깨어날 때·10분마다. 넘으면 까닭(`로그인 유지 30일 만료`)을 남기고 → «나갔다» 신호를 적고 → `signOut` → 끊긴 «뒤에» 이 기기에 남은 로그인 열쇠(`pu_auth_uid`·이알피 자동 로그인·정부사업일정 `p_autoSession`)를 지운다. 로그인 화면 한 줄(`PuLogoutWhy`)에 까닭이 보인다.
   - 포털은 열기 «전에» 검사한다(`PuKeepLogin.guard(user)`). 앱을 바로 열어도(바탕화면 아이콘·폰 앱) 같은 검사가 돈다 — 그래서 포털만이 아니라 모든 화면이 싣는다.
   - ⚠ 신호를 «먼저», `pu_auth_uid` 를 «나중에» 지우는 까닭: 이 탭의 `pu-authsync.js` 가 「로그인해 있던 화면이었나」를 알아야 로그인 화면으로 밀어낸다(외부 검토 지적). 밀어내기가 안 일어난 화면은 4초 뒤 「로그인이 필요합니다」 화면(없으면 포털)을 띄우되, 그 사이 다시 로그인했거나 로그인 칸이 «보이는» 화면이면 건드리지 않는다.
   - ⚠ 끊기가 «실패»하면 새 30일을 주지 않고 다시 끊어 본다(세 번까지). 표시는 끊기가 «성공한 뒤에만» 지운다 — 어떤 로그아웃(단추·유휴·만료)이든 마찬가지다(부르는 순간 지우면 실패했을 때 다음 검사가 「처음 본 사람」으로 오해한다).
2. **유지 끔 보호** — 이 기기가 「유지 끔」(`pu_portal_auto='0'`)이면 앱이 부른 `setPersistence(LOCAL)` 을 SESSION 으로 낮추고, 앱 안의 따로 있는 로그인 칸(`signInWith…`)도 로그인 직전에 SESSION 을 먼저 못 박는다. 못 박기가 «거절»되거나 «동기 오류»를 내면 로그인하지 않는다(포털과 같다 — 세션으로 못 정한 채 들어가면 공용 PC 에 영구 로그인이 남을 수 있다).
   - 까닭: 경력관리·정부사업 등 여러 앱이 시작할 때 `setPersistence(LOCAL)` 을 무조건 부른다. 파이어베이스는 그때 지금 로그인을 LOCAL 로 **옮기므로**, 공용 PC 에서 유지를 끈 사람이 앱을 한 번 열면 «영원히 남는» 로그인이 된다.
   - ⚠ 유지는 **포털 체크칸에서만** 고른다. 정부사업일정의 자체 로그인 칸(`#loginRemember`)은 HTML 에서 «기본으로 체크»돼 있어, 거기서 `begin(true)` 를 부르면 사람이 안 보고 지나친 체크가 공용 PC 의 유지 끔을 뒤집는다 — 그래서 부르지 않는다(포털에서 유지 끔을 고른 기기는 그 칸의 LOCAL 요청도 SESSION 으로 낮춰진다). 같은 까닭으로 그 칸은 «유지 끔» 기기에서 앱 자체 세션(`p_autoSession`: 이름·역할)도 남기지 않고 이미 남은 것도 지운다.
3. **로그아웃이 표시를 지운다** — 로그아웃은 어디서 불러도 파이어베이스 `signOut` 을 지나므로 한 곳에서 감싼다(`pu-logout-why.js` 와 같은 방식). 포털의 로그아웃 단추·유휴 로그아웃은 `broadcastLogout()` 에서도 지운다.
4. 로그인한 때는 로그인 «직전»에 적는다(`begin`/`stamp`) — 끝난 뒤에 적으면 옛 표시로 방금 로그인한 사람을 내보낼 수 있다. 앱이 표시를 못 적고 들어온 경우를 위해 파이어베이스의 `metadata.lastSignInTime` 이 표시보다 새것이면 그것을 기준으로 삼는다.

## 새 화면을 만들 때

- 로그인이 필요한 화면(`js/pu-gate.js` · `js/pu-logout-why.js` 를 싣거나 `setPersistence(` 를 부르는 화면)은 `<script src="js/pu-keep-login.js?v=1"></script>` 를 싣는다. 빠지면 `tests/keep-login-30days.test.js` ④ 가 알려 준다.
- 고객·근로자가 로그인 없이 여는 공개 화면에는 싣지 않는다.

## 이 기능이 «안 하는 것»

- 급여아웃소싱·관리자 화면을 더 강하게 지키는 일(2중 로그인·화면별 자리비움 잠금) — 별개 결정이다(`docs/규칙/급여아웃소싱-2중로그인.md`, 대표 지시 전까지 켜지 않는다).
- 로그아웃해도 체크칸의 «마지막 선택»은 기억한다(2026-09-29 결정). 공용 PC 에서 실수로 켠 뒤 로그아웃하면 다음 사람 화면에도 체크가 켜져 있다 — 바꾸려면 로그아웃 때 `pu_portal_auto` 를 지우면 된다(한 줄, 대표 결정).
