# 푸른 문서뷰어 — 폰에서 광고 없이 한글·PDF·엑셀·PPT 보기 (설계, 2026-10-25)

> ✅ **1판 구현됨 (2026-10-25)** — 한글·PDF·엑셀(xlsx·xls·csv) · 폰 화면 · 공유받기 · PC 설치/연결 프로그램 · 격리 칸 · 검사.
> 대표 결정(「추천대로」): PPT 는 ㉮ 글·그림 근사(2판) · 최근 파일은 이름만 · 포털 타일 + 독립 설치(**타일은 보류** — 7절).
> 4번(아이폰)·5번(사용 범위)은 추천을 드리지 않았다 → 아이폰은 「파일 열기」로 열고, 직원 누구나 쓰는 것으로 가정했다.
> 아래는 설계 원문이고, 구현하며 «달라진 곳»은 각 절에 **「구현 결과」** 로 적었다.

> 대표 요청: 「핸드폰에 광고 없이 한글이나 PDF, PPT, 엑셀 등 쉽게 보고 싶다. 내 PC에도 쓸 수 있게」
> 계기: 이음오피스(ieumoffice.com)는 Windows·Mac·Linux 설치형 베타라 폰에 못 깐다(2026-10-25 공식 페이지 확인).
> 이름은 «푸른 문서뷰어»(key `viewer`) — ⚠ `ieum-view.html` 은 이음센터 근무일정 페이지라 «이음» 은 쓰지 않는다.

## 0. 한 줄 결론

**«보기 전용» 앱 하나**를 새로 만든다. 폰 화면에서 파일을 고르거나 «공유 → 푸른 문서뷰어» 로 보내면 그 자리에서 펼쳐 준다.
**파일은 폰 밖으로 안 나가고, 광고·추적·외부 주소가 없다.** 같은 앱을 PC(엣지·크롬)에 설치하면 PC 에서도 같은 모양으로 쓴다.
해석기는 저장소에 이미 다 들어 있다 — **없는 것은 PPT 하나**다.

이음오피스와 다른 점: 이음오피스는 «고치고 원래 형식으로 저장»까지 한다. 이 앱은 **보기만** 한다(편집은 범위 밖 — 12절).

## 3. PPT 는 어떻게 — 결정이 필요하다

| 길 | 얻는 것 | 잃는 것 |
|---|---|---|
| ㉮ **jszip 으로 슬라이드의 글·그림만 뽑는다**(직접 짠다) | 외부 부품 0, 작다, 검사하기 쉽다 | 서식·도형·애니메이션은 근사. «슬라이드 N쪽: 제목·본문·그림» 정도 |
| ㉯ 오픈소스 PPTX 그리개를 `vendor/` 에 들인다 | 모양이 더 가깝다 | 바깥 부품 — 라이선스·보안(남의 코드가 파일을 해석)·크기를 따로 검토해야 한다. CLAUDE.md 가 바깥 부품을 들이는 쪽을 경계한다 |

**추천: ㉮ 로 시작.** 「폰에서 «내용을 확인»하는 것」이 목적이라 ㉮ 로 충분할 가능성이 높다. 모양이 모자라면 ㉯ 를 그때 검토한다.

## 4. 폰 화면 (CLAUDE.md 「폰 화면」·「☐ + 번호」 규칙을 따른다)

**첫 화면**
- 머리 한 줄: 「푸른 문서뷰어」 + ⋯(안내). 부제 없음.
- 큰 단추 하나 **[📂 파일 열기]** (손가락으로 누를 만큼 넉넉하게). 아래에 한 줄 안내 «한글·PDF·엑셀·PPT · 파일은 이 폰 밖으로 나가지 않습니다».
- **최근 연 파일** 목록 — **이름·크기·연 날짜만**(내용은 저장하지 않는다, 6절). 이 목록은 «정리하는 목록»이라
  맨 왼쪽 **☐ 고르기 칸 + 번호**를 둔다(애매하면 넣는다). 고른 뒤 «N건 선택 · 목록에서 빼기». 번호는 보이는 순서, 저장하지 않는다.
  줄은 폰에서 «두 줄 카드» — 1줄 ☐·№·이름, 2줄 «말을 하는» 값(크기·날짜)만.

**보는 화면**
- 위: 한 줄 머리(← · 파일 이름 `…` · `3/12쪽`). 본문이 화면 양 끝 8~14px 안에서 시작·끝, 겹겹 여백 없음.
- 본문: 쪽 폭을 화면에 맞춰 세로로 이어 보기. 핀치 확대(`user-scalable` 막지 않음). 가로로 돌리면 폭을 다시 맞춘다.
- 아래: 쪽 이동(`‹ ›`·쪽 번호 입력), 엑셀은 시트 탭(한 줄 + 옆으로 밀기). 단추는 그림만 + `title`.
- 떠 있는 단추는 새로 만들지 않는다 — 공용 앱바(`js/pu-appbar.js`)에 맡긴다.

## 5. PC 에서도 — 같은 앱을 «설치»한다

- PC: 엣지·크롬에서 **설치(앱으로 열기)** → 바탕화면 아이콘. `manifest` 의 `file_handlers` 로 `.hwp .hwpx .pdf .xlsx .pptx` 를
  «연결 프로그램»에 올릴 수 있다(데스크톱 크롬·엣지 전용 기능). 파일을 더블클릭하면 뷰어로 열린다.
- 폰(안드로이드): 설치하면 `share_target` 으로 카톡·파일관리자의 «공유» 목록에 뜬다. **아이폰은 공유받기를 못 한다**(기존 앱과 같은 제약) — 파일 열기 단추로만.
- ~~오프라인: 서비스워커가 앱 틀과 엔진을 캐시한다.~~ → **구현 결과: 1판은 오프라인을 약속하지 않는다.**
  서비스워커는 한 범위에 하나뿐이라 «공유받기»를 받는 공용 `pu-sw.js` 한 파일을 모든 앱이 함께 쓰는데, 이 파일은 **일부러 아무것도 캐시하지 않는다**
  (캐시를 두면 `pu-version.js` 의 새 판 자동 적용과 싸워 옛 화면이 남는다). 그래서 이 앱만 캐시를 두지 않았다.
  한글 엔진(`rhwp_bg.wasm` **9.9MB**)은 한글 파일을 처음 열 때만 받고, 그 뒤는 브라우저 기본 캐시에 기댄다(보장 아님).
  오프라인이 꼭 필요하면 «공용 서비스워커에 이 앱 전용 캐시를 더하는» 별도 결정이 필요하다.
- 계정·로그인은 **없다**(자료를 서버에서 읽지 않으므로). 포털 타일은 «자료함» 줄에 하나 둔다(결정 ②).

## 6. 보안·개인정보 — 이 앱의 핵심 설계

고객 급여대장·주민번호가 든 파일을 폰에서 열 수 있으므로, **«열기만 해도 새는 길»을 구조로 막는다.**

1. **서버로 안 보낸다.** 이 화면은 Firebase·`fetch`·XHR·WebSocket·외부 스크립트(CDN)를 **싣지 않는다.** 엔진은 전부 `vendor/` 의 저장소 사본.
   `<meta http-equiv="Content-Security-Policy">` 로 `connect-src 'none'` · `script-src 'self'` · `img-src 'self' blob: data:` 를 건다.
2. **해석은 «격리된 칸» 안에서.** 모든 앱이 한 주소(nabaho.github.io)를 쓰므로, 해석기 약점(pdf.js CVE-2024-4367 같은 것)이
   열린 «나쁜 파일»로 뚫리면 같은 주소의 로그인 증표가 위험하다. 그래서 문서를 그리는 부분을
   `sandbox="allow-scripts"`(주소 없는 `iframe`, `allow-same-origin` 없음) 안에서 돌리고, 부모와는 `postMessage` 로 «바이트 → 그림»만 주고받는다.
   그 위에 `isEvalSupported:false` 도 건다(이중 방어).
3. **파일 내용을 저장하지 않는다.** 최근 목록은 이름·크기·날짜뿐(`localStorage`, `try/catch`). «다시 열기»는 파일 선택기를 다시 띄운다.
   (폰을 잃어버렸을 때 고객 자료가 남지 않게 — 결정 ③ 의 기본값.) 화면을 떠나면 읽은 바이트를 놓는다(`doc.free()` 등).
4. **파일 크기 한도.** 엔진 기본 100MB 는 폰에 너무 크다. 폰 한도는 시험 제작에서 재서 정한다([확인 필요]).
5. **문서 안의 글은 «자료»다.** 파일 안의 링크·스크립트·매크로는 실행하지 않고, 파일 이름은 `textContent` 로만 넣는다.
6. **광고·추적 없음.** 분석 코드·외부 글꼴·외부 이미지 없음 — 위 1번의 CSP 가 기계로 막는다.

## 7. 온톨로지·규칙 (CLAUDE.md 준수)

> **구현 결과**: 이 앱은 `PuOntology.EXCLUDED_SCREENS`(사유와 함께 «등록 제외»)에 `pu-viewer.html`·`pu-viewer-frame.html` 로 올렸다 —
> 기존 `install.html` 과 같은 길이다(「업무 자료를 담지 않는다」). `tests/ontology-registry.test.js` 가 모든 화면이 등록부·딸린 화면·제외 중 하나인지 본다.
> **포털 타일은 달지 않았다.** 타일을 달면 `PROGRAMS` 에 등록해야 하는데 `tests/ontology-contract.test.js` 가 «모든 프로그램에 primaryRoots(저장 자리)가 있다» 를 요구한다.
> 저장 자리가 없는 이 앱에 가짜 저장 자리를 적는 것은 옳지 않다. 타일 + 공용 앱바(즐겨찾기)·로그아웃 화면(`pu-gate`)·내 자리 표시(`pu-whoami`) 같은 포털 공통 부품 규칙도 함께 정해야 한다.
> → **대표 결정 대기: 「저장 자리 없는 프로그램」을 등록부가 받도록 규칙을 고칠지**(고치면 타일 가능), 아니면 독립 설치 앱으로만 둘지. 그때까지는 바로 가기 주소(`pu-viewer.html`)와 설치로 쓴다.

(아래는 설계 당시 생각이다 — 위가 현재 상태.)

- 이 앱은 **자기 업무 자료가 없다**(읽기만). `PuOntology.PROGRAMS.viewer` 에 `primaryRoots:[]` 로 등록하고
  `READ_ADAPTERS.viewer` 는 `strategy:'in_app'` 으로 선언한다(컨설팅보고서가 쓴 방식). 새 개체·관계를 만들지 않는다.
- `writeContracts` 는 **비어 있다** — 저장하는 길이 없다는 것을 선언하는 것이다. Firebase 를 안 싣는 앱이라 `pu-ontology-write.js` 를 싣는 의무가
  어떻게 적용되는지는 `tests/ontology-contract.test.js` 로 먼저 확인한다([확인 필요] — 이 검사가 «Firebase 없는 앱»을 어떻게 보는지 아직 안 읽었다).
- 보안규칙(Firebase)·창고 규칙은 **건드리지 않는다** — 서버 자료를 안 쓰므로 바꿀 것이 없다.
- 폰 규칙: `tools/phone-audit/seeds/viewer.js` 를 함께 만든다(지어낸 파일 목록 — 실제 고객·직원 이름 금지).
  파일을 «그려서» 재는 일은 CI 에서 못 하므로 만든 뒤 `node tools/phone-audit/run.mjs viewer` 를 직접 돌린다.

## 9. 검사 («규칙»을 못 박는다 — «지금 값»이 아니라)

- **새는 길이 없는가**: `pu-viewer*.js`·`pu-viewer.html` 에 `fetch(`·`XMLHttpRequest`·`WebSocket`·`firebase`·외부 `http(s)://` 스크립트가 «없는가».
- **격리가 걸려 있는가**: `sandbox` 속성이 있고 `allow-same-origin` 이 «없는가». CSP `connect-src 'none'` 이 «붙어 있는가».
- **pdf.js**: `tests/pdfjs-no-eval.test.js` 가 새 `getDocument(` 자리를 자동으로 잡는다 — 따로 만들지 않는다.
- **형식 가리기**: 서명이 `PK`(zip)면 안의 `word/document.xml`·`xl/workbook.xml`·`ppt/presentation.xml` 로 가른다 — 확장자를 속인 파일도 «진짜 형식»으로.
- **최근 목록**: 저장되는 칸이 이름·크기·날짜뿐인가(내용 칸이 «없는가»).
- **☐·번호**: 목록 맨 왼쪽이 ☐ → 번호 순서인가, 머리줄 ☐ 가 «보이는 줄만» 고르는가.
- 값 자체가 규칙인 것(파일 한도 바이트 등)만 박고, 같은 줄에 `검사고정-허용` 과 까닭을 적는다.

## 11. 시험 제작에서 «먼저 재 볼» 위험

**구현하며 잰 것 (2026-10-25, 데스크톱 Chromium 으로 폰 크기 411px 흉내 — 진짜 폰 아님)**
- 1번 ✅ 격리 `iframe`(sandbox="allow-scripts") 안에서 **한글·PDF·엑셀 모두 그려진다.** pdf.js 일꾼(worker)은 Blob 으로 띄워 돈다. 격리 칸 안에서 바깥으로 나간 요청 0건, CSP 위반 0건.
- 쪽 메모리: PDF 30쪽에서 «한 번에 그려진 캔버스 2장» — 보이는 곳에서 멀어지면 비운다. 쪽 이동·뒤로가기·최근 목록 동작 확인.
- 한글 파일 첫 열기 약 1.9초(데스크톱·로컬 서버). **폰에서의 시간은 아직 모른다.**
- 알게 된 것: ① 저장소의 엑셀 읽개(`vendor/xlsx.full.min.js`)는 **SheetJS 0.18.5** 로 알려진 보안 약점(CVE-2023-30533·CVE-2024-22363)이 있는 옛 판이다 — 격리 칸이 있어 피해가 칸 안에 갇히지만, 판을 올리는 일은 따로 해야 한다.
  ② pdf.js 한글 글꼴 지도(CMap)가 저장소에 없다 — 글꼴을 PDF 에 심지 않은 한글 PDF 는 글자가 안 나올 수 있다(대부분의 PDF 는 심는다). ③ 한글 엔진 기본값이 외부 주소(cdn.jsdelivr.net)부터 부르는 것을 막으려고 `cdnBase:''` 로 저장소 사본만 쓰게 했다(검사로 지킨다).

**아직 모르는 것(진짜 폰에서 재야 한다)**: 2번 폰에서 9.9MB wasm 첫 로딩 시간·메모리 · 3번 폰 대체 글꼴 모양 차이 · 4번 수만 줄 엑셀(지금은 앞 500줄 + 「더 보기」로 1,000줄씩) · 5번 `file_handlers` 가 설치된 PC 에서 연결 프로그램으로 뜨는지.

(아래는 설계 당시 목록이다.)

1. **격리 `iframe` 안에서 pdf.js worker 가 도는가.** 주소 없는 칸에서 같은 출처 worker 파일을 못 불러올 수 있다 → `Blob` worker 나 worker 없는 방식. 안 되면 «격리» 설계를 바꿔야 한다.
2. **rhwp 9.9MB wasm 이 폰에서** 첫 로딩 몇 초인지, 메모리가 모자라 탭이 죽는 쪽 수가 몇 쪽부터인지.
3. **폰에는 한컴 글꼴이 없다.** 엔진은 «기기에 깔린 글꼴로 대신 그린다»(`vendor/rhwp-studio/푸른-메모.md`). 안드로이드의 대체 글꼴에서 줄바꿈·쪽 수가 한글과 달라질 수 있다 —
   «원본 모양과 완전히 같다»고 약속하지 말고 화면에 «글꼴이 달라 모양이 조금 다를 수 있음» 을 적는다.
4. **큰 엑셀**(수만 줄)을 폰에서 — 앞 몇 백 줄만 그리고 «더 보기» 로 이어야 할 수 있다.
5. `file_handlers` 가 실제로 설치된 PC 에서 연결 프로그램으로 뜨는지(브라우저·윈도 판에 따라 다르다).

## 12. 범위 밖 (일부러 안 한다)

- **편집·저장.** 이음오피스와 가장 다른 점이다. PC 에서 한글을 고쳐야 하면 이미 있는 한글 편집기(`vendor/rhwp-studio`, `PureunHwp` 편집기 길)를 쓴다 — 뷰어에서 편집기로 «보내기»는 2판 이후에 따로 정한다.
- 서버 저장·클라우드 동기화·여러 사람 공유. 이 앱은 «내 폰의 파일을 내 폰에서 본다».
- 문서 안의 매크로·외부 링크 실행.

## 13. 대표님이 정해 주실 것 (1~3번은 「추천대로」로 정해졌다 — 위 머리말)

1. **PPT**: ㉮ 글·그림 근사(추천) / ㉯ 외부 그리개 검토.
2. **자리**: 포털 «자료함» 줄 타일 + 독립 설치(추천) / 독립 설치만.
3. **최근 파일**: 이름만 기억(추천, 분실 대비) / 내용까지 폰에 저장(다시 열기는 편하나 고객 자료가 폰에 남는다).
4. **아이폰**이 필요한가(공유받기가 안 되는 제약이 있다).
5. 직원 모두가 쓰는가, 대표만 쓰는가(전원이면 폰 점검을 여러 폰 글자 크기로 한다).
