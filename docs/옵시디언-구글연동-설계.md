# 구글 캘린더·시트·지메일 → 옵시디언 자동 수집 설계안 (초안 · 2026-11-01)

대표 요청: 구글 캘린더·지메일·구글 시트(직원별 업무·자문·급여·기금)를 옵시디언에 자동으로 모아 `[[사람]]`·`[[업체]]` 로 잇기.
**상태: 설계안이다. 코드는 아직 없다. 아래 «결정 필요 3가지»가 정해져야 만든다.**

## 1. 결론 (한 장 요약)
**새 길을 뚫지 않는다. 이미 푸른 시스템 안에 들어와 있는 자료를 보관함으로 «내보낸다».** 같은 자료를 구글에서 또 읽으면 두 벌이 되어 어긋난다(`CLAUDE.md` «이미 있는 것부터 찾는다»).

| 자료 | 지금 푸른 시스템에서 | 이 설계의 길 | 추천 |
|---|---|---|---|
| 구글 캘린더 | 매일 새벽 `gcal-archive` 가 공용 달력 전부를 푸른 캘린더(`data/gcal_archive`)에 베껴 둔다 · 일정에 담당자 번호(`puSid`)가 붙는다 | 푸른 캘린더 보관함을 «메일 내보내기»와 같은 방식으로 `일정/` 에 적는다 | **함** |
| 직원별 업무·자문·급여·기금 (시트) | 계약·사건·컨설팅·기금·자문은 이알피가 이미 갖고 있고, 이알피 «옵시디언 업무요약»(`raw/erp`)이 있다 | 이알피가 기준. 시트는 자동 수집하지 않고 **한 번 대조**만 한다 | **자동 안 함** |
| 메일 | 다음메일(370-6)은 `mail-sync` 로 목록이 들어오고, 기업별·사람별·담당자별 내보내기가 합쳐져 있다 | 이미 됨 | 완료 |
| 지메일 | 구글 연결 권한은 «달력 일정» 하나뿐이다(`gcal-link` SCOPE) — 메일 권한 없음 | 새 동의·새 열쇠가 필요 → 별도 결정 | **보류** |

## 2. 이미 있는 것 (재사용)
- `functions/gcal-archive.js`: 공용 달력 전부를 매일 `data/gcal_archive` 에 보관(처음 2000년부터, 그 뒤 바뀐 것만). 읽기는 공개 읽기 열쇠 하나 — 사람 로그인 불필요.
- `functions/gcal-proxy.js`·`js/pu-gcal-auth.js`: 일정에 `extendedProperties.shared.puSid`(담당자 번호), `private.puSourceKind/puSourceId`(어디서 왔는지)를 남긴다. → **담당자는 번호로 잇고 이름으로 잇지 않는다.**
- `js/pu-mail-obsidian.js`: 브라우저에서 보관함 폴더에 쓰는 길(폴더 손잡이 기억 · 주민번호 지우개가 없으면 쓰기 전에 멈춤 · 총괄관리자 전용 · 서버에 안 씀). **일정 내보내기도 이 길을 그대로 탄다.**
- `js/pu-obsidian.js`: 이알피 업무요약 → `raw/erp/`.

## 3. 갈래별 설계

### 3-1. 캘린더 → `일정/`
- **무엇을**: 날짜·시간·제목·장소·담당자(`puSid` → 이름)·연결된 업체(있을 때만). **설명 글과 참석자 이메일은 뺀다**(공용 달력은 바깥 참석자도 보고, 설명에 개인정보가 들어간 적이 있다).
- **모양**: 월별 한 장 `일정/2026-11.md`(표 한 줄 = 일정 하나) + 담당자 장 `일정/담당자/<이름>.md`(이번 달·다음 달 일정). 일정 한 건마다 파일을 만들지 않는다(2017년부터 1만 건 넘음).
- **기간**: 지난 12개월 + 앞으로 3개월(추천). 더 옛것은 푸른 캘린더 보관함에서 본다.
- **업체 연결**: `puSourceKind/puSourceId` 가 업체·건을 가리킬 때만 `[[업체]]`. **제목에 업체 이름이 있다고 잇지 않는다**(이름으로 회사 맞추기 금지). 못 잇는 일정은 «업체 미확인».
- **어디서 도나**: `pu-cal.html`(또는 이알피 설정)에 «🪨 옵시디언으로 내보내기» 한 줄 — 메일과 같은 모양.

### 3-2. 시트 → 자동 수집 안 함, 한 번 대조
- 시트(자문사 명단·급여업체 명단·노무사별 업무·기금 담당자)의 내용은 이알피의 계약·사건·컨설팅·기금과 **겹친다.** 시트를 또 자동으로 읽으면 어느 쪽이 진짜인지 모르게 된다.
- 대신 **한 번**: 시트 명단을 이알피와 견줘 «시트에만 있는 것·이알피에만 있는 것»을 목록으로 낸다(읽기 전용). 이관이 필요하면 이알피의 일괄 입력 길(`validateWorkBatch` — 전 행 먼저 검사, 실패하면 원본 유지)로만 한다.
- 알려진 불일치부터: 기금 담당자 시트 29 ↔ 담당자별 합 30.

### 3-3. 지메일 → 보류
- 지금 구글 연결에는 메일 권한이 없다. 넣으려면 ① 구글 동의 범위 확대(메일 읽기) ② 서버가 들고 있는 갱신 열쇠의 범위 확대 ③ 직원 동의 — **보안 변경**이라 따로 결정한다.
- 대상에서 **빼는 것**: GitHub 알림(저장소에 이미 있다) · 세금계산서(금액·사업자번호 = 재무 자료).
- 꼭 필요하면: **라벨 하나**(예: «위키») 붙인 메일만, **목록과 첨부 이름만**, 읽기 전용. 본문은 안 담는다.

## 4. 보관함 쪽 규칙
- 대표 `schema.md` 가 기준이다. 자동 생성 색인(`일정/` · `메일/`)은 **위키 정리 대상이 아니다** — 위키 장(`wiki/entities/…`)이 `[[일정/…]]`·`[[메일/…]]` 로 링크만 건다.
- 연결 열쇠는 `sid`(직원) · `companyId`(업체). 이름은 표시용.
- 자동 생성 파일은 다시 내보내면 덮인다(지우지는 않는다) — 손 메모는 폴더 밖에.

## 5. 안전
- 총괄관리자만 · 읽기 전용 · 서버에 쓰지 않음 · 주민번호 지우개 필수.
- **외부 AI 서비스로 이 자료를 보내지 않는다**(내보내기 파일은 PC 폴더에만). 외부 채팅에는 마스킹본(구조만)을 쓴다.
- 일정 설명·참석자 이메일·금액은 담지 않는다.
- 보관함은 개인 PC 폴더 — 공유·클라우드 동기화 폴더 금지.

## 6. 만드는 순서
1. **S1 일정 내보내기**: `js/pu-cal-obsidian.js`(메일 내보내기와 같은 골격) + 단추 + 검사(링크가 실제 파일을 가리킴 · 설명·참석자 제외 · 지우개 없으면 쓰기 전 멈춤 · 총괄관리자 전용).
2. **S2 이알피 업무요약 보강**: `raw/erp` 노트 머리말에 `sid`·`company_id` 를 넣어 위키가 이름이 아니라 번호로 잇게.
3. **S3 시트 대조 목록**(1회성, 읽기 전용).
4. **S4(선택) 지메일 라벨 한정** — 보안 결정 뒤에.
- 검증: 지어낸 자료로 단위 검사 → 대표 PC 에서 첫 실행(업체 미확인 비율 확인).

## 7. 결정이 필요한 것 (추천 포함)
1. **일정 기간**: 지난 12개월 + 앞 3개월 *(추천)* / 전체 / 직접 지정
2. **지메일**: 지금은 하지 않음 *(추천)* / 라벨 한정으로 하기
3. **시트**: 이알피와 한 번 대조만 *(추천)* / 시트를 계속 읽어 수집

## 8. 확인 못 한 것
- 일정 `puSourceKind` 가 가리키는 종류(업체·건·명함 등)의 전체 목록 — 코드에서 확인 후 «업체로 이어지는 종류»만 `[[업체]]` 로 건다.
- 시트 안의 실제 내용(구글에 접속하지 않음). 열 이름·건수는 대표 제공 요약 기준.
- 대표 PC 에서의 동작(폴더 쓰기 권한·브라우저).
