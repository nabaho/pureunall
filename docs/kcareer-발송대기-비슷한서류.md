# 경력관리 «발송 대기» — 비슷한 서류가 오면 (2026-11-05 검토)

대표 지시: 「다른 유사한 서류가 들어올 경우 어떻게 해야 하는지도 검토해라」
판정은 `js/kcareer-sendq.js` 의 `similarPolicy` 한 곳이 한다 — 아래 표와 코드는 `tests/kcareer-sendq-doc.test.js` 가 견준다.

## 한 줄 원칙
**알던 것과 «정확히 같을 때만» 채운다. 조금이라도 다르면 채우지 않고 사람에게 넘긴다. 어느 경우에도 자동으로 보내지 않는다.**
도장·주민번호가 든 서류라, 틀리게 채워 나가면 되돌릴 수 없다. 반대로 «확인 필요»로 돌리는 비용은 사람이 한 번 보는 것뿐이다.

## 갈래표

| # | 상황 | 하는 일 | 사람이 할 것 |
|---|---|---|---|
| 1 | 같은 기관 + 같은 양식 | 채워서 **발송 대기**에 올림 | 내용 보고 «✉ 답장 보내기» 한 번 |
| 2 | 같은 기관 + **양식이 바뀜** (동의 칸 수·서명 줄·날짜 줄이 다르거나 기관 이름이 다름) | 채우지 않음 → **확인 필요** | 서식 채우기에서 직접 확인 |
| 3 | 같은 기관 + **수집 항목이 늘거나** 신분증·사본·여권 같은 말이 새로 들어옴 | 채우지 않음 → **확인 필요**(경고 표시) | 개인정보 범위가 넓어졌는지 노무사 판단 |
| 4 | **다른 기관** + 같은 양식 | 채우지 않음 → **확인 필요** + «✔ 이 기관도 같은 규칙으로» | 맞으면 한 번 눌러 규칙에 더함 → 바로 채워 대기로 |
| 5 | 이미 **채워져 온** 서류 (동의 ■·서명 이름이 있음) | 다시 채우지 않음 → **확인 필요** | 그대로 쓸지 확인 |
| 6 | 알던 서류가 아닌 **전혀 다른 양식** | 채우지 않음 → **확인 필요** | 해당 서식으로 직접 작성 |
| 7 | **같은 메일의 같은 첨부**를 또 넣음 (재전송·중복 수신) | **이미 있음** — 새 줄을 만들지 않음 | 없음 |
| 8 | 관계없는 메일 | 무시 | 없음 |
| 9 | 첨부를 못 읽음 / 성명·도장이 없음 | 채우지 않음 → **확인 필요**(까닭을 적음) | 환경설정에서 성명·도장 확인 |

## 금액·날짜는 «양식 지문»에 넣지 않는다
교육일·강사비·원천세는 **매번 다르다.** 지문에 넣으면 정상 서류가 늘 확인 필요가 된다.
대신 카드에 그대로 보여 눈으로 확인하게 하고, 양식 안의 셈만 검산한다(원천세 = 강사비 × 8.8%, 실지급액 = 강사비 − 원천세).
어긋나면 **빨간 경고**를 띄우지만 막지는 않는다 — 8.8%는 «이 양식에 적힌 값»이고 세법 판단은 담당 노무사가 한다. [확인 필요]
연도도 지문에 넣지 않는다(해가 바뀌어도 같은 양식으로 읽힌다).

## 한 걸음이라도 안 되면 «반쯤 채운 서류»를 대기에 올리지 않는다
채우기 → 도장 → 파일 싸기 → 보관, 어느 한 걸음이 실패하면 전부 «확인 필요»로 돌린다(원본은 남는다).

## 규칙은 어디에 있나 (공개 저장소 주의)
- 코드의 기본 규칙(`DEFAULT_RULES`)에는 **실제 기관 이름·메일 주소를 적지 않는다.** 저장소가 공개라서다(검사가 `@` 가 없는지 본다).
- 보낸 곳은 사람이 «✔ 이 기관도 같은 규칙으로»를 눌러 더한다. 규칙은 경력관리 비공개 클라우드(`sendq_rules`)에만 남는다.
- 규칙을 잘못 더했으면 비용 서류 도구줄의 **«⚙ 발송 대기 규칙»** 에서 그 주소를 뺀다(2026-11-08).
  ☐ 로 고르고 «✕ 고른 곳 빼기», 또는 줄마다 «✕ 빼기» → 몇 곳인지 묻고 «규칙에서 빼기»를 눌러야 저장된다.
  - 뺀 곳에서 다음에 오는 서류는 채우지 않고 **확인 필요**로 올라온다(4번 줄과 같다 — «✔ 이 기관도»로 다시 더할 수 있다).
  - 규칙(양식 지문)은 지우지 않는다 — 보낸 곳이 하나도 없어도 규칙은 남는다.
  - **이미 대기·보류 중인 건은 그대로 둔다.** 묻는 쪽지에 몇 건인지 알리니, 필요하면 «✕ 치우기»로 치운다.

## 아직 안 되는 것 (숨기지 않는다)
1. **메일함이 새 메일을 알아보고 자동으로 넘기는 길은 «메일 방» 몫**이라 아직 없다. 지금은 받은 첨부를 «📥 메일에서 받은 서류 넣기»로 넣는다.
   넘겨받는 자리(`sqProcess(bytes, name, {from, subject, org, mailKey})`)는 같게 두었다 — 메일 방이 열쇠와 첨부를 주면 같은 길로 들어온다.
2. 규칙이 여럿일 때의 편집 화면(제목 낱말·첨부 이름을 고치는 화면). 보낸 곳을 보고 빼는 것은 «⚙ 발송 대기 규칙»에서 된다(2026-11-08).
3. 채운 서류의 **한글 열림**은 한컴(COM)으로 실측했다(2026-11-05, 1쪽·■·도장 위치). 브라우저 안 엔진이 만든 파일은 같은 방식으로 다시 열어 확인해야 한다. [확인 필요]
4. 답장은 «보내는 서버(sendMaterialMail)»로 나가 **원 메일의 스레드에 붙지는 않는다**(제목 «RE: …»로만 이어진다).
5. 같은 협회의 다른 서류(예: 비용지급확인서 양식)는 **다른 규칙**이다. 지문은 이 양식 하나뿐이다 — 양식이 늘면 규칙·지문을 더해야 한다.
