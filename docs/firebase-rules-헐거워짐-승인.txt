#  실시간DB 규칙 — 권한이 «넓어지는» 고침 승인
#
#  ★ 무엇인가 — scripts/rules-deploy.js 는 사라지는 규칙만이 아니라
#    «권한이 넓어지는» 고침도 막는다. 사라지는 것만 보면, 예컨대
#    `.read` 가 「관리자만」에서 「전 직원」으로 바뀌는 것이 긴 목록에
#    한 줄로 흘러간다. 사람은 긴 목록을 안 읽는다.
#
#  ★ 무엇을 «넓어짐»으로 보나 — 확실히 말할 수 있는 것만 본다.
#      · true 가 되면        (누구나)
#      · false 였다가 아니게 되면  (아무도 → 누군가)
#      · && 로 이어진 조건이 «빠지면»  (A && B 는 A 보다 좁다)
#      · 없던 칸이 `.read: true` 로 태어나면  (없던 자리는 원래 아무도 못 읽는다)
#    가릴 수 없는 것은 「판단못함」이라 적어 화면에 보이기만 하고 막지는 않는다.
#    아는 척하지 않는 것이 요점이다.
#
#  ⚠ 이것은 --force 가 아니다. 옛 몸도 새 몸도 «글자까지» 맞아야 그 «하나»만
#    지나가고, 그 뒤의 어떤 흔들림도 다시 멈춘다.
#
#  ▶ 올린 뒤에 할 일: 그 줄을 «지운다». 올리고 나면 새 몸이 기준이라,
#    남겨 두면 다음 사람이 「아직 안 올라간 고침」으로 읽는다.
#
#  적는 모양 — 머리는 규칙의 «길»이다(창고 쪽은 함수 이름이라 다르다):
#
#    [/data/companies/.read]
#    왜: (왜 넓혀도 되는지 — 다음 사람이 읽는다)
#    옛: root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true
#    새: auth != null && ...
#
#  지금 승인된 것: 없음
# ═══════════════════════════════════════════════════════════════════
