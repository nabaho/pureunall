#  창고(Storage) 규칙 — 보조 함수 «고침 승인»
#
#  ★ 무엇인가 — scripts/storage-rules-deploy.js 의 안전장치는 기준
#    (docs/firebase-storage-콘솔원문-<날짜>.txt)에 있던 보조 함수가 한 글자라도
#    달라지면 멈춘다. 그것이 맞다 — 보조 함수 한 줄이 창고 전체의 문이다.
#    다만 그 때문에 «조이는 고침»조차 할 수가 없어, 여기에 옛 몸과 새 몸을
#    그대로 적어 두면 그 «하나»만 지나간다.
#
#  ⚠ 이것은 --force 가 아니다. 옛 몸도 새 몸도 글자까지 맞아야 지나가므로,
#    승인한 그 고침 말고는 어떤 흔들림도 다시 멈춘다.
#
#  ▶ 올린 뒤에 할 일: 콘솔 원문을 새 날짜 파일로 남기고 «이 승인 줄을 지운다».
#    그때부터는 새 몸이 기준이라, 남겨 두면 다음 사람이 헷갈린다.
# ═══════════════════════════════════════════════════════════════════

[isStaff]
왜: 2026-10-14 사무실 보안 검토 — 도메인만 보면 누구나 아무개@pureun.kr 로 «가입»해 지나간다(메일 인증 안 봄). 서버가 uid_roles 재직자에게만 새기는 staff 표시를 함께 본다. 조이는 쪽.
옛: return request.auth != null && request.auth.token.email != null && request.auth.token.email.matches('^[^@]+@pureun[.]kr$');
새: return request.auth != null && request.auth.token.staff == true && request.auth.token.email != null && request.auth.token.email.matches('^[^@]+@pureun[.]kr$');
