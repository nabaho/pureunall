# 클라우드 방에서 배포하기 — GitHub «Firebase 배포» 작업 (2026-10-31)

대표 지시: 「니가 직접 하면 안되나 아니면 한번에 하게 가능하게 하던가」
— 대표 PC 가 아닌 곳(클라우드 방의 Claude, 폰으로 연 방)에서도 **규칙 게시 · 서버 함수 배포 · 매일 정리 스위치**를 한 번에 한다.

작업 파일: `.github/workflows/firebase-deploy.yml` · 함수 이름 거르개: `scripts/firebase-deploy-check.js`

## 1. 한 번만 — 배포 열쇠 넣기 (대표님)

열쇠는 **GitHub 비밀 칸에만** 둔다. 저장소는 공개라 파일로 올리면 안 된다. 채팅·메일에도 붙이지 않는다.

### 권장 — 서비스 계정 열쇠 (푸른 프로젝트 하나에만 닿는다)
1. Firebase 콘솔 › ⚙ 프로젝트 설정 › **서비스 계정** › 「새 비공개 키 생성」 → JSON 파일이 내려받아진다.
2. Google Cloud 콘솔 › IAM 에서 그 계정(`firebase-adminsdk-…@pureun-erp.iam.gserviceaccount.com`)에 역할을 더한다:
   **Cloud Functions 관리자 · 서비스 계정 사용자 · Secret Manager 보안 비밀 접근자**.
   [확인 필요] 첫 함수 배포에서 «권한이 모자라다»고 나오면 그 말에 적힌 역할(예: Artifact Registry 작성자·Cloud Build 편집자)을 더한다.
   규칙 게시와 스위치는 Firebase 관리자 계정이라 위 역할 없이도 된다.
3. GitHub › `nabaho/pureunall` › Settings › Secrets and variables › **Actions** › New repository secret
   — 이름 `FIREBASE_SERVICE_ACCOUNT`, 값은 JSON 파일 내용 **전체**.
   (대표 PC 의 Claude 에게 「`gh secret set FIREBASE_SERVICE_ACCOUNT --repo nabaho/pureunall < 키파일` 로 넣고 키 파일을 지워 줘」라고 해도 된다.)
4. 내려받은 JSON 파일은 지운다.

### 대안 — `firebase login:ci` 토큰 (덜 권장)
대표 PC 에서 `firebase login:ci` → 나온 토큰을 비밀 `FIREBASE_TOKEN` 으로(`gh secret set FIREBASE_TOKEN --repo nabaho/pureunall`).
⚠ 대표 구글 계정의 권한이 통째로 실린 열쇠라 서비스 계정보다 넓다. 파이어베이스도 이 방식을 «곧 없앨 것»으로 표시해 두었다.

### 선택 — 올리기 전에 대표 승인 받기
Settings › Environments › `firebase-prod` › **Required reviewers** 에 대표를 넣으면, Claude 가 불러도 대표가 GitHub 에서 「Approve」를 눌러야 올라간다.
비워 두면 Claude 가 부르는 즉시 올라간다(대표 지시 「니가 직접」).

## 2. 부르는 법

- **Claude(클라우드 방)**: GitHub 작업 실행 — 작업 `firebase-deploy.yml`, 가지 `main`, 입력
  `rules`(true/false) · `functions`(쉼표로 이름, 예 `collectRulesMail,collectRulesMailAsk`) · `daily_mode`(비움·dry·live·off).
- **사람**: GitHub › Actions › 「Firebase 배포」 › Run workflow — 같은 세 칸.

## 3. 지키는 것
- 수동 실행만, main 에서만 — push·PR 로는 안 돈다. 남이 연 PR 은 비밀을 못 본다.
- 규칙은 **`scripts/rules-deploy.js --deploy` 로만** — 살아 있는 콘솔과 견줘 사라질 규칙이나 승인 없는 헐거워짐이 있으면 **멈춘다**(종료코드 2·3·4). 우회 깃발 없음.
- 함수는 **이름을 찍어서만**, `functions/index.js` 에 실제로 있는 이름만, 한 번에 10개까지(전체 배포는 할당량에 걸린다).
- 스위치는 `rules_mgmt/library/auto/cfg` 한 칸에 `{mode, by:'github-actions', at}` 만 쓴다.
- 열쇠 파일은 작업 끝에 지운다. 입력은 env 로만 넘긴다(입력 글이 셸 명령이 되지 않게).

## 4. 올린 뒤 (Claude 가 이어서 한다)
규칙을 올렸으면 `rules-deploy.js` 가 작업 안에서 «새 기준»(`docs/firebase-rules-콘솔원문-YYYY-MM-DD.json` — 만들개 출력과 같다)을 남기지만,
작업 칸은 저장소에 안 쓴다. 그래서 Claude 가 같은 내용으로 **뒷정리 PR**(새 기준 파일 + `tests/photos-staff-share.test.js` 의 PENDING 비우기)을 만든다.
