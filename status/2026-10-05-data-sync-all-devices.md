# 2026-10-05 · 이알피: 기기마다 갈라지던 자료 넷을 «모든 PC 가 같게» (fix/data-sync-all-devices)

대표 지시: 「다른모든 프로그램에서도 데이터가 분리되지 않게 처리해라」 — 크롬↔엣지, PC↔PC 가 다른 것을 보면 안 된다.

## 한 것 (pu-erp.html)
1. **레코드 그림(명함·사업자등록증·직인)** — 이 PC 의 IndexedDB 에만 두고 `idb:img_…` 참조만 서버로 보내던 것.
   - 참조를 만들 때 창고 `pureun-erp-hrphotos` 의 `erp_img/{id}` 에도 올린다(자리는 id 로 계산 — 옛 참조도 그대로 풀린다).
   - 보통 정리(저장 직후 자동·정리 단추·접속 정리)는 **창고에 올라간 뒤에만** 참조로 바꾼다. 못 올리면 그림을 레코드에 그대로 둔다(예전처럼 레코드와 함께 동기화).
   - 예외는 저장공간 초과로 **저장이 실패한 비상 정리 한 곳** — 먼저 참조로 바꾸고 뒤에서 다시 올린다.
   - `AsyncImg`/`ImgStore.load` — 이 PC 에 없으면 창고에서 받아 온다. 이 PC 에 있는데 창고에 없으면(옛 참조) 보이는 순간·접속할 때 올린다(`erpImgCloudSweep`).
   - 이알피는 창고 꾸러미를 기본으로 안 싣는다 — 필요한 순간에만 싣는다(`erpImgStorage`).
2. **사건 업무 메모** — `localStorage` 에 바로 쓰던 것을 동기화 표 `case_memos`(건별 저장 표·굳은 명단)로. 옛 메모는 접속 때 한 번 합친다(같은 id 가 표에 있으면 표가 이긴다 · 저장된 뒤에만 옛 열쇠를 지운다).
3. **홈택스 세금계산서 아카이브** — 판단: **동기화해야 한다**(발행관리 회색 줄·입금 매칭 색인이 읽는다 — PC 마다 다르면 같은 입금을 다르게 맞춘다).
   실시간DB 뿌리 `invoice_arc`(재무 권한자만, data 밑 아님). 담은 뒤 올리고(`erpInvArcPush`), 읽기 전에 «지난번 이후 줄만» 받는다(`erpInvArcPull`). 업체별 집계는 올리지 않고 줄로부터 다시 센다. 「전체 삭제」는 모든 PC 에서 지운다(세대 번호).
4. **못 보낸 변경** — 메모리에만 있던 `_fbPendingOps` 를 localStorage(사람마다 따로)에도 적고, 접속해 서버 값을 받기 «전»에 되읽는다.
   ★ 연결이 끊긴 채 보내면 실시간DB 는 «실패하지 않고 기다린다» — 그래서 dbSet 이 보내기 시작한 저장도 «보내는 중»으로 적고(`_fbWalOpen`), 서버가 받았다고 답하면 지운다.

## 규칙 (올렸다)
- 실시간DB: `data/case_memos`(재직 직원 — 사건 기록과 같게) · `invoice_arc`(재직 중인 재무 권한자, `h` 의 `t` 색인). 살아 있는 콘솔과 견줘 «새로 생기는 2개 · 사라지는 0개» 확인 후 배포. 새 기준 `docs/firebase-rules-콘솔원문-2026-10-05.json`.
- 창고: `erp_img/{imgId}` — 직원(@pureun.kr) 읽기 · 새로 쓰기만(고치기·지우기 없음) · 그림만 10MB. 창고 3곳 배포.
  - **새로 보이게 된 것**: 업체·계약·사건 레코드의 그림이 «직원 전체»에게 보인다 — 그 레코드를 보는 범위(재직 직원 전원)와 같다.
  - ⚠ 창고 기준은 2026-10-03 사본이다(창고 규칙은 CLI 로 못 읽는다).

## 배포 뒤 PC 마다 할 일
- **없다** — 새로고침만 하면 된다. 다만 옛 그림·옛 메모·옛 홈택스 줄은 «그것을 가진 PC» 가 한 번 접속해야 올라간다.
