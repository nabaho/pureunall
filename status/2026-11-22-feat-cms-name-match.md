# 자동 처리 «처음 보는 회원» 후보 — 사업자번호 먼저 · 이름은 표기 차이를 걷고 견준다 (대표 2026-11-22 「비슷한 이름을 제대로 비교해 일치」)

## 무엇이 문제였나
재무관리 › 자동 처리의 «확인할 것 141건» 중 131건이 «처음 보는 회원»이었고 대부분 「후보 없음」이었다. 업체는 ERP 에 있는데도.
읽기만으로 대조해 보니(서버·화면은 건드리지 않음):
- 131건은 **회원 26명이 달마다 되풀이된 것**이었다 — 실제로 맞출 곳은 26곳.
- 줄에는 사업자번호가 있는데(회원 17명) 이 화면은 **번호를 후보 찾기에 안 넘기고 이름만** 견줬다.
- 업체 이름의 괄호 설명(`○○(구 △△)`)·옛 상호(`옛이름→새이름`) 때문에 이름 «전체»를 견주면 한 글자도 안 맞았다.
- 같은 이름의 **종료** 업체가 따로 있으면 «종료 업체»로 안내했다 — 번호는 활성 업체를 가리키는데도(3곳).

## 고친 것 (`pu-erp.html`)
- `erpCmsAutoCandidate(ix, name, bizNo, amount)` — ① 번호(활성→종료) ② 이름 꼭 같음·예전 이름·별칭 ③ **비슷한 이름**(활성만, 한 곳일 때만). 충돌(번호와 이름이 다른 업체를 가리킴)은 알린다.
- 이름 열쇠 `erpCmsNameKeys` — 지금 이름·괄호 설명·예전 이름으로 가르고, 같음/예전 이름/일부 같음(4글자↑)/한 글자 다름(4글자↑)으로 견준다.
- 줄의 안내 글에 «무엇을 보고 찾았는지»(사업자번호가 같음 · 월 금액도 같음 …)를 적는다. 닮은 곳이 여럿이면 이름들을, 닮은 종료 업체는 이름만 알려 준다.
- 「한꺼번에 잇기」 — 번호가 같은 활성 업체이고 충돌이 없는 회원만, 한 번 묻고 **잇기만** 한다. 다시 읽기는 미리보기(`write:false`)로만(자동 확정을 한꺼번에 터뜨리지 않는다).
- 그대로 둔 것: 후보는 제안일 뿐 잇는 것은 사람 · 종료 업체는 이름·번호가 꼭 같을 때만 · 종료 업체에는 회원코드를 잇지 않음 · 자동 판정(`PuCmsAuto.judgeRows`)은 회원코드로만 업체를 찾음.
- 문서 `docs/규칙/더빌-회원-업체-잇기.md`.

## 막아 둔 것 (자동 검토 세 번을 거치며 정리)
- **모호하면 고르지 않는다** — 같은 사업자번호·같은 이름·같은 예전 상호를 쓰는 활성 업체가 여럿이면 하나를 고르지 않고 이름만 알린다(색인은 첫 업체만 들고 있으므로 따로 센다).
- **충돌은 알린다** — 번호가 가리키는 업체와 이름이 가리키는 다른 활성 업체가 있으면(법인 표기·괄호 설명이 붙은 이름·예전 상호 포함) 표시하고 한꺼번에 잇기에서 뺀다. 판정은 현재·예전 상호만 보고 흔한 괄호 설명은 안 본다.
- **다른 곳을 오타로 제안하지 않는다** — 숫자가 다르거나(1공장·2공장) 같은 꼬리(점·공장·지점…) 앞이 다르면(아산점·예산점) 한 글자 다름에서 뺀다. 번호가 서로 다르면 이름이 닮아도 다른 업체.
- **약한 후보로 이어도 입금표시를 바로 만들지 않는다** — 이름만 닮았거나 충돌이 있는 후보는 이은 뒤 미리보기로만 다시 읽는다.
- **누르는 «지금» 다시 고른다** — 한꺼번에 잇기와 한 줄 잇기 모두 그 순간의 업체 목록으로 후보를 다시 구해, 처음 보여 준 업체와 같을 때만 잇는다. 한꺼번에 잇기는 종료된 업체·다른 업체에 이어진 코드도 건너뛴다.
- 이름 열쇠: 구분 글자가 있을 때만 「구」·「전」을 예전 이름 표지로 보고(「구로지점」을 안 자름), 괄호 안의 「(주)」도 먼저 걷고, 후보 캐시는 이름을 그대로 키로 쓴다.
- 안 한 것: 768px 에서 표의 «할 일» 열이 가로 스크롤로 밀리는 것(이 화면의 기존 반응형 구간 — `js/pu-fin-phone.js` 는 640px 이하만 카드로 바꾼다) · 탭 단추의 `role=tab`.
- **마지막 두 가지**(같은 예전 상호 여럿 · 한 줄 잇기 직전 다시 구하기)는 자동 검토 재검증 한도(2회)를 채워 **재검증하지 못했다** — 검사 2개 + 막는 코드를 망가뜨려 보는 확인 4곳으로만 확인했다.
