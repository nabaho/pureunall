# 2026-09-20 · TypeSafe(Jev) 검토 — 「관리자만 일단쓴다」

대표 지시: 「관리자만 일단쓴다. 1,2는 다시 질문한다.」
(사용범위 판단 셋 가운데 ③ 만 정해짐 — ① 이름·업체명 가림 ② 국외보관 수용은 아직 대기)

## 무엇을

**화면**(`js/pu-typesafe.js`)과 **서버**(`functions/index.js`) 양쪽에 관리자 확인을 넣었다.
어느 한쪽만 막으면 뜻이 없다 — 화면만 막으면 개발자 도구로 직접 불러 우회하고,
서버만 막으면 관리자 아닌 사람이 눌러 본 뒤에야 거절당한다(글은 안 나가지만 헛손질이다).

- **서버**: 로그인 확인(`requireReader`) 다음, **무엇보다 먼저** `uid_roles/{uid}` 를 봐서
  `isAdmin`·`isSubAdmin` 이 아니면 403(`why:'adminOnly'`)으로 끊는다. 열쇠 유무·하루 문
  확인보다도 앞에 둔다 — 관리자가 아닌 사람에게는 서버 금고 상태조차 알려 줄 까닭이 없다.
  ⚠ 못 읽으면 «막는다»(권한 확인은 fail-closed) — 하루 문(`typeSafeDayLeft`)이 못 읽으면
  «연다»(fail-open)와 정반대다. 하루 문은 못 읽어도 사고가 안 나지만(한도가 잠깐 없어질
  뿐), 관리자 확인을 못 읽고 열어 두면 권한 없는 사람에게 권한을 준 것과 같다.
- **화면**: `js/pu-typesafe.js` 가 `isLoggedIn() && isAdmin()` 을 함께 봐야 단추를 보인다.
  이알피는 이미 아는 `CURRENT_USER.isAdmin || CURRENT_USER.isSubAdmin` 을
  `window.PU_TYPESAFE_IS_ADMIN` 에 채워 넣어 준다(로그인 판정을 넘기던 것과 같은 자리).
  다른 화면이 이 부품을 붙이면서 그 이름을 안 채우면, 부품이 스스로 `uid_roles/{uid}` 를
  읽어 알아낸다(`js/pu-backup.js` 가 관리자 단추를 보일 때 쓰는 것과 같은 자리·같은 뜻).
  ⚠ 이것도 fail-closed — 아직 모를 때(서버 왕복 전, 또는 못 읽었을 때)는 안 보여 준다.

기준은 이 저장소의 다른 관리자 전용 기능과 «같은 기준»이다 —
`CURRENT_USER.isAdmin || CURRENT_USER.isSubAdmin` (부관리자 포함).
