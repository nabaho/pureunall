상태: 완료(코드) · 검사 통과 · 배포 뒤 실제 화면 확인 대기
# 2026-11-16 · P박스 수파베이스 연결 고침 — 「연결 안 됨」을 성공으로 처리하지 않기 · 직접 연결 머리글 정정

가지: `claude/supabase-1f3c5c` (`js/pu-pbox-store.js` · `js/pu-pbox-app.js` · `functions/pbox-sync.js` · `pu-pbox.html` · `tests/pbox.test.js`)
대표 지시: 「고치기」 — 앞 점검(PR #3134)에서 나온 «연결 오표시 · 머리글» 두 가지.

## 한 것

- **서버**(`functions/pbox-sync.js`): 수파베이스 연결 값(`SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`)이 없으면 공유(push)·삭제(delete) 응답에 `configured:false` 를 싣는다.
  «보낼 문서가 없음»과 «연결 안 됨»이 같은 `skipped:true` 로 보이던 것을 가른다(당겨오기 `pull` 응답에 이미 있던 표시와 같게).
- **화면 저장 모듈**(`js/pu-pbox-store.js`):
  - 공유 요청에 서버가 `configured:false` 로 답하면 공유 성공으로 치지 않고 `sharedToOffice=false` 로 되돌린 뒤 «사무실 공유 DB가 아직 연결되어 있지 않아 이 기기에만 저장되었습니다.»로 한 번 알린다.
  - 브라우저 직접 연결의 요청 머리글을 수파베이스 공식 규칙대로 바로잡았다 — `apikey` 에는 프로젝트 **공개 키**, 직원 증표(JWT)는 `Authorization` 에만(전에는 `apikey` 에도 직원 증표를 넣었다).
  - 공개 키는 `sb_publishable_…` 또는 옛 `anon` 만 받는다. 서버용 비밀 키(`sb_secret_…` · `service_role`)는 연결 시험에서 막고, 설정에 저장하지도 않는다.
  - 공개 키가 없으면 «공유DB 연결됨» 표시(`supabaseConnected`)와 직접 당겨오기를 켜지 않는다.
- **화면**(`js/pu-pbox-app.js`): 설정 창에 «Supabase 공개 키» 칸을 더했다(저장·연결 시험에 함께 쓴다).
- **자동 검토 반영**(안티그래비티 기능 검증 통과 · 코덱스 보안 중간 2건):
  - 직원 JWT 칸에도 서버용 비밀 키(`sb_secret_…` · `service_role`)를 받지 않는다 — 연결 시험에서 막고 메모리에도 저장하지 않는다.
  - 공유했던 문서를 지우는데 서버에 공유 DB 연결이 없으면 «공유 서버의 문서는 삭제되지 않았습니다»로 알린다(공유한 적 없는 문서는 조용히 정상 처리).
  - 연결 시험 단추를 누르는 동안 다시 누르지 못하게 했다.
  - 재검증에서 나온 «길게 늘여 비밀 키 검사를 피해 가는 길»을 막았다 — 비밀 키 판별을 길이 제한보다 먼저 하고, 열쇠·증표는 8192자를 넘으면 어느 칸에서도 받지 않는다(경계 8192자/8193자 검사 포함).
  - ⚠ 마지막 8192자 상한 수정은 자동 검토 재검증 한도(2회)를 다 써서 **작업자 검증을 거치지 않았다**(P박스 검사 14개·저장소 전체 검사·고침을 되돌려 실패하는지 확인까지만). 합치기 전 사람이 보고 판단한다 — 그래서 제목에 `[보류]`.
- **캐시 번호**(`pu-pbox.html`): `store.js ?v=19` · `app.js ?v=20`.
- **검사**(`tests/pbox.test.js` ⑬): 머리글 위치 · 비밀 키 차단 · 공개 키 없을 때 미연결 표시 · 서버 `configured:false`(보낼 게 없을 때는 아님) · 연결 없는 공유 요청이 «이 기기에만 저장»으로 알려지는지. 고침을 되돌리면 새 검사가 실패하는 것도 확인했다.

## 무엇을 막았나

- 서버용 비밀 키가 브라우저 설정 창(공개 키 칸·직원 JWT 칸 모두)에 들어가 저장되는 길을 막았다.
- 연결 값이 없는 서버가 공유 «성공»으로 오해되게 답하는 것을 막았다.

## 안 한 것 · 남는 것

- 수파베이스 연결 자체는 켜지 않았다(서버 함수에 주소·열쇠를 넣는 일은 대표 지시와 수파베이스 대시보드 확인 뒤).
- 직접 연결은 여전히 수파베이스 쪽 직원 증표(`app_metadata.staff` + 재직 명부)가 있어야 열린다 — 파이어베이스 증표만으로는 열리지 않는다. 실제 길은 서버 중계다.
- 서버 함수 주석(`functions/index.js`)의 «실시간DB에 아무것도 쓰지 않는다»는 요청 간격 확인 때문에 사실과 조금 다르다 — 주석만의 문제라 이번엔 손대지 않았다.
- 무료 요금제 한계(용량·7일 무활동 정지·백업)는 코드로 못 막는다 — 공유 문서를 두려면 Pro·백업을 먼저.
- 다른 폴더(`E:\pu-wt-pbox`, `feat/pbox-connected-laws-search-ux`)의 진행 중 변경은 `functions/pbox-sync.js` 의 SSR 수집 구간이라 이번 고침과 줄이 겹치지 않는다.
