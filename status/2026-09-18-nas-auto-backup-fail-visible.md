# 2026-09-18 · 나스 자동 백업이 «조용히» 실패하던 것 — 화면은 초록으로 「활성화됨」만 말했다

가지 `claude/login-start-screen-386qu2`

## 무엇이 있었나

대표님이 나스를 막 연결하시고 「다음 뭐해야되나 나스」라고 물으셨다. 다음 할 일을 짚다가
자동 백업 코드에서 이것을 봤다 —

```js
.catch(function(){ /* 자동 백업 실패는 조용히 무시 … — ⚠ 남은 일: 실패를 설정 화면 기록에라도 남길 것 */ })
```

7일 자동 백업은 **아무도 안 볼 때** 돈다. 그 실패를 통째로 삼키고 있었다.
그 사이 설정 화면은 초록 띠로 「주 1회 자동 백업 활성화됨」이라고만 말한다.
**한 장도 안 올라갔어도 사람은 백업이 있는 줄 안다.**
백업은 «없는 것»보다 **«없는 줄 모르는 것»**이 나쁘다 — 정작 필요할 때 없다.

하나 더: 실패하면 성공 시각을 안 남기므로 **앱을 열 때마다** 저장소 4MB 를 풀어 글자로 만들고
나스에 붙어 보고 또 실패했다. 사무실 밖에서는 그것이 «늘»이다(화면이 그때마다 몇 백 ms 멈춘다).

## 고친 것

| | 전 | 후 |
|---|---|---|
| 실패 | `catch(){}` 가 삼킴 | `nasAutoNote(false, 까닭)` 로 남김 |
| 되풀이 | 앱 열 때마다 4MB 풀고 재시도 | 실패 뒤 **하루** 쉼 (`NAS_AUTO_RETRY_MS`) |
| 설정 화면 | 언제나 초록 「활성화됨」 | 실패면 **빨강** + 까닭 + 「마지막 성공은 언제」 |
| 까닭 | — | 사람 말로 (`Failed to fetch` → 「사무실 밖이거나, 인증서를 안 믿거나, CORS 가 빠졌습니다」) |
| 「지금 초기화」 | 성공 열쇠만 지움 | 물러서기 기록도 함께 품 (안 그러면 눌러도 하루를 쉰다) |

새 도우미는 `nasInfoLine` 뒤 한자리에 모았다 —
`NAS_AUTO_KEY` · `NAS_AUTO_TRY_KEY` · `NAS_AUTO_RETRY_MS` · `nasAutoWhy` · `nasAutoNote` ·
`nasAutoLastTry` · `nasAutoClear`.

## 덧 (같은 날 저녁) · 「닿지 못했습니다」가 네 가지를 늘어놓고 고르라고 했다

대표 화면 둘째 장 — 인증서를 받으신 «뒤에도» 연결 테스트가 실패했고,
실행 로그에 **똑같은 넷이 두 번** 찍혀 있었다(5:55:54 · 5:55:59):
①인증서 ②CORS ③사무실 밖 ④수동 백업. ①을 이미 하신 분께 같은 넷을 또 보이는 것은 안내가 아니다.

까닭: 브라우저의 `fetch` 는 **인증서를 안 믿어도, CORS 가 막아도, 사무실 밖이어도
똑같이 `Failed to fetch`** 다. 우리 코드가 아무것도 모르니 사람에게 떠넘겼다.

**가르는 길 — 표시 둘을 함께 본다**

| 두드린 결과 | 뜻 | 화면이 하는 말 |
|---|---|---|
| `no-cors` 응답이 **온다**(opaque) | TLS·서버 다 멀쩡 | **CORS 하나**다 — DSM 헤더 두 줄을 넣으세요 |
| **빨리** 튕긴다(3초 안) | 서버는 «거기 있다» | 인증서 or 크롬 사설망 차단 |
| **오래** 기다리다 끊긴다 | 응답 자체가 없다 | 사무실 밖 or NAS 꺼짐 |

`no-cors` 응답은 읽을 수 없다(opaque). **읽을 필요가 없다 — «왔다»는 사실만 쓴다.**

**하나 더 — 헤더가 «두 줄»이다.** 크롬은 «공개 사이트(github.io) → 사설망(192.168.x)» 요청을
CORS 와 **따로** 막는다(PNA). 첫 줄만 넣으면 헤더를 넣고도 그대로 막혀
「시킨 대로 했는데 안 된다」가 된다.

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Private-Network: true
```
