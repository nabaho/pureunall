# 2026-09-19 · 「다시 올려달라」 — 이미 있는 열쇠 값을 «버리고» null 을 돌려주고 있었다

가지 `claude/login-start-screen-386qu2`

## 무엇이 있었나

처음 `--deploy` 했을 때는 열쇠를 새로 만들어 클립보드에 완성 스크립트(URL·NAS_KEY 다 채운 것)를
담아 줬다. 대표님이 나스 화면을 만지시다(다른 걸 복사하시면서) 클립보드가 덮이자
「붙여넣을거 다시 올려달라」며 같은 명령을 다시 돌리셨는데, **이번엔 아무것도 안 담겼다.**

## 까닭

`열쇠준비()` 는 열쇠가 있는지 확인하려고 `firebase functions:secrets:access` 로
**진짜 값을 이미 받아 왔다.** 그런데 「있다」로 판정되면 그 값을 그대로 버리고 —

```js
if (있나) {
  말('② 열쇠 ✓  이미 서버에 있습니다 — 다시 만들지 않습니다.');
  return null;   // ← 손에 쥔 값을 버린다
}
```

**`null`을 돌려줬다.** 뒤이어 나스 스크립트를 완성해 클립보드에 담는 대목은
`if (열쇠 && 열쇠 !== '(올릴 때 만듭니다)')` 로 갈리는데, `null` 이 오면
「열쇠가 이미 서버에 있어 여기서는 모릅니다」라는 **거짓말**을 했다 —
사실은 몇 줄 전에 이미 그 값을 손에 쥐고 있었다.

## 고친 것

```js
기존값 = (out && out.trim()) ? out.trim() : null;
if (기존값) {
  말('② 열쇠 ✓  이미 서버에 있습니다 — 다시 만들지 않습니다.');
  return 기존값;   // 이미 읽은 값을 그대로 재사용한다
}
```

새로 만드는 것도, 서버에 다시 쓰는 것도 아니다 — **존재를 확인하며 이미 읽은 값을
버리지 않고 재사용할 뿐**이라 위험이 없다. 이제 몇 번을 다시 돌려도(열쇠가 새로 생기든
이미 있든) 매번 나스에 붙여넣을 완성본을 클립보드에 담아 준다.
