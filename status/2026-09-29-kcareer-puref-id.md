# 경력관리 ↔ 이알피 연결을 영구 번호로 (온톨로지 검토)

- 대표 질문 2026-09-29 「이알피 번호와 경력관리 ID 가 다르다 — 어떻게 일치시키나」 → 검토 후 「추천대로 모두 다」.
- 결론: 번호를 «같게» 만들지 않는다. CS0034 는 사람별 «경력 실적», 산재등-2026-901 는 이알피 «사건»이라 다른 게 맞다. 잇는 것은 영구 id.
- ① 연결 열쇠 `puRef` 가 `cases/3`(이알피 목록의 «몇 번째 줄») → `cases#<id>`. 옛 열쇠는 동기화 때 그 줄이 아직 같은 업체·같은 내용일 때만 옮기고, 아니면 `puRefCheck`(확인 필요)로 표시해 상태 자동 갱신을 멈춘다. 자동으로 다른 건에 붙이지 않는다.
  - id 없는 옛 이알피 레코드만 줄 번호 열쇠 + `puRefWeak`, 상태 갱신은 업체가 같을 때만.
  - 새 칸: `sourceKind`·`sourceId`(온톨로지 정식), `sourceNo`(관리번호 — 이름표라 이알피를 따라 고침).
- ② 「업체+연도가 같으면 자동 연결」을 없앴다 → 동기화 미리보기의 «연결 제안»에서 사람이 고른다(보류/새로 추가/이 실적에 연결). 하루 한 번 자동 동기화는 제안을 건너뛰고 알림만.
- ③ 새 번호는 비어 있는 가장 작은 번호가 아니라 «목록+휴지통의 가장 큰 번호 다음»(kcNextNo). 첨부 원본을 레코드 번호로 찾아서, 번호를 다시 주면 옛 건 원본이 새 건에 붙어 보였다. 휴지통이 30일 뒤 비워지면 그 번호는 다시 나올 수 있다(그땐 원본도 지워진 뒤).
- ⑤ 온톨로지 사전에 `CareerRecord:'경력 실적'`, `derivedFrom` 에 CareerRecord → Case|Project|Organization.
- ④ 화면(이알피 관리번호를 앞에, CS 번호는 작게, 확인 필요 표시)은 목업 보고 결정 대기.
- 검사: tests/kcareer-puref-id.test.js(되돌려 6개 우는 것 확인) · kcareer-pusync · kcareer-advisory · kcareer-paste-in · kcareer-html.
- ⚠ 실제 자료로는 아직 안 돌렸다 — 첫 동기화 미리보기에서 «옛 연결 N건 옮김 / 어긋난 N건»이 뜬다. 어긋난 건수가 많으면 그 목록부터 볼 것.
