# 지역뉴스 동시 승인 저장 보완

## 원인과 변경

- 이전 후보 선점은 같은 후보의 중복 승인만 막았다. 서로 다른 후보를 승인할 때 회차 전체 목록을 덮어써 기사 유실 가능성이 있었다.
- 일반 회차저장에서 지역뉴스 쓰기를 제거했다. 본문 수정으로 타인의 지역뉴스나 철회 상태를 덮어쓰지 않는다.
- 후보 승인과 회차 등록은 공통 부모 `newsletter`에서 한 트랜잭션으로 처리한다. 서버 최신 회차에 한 건만 추가하며 후보도 함께 승인된다.
- 수동 등록은 회차 트랜잭션으로 추가하고 Firebase push 키로 ID 충돌을 막는다. 이미 발송된 회차에는 추가하지 않는다.
- 승인 복구는 후보와 회차를 동일한 서버 스냅샷에서 확인한다.
- 종전 10분 경과 자동 잠금 해제는 제거했다. 옛 탭의 지연 저장이 남았는지 시간만으로 판별할 수 없기 때문이다. 회차 저장이 확인된 기존 승인만 완료로 복구하며 미확인 후보는 보존한다.

## 검증과 적용 범위

- 두 후보 동시 승인 재시도, 동일 후보 중복, 철회 후 추가, 발송 회차 차단, 실패 시 원본 불변 시험 통과.
- 지역뉴스 관련 31개 통과. 전체 회귀시험 및 배포 결과는 PR 기록 참조.
- 첫 CI 실행에서 날짜가 2026-09-13으로 바뀌자 계약종료·중소기업 확인서 검사 3개가 깨졌다. 운영 계산은 맞았고 검사 실행창의 `new Date()`만 실제 오늘을 보던 문제여서, 두 검사 모두 고정 기준시각을 쓰게 보완했다.
- 이번 변경은 지역뉴스 저장에 한정한다. 일반 본문 상호 편집, 이미 예약된 발송 사본의 철회 반영까지 보장하는 변경은 아니다.
- 새 코드 적용을 위해 기존에 열어 둔 뉴스레터 탭은 새로고침해야 한다. 옛 탭 쓰기를 서버 규칙으로 차단하는 이관은 이번 범위에 포함하지 않는다.
- 승인 트랜잭션은 뉴스레터 하위 데이터를 읽는다. 자료 규모가 커지면 서버 측 전용 승인 경로로 옮기는 것을 검토한다.
