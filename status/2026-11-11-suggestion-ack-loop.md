# 2026-11-11 · 건의함 «최종 확정» — 완료와 확정을 가르고 건의자 확인까지 챙긴다

대표 지시: 「오늘 들어온 건의함 체크하고 최종수정하고 담당자에게 최종확정되었는지 확인 답변까지 받게 시스템 개선해달라」

## 오늘 들어온 건 점검
- 오늘(11-11) 접수 1건 — 거래내역 확정 이력에서 되돌린 입금이 입금 리스트에 남음. 자동감시가 접수 답(ing)과 수정 PR #3005(`[보류]`)를 이미 올렸다.
- PR #3005 검토: 입금 리스트·종류별 입금 탭에 `erpIncomeLive` 거르개 3줄 + 새 검사. 성과 쪽은 `erpPerfCounts` 가 이미 되돌린 입금을 빼고 있어 진단이 맞다. 합치는 것은 대표 결정(`[보류]`). 실제 화면 확인은 못 했다.

## 빈틈
`done` 은 «우리가 고쳤다» 일 뿐인데 («확정» = 건의자가 ☑ 해결됐어요) 그 답이 대표 목록에 안 보였고, 답이 없어도 아무도 다시 묻지 않았다.
실제로 8월 13일에 완료한 건 하나가 90일 가까이 답 없이 «완료» 로 남아 있었다(`scan` 으로 확인).

## 한 것
- `scripts/suggestion-watch.js`: `ack`(완료 건을 확정·미해결 회신·확인 대기로 가름, 읽기만) · `scan`(미처리 + 확인 상태를 한 번에). 확인 칸이 없던 때 마감된 예전 15건은 «예전 건» 으로 따로 세고 재촉하지 않는다.
- `enter.html` 대표 건의함: 완료한 건에 ✅ 건의자 확인 · 🙅 미해결 회신 · ⏳ 확인 대기 표시, 대기가 있으면 「⏳ 확인 대기 N」 칩, 상세에 «확인을 기다리는 중». 관리자만·한 번에 60건까지·읽기만, 실패해도 목록은 그대로.
- 감시 예약 작업 지시문(저장소 밖)에 C 절 추가 — 새 확정은 한 줄 알림, 완료 뒤 3일 넘게 답이 없으면 한 번만 대표에게 알림. 접수·완료 답 끝에 «건의자가 할 일(☑ 해결됐어요 → 완료)» 를 늘 적게 했다.
- 지시문 **원본을 저장소에 둠** `docs/규칙/건의함-감시-지시문.md` — 11-07 재설치로 지시문이 사라졌던 일의 재발 방지.
- 규칙 문서·CLAUDE.md·AGENTS.md 에 «완료 ≠ 확정» 한 줄씩.

## 외부 검토(Antigravity 기능 검증 · Antigravity 보안, 1차) → 고친 것
- **높음 · 명령 삽입(보안)**: 윈도우에서 `firebase` 를 `shell:true` 로 부르는데, 건의 번호(키)는 직원이 쓸 수 있는 자리(건의자 진행함 `suggestions_resolved_private/{본인 uid}` 아래 — 규칙에 키 검사가 없다)에서 온다.
  키에 `& | ^ %` 따옴표를 넣으면 대표 PC 에서 명령이 실행될 수 있었다(기존 `pending → show` 길에도 같은 구멍). → 모든 호출의 길목 `fb()` 가 DB 자리를 `/[A-Za-z0-9_/-]*` 만 통과시키고, `show·reply·notify` 가 번호를 먼저 검사한다. 현재 번호 37개는 모두 통과하는 모양.
- **중간 · 가짜 진행함 줄**: 진행함도 직원이 쓸 수 있어 가짜 «확정»·«대기» 줄로 알림을 부풀리거나 건마다 firebase 를 부르게 해 감시를 멈출 수 있었다. → 실제 «완료» 건(meta)의 건의자 uid 와 같은 줄만 인정, 번호·uid 모양 검사, 대기 읽기 상한 20, 제목은 제어문자를 걷고 80자로.
- **중간 · 저장형 XSS**: 대표 목록의 `data-id` 에 번호를 날것으로 넣던 것(기존 코드) → `sgEsc`.
- **중간 · 45일 제한**: 90일째 답 없는 건이 대표 목록에서 빠지던 것 → 나이로 자르지 않고 «최근 완료 60건» 으로 건수 한도만.
- **중간 · 375px**: 대기 칩이 두 줄로 꺾이고 확인 표시가 한 줄 끝에서 잘리던 것 → 칩을 「⏳ 대기 N」로(title 로 뜻 보충), 확인 표시를 한 줄 앞쪽으로.
- **낮음**: 검색창에 글자를 치는 중이면 다시 그리기를 미룬다(입력·한글 조합이 끊기지 않게). 팔레트 밖 색 `#b45309` → 팔레트의 `#854d0e`.
- 고치지 않은 것(기존 문제): 목록 항목 키보드 접근성(`.sg-item` 에 tabindex·Enter 처리 없음), 닫기 단추 터치 영역 협소.
- ⚠ **근본 구멍은 보안규칙**(진행함·건의 자리의 키 모양을 검사하지 않음)이다 — 도구에서 막았지만 규칙에도 `$id` 모양 검사를 넣는 게 맞다. 규칙은 이 PR 에서 안 건드렸다(규칙 올리기 절차가 따로 있다).
