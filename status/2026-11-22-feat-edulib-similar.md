# 2026-11-22 · feat/edulib-similar — 강의자료 «마지막에 언제 강의랑 비슷한지» 표시

대표 지시(2026-11-22, 자세히 화면 갈무리와 함께) 「만약에 기존 강의를 바꾼 게 있다 그러면 마지막에 언제 강의랑 유사하다 그런 표시도 좀 있으면 좋겠다」.
(같은 말의 앞 절반 «PPT 를 작게 늘어놓기»는 #3271 — 합쳐짐.)

## 바꾼 것
- `js/pu-edulib-core.js`(+ `functions/edulib-core/` 사본) — 내용 지문: 슬라이드·문서 글을 «낱말 두 개씩 짝»으로 쪼개 MinHash 32개(16진수 256자)로 줄인다.
  같은 자리 값이 같은 비율 ≈ 두 글의 겹침. `simSig`·`simScore`·`makeSim`·`similarOf`·`lastSimilar`(비슷한 것 가운데 강의일이 앞선 것의 가장 늦은 것)·`lastSimilarAll`.
  기준 `SIM_MIN` 0.5. 숫자만인 낱말(쪽 번호·연도)은 뺀다. 글이 적은 자료(그림 위주)는 `mh:''`(«비교 안 함»)로 남겨 다시 받지 않는다. 지운 자료와는 잇지 않는다.
- `js/pu-edulib-preview.js` — 글 뽑기에 한글(hwpx, Contents/section*.xml) 더함(지문용).
- `js/pu-edulib-app.js`
  - 지문은 `edulib/sims/{자료 id}` 에 따로 — 자료 기록의 «고친 때»를 바꾸지 않는다. 글 자체는 저장하지 않는다(숫자뿐).
  - 만드는 때: ① 자료함 원본을 미리보기로 열 때(pptx·ppsx·docx·hwpx, 바이트가 칸으로 넘어가기 전 사본으로) ② 새로 올릴 때(원본 붙이기·넣기·메일/정리함에서 넣기)
    ③ 관리자가 한눈에의 «비슷한 강의 찾기 → ▶ 남은 N건 지문 만들기»를 누를 때(받는 양을 묻고, 권한 확인 길로 차례로 받고, 멈출 수 있다).
  - 보이기: 목록(카드·표) 제목 앞 ↺ — 마우스를 올리면 «2025-07-16 「…」와 82% 비슷». 자세히 «비슷한 강의» 칸 — «↺ 마지막으로 비슷했던 강의 …»와 비슷한 것 여섯까지(⧉ 로 두 자료 나란히).
- `scripts/make-firebase-rules.js` — `edulib/sims/$id`: 쓰기 재직 직원(지우기 금지) · id=sourceId=열쇠 · entityType · mh 는 16진수 512자까지. **콘솔에 올렸다**(새로 1·바뀜 0·사라짐 0, 다시 읽어 같음 — 더 넓게 보이게 된 칸 없음).
- `js/pu-ontology.js` — `EduSimilarity`(강의 내용 지문) · writeContracts `edulib/sims/{id}` · 캐시 110.
- 점검 도구 시드 — 지어낸 지문(성희롱 예방 자료끼리 겹침).
- 검사 `tests/edulib-similar.test.js`(8개).
- 곁다리: `functions/edulib-mail-sweep.js` — 자동 정리함 «본 것»의 같은 파일 열쇠 칸 `id` → `item`(첫 밤 기록에 서버 저장 감시가 «레코드인데 공통 칸이 없다»고 경고).
  다음에 `edulibMailSweep` 을 올릴 때 반영된다(경고일 뿐 막히지 않음). 첫 밤 결과(토큰 729건 지움 · 자동 정리함 4건)는 STATUS.md 2절에 적었다.
