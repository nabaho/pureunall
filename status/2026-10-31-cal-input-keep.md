# 2026-10-31 · 푸른 캘린더(폰) — 입력창이 깜빡이고 입력이 안 되는 것 (feat/cal-input-keep)

대표 요청: 「폰에서 일정 입력하려고 창을 열거나 이름을 고르거나 내용을 열려면 자꾸 화면이 깜빡이거나 뒤로 가는 증상 — 내용 입력이 어렵다」.

## 원인 (폰 폭 화면에서 재현·측정)
- `render()` 가 `#app` 전체를 갈아 끼운다 → 입력칸이 «새 칸»이 되어 쓰던 글·커서·키보드(포커스)가 사라진다.
  (재현: 새 일정 창 제목에 글을 쓰고 `render()` 를 한 번 부르면 같은 칸이 아니고, 값은 빈 문자열, 포커스는 body.)
- 폰은 입력칸을 누르면 키보드가 올라와 `resize` 가 오고, 그 처리가 `render()` 를 바로 부른다(+ `용량재기`가 한 번 더 → 한 번의 resize 에 두 번 그림).
  입력창이 새로 그려져 키보드가 내려가면 화면 크기가 또 바뀌어 resize → 반복 = 깜빡임. 새 칸이 맨 위에서 시작해 «뒤로 간 것»처럼 보인다.
- 서버 자료(readOnce) · 구글 일정(gcalLoad) · 보관함 · 알림(toast) 이 «뒤에서» 도착해도 같은 일이 생긴다.
- 검색칸도 같은 까닭: 키보드가 올라오며 칸이 새로 생기고, 빈 칸이 포커스를 잃으면 검색이 닫힌다(앞서 말씀하신 「폰터치 검색 안 된다」와 맞는다).
- ⚠ `modalRead()`(적던 글을 S.modal 에 담는 것)는 이미 있었으나 호출하는 15곳에서만 지켜졌다 — 뒤에서 오는 render 는 지켜 주는 자리가 없었다.

## 한 것 (pu-cal.html)
- ① resize — «너비는 그대로, 높이만» 바뀌었고 글을 쓰는 중이면 다시 그리지 않는다(`입력중인가()`). 포커스가 없거나(키보드가 내려간 뒤) 너비가 바뀌면(회전) 그대로 그린다.
- ② render() 앞뒤 — `창입력지킴()`: 그린 뒤 사용자가 친 칸만 S.modal 에 담고 포커스·커서·창 스크롤을 기억 → 그린 뒤 `창입력되살림()` 으로 되돌린다(검색칸 포커스·커서도).
  ⚠ 통째로 modalRead 를 부르지 않는다 — 코드가 S.modal 을 바꾼 뒤 render 하는 길(캡처 결과 채우기 · 새 창을 열고 시각 넣기)에서 옛 칸 값이 새 값을 덮는다.
  «마지막으로 그린 값(_그린창값)과 다른 칸 = 사용자가 친 칸»만 옮기고, 코드가 바꾼 칸은 코드가 이긴다.
