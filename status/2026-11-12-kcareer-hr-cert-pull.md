# 경력관리 «푸른인사관리에서 재직증명서 당겨오기» (2026-11-12)

대표 지시: 「경력관리에 재직증명서 당겨오는 기능 만들어 달라.」 「경력증명서·재직증명서는 푸른인사관리에서 가지고 와라.」
(보낸 서류는 항상 경력관리에 보관한다는 상시 요구의 «받는 쪽» — 인사관리가 발급한 증명서를 서류 보관함(증명서)으로 모은다.)

## 먼저 읽은 것 — 인사관리 증명서 모듈 (`pu-erp.html` ~70400–71145)
- 발급할 때마다 `saveLog` 가 «발급 이력» 한 줄을 `data/cert_log`(이알피 봉투 `{v,u}`, **배열 통째 저장**)에 남긴다.
  줄의 모양: `id`(cl-…) · `certNo`(PU-연도-순번) · `kind`(employment·career·옛 salary) · `kindLabel` · `targetSid` · `targetName` · `targetTitle` · `purpose` · `submitTo` · `recipient` · `issuedBy` · `contactName` · `issuedAt`(UTC ISO) · `method`(print·download·mail) · `canceled`·`canceledAt`·`canceledBy`.
- **증명서 «본문»(HTML·PDF·변수)은 어디에도 남지 않는다 — 못 찾았다.** 본문은 발급하는 순간 화면(미리보기)에서 그려 인쇄·HTML 저장·메일 PDF 로 «나갈 뿐»이다. 생년월일·담당업무·직인 같은 «그때 적은 값»도 남지 않는다. 인사관리 자료(user_accounts·company_info)로 다시 그리면 그때 나간 문서와 달라질 수 있어, 다시 그려 «발급된 것처럼» 만들지 않기로 했다.
- 읽기 권한: `scripts/make-firebase-rules.js` 의 `cert_log: { '.read': HRW, '.write': HRW }` — 재무 권한자·관리자·위임관리인만. **규칙은 넓히지 않았다**(못 읽는 계정은 이유를 안내한다).
- 발급번호는 «그해 발급 줄 수 + 1» 로 센다(2026-10-11 시안) — 번호가 없는 옛 줄이 있을 수 있다(그런 줄은 넣지 않는다).

## 약속
- **읽기 전용** — `data/cert_log` 에 쓰지 않는다(검사가 «경력관리 어디에도 cert_log 를 쓰는 줄이 없다»를 지킴). 읽은 전체 목록은 창을 닫으면 버린다(남의 줄은 저장하지 않는다).
- 사람은 **sid 로만** 맞춘다 — 이름으로 «내 것»을 찾지 않는다. 로그인한 직원의 sid 를 모르면 읽지도 않는다.
- 가져오는 것은 발급번호·종류·발급일·용도·제출처뿐 — **이름·직위·생년월일·주소·받는 메일·발급자·담당자는 담지 않는다.**
- 연봉증명서(임금 정보)는 넣지 않는다. 인사관리에서 «취소» 표시한 줄은 넣지 않는다 — 이미 넣은 줄이 뒤늦게 취소되면 열 때 «취소됨»을 표시한다(취소가 풀리면 지움).
- 같은 발급번호는 두 번 넣지 않는다(보관함·휴지통 모두). 지운 적 있는 줄은 «지운 적 있음»으로 보이고 자동으로 고르지 않는다.
- 대표 본인 화면에서만 — 직원 «보기 전용»(`body.kc-staff`)에서는 단추를 감추고, `kcOwnerState()` 가 대표가 아니면 열리지 않는다.
- 로그인된 푸른 앱에서 증명서를 발급(인쇄/PDF)하거나 저장·삭제하지 않았다.

## 남은 일 (숨기지 않는다)
- **본문이 없다** — 넣은 줄은 «기록»이고 파일은 사람이 붙인다. 인사관리가 발급 때 본문을 남기게 하려면 `cert_log` 는 배열 통째 저장이라 줄마다 본문을 넣으면 한 번 쓸 때마다 전체가 커진다 → 별도 자리(예: 발급번호별 본문)와 보안규칙이 필요하다 [대표 결정 필요 — 돈·정책이 아니라 «저장 구조» 결정].
- **발급일은 «발급 기록 시각»의 한국 날짜**다. 인사관리 화면에서 발급일을 따로 골라 찍은 경우 종이의 날짜와 다를 수 있다(발급 이력에 «찍힌 발급일»이 없다). 증명 기간(재직기간)도 이력에 없어 비워 둔다.
- 읽을 수 있는 사람은 규칙이 정한 인사 담당(재무 권한자·관리자·위임관리인)뿐 — 대표 계정은 읽는다. 못 읽는 계정은 안내만 한다.
- 기존 «증명서 보관함 표»(`_cdTable`)는 이 기능 이전부터 폰에서 칸이 짓눌렸다 — 당겨온 줄이 들어오면 페이지가 옆으로 밀려 **공용 표 옷(`.dt`)+칸 이름표로 바꿨다**(PC 에서도 공용 표 모습으로 바뀜 — 머리글 바탕·테두리). 다만 **☐ 고르기 칸 + 번호와 «N건 선택» 일괄 작업은 이 표에 아직 없다**(CLAUDE.md «☐ + №» 규칙 위반이 전부터 있던 것 — 별도 일로 남김). 새 «당겨오기» 창은 규칙대로 만들었다.
- 어두운 판·폰 대비는 이 기능이 다루는 두 표만 맞췄다. 공용 `.dt` 표 전체의 어두운 판 문제(칸 글자 #1e293b 가 폰 카드의 어두운 바탕에서 묻힘)는 그대로다 — 전역 규칙이라 별도 일 [확인 필요].
- 실제 대표 화면(진짜 인사관리 발급 이력)에서의 확인은 하지 못했다 — 가짜 환경 점검뿐이다 [확인 필요].
