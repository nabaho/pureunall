# 한글 편집기 반응 속도·눈금자·커서 따라가기 (2026-11-01)

가지: `fix/hangul-perf` (origin/main 에서 새로 땀)

## 문제 (사용자 보고)
큰 문서(공공기관 편람 42쪽·문단 1,521·표 62)에서 글을 치거나 단추·팝업을 누르면 반응이 늦고, 글이 아래로 내려가지 않고 멈춘 것 같다. 눈금자 숫자가 잘 안 보인다.

## 원인과 고친 것 (`hangul/js/editor.js` v4)
- 글을 고칠 때마다 전체 쪽 나눔(`paginate`)이 약 1.25초 걸렸고 그중 `trailingSpaces` 0.7초·`tableBorderWidths` 0.6초가 대부분 — 문단·표마다 «스타일 바꾸기 → 위치 읽기»를 되풀이해 강제 재배치가 수십~수백 번 일어났다.
  - 두 함수를 «지우기/바꾸기 → 한꺼번에 읽기 → 쓰기» 순으로 모음. 계산식은 그대로. 안쪽 표는 바깥 표 다음 단계에서 처리해 순서에 따른 결과도 그대로.
  - 쪽 나눔 1.25초 → 약 0.2초, 큰 문서 열기 34.7초 → 5.7초.
- 고친 직후 쪽 나눔을 다시 그리면서 화면이 커서를 놓치는 경우가 있어, 글을 고친 직후에 커서가 화면 밖이면 보이게 함(`keepCaretVisible`, 고친 뒤 1.5초 안에만). 큰 문서 맨 끝에서 60줄을 이어 쳤을 때 전에는 화면이 문서 중간에 멈췄고(커서는 맨 끝), 지금은 커서가 화면 안에 남는다.
- 눈금자 숫자: 9px 회색 → 굵은 11px 검정.

## 확인
- 배치 서명(쪽 수·쪽 나눔 표시 수·표 테두리 값·모든 문단의 위치와 크기 해시)이 수정 전후 같음: 큰 문서 1개 + 한컴 기본 서식 75개(그중 8개는 줄 끝 빈칸 처리 동작) = 76개 모두 동일, 오류 0.
- 숨은 창에서 측정해 실제 화면 그리기 시간은 [확인 필요].
