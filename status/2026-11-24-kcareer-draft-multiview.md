# 경력관리 — 작성 중 서류 «한꺼번에 보기» (2026-11-24, 대표 지시)

대표 지시: 「서류가 여러장인 경우 한번에 모두 볼 수 있게 만들어 달라」
(한 건이 여러 장 — 공적조서 앞·뒤, 이력서, 동의서 — 인데, 작성 중 서류 목록에서 장마다 「↩ 이어서」를 눌러 열어야 서로 맞는지 견줄 수 있었다.)

## 바꾼 것 (`kcareer.html`)
- **선택 줄**(☐ 로 고르면 나오는 «N건 선택» 줄)에 「👁 한꺼번에 보기」, **목록 아래**에 「👁 전부 한꺼번에 보기」(고르지 않아도 «작성 중 전부»).
- 새 창 `#modalDraftMulti` — 고른 장마다 한 칸(`№ 보는 번호 · 이름 · 쪽수 · ↩ 이어서`)에 쪽 그림을 펼친다. PC 는 «작게 모아 보기»(넓은 창에서 4장 나란히) / «크게 보기» 를 고른다. 폰은 한 줄에 한 장.
- 그리는 일은 「한글 문서 보기」와 같은 엔진 하나(`PureunHwp.renderPreview`)다 — 새 그리개를 만들지 않았다. 담겨 있는 문서 파일을 그대로 그린다(보기 전용 — 저장을 바꾸는 길을 부르지 않는다).
- 지금 열어 둔 서류가 고른 것에 들었으면 먼저 `rhDraftNow(true)` 로 담는다(방금 고친 것이 빠지지 않게).
- 한 장이 못 그려져도 나머지는 그린다(그 칸에 까닭). 닫으면(Esc·닫기) 그림을 비운다 — 그리는 도중에 닫거나 다시 눌러도 «뒤 요청»만 남는다(`_dmRun`).
- 쪽은 `dpr:1` 로 그린다 — 여러 장이라 화면 배율(2~3배)로 그리면 A4 한 쪽(793×1122)마다 메모리가 한없이 든다.

## 같이 고친 것 (폰, 새 기능 이전부터 있던 흠)
- 폰 점검에서 작성 중 서류 목록이 **375px 에서 275px 옆으로 넘쳤다**(main 에서도 같은 숫자 — 이 PR 이전부터). 표(`min-width:620px`)가 격자 칸을 밀던 것 → 폰 구간에서만 `#rhDraftPanel{min-width:0}`. 표는 제 상자 안에서만 좌우로 민다(원래 의도). 고친 뒤 375·411px 모두 옆넘침 0.

## 점검 도구

## 아직 안 된 것 / 알아 둘 것 (숨기지 않는다)
- 실제 대표 계정의 «작성 중 서류»와 **진짜 폰**에서는 열어 보지 못했다(점검은 지어낸 자료·가짜 파이어베이스).
- 서류 «한꺼번에 보기»는 **작성 중 서류**에만 넣었다. 서류 보관함(완성본)·양식 보관함 줄에도 같은 길이 필요하면 따로 — 같은 `rhDraftViewMany` 얼개를 쓰되 파일을 읽는 자리만 다르다.
- 입력판에서 친 값(저장 «옆칸»)은 문서 파일에 구워지기 전이라 이 창에 안 보인다 — 한글 편집 안에서 고친 것·도장·사진은 들어 있다. 창 머리에 «저장되어 있는 그대로(보기 전용)»라고 적었다.
