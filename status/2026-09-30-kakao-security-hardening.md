# 2026-09-30 · 카카오 로그인 보안 보강

대표 요청: 「푸른통합시스템 카카오 로그인 기능 검토해라. 적절한지 보안에 취약한지 개선 필요하면 설명해라」 → 「개선할 수 있나 니가 직접」.

## 직접 고친 것

- OAuth `state`를 화면 난수에서 **서버 서명(HMAC-SHA256)·10분·1회용**으로 바꿨다. 함수 주소를 직접 불러 화면 검사를 건너뛰는 요청도 서버가 거절한다.
- 카카오 계정 연결은 **비밀번호 또는 패스키로 최근 10분 안에 본인 확인한 재직자**만 할 수 있다. 오래 열린 창과 카카오 로그인 세션으로는 새 카카오를 연결하지 못한다.
- Firebase ID 토큰은 폐기 여부까지 확인한다(`verifyIdToken(..., true)`).
- 같은 카카오를 두 직원이 동시에 차지하지 못하게 카카오별 transaction을, 같은 직원이 두 카카오를 동시에 연결하지 못하게 직원별 30초 잠금을 두었다.
- 화면과 관리자에게 보이던 카카오 회원번호 원문을 없앴다. 새 연결은 SHA-256 지문 열쇠만 저장하고, 옛 연결은 다음 성공 로그인 때 새 꼴로 이관한다.
- 새 꼴과 옛 꼴을 함께 읽어 기존에 연결해 둔 직원의 로그인이 갑자기 끊기지 않게 했다.
- 응답은 `Cache-Control: no-store`, 화면 스크립트는 `pu-kakao.js?v=5`로 올렸다.

- 새로 겨눈 구멍: 위조·재사용·만료 state, 로그인/연결 용도 바꾸기, 오래된 세션, 카카오 세션 재연결, 회원번호 원문 노출, 같은 직원·같은 카카오의 동시 연결.

## 배포 순서

옛 화면은 `state`를 보내지 않고 새 화면은 서버 발급 `state`를 요구하므로 한쪽만 먼저 올리면 잠깐 로그인이 끊긴다. 먼저 옛·새 화면을 함께 받는 전환용 함수를 올리고, Pages에서 `v=5`가 확인된 뒤 엄격한 최종 함수를 올린다.
