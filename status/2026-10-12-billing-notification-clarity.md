# 2026-10-12 청구 알림 표시·메일 동기화 중복 읽기 점검

- 실측: 10월 11일 확정 Cloud Billing 기준 Realtime Database 다운로드가 월 누적 비용의 약 85%였다. 10월 10일 6.34 GiB/₩8,143에서 10월 11일 0.96 GiB/₩827로 감소했다. 10월 12일 사용분은 당시 청구서에 아직 나타나지 않았다.
- Firebase 사용량 화면은 당일에도 시간당 수십 MB 다운로드가 남아 있음을 보였다. RTDB 프로파일러 5분 샘플에서 `data/companies/v` 전체 REST 읽기 3회(약 1.24 MB), `data/companies` 전체 읽기·수신 리스너 각각 1회(각 약 414 KB), `data/contracts/v` 리스너 1회(약 299 KB)를 확인했다. 프로파일러 바이트는 청구 바이트와 동일하지 않다.
- 새 메일 동기화의 이름 가리기·신규 문의·담당 알림이 같은 회차에 업체 원장 전체를 따로 읽지 않도록 회차 범위 Promise를 공유한다. 담당 알림에 필요한 표도 여러 폴더에서 다시 받지 않는다. 자동 채우기가 업체를 고치면 둘 다 무효화한다. 자동 채우기 자체는 기존 10분 캐시를 유지한다.
- 포털 사용액 창에서 청구 알림 도착 시각을 실제 비용 발생 시각/원인으로 잘못 읽지 않도록 제목·설명을 바로잡고 Firebase 다운로드량 화면을 연결했다. 기록은 15분 한도로 재조회하고 새 청구 알림이 도착하면 즉시 갱신한다.
- 관련 회귀 검사에서 중복 읽기 1회 및 기존 동작을 확인했다. 전체 검사·배포 후 다시 RTDB 사용량을 관찰해야 실제 절감 폭을 확인할 수 있다. 남아 있는 모든 다운로드가 불필요하다고 단정하지 않는다.
