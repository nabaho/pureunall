# 푸른 캘린더에서 «넣고 고칠 수» 있게 됐다 (1걸음-나)

대표 지시 2026-09-18 「계속」 · 가지 `feat/cal-write-gate`
새 파일 `js/pu-cal-write.js?v=1` · `js/pu-cal-read.js?v=2`

1걸음은 읽기까지였다. 이제 일정·연차·근태를 **푸른 캘린더에서 바로** 넣고 고치고 지운다.
빈 칸을 누르면 새로 넣고, 일을 누르면 고친다.

## 왜 문을 따로 지었나 — 규칙이 갈리면 급여가 틀어진다

일정·근태의 주인은 이알피다. 우리가 «다른 규칙»으로 쓰면 두 앱이 서로를 덮는다.
그래서 저장은 **반드시 한 문**(`js/pu-cal-write.js`)을 지난다. 지나야 할 여섯 —

| | 막는 것 | 안 막으면 |
|---|---|---|
| ① | 번호 없는 항목 | 그 표가 «통째 저장»으로 떨어져 두 기기가 서로를 덮는다 |
| ② | 번호·칸 이름의 금지문자 | 엉뚱한 자리에 쓴다 |
| ③ | 마감된 달 (**새 날짜와 옛 날짜 둘 다**) | 마감 뒤 근태가 바뀌어 급여가 틀어진다 |
| ④ | 아직 «배열»인 표 | `v/{번호}` 를 쓰면 배열에 글자 열쇠가 섞여 표가 깨진다 |
| ⑤ | 레코드 통째 덮어쓰기 | 두 사람이 다른 칸을 고쳐도 나중 사람이 앞사람을 되돌린다 |
| ⑥ | 번호 안 보내기 | 서버에 «본문에 번호 없는 껍데기»가 생긴다 (①로 이어진다) |

③은 «옮기는 것»도 막는다 — 잠긴 달에서 빼내는 것 역시 그 달을 고치는 일이다.
④가 걸리면 쓰지 않고 **이알피로 보낸다.** 이알피에는 그 표를 통째로 안전하게 저장하는
길이 따로 있고, 우리는 그 길을 흉내 내지 않는다.

⚠ 날짜가 없는 기록은 막지 않는다 — 어느 달인지 알 수 없다(막으면 영영 못 고친다).
⚠ 일정(`my_schedules`)은 마감 대상이 아니다. 마감된 달에도 일정은 넣을 수 있다.

## 검사가 진짜 문제를 둘 찾았다

**① 번호가 겹쳤다.** 이알피가 쓰는 번호 짓는 법(시각 + 아무값 세 글자)을 그대로 썼는데,
재어 보니 **오백 번에 세 번 겹쳤다.** 번호가 겹치면 한 건이 다른 한 건을 **조용히 덮는다.**
달력은 잇따라 여러 건을 만들 수 있어 이알피보다 겹칠 자리가 많다 — 아무값을 넉넉히 했다.
지금은 20만 번에 0건.
⚠ 번호의 «생김새»는 규칙이 아니다(속뜻 없는 딱지다) — 길게 해도 이알피와 갈리는 것이 아니다.

**② 직원 명부가 지도로 오면 이름 대신 사번이 떴다.** 배열만 받고 있었다.
틀린 화면이 아니라 «맞는 척하는» 화면이라 더 나쁘다 — 두 꼴을 다 받게 고쳤다.

흉내 서버에 물려 사람이 하듯 눌러 확인했다(진짜 이름은 안 썼다):

| 해 본 것 | 결과 |
|---|---|
| 마감된 달에 연차 넣기 | **막힘** — 「2026-08 근태·휴가는 마감됐습니다」 · 서버로 아무것도 안 감 |
| 마감된 달에 일정 넣기 | 됨 (일정은 마감 대상이 아니다) |
| 있던 근태의 «메모만» 고치기 | `note` 만 감. 날짜·유형은 **안 감**(남의 손질을 안 되돌린다) |
| 지우기 | 그 자리만 `null` · 표를 다시 안 씀 |
| 지운 뒤 화면 | 바로 사라짐 |

## 파이어베이스 규칙 — 이름을 붙였습니다

`data/attendance_records` · `data/my_schedules` 가 여태 **이름이 없어 `$other` 로** 떨어져 있었다.

```
새로 생기는 규칙 2개  + /data/attendance_records  + /data/my_schedules
값이 바뀌는 규칙 0개 · 사라지는 규칙 0개
```

★ **권한은 «지금 그대로»다** — 재직 직원 전원 읽기·쓰기. 이름만 적었고 동작은 한 톨도 안 바뀐다.
이름을 붙인 까닭: 푸른 캘린더가 이 자리를 이름 그대로 쓰게 되면서, 무엇이 어디에
열려 있는지 셀 수 있어야 하기 때문이다(검사가 그것을 본다).

⚠ **대표께 알립니다 — 지금 누가 근태를 고칠 수 있나**: 직원 누구나, 제 것도 남의 것도.
마감된 달만 **앱이** 막는다(서버 규칙이 아니다). 좁힐지는 대표 판단이다.
마감 자물쇠를 서버 규칙으로 옮기는 것은 따로 볼 일이다 — 지금 옮기면 마감 해제·일괄 정리
같은 관리자 길이 함께 막힌다.
