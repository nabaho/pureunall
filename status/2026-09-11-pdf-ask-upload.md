# 2026-09-11 · 사진첩 — 여러 쪽 PDF 가 «한 번도» 안 올라갔다 (한 줄 고침)

- PR: (열면서 채움)
- 대표 물음 2026-09-10: 「왜 이 서류를 업로드해서 ocr 하려는데 계속 안 되나」
  → 화면 캡처: **「올리기를 취소했습니다」**

## 무엇이 잘못돼 있었나

여러 쪽 PDF 를 고르면 「한 문서로 / 쪽마다 따로」를 묻는 창이 뜬다(2026-08-24 에 만든 것).
그 창에서 **무엇을 눌러도** 「올리기를 취소했습니다」가 뜨고 **한 장도 안 올라갔다.**

까닭은 한 줄이다 —

```js
ok.onclick = function () { … closeKindPopup(); done(p); };
//                             ↑ 이 안에서 _pdfAskCancel() → done(null) 이 먼저 불린다
```

`closeKindPopup` 은 「창이 닫혔으면 올리지 않는다」를 지키려고 취소 약속을 부른다.
「이대로 올리기」가 그것을 **내려놓지 않고** 창을 닫았으므로 `done(null)` 이 먼저 불리고,
뒤이은 `done(고른값)` 은 이미 끝난 약속이라 조용히 버려졌다.

→ 고침: 창을 닫기 **전**에 `_pdfAskCancel = null`.

## ★ 얼마나 오래

**창이 생긴 날(2026-08-24)부터 어제까지 18일.** 한 쪽짜리 파일은 이 창을 아예 안 거치므로
멀쩡했고, 그래서 아무도 못 알아챘다. 그 사이 **여러 쪽 스캔은 한 장도 안 담겼다.**

## 어떻게 찾았나 — 짐작 말고 쟀다

1. 서버 기록: 그날 `readDoc` 부름 **0건** → 「판독」이 아니라 그 앞에서 멎었다
2. 실시간DB: 그날 올라온 사진 **0장**(회사 전체) → 「올리기」에서 멎었다
3. PDF 자체를 같은 코드로 돌려 봄: 2쪽·A4·잠금 없음 → **1905×2693 로 잘 그려진다**(파일 잘못 아님)
4. 「올리기를 취소했습니다」 글월을 코드에서 찾음 → `askPdfSplit` 이 null 을 준 것
5. 진짜 함수를 vm 에 싣고 단추를 눌러 봄 → **`null`** (고친 뒤에는 `{"scan0007":false}`)

## ⚠ 남긴 함정

- `kindPopup` 은 **한 창을 여러 일에 돌려 쓴다**(분류 만들기·분류 지정·쪽 나누기).
  그래서 `closeKindPopup` 이 뒷정리를 다 한다 — 거기에 «약속 풀기»가 섞여 있다.
  이 창에 새 일을 붙일 때 **약속을 먼저 내려놓고 닫는지** 확인할 것.
- 검사에 «기다림 끝»(3초)을 붙였다. 이 창의 고장 하나는 «약속이 영영 안 풀리는» 것인데,
  그대로 기다리면 검사가 **실패가 아니라 멈춘다** — 되돌림 검사를 돌리다 실제로 멈췄다.
  **멎은 검사는 무엇이 틀렸는지 한 마디도 안 해 준다.** 안 풀리면 실패하게 두었다.
