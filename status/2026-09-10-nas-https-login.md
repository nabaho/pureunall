# 2026-09-10 · NAS 연결 검토 ① — 비밀번호가 주소줄에 실리지 않게 · HTTPS 가 기본

대표 지시 「순서대로」 — ①HTTPS ②되돌리기·정리 ③AI 색인 설계 가운데 첫째.

## 무엇이 문제였나
- NAS 로그인이 `auth.cgi?…&passwd=비밀번호` 로 **GET** — DSM 접속 로그에 그대로 남고,
  HTTP(옛 기본값)면 사무실 네트워크에 평문으로 흐른다.
- 로그인 코드가 **두 벌**(설정 화면 · 7일 자동 백업). 한쪽만 고치면 다른 쪽이 남는다 —
  백업 거름망(SECRET_KEYS)에서 막 겪은 그 모양.
- 오류 안내가 「아래 "HTTPS 모드" 켜고」라고 했지만 **그 단추가 화면에 없었다.**
  없는 단추를 찾게 하는 안내는 없느니만 못하다.

## 고친 것
- NAS 부르기를 **한 벌**로(`nasBaseOf`·`nasLoginWith`·`nasLogoutWith`·`nasUploadWith`, fetchT 위).
  설정 화면·연결 테스트·수동 백업·복원·7일 자동 백업이 모두 이것을 쓴다.
- 비밀번호는 **POST 몸통**으로만. 옛 DSM 이 POST 를 안 받을 때(405·101·103)만 GET 으로
  물러서고 **그 사실을 기록에 적는다**. 비밀번호가 틀린 것(400)은 방법 탓이 아니라 물러서지 않는다.
- **HTTPS 가 기본**(안 정했으면 5001). 화면에 「🔒 HTTPS 로 연결」 토글·HTTPS 포트 칸을 «실제로» 두었다.
  HTTP 를 고르면 빨간 띠 「비밀번호가 평문으로 흐릅니다」 + 「HTTPS 로 바꾸기」 한 번 누르기.
  HTTP 로 «저장»하려면 한 번 묻는다.
- 오류 안내를 사실에 맞췄다(Netlify 라는 옛 이름도 뺐다).

## ⚠ 대표님이 하실 것
기존 설정은 `useHttps:false` 로 저장돼 있을 수 있다(옛 기본값). 환경설정 → NAS 자동 백업 →
빨간 띠가 보이면 「HTTPS 로 바꾸기」 → 「설정 저장」 → 「연결 테스트」.
NAS 인증서가 자체서명이면 브라우저가 한 번 믿어 줘야 한다(https://NAS주소:5001 을 한 번 열어 «계속»).
