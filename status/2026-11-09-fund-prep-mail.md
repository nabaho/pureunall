## 남은 것 · 대표 판단이 필요한 것
- **문안은 초안**이다 — 「함께 정해 주실 사항」 세 줄과 맺음말은 설립 12단계(EST-03~06) 말에서 따 썼다. 담당 노무사가 읽고 고칠 수 있게 쓰기 창에서 수정한다. 문구를 확정해 주면 고정한다.
- 기본으로 고르는 서류는 «준비처 ≠ 기금법인»이다. `tax_handover`(사무인계서·출연금 입금 통보, 준비처 «기금·참여기업»)처럼 우리와 기업이 함께하는 줄도 들어간다 — 빼려면 □ 를 끈다.
- 여러 기업에 **한꺼번에 자동 발송**(예약·일괄 서버 발송)은 하지 않았다 — 기업마다 쓰기 창을 열어 사람이 확인하고 보낸다. 자동 발송이 필요하면 서버 함수 + 승인 절차를 따로 설계해야 한다.
- 기업별 «서류 받음» 상태(기업마다 무엇을 받았는지)는 아직 기금 단위 확인(`req_docs`)뿐이다 — 기업별로 나누려면 자료 구조가 먼저 필요하다.
- **쓰기 창이 «아직 안 떠 있을» 때(처음 누를 때)** 는 받는이·제목만 주소로 채워지고 본문은 복사만 해 둔다 — 붙여 넣어야 한다. 메일함이 이미 떠 있으면 본문까지 한 번에 채워진다(진짜 메일함 화면으로 확인). 푸른메일함을 먼저 한 번 열어 두면 첫 기업부터 본문까지 채워진다.
- ⚠ 그 처음 경로는 받는 이메일·기업명이 **주소(URL)에 실린다**(브라우저 기록·정적 호스팅 로그에 남을 수 있다 — 외부 보안 검토 «낮음»). 기존 명함·공문 메일 열기(`pu-cards.html` 의 `to=`)와 같은 약속이라 이번에는 그대로 두었다. 메일함이 «떠 있는 창에 직접 받는» 길을 처음 경로에도 만들면 함께 사라진다 — 따로 할 일.
- 공용 모달 한계(이 PR 은 건드리지 않음): Esc 로 닫기·초기 포커스·포커스 가두기·토스트 `aria-live` 가 없다. 표 머리·번호의 `--faint` 글자색 대비(2.56:1)는 앱 공통 스타일이다.
- ⚠ 이미 있던 것: `_sitesFill` 가 부르는 `_cardBySite` 는 어디에도 정의돼 있지 않아(`typeof` 로 건너뜀) 서식 자동 채움의 «기업정보함 빈 칸 보충» 1번이 한 번도 돌지 않는다. 이 PR 은 건드리지 않았다.
