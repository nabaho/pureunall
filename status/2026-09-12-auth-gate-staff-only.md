## 고침

```js
const 비번로그인 = "auth != null && (sign_in_provider === 'password' || passkey === true)";
const 재직자 = "root.child('uid_roles').child(auth.uid).child('status').val() === 'active'";
const LOGIN = `${비번로그인} && ${재직자}`;
```

그리고 `uid_roles/$uid` 에 **명단맞춤**(`.validate`) 을 걸었다 —
`sid` 와 `status` 를 **`sid_roles`** 와 견준다. 그 자리는 «관리자만» 쓰므로 믿을 수 있다.

### 일부러 그렇게 한 것 셋

**① 쓰기 문은 «옛 조건»(비번로그인)을 그대로 쓴다.**
새 `LOGIN` 을 쓰면 아직 등록 안 된 새 직원이 자기 칸을 못 만들어 **영영 못 들어온다**(닭과 달걀).
대신 내용을 명단과 견주므로 뚫리지는 않는다.

**② uid 가 아니라 «이메일»로 묶었다.**
uid 는 그 사람이 처음 로그인해야 생기는데, 관리자는 그 전에 명단을 적어 둬야 한다.
이메일은 미리 안다 — 그래서 **관리자가 사번+이메일만 넣어 두면 첫 로그인에 저절로 등록된다.**

**③ 익명 로그인은 «끄지 않았다».**
전자서명(`sign.html`)·이음(`ieum-view.html`)이 쓴다 — 끄면 근로자가 서명을 못 한다.
대신 익명으로 열리는 자리를 검사로 **둘로 못 박았다**(`ieum_public` · `esign/…/meta`).
