# 캘린더 떼어내기 0걸음 — 근태·휴가 규칙을 «한 자리»로 (화면은 안 바뀐다)

대표 지시 2026-09-18 「이알피에서 법인대시보드와 이음센터만 완전히 따로 빼서 캘린더를
만들고 싶다 … 분리시킬때 문제 발생하면 안된다」 · 가지 `feat/cal-core-step0`
새 파일 `js/pu-work-core.js?v=1`

대표 결정: **법인 대시보드 통째로 + 이음센터**를 뺀다. 순서는 **0걸음(뿌리 정리)부터.**

## 먼저 잰 것 — 떼어내기가 얼마나 위험한가

| 물음 | 잰 값 |
|---|---|
| 이알피 나머지가 대시보드·이음을 부르는 자리 | **5곳** (화면전환 2 · 문자링크 1 · 일정공개 3) |
| 대시보드가 이알피 안쪽을 읽는 자리 | 공용 함수 **33개** · 데이터 칸 **29개** |
| 그중 캘린더가 실제로 쓰는 칸 | 10개 (나머지 19개는 매출·계약·급여 — 경영지표 쪽) |
| 캘린더를 검사하는 검사 | **27개** (지금은 `pu-erp.html` 을 본다) |
| `pu-erp.html` 손질 횟수 | 30일에 **289번** (하루 10번) — 큰 덩어리를 들어내면 충돌한다 |

**나가는 문이 다섯뿐**이라 사무관리·환경설정은 안 부서진다.
어려운 쪽은 반대 방향이고, 그래서 0걸음이 먼저다.

## 0걸음에서 한 일 — 갈라져 있던 규칙을 모았다

떼어 내면 같은 규칙이 두 앱에 각각 있게 된다. 그런데 **떼기도 전에 이미 갈라져 있었다.**

### ① 「연차 며칠 썼나」 공식이 **여덟 벌**이었다

개인 연차칸 · 대시보드 직원카드 · 대시보드 기간집계 · 근태관리 직원칩 · 근태관리 월통계 ·
연차 산정 · 연차 요약 · 휴가관리.

그중 **넷은 8시간으로 나누고 넷은 그 사람의 소정근로시간으로 나눈다.**
같은 사람의 잔여 연차가 화면마다 다를 수 있었다.

→ `PuWork.leaveUsed(기록들, 하루시간)` 하나로. **지금 돌던 대로 그대로 둔다** —
하루시간을 인자로 받아 그 «다름»을 숨기지 않고 드러낸다. 맞출지는 대표님이 정하실 일이다.

### ② 근태 유형표가 **일곱 벌**이었다

그중 **셋이 셈에 쓰이는 표**(유형 → 몇 시간짜리)였고, 둘은 글자 하나까지 같은 복사본이었다.
게다가 담고 있는 유형이 서로 달랐다:

| | 아는 것 | 모르는 것 |
|---|---|---|
| 근태관리 | 공가·지각·조퇴·결근 | 출산휴가·육아휴직 |
| 캘린더 | 출산휴가·육아휴직·특별휴가 | 공가·지각·조퇴·결근 |

캘린더에서 넣은 **출산휴가가 근태관리 화면에선 이름이 없었다.**

→ 합쳐서 15종을 `js/pu-work-core.js` 한 자리에. 어느 화면이 무엇을 고를 수 있는지는
`inAtt`·`inCal` 로 **지금 그대로** 적어 둔다 — 합쳤다고 없던 단추가 생기면 화면 변경이다.

### ③ 이름도 달랐다

근태관리 「연차(오전)」 ↔ 캘린더 「오전반차」. `labelFor(코드, 어느화면)` 로 **둘 다 남긴다.**
한쪽으로 몰래 맞추지 않는다.

### ④ 마감 자물쇠 대상표

`PuWork.LOCK_TABLES` 로. **캘린더가 다른 앱으로 나가도 이 문을 지나야 한다** —
안 지나면 마감한 달의 연차가 캘린더에서 뚫리고 급여가 조용히 틀어진다.

## 화면은 하나도 안 바뀐다

그림·색만 담은 «보기용» 표는 아직 셋 남아 있다 — 개인 캘린더 · 빠른 등록창 · 근태관리가
같은 연차를 🌴 · 🏖️ 로, 반차를 초록 · 파랑으로 다르게 그린다.
**합치면 화면이 바뀌므로 이번엔 안 건드렸다.** 0걸음은 되돌리기 쉬워야 하는 단계다.
합칠지는 대표님이 보시고 정하실 일이다(0걸음-나). 검사 주석에 그 범위를 적어 두었다.
