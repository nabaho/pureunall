# 2026-10-28 · 건의 «재요청»에 화면 캡처를 붙일 수 있다

대표 지적(재요청 접수 카드 붙여넣기): 「캡쳐안된다 확인해라」

## 무슨 일이었나
- 건의자가 처리 결과를 「🙅 아직 안 됐어요」로 회신하면 «재요청 건의»가 새로 접수된다(`enter.html` `sgCheckResolved`).
  그 양식에는 글 칸뿐이었고, 접수 기록은 `images:[]` 로 «못 박혀» 있었다 → 건의자가 캡처를 붙일 방법이 없었다.
- 실측(실시간DB `suggestions_private`): 처음 건의(엔타스시, 10/27 13:48)는 캡처 2장, 재요청(16:33)은 `images` 칸 자체가 없다.
  그래서 관리자 카드에도 캡처가 안 보였고, 「고른 업체가 없습니다」 같은 붉은 알림 글자를 말로만 적어 왔다.

## 한 것 (`enter.html`)
- 재요청 양식에 「📎 캡처 붙이기」 — 고르기 + 글 칸에서 Ctrl+V, 최대 3장(처음 건의와 같은 한도·같은 줄여 담기 `sgCompress`), ✕ 로 지우기.
- 접수 기록의 `images` 에 붙인 캡처를 담는다. 관리자 상세 화면은 `images` 를 이미 보여 준다(그대로).
- 그림이 아닌 파일 · 못 읽는 그림 · 4장째는 «말해 준다»(조용히 버리면 「안 된다」로 보인다).

## 검사
- 새 `tests/suggestion-rerequest-capture.test.js` — 마크업 규칙 + 배선을 가짜 칸으로 «실제로 돌려»(고르기·3장 한도·붙여넣기·글자 붙여넣기 안 막음·오류 안내) 본다.
  `images:[]` 로 되돌려 보면 2개가 빨갛게 변하는 것까지 확인(이빨 있음). 전체 묶음 통과.

## 남은 일 / 모르는 것
- 폰·PC 실제 화면에서 눌러 본 것은 아님(로그인이 필요한 포털 팝업). 배포 뒤 건의자 계정으로 한 번 확인 필요.
- 같은 날 CMS 건 자체(엔타스시 「고른 업체가 없습니다」)는 재요청(16:33)이 «반쪽 고침(#2786)» 때 시험한 것으로 보인다 —
  둘째 고침(#2787)은 17:49 에 합쳐졌다. 건의함 답변은 건의자가 다시 시험한 뒤에 정한다.
