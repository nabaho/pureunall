# 백업에 «다 담는다» (2026-09-20 대표 지시 「다담아라」)

가지: `claude/login-start-screen-386qu2`

## 먼저 — 내가 잘못 보고했다

나스 자동백업이 돌기 시작한 날 대표께 이렇게 말씀드렸다:

> 「지금 백업은 21개 칸만 담습니다 … 빠진 것 중에 근로계약서·퇴직정산·지출·청구서·계정이 있습니다」

**틀렸다.** `SERVER_BACKUP_KEYS`(21개)는 **담을 것을 고르는 거름망이 아니다** —
「이 중 하나라도 자료가 있어야 백업할 값어치가 있다」를 보는 잣대다.
실제로 담기는 것은 `buildBackupSnapshot` 이 localStorage 를 통째로 훑은 것이다.
근로계약서·퇴직정산·지출·청구서·계정은 **처음부터 담기고 있었다.**

이름이 「백업 키」라서 그렇게 읽었다. 그 이름 옆에 이제 못을 박아 두었다.

## 그런데 «진짜로» 빠진 것이 하나 있었다

**`ledger_batches` — 통장 묶음.**

| | |
|---|---|
| 서버로 실시간 공유되나 | ✅ 된다 |
| 유실검사(DIFF_KEYS)가 보나 | ✅ 본다 |
| 백업에 담기나 | ❌ **안 담겼다** |

**없어지면 알려는 주는데 되돌릴 백업이 없었다.** 경보만 울리고 소화기가 없는 셈이다.

빼 둔 까닭은 통장 4,000행이 스냅샷을 실시간DB **한 번 쓰기 한도(16MB)** 위로
밀어 올렸기 때문이다(`write_too_big` — 실제로 났다). 그런데 그 뒤
`erpBackupBatches` 가 **큰 배열을 행 단위로 쪼개** 싣도록 고쳐졌다.
**까닭은 사라졌는데 「빼 둔 것」만 남아 있었다** — 이런 자리가 가장 오래 안 보인다.

## 무엇을 했나

| 파일 | 바뀐 것 |
|---|---|
| `pu-erp.html` | `SNAP_EXCLUDE` 에서 `ledger_batches` 를 뺐다(=백업에 담는다) |
| 〃 | 백업 직전에 `FB_COLD_KEYS`(급여감사기록)를 받아 온다 |
| 〃 | `SERVER_BACKUP_KEYS` 옆에 «거름망이 아니다» 라고 적었다 |
| `tests/backup-covers-sync-keys.test.js` | 새 검사 6개 |
| `tests/ledger-batches.test.js` | 옛 «빠져 있는지» 못을 뒤집었다 |

### 급여감사기록이 빠지던 자리

스냅샷은 localStorage 를 훑어 만든다. 그런데 `payroll_audit_log` 는
**그 화면을 열어야** 내려온다(`FB_COLD_KEYS`). 아무도 안 연 날은 통째로 빠졌고,
**빠진 줄도 몰랐다.** 이제 백업 직전에 받아 온다 —
못 받아도 백업은 그대로 간다(한 칸 때문에 백업 전부를 잃는 것이 더 나쁘다).

## 여전히 «안» 담는 것 — 그리고 왜인지

| 키 | 왜 안 담나 |
|---|---|
| `bank_ledger_draft` | 올리다 만 통장 임시본. 서버에도 안 올라간다. 원본 엑셀이 있으면 다시 만든다 |
| `co_merge_log`·`co_link_log`·`co_vat_log` | **이 PC 에서 누른 것**을 되돌리려는 기록. 남의 PC 에 되살리면 지키는 게 아니라 섞는 것이다 |
| `api_key`·`token`·`secret`·`password` 류 | 백업은 «잃은 자료를 되찾는 것»이지 «열쇠를 옮기는 것»이 아니다 |

## 검사 — 값이 아니라 규칙을 못 박았다

키 이름을 세지 않는다. 목록이 늘어도 안 깨지고, 다음에 누가 업무 키를
백업에서 빼면 그 자리에서 걸리는 규칙만 적었다.

1. 서버에 올라가는 키(`FB_ALL_SYNC_KEYS`)는 백업에서 빼지 않는다
2. 유실검사가 보는 키(`DIFF_KEYS`)는 반드시 백업에 담긴다
3. 부팅 때 안 받는 키(`FB_COLD_KEYS`)는 백업 **직전**에 받아 온다
4. 비밀(`SECRET_KEYS`)은 여전히 안 담는다
5. **글자가 아니라 재서 확인한다** — 진짜 `erpBackupBatches` 에 8만 행
   (실제 최대치의 스무 배)을 먹여, 한 번 쓰기가 16MB 안인지 **바이트로** 센다
   (한글은 한 글자가 3바이트다 — 글자로만 재면 세 배를 놓친다)
6. 쪼개기의 «바닥»을 적어 두었다 — 한 묶음 혼자 한도를 넘으면 더 쪼갤 곳이 없다

돌연변이 확인 4회 — 넷 다 걸린다.
