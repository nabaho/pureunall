# 2026-10-05 · 이알피 — 다른 브라우저·계정에서 「96건 삭제」 오판한 경쟁

대표 제보: 크롬·엣지·다른 창·다른 로그인으로 푸른이알피를 열면
`finance_expense` 96건이 한꺼번에 지워졌다는 확인창이 반복됨.

## 근본 원인

- 서버가 목록 꼴을 배열→id 지도로 바꾸거나 다시 쓰면 Firebase가 같은 줄을
  `child_removed` 여러 개 뒤 `child_added` 여러 개로 알릴 수 있다.
- 예전 화면은 다시 올 줄을 잠깐도 기다리지 않고 지움을 한 건씩 먼저 반영했다.
- 대량 삭제 질문이 뜨는 시점에는 절반 가까이 이미 로컬에서 지워졌다.
  따라서 「취소」를 눌러도 브라우저별 자료가 갈라졌다.

실시간DB를 직접 읽어 `finance_expense` 96건이 서버에 그대로 있음을 확인했다.

## 고친 것

- 지움 알림을 120ms 동안 묶어 두고 실제로 남은 지움만 한 번에 반영.
- 같은 id가 재추가되면 「자료 삭제」가 아니라 「저장 모양 바꿈」으로 보고 지움 취소.
- 대량 삭제는 사람이 확인하기 전에 로컬 자료를 한 건도 지우지 않음.
- 취소하면 최초 목록이 그대로 남음.

## 검사

- `tests/erp-boot-sync.test.js`: 삭제→같은 id 재추가는 경고·변경 없음.
- 대량 삭제 취소 시 처음 건수 전체 보존.
- 정상 한·두 건 삭제는 그대로 반영.
