## 찾은 것 — 실시간DB 는 갈렸는데 창고는 «안» 갈려 있었다

PR #1225 가 「로그인했다」와 「우리 직원이다」를 갈라 232곳을 막았다.
그런데 그것은 **실시간DB 쪽만**이었다. 창고 규칙은 이랬다.

```
function isStaff() {
  return request.auth != null && request.auth.token.email != null;
}
```

파이어베이스 **「새 가입 막기」는 여전히 꺼져 있다**(#1225 가 일부러 안 건드렸다 —
켜면 전자서명의 익명 로그인까지 막힐 수 있어서다). 그러니 위 함수의 실제 뜻은
**「아무 이메일로나 가입한 사람」**이었고, 그 한 줄에 매달린 것이 이만큼이다.

| 자리 | 무엇이 들어 있나 |
|---|---|
| `pucards/photos` | 명함첩 |
| `pucards/mailout` | 메일에 붙인 내 PC 파일 |
| `gov_evidence` | 자문 증빙 사진 |
| `casebook` | **서고 원본 — 근로자 이름·서명·도장** |
| `pu_paydata` (읽기) | **급여데이터함 전체** |

⚠ #1225 의 「이제 가입해도 아무것도 못 읽는다」는 **실시간DB 에만 맞는 말**이었다.

## 고침 — 토큰으로 할 수 있는 가장 좁은 잣대

창고 규칙은 실시간DB 를 **못 읽는다** — `uid_roles` 의 「재직 중인가」를 여기서
볼 수가 없다. 토큰에 있는 것으로만 판정해야 해서, 지금 쓸 수 있는 가장 좁은
잣대가 «우리 도메인»이다.

```
&& request.auth.token.email.matches('^[^@]+@pureun[.]kr$')
```

★ 정규식의 함정 둘을 일부러 피했고, **검사가 그 둘을 글자로 못 박는다**.
- 점을 `[.]` 로 묶는다 — 안 묶으면 `pureunXkr` 도 맞는다.
- `^…$` 로 끝을 박는다 — 안 박으면 `나@pureun.kr.남의집.com` 이 통과한다.

⚠ `signedIn()` 은 **안 건드렸다** — 전자서명(익명)과 본인 전용 자리가 거기 매여 있다.
⚠ `email_verified` 는 **안 걸었다** — 지금 계정들이 확인 절차를 안 거쳤을 수 있어,
걸면 전 직원이 그날로 막힌다.
▶ 더 단단하게 하려면 구름함수로 «직원이다»를 계정에 새기고(custom claim) 그것을 보면 된다.
지금 저장소에 `setCustomUserClaims` 는 **한 군데도 없다**(실측). 그것은 다음 일이다.

## ★★ 올리개가 «조이는 고침»을 아예 못 하고 있었다

`scripts/storage-rules-deploy.js` 의 안전장치는 보조 함수가 한 글자라도 달라지면
멈춘다. 그것이 맞다 — 보조 함수 한 줄이 창고 전체의 문이다. 그런데 그 때문에
**조이는 고침조차 할 수가 없었다.** 그러면 다음 사람이 결국 `--force` 를 만든다 —
그 파일이 스스로 「만들지 말라」고 적어 둔 그것이다.

그래서 우회로 대신 «적어 두고 지나가는» 길을 냈다.
`docs/firebase-storage-보조함수-고침승인.txt` 에 **옛 몸과 새 몸을 그대로** 적으면
그 «하나»만 지나가고, 화면에 크게 찍힌다.

★ 이것은 `--force` 가 아니다. **옛 몸도 새 몸도 글자까지 맞아야** 지나가므로,
승인한 그 고침 말고는 어떤 흔들림도 다시 멈춘다(검사 ⑤⑥이 그것을 지킨다).
▶ 올린 뒤에 할 일: 콘솔 원문을 새 날짜 파일로 남기고 **승인 줄을 지운다.**
그때부터는 새 몸이 기준이라, 남겨 두면 다음 사람이 헷갈린다.
