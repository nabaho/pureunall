# 2026-09-16 · 「클릭도 안 했는데 메일쓰기가 열린다」 — 늦게 온 되부름이 화면을 빼앗았다

> 대표 지적: 「메일함에 갑자기 메일쓰기로 나온다 클릭도 안 했는데 오류 찾아내라」

## 무슨 일이었나

`openMailPage()` 는 자료함을 아직 못 읽었으면 이렇게 물러났다.

```js
if(!_matLoaded && Store.mode==='firebase'){ loadMaterials(()=>openMailPage(pre)); return; }
```

- 누른 순간에는 **아무 일도 안 일어난다** — 화면이 그대로다.
- 그래서 누른 사람은 「안 눌렸네」 하고 **메일함을 계속 본다.**
- 몇 초 뒤 자료함이 도착하면 되부름이 돌아 **쓰기 화면이 저절로 열린다.**

누른 적 없는 사람에게는 「갑자기 메일쓰기로 나온다」가 된다. **대표께서 보신 그대로다.**

⚠ 같은 흠이 `openSendMaterials` 에도 있었다(자료 고르기 팝업이 늦게 튀어나온다).

## 고침 — 자리를 적어 두고, 옮겼으면 버린다

```js
function screenSig(){ /* 화면 · 갈래 · 읽는 중 · 칸 */ }
function matLater(go){
  const at = screenSig();
  toast('자료함을 읽고 있습니다…', 2500);
  loadMaterials(function(){ if(screenSig() === at) go(); });
}
```

- ⚠ **고치는 자리는 «되부름»이지 openMailPage 가 아니다.** 눌린 순간의 자리를 적어 두고,
  자료가 도착했을 때 그대로면 잇는다. 옮겼으면 **조용히 버린다** — 옮긴 사람의 화면을
  빼앗지 않는 것이 요점이다.
- ⚠ 「어디인가」에 **읽는 중(mbOpen)·칸(mbBox)까지** 넣는다. 같은 메일함 안에서 한 통을
  열었거나 칸을 옮긴 것도 «자리를 옮긴 것»이다.
- ⚠ 기다리는 동안 **한마디 한다.** 안 그러면 누른 것이 아무 일도 안 한 것처럼 보여
  또 누르게 되고, 그만큼 되부름이 쌓인다.

## 덤 — 검사 하나가 「지금 값」을 박아 두고 있었다

`cards-mail-always-own-window.test.js` 가 `loadMaterials(()=>openSendMaterials(id, opt))` 를
**글귀 그대로** 박아 두어, 기능은 그대로인데 감싸기만 바꾸자 깨졌다.
지킬 것은 «무엇으로 감싸느냐»가 아니라 «opt 를 들고 다시 들어가느냐»라서 그렇게 고쳐 썼다
(CLAUDE.md 「지금 값이 아니라 규칙을 못 박는다」).
