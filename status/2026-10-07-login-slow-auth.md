# 2026-10-07 · 「앱 들어갔다 나오면 로그인 화면이 떴다가 또 로그인된다」 — 원인과 고침 (fix/portal-login-flash)

대표 보고(폰 S25 캡쳐 — 포털 로그인 화면): 「자꾸 로그인 이후에 앱에 들어갔다 나오면 튕겨서 다시 로그인 하는 화면
나오고 또 로그인되고 반복한다 정확한 이유 좀 찾아 해결해라」.

## 원인 (증거 셋)
1. **실제 로그아웃이 아니었다** — 서버 login_events: 대표 폰(크롬 4r4n)의 10/7 실제 로그인은 12:15 한 번뿐
   (지문·카카오·비밀번호 어느 길이든 남는다). 튕긴 횟수만큼 로그인이 없었다.
2. **까닭 한 줄이 없었다** — #2075 의 «지난번 로그아웃» 줄은 포털이 «로그인 없음»을 확정할 때만 붙는다.
   캡쳐에 없었다 = 포털은 «없음»을 확정한 적이 없다.
3. **구글 인증 도구(10.13)는 저장된 로그인을 쓰기 «전에» 서버에 다녀온다** — 원문 확인:
   `initializeCurrentUser → reloadAndSetCurrentUserOrClear → _reloadWithoutSaving`(열쇠 갱신 + accounts:lookup).
   폰이 앱을 오가며 막 깨어나면 이 왕복이 8초를 넘긴다.
   → 포털: 8초 안전장치가 가림막을 걷어 그 밑의 로그인 화면이 드러났다 → 응답이 오면 저절로 포털 = «또 로그인됨».
   → 이알피: 8초 뒤 대기를 풀고, 확인 중(currentUser 비어 있음)을 «로그인 없음»으로 읽어 자물쇠를 띄웠다.

## 고친 것
- `enter.html` 가림막: 8초가 지나도 인증 도구가 있으면 걷지 않고 「연결이 느려 로그인 확인이 늦어지고 있습니다…」 +
  「기다리지 않고 로그인 화면 보기」 단추. 마지막 안전망 40초(구글 요청 30초보다 길게). 인증 도구가 없거나
  카카오에서 돌아온 참은 예전대로.
  ⚠ 로그인이 «없는» 기기는 영향 없음 — 저장된 로그인이 없으면 서버에 안 묻고 곧장 «없음» → 바로 로그인 화면.
- `pu-erp.html`: 포털 경유 대기 8초 → 40초. 자물쇠 판정은 인증 확인이 끝날 때까지(`window.__puAuthKnown`) 0.5초마다 다시 본다.
- 시간으로 판정하던 곳은 이 두 곳뿐 — 다른 앱은 onAuthStateChanged(null) 뒤에만 PuGate 를 띄운다.
- 검사 `tests/login-slow-auth-no-flash.test.js` 7개(가림막은 가짜 시계로 실제로 돌림) — 일부러 망가뜨린 10가지 모두 운다.

## 남은 것
- 근본적으로 «왕복 자체»를 줄이는 길(저장된 로그인을 먼저 보여 주고 뒤에서 확인)은 보안 판단이 필요해 안 했다.
- 폰에서 실제로 «느리다» 화면이 뜨는지는 대표 폰으로만 확인된다.
