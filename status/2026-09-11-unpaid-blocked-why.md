# 2026-09-11 · 거래내역 — 「받을 항목은 있는데 금액이 비었습니다」를 말해 준다

- PR: (열면서 채움)
- 무엇: 성공보수를 「%」로 두고 **승소금액을 안 넣으면 금액이 0 이 되어 후보에서
  «말없이» 빠지던 것**을, 거래내역이 그 자리에서 알려 주게 했다.
- 왜: 건의 2026-09-10 「2025년 수임 사건의 성공보수가 2026년에 들어왔는데
  거래내역에서 매칭이 안 됩니다」 · 대표 결정 2026-09-11 「원인 확인 후 고치기」

## ★ 실측 — 해가 바뀐 것과는 상관이 없다

후보 목록(`pending`)에 **연도 거르개는 없다.** 건의자가 「2025년 건이라서 그런가」로
읽은 것은 자연스럽지만 원인이 아니다. 진짜 원인은 `erpUnpaidParts` 의 이 한 줄이다.

```js
function add(kind, splitLabel, kindLabel, fee, ...){
  var f = parseInt(fee, 10) || 0;
  if(f <= 0) return;        // ← 여기서 «말없이» 빠진다
```

`caseSuccessFeeAmount` 는 성공보수가 `percent` 일 때 `승소금액 × %` 를 낸다.
승소금액이 비면 0 이고, 그러면 위 줄에서 조용히 사라진다.

## ⚠⚠ 진짜 결함은 「말없이」다

사건 편집창에는 **이미 경고가 있었다** — 「⚠️ 승소금액을 넣어야 입금관리에 뜹니다」.
그런데 **편집창을 열어야만 보인다.** 돈을 찾는 사람은 거래내역에 서 있지 사건
편집창에 있지 않다. 게다가 거래내역의 「왜 후보가 없나」는 이 경우를
**「등록된 업체지만 받을 항목이 없습니다」**로 잘못 말했다 — 건은 이미 있는데
「사무관리에 건을 만드세요」라고 안내한 셈이다.

## 고친 것

| 어디 | 무엇 |
|---|---|
| `erpUnpaidBlocked(it)` (새 함수, `erpUnpaidParts` 옆) | 「받을 것이 있는데 금액을 못 내는」 항목을 찾아 까닭·고치는 법과 함께 돌려준다 |
| 거래내역 `whyNone` | `blocked` 갈래를 새로 — 「받을 항목 없음」과 **갈라서** 말한다 |
| 거래내역 표 | 「받을 항목은 있는데 금액이 비었습니다 — 성공보수」 + 무엇이 비었는지·어떻게 고치는지를 말풍선에 |

## 되돌리지 말 것

- ⚠⚠ **`erpUnpaidParts` 를 고치지 않았다.** 금액 0 짜리를 후보에 넣으면 매칭·합계가
  모두 흔들린다. 빠지는 것은 그대로 두고 «왜 빠졌는지»만 따로 알려 준다.
- ⚠ 화면에서 `blocked` 갈래를 **`noitem` «앞»에** 그려야 한다. 뒤에 두면 `noitem` 이
  가로채 영영 안 보인다(검사 ⑥ 이 차례까지 못 박는다).
- ⚠ 사건 편집창의 경고를 지우지 말 것 — 두 자리가 같은 말을 해야 고치러 갔을 때 또 안 헤맨다.

## 아직 확인 못 한 것

**그 건의가 정말 이 경우인지는 실제 자료를 봐야 확정된다.** 나는 운영 자료를 못 읽는다.
이제 거래내역이 스스로 말해 주므로, 그 입금 줄을 열어 보면 바로 알 수 있다.
- 「받을 항목은 있는데 금액이 비었습니다」로 뜨면 → 사건을 열어 승소금액을 넣으면 끝.
- 다른 말이 뜨면 → 그 말이 곧 다음 단서다(업체를 못 찾음 / 금액이 안 맞음 / 항목이 없음).
