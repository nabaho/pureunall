## 무엇을 했나
계획 5(`docs/superpowers/plans/2026-11-15-quote-auto-plan5-case-stage-marks.md`)의 **단계 D** — 대표 승인 2026-11-15 「D 만들기」.
계약 창의 «⚖ 심급·단계» 줄 아래에, 사람이 ☑ 한 단계의 **다음 단계**를 «↪ 후속 계약 후보»로 보여 준다
(지노위→중노위→행정소송 · 요양→심사→재심사→행정소송, 순서는 `caseNextStageCode`). 누르면 사건의 「재심·후속사건 계약 등록」과 **같은 길**로 새 계약 창이 열린다.

## 어떻게 열리나 (새 길을 만들지 않았다)
`erpStageGoFollowup` 이 씨앗을 `sessionStorage`(`ERP_CT_SEED_KEY`)에 넣고 계약 창을 닫는다 → 계약관리의 기존 `useEffect(!modal → takeNewContractSeed)` 가 씨앗을 받아 «계약 추가» 창을 연다(여느 새 계약과 같은 검사: 월 잠금·업체 연결·중복 — 원계약과 이어진 같은 사업장은 「중복이 아닙니다」로 나온다).
씨앗은 원계약의 사업장·담당·사건 유형·근로자를 잇고, `parentContractId`·`stageCode`(다음 단계)·`parentCaseId`(이관해서 생긴 원심 사건이 있으면)를 단다. 업무 요약은 `[중노위] ` 를 앞에 붙여 40자.

## 정한 것
| 정한 것 | 까닭 |
|---|---|
| 자동으로 계약을 만들지 않는다 — 창이 «열릴 뿐» | 계획 §4-4, 「이관은 사람」과 같은 결 |
| 후보는 사람이 ☑ 한(checked) 단계에서만 · ✕ 한·읽기만 한(auto)·이미 맡은 다음 단계는 안 낸다 | 잘못 읽은 단계가 후속 계약으로 번지지 않게 |
| **계약확정 뒤에만**(확정·이관·종료) · 상담접수·계약협의·취소는 안 낸다 | 확정 전 계약에서 다음 단계 계약을 권하면 이르다(계획에 명시는 없던 내 판단 — 바꾸기 쉽다 `erpStageNextCandidates`) |
| 저장된 계약(`props.cur`)에서만 | 새 계약 창·고치는 중의 값이 아니라 «저장된 단계»로 판단. 쓰던 창의 입력은 임시저장에 남는다 |
| 금액·기간은 씨앗에 안 싣는다 | 단계마다 새 계약 — 금액이 겹쳐 잡히지 않게 |
| 이미 만든 후속 계약(`parentContractId`+`stageCode`)이 있으면 단추 대신 «✔ 후속 계약 있음 · 계약번호» | 같은 단계 계약이 둘 생기지 않게(지워진 것은 «없음») |
| 이 사건 유형에서 못 고르는 단계는 안 낸다 | 저장 때 조용히 지워지는 값을 권하지 않는다 |
