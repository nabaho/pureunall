# 2026-11-18 · 건의한 본인은 로그인하면 «해결됐는지 반드시 확인» — 경고 표시

상태: 코드 완료 · 합쳐져 배포돼야 직원 화면에 나타난다 · 진짜 서버 자료·진짜 로그인으로는 «확인하지 못했다»(가짜 자료로 확인창·단추 모양만 봄)

- 대표 지시: 「건의한 본인은 로그인하면 건의함 해결됐는지 반드시 확인해달라. 이렇게 경고 표시를 하게 해달라」
- 가지: `claude/suggestion-login-confirm` · 고친 곳: `enter.html`(포털 건의함) 한 파일 + 검사 + 이 기록·`docs/규칙/건의함.md`

## 한 것

1. 로그인 직후 뜨는 확인 창을 «🎉 해결되었습니다» → **«⚠ 건의 해결 여부를 확인해 주세요»** 경고로 바꿨다(붉은 머리·경고 상자 — 반드시 확인, 직접 확인해야 최종 종료).
2. **확인 창이 가장 먼저** — 관리자 «처리할 건의» 팝업은 확인 창이 닫힌 뒤에 뜬다(`sgCheckResolved(after)`).
3. 첫 칸을 「나중에 확인」→ **☑ 해결됐어요** 로 바꿨다(Enter 한 번에 넘어가던 것).
4. 「나중에 확인」으로 넘겨도 **«💬 건의하기» 단추가 붉게 ⚠ 깜빡이고** 건수가 title 로 뜬다(`sgSetNeed`) — 확인하면 거둔다. 움직임 줄이기 설정을 따른다.
5. 건의함 안쪽(직원 홈·관리자 목록) 위에 **「지금 확인하기」 경고 띠**, 내 진행 목록에 「⚠ 확인 필요」.

## 바꾸지 않은 것

- 확인 창을 «못 닫게» 막지 않았다(다른 업무를 못 보게 되므로) — 대신 확인할 때까지 표시가 남는다.
- 서버 규칙·감시 도구·답변 세 자리 쓰기·팝업 대상 판정(`!seen && status==='done'`)은 그대로.
- 단추는 떠 있게 하지 않았다(공용 앱바 규칙) — 머리줄 `#sgFab` 안의 글자·색만 바꿈.

## 검사·검토

- 새 `tests/suggestion-login-confirm.test.js` 14개 — 경고 머리·문구, 확인 창 → 관리자 팝업 순서(진짜 함수를 돌려 «닫힌 뒤»에 불리는지), 나중에 확인 뒤에도 단추 표시가 남는지, 첫 칸·다음 칸 포커스, 관리자 단추 경고, 띠, 떠 있지 않음. **일부러 망가뜨린 복사본 8가지를 모두 잡는다**(임시 폴더에서 확인).
- 전체 검사 31,014개 통과(실패 0) — 최종 코드로 다시 돌림.
- 자동 검증(antigravity): **통과**. «낮음» 4건을 고쳤다 — 띠 단추 높이 28px→36px · 공백 없는 긴 제목 줄바꿈 · 한 건 확인 뒤 다음 ☑ 칸으로 포커스 · 관리자 단추 ⚠ 를 «내 건의 확인 대기» 수로 맞춤. 이 검증은 고치기 «전» 코드로 했고, 고친 뒤에는 위 검사·전체 검사로 확인했다(검증을 다시 돌리지는 않았다).
- 보안 검토: 첫 시도는 시간 안에 끝나지 않아(통과로 안 침) 최종 코드로 다시 돌렸고 **발견 사항 없음**. 이전 시도의 작업자 1개는 아직 일하는 중이라 Orca 가 스스로 정리하게 둔다.
- 화면: 지어낸 자료로 PC(1366)·폰(360)에서 경고 창·붉은 ⚠ 단추·경고 띠를 직접 봤다. **진짜 포털 전체 화면(가짜 로그인)은 자동 로그인이 풀려 못 봤다** — 실제 enter.html 의 CSS·마크업·함수를 그대로 담은 확인용 페이지로 대신했다.
