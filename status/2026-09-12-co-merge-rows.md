## ⚠ 먼저 — 검토 보고 ②를 바로잡는다

「앱이 스스로 경고만 하고 고칠 길이 없다」고 적었는데 **과했다.**
재 보니 이미 **상호↔사업자번호 다리**(`nameIdx`)가 있어 대부분은 자동으로 붙는다.

| 경우 | 지금 | |
|---|---|---|
| 등록증「주식회사 가나」 + 명함「가나」 | **한 줄** | 이미 붙는다 |
| 명함만 「가나」「(주)가나」 | **한 줄** | 이미 붙는다 |
| 등록증 둘(번호 다름) | 두 줄 | **맞는 동작** — 다른 사업자다 |
| 등록증「가나상사」 + 명함「가나」 | 두 줄 | ← **여기만 남는다** |

`_norm` 이 (주)·주식회사·㈜·빈칸을 떼므로 표기 차이는 이미 이어진다.
**남는 것은 이름 자체가 다르게 적힌 경우뿐**이고, 그것은 짐작으로 할 수 없다.

## ⚠⚠ 그래서 «짐작하지 않는다»

이름이 겹쳐도 다른 곳인 쌍이 실제로 있다 — 「천성」/「천성전자」·「화담원」/「화담원 아산점」.
급여데이터함이 **같은 자리에서 겪었고**(STATUS 2절), 그래서 그쪽도 짐작을 사람 손 아래 두었다.
**후보를 지어내지 않는다.** 사람이 상호나 사업자번호를 적어 고른다.

## 만든 것

| | |
|---|---|
| 짚어 두는 자리 | `coInfo/{열쇠}/sameAs` — 담당·메모와 **같은 저장 길**(`coSaveInfoField`) |
| 줄을 모으는 곳 | `coListBuild` 안의 `_same()` — 열쇠를 정하는 **두 자리**에만 건다 |
| 찾기 | `coMergeFinds` — 적은 말로 상호·**사업자번호**를 훑는다. 빈 말이면 하나도 안 준다 |
| 고르기 | `coAskMerge` → `coMergePickHtml` → `coDoMerge`(묻고 나서) |
| 되돌리기 | 남은 줄의 `coMergeRowHtml` 에 「○○ 풀기」 |

**실측:** 두 줄 → 합치면 한 줄(명함 2장·서류 1건이 함께 옮겨감) → 풀면 다시 두 줄.

## ★ 못 박은 것

1. **서로 가리키면 아무 데도 안 간다.** 가→나·나→가로 두면 둘 다 제자리다.
   조용히 한쪽을 고르면 다시 그릴 때마다 답이 달라진다.
   ⚠ 이빨 확인에서 이 고장이 **샜다** — 줄 «수»만 보면 둘이 자리를 맞바꿔도 그대로 둘이다.
   무엇이 어느 줄에 앉았는지까지 보게 고쳤다.
2. **되돌릴 수 있어야 한다.** 합쳐진 쪽은 목록에서 사라지므로, 남은 줄이 유일하게
   되돌릴 수 있는 자리다. 푸는 길이 없으면 잘못 합친 것을 영영 못 되돌린다.
3. **묻고 나서 합친다** — 무엇이 몇 개 옮겨가는지, 다시 풀 수 있다는 것까지 말한다.
   ⚠ 이것도 이빨 확인에서 **샜다**. 「`confirm(` 이 있나」로만 보면 `if(false && confirm(…))`
   도 통과한다 — **실제로 눌러** 「아니오」면 안 쓰는지 보게 고쳤다.
4. **합친 뒤 남는 줄을 연다** — 아무것도 안 열리면 「눌렀더니 회사가 없어졌다」가 된다.

## ⚠ 「확인 필요」에 넣었다가 «되돌렸다»

처음엔 합치기 줄을 ⚠ 확인 필요 카드에 넣고, 「번호 없음」을 그 개수에 셌다.
그랬더니 **고유번호증 기관처럼 사업자번호가 원래 없는 곳**이 영영 노래졌다 —
늘 노란 딱지는 눈이 배경으로 배운다. 검사가 바로 걸었다
(`cards-co-panel-tidy` 의 「멀쩡한 회사에 확인 필요 0이 붙으면 안 된다」).
합치기 줄은 **제 자리**(`coMergeRowHtml`)로 옮겼다.

## 덧 — 「확인 필요」 셈을 한 곳으로 모았다

카드(`coNeedHtml`)와 숫자 칸(`coTilesHtml`)이 **똑같은 셈을 따로** 적고 있었다.
한쪽에 한 줄을 더하다 「숫자 칸은 2인데 카드에는 3줄」이 될 뻔해서 `coNeedCount` 로 모았다.
