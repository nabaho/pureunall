# 2026-09-18 · 신청서의 «담당자»를 제 칸에 담는다

- 대표 지시: 「**읽히게**」 — 신청서 2쪽의 「담당자 정보」 표를 가리키셨다.

## ★ 실측이 짐작을 뒤집었다 — 판독은 «이미 다 읽고 있었다»

제가 「안 읽힌 것 같다」고 여쭈었는데, 서버를 직접 읽어 보니 **여섯 칸이 모두 `pairs` 에
들어 있었습니다.**

| 칸 | 읽은 값 |
|---|---|
| 담당자명 | 김철수 |
| 담당자 이메일 | chulsoo@daum.net |
| 담당자 부서 | 총괄 |
| 담당자 직위 | 감사 |
| 담당자 유선 | 041-123-4567 |
| 담당자 휴대전화 | 010-1234-5678 |

문제는 **«어디로 갔느냐»**였습니다.

1. **이름·부서·직위는 어느 칸에도 안 갔다** — `pairs` 에만 남아 서류 밑에 묻혀 있었다.
2. ⚠ **이메일·휴대전화는 더 나쁘게 «회사 칸»에 앉았다** — 기업 상세의 「이메일」이
   담당자 개인 메일이고 「휴대폰」이 담당자 번호였다.
   **그 사람이 나가면 못 쓰는 번호가 회사 번호로 남는다.**

실측: 담당자가 읽힌 서류 **8곳**. 이름표가 제각각이라 하나도 못 갔다 —
담당자명 · 담당자 성함 · 담당자 성명 · 담당부서 · 담당자 부서 · 담당자 연락처 · 담당자 유선 …

## 고친 것 셋

### ① 이름표 사전에 담당자 표기 열넷

`PAIR_TO_KEY` 에 담당자명·성함·성명·이름 / 담당부서·담당자 부서 / 담당자 직위·직책 /
담당자 이메일·메일 / 담당자 휴대전화·휴대폰 / 담당자 유선·전화·전화번호·연락처를 더했다.

⚠ **이름은 `name` 그대로** 둔다 — 서식이 명함이 되는 길(`formHasContact`)이 이 칸을 본다.
바꾸면 담당자가 적힌 서식이 명함 후보에서 통째로 빠진다.

### ② ⚠⚠ 기업 상세로 보낼 때 «서식일 때만» 사람 연락처를 갈라낸다

`sendToCoInfo` 안에 `contactKeys` 를 두었다 —
`contactName` · `contactDept` · `contactTitle` · `contactTel` · `contactMobile` · `contactEmail`.

- **명함으로 갈 때는 안 옮긴다.** 명함의 이메일·휴대폰은 «그 사람 것»이 맞다.
  그래서 이 갈아끼우기는 `sendToCoInfo` 안에만 있다(중소기업확인서 `smeKeys` 와 같은 결).
- ★ **회사 대표번호(`companyTel`)는 그대로** 둔다. 그것은 회사 것이다.

### ③ 기업 상세 화면에 여섯 칸

`CO_FIELDS` 에 「담당자 · 담당자 부서 · 담당자 직위 · 담당자 전화 · 담당자 휴대전화 ·
담당자 이메일」을 냈다. **담는 곳과 보이는 곳은 늘 짝이다.**

## 안 한 것

- **판독 지시문을 안 고쳤다.** 고치면 판 번호가 올라 이미 읽은 것이 다시 읽히고
  그것이 그대로 요금이다. **읽는 것은 이미 되고 있으므로 «옮겨 담기»만 한다(요금 0원).**
- **이미 회사 칸에 들어간 옛 값은 안 지운다.** 사람이 ✎ 로 고치는 길이 열려 있다
  (2026-09-18에 넣었다).
