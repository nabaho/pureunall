# 2026-11-22 · 다음메일에 새 폴더가 생기면 푸른메일함에도 저절로 — 열린 화면 틈 고침 (mail-new-folder-follow)

상태: 코드·검사 완료 · **화면(pu-cards.html)만 고침 — 서버 함수 배포 없음** · 실서버·실제 화면에서는 **아직 확인하지 못했다**(합쳐져 배포된 뒤 대표 화면에서 확인)
가지: claude/mail-new-folder-follow
작업폴더: .claude/worktrees/mail-star-60bc62

대표 지시: 2026-11-22 「다음메일에서 새로운 폴더 만들면 푸른메일함도 동기화 되어 자동으로 만들어지고 거기에 메일이동되면 자동으로 연결되게 해달라」 (푸른메일함 「푸른 분류 → 업무별」 옆줄과 다음메일 「내 메일함」 폴더 목록 화면 두 장을 함께 주심)

## 1. 먼저 알아낸 것 — «이미 되어 있던 것»과 «빠져 있던 것» (코드만 읽고 확인, 실서버 자료는 읽지 않았다)

이미 되어 있던 것 (새로 만들지 않았다):
- **서버가 다음메일 폴더 «전부»를 읽어 온다** — `syncMailbox` 가 10분마다(한국시간 07:00~21:59) `client.list()` 로 폴더 목록을 받아 `mailbox/folders/<slug>` 에 적는다(`functions/mail-sync.js` runSync ①). 폴더를 만든 사람이 누구든, 이름이 무엇이든 «손으로 만든 폴더»는 kind `custom` 으로 적힌다. 읽기만 한다(다음메일에는 아무것도 쓰지 않는다).
- **새 폴더는 「업무별」 칸으로 저절로 선다** — `mbBins()`(pu-cards.html)가 적어 둔 칸 + 「아직 손대지 않은 다음 폴더」를 합쳐 칸 목록을 만든다. 코드 주석도 이미 «다음에 새 폴더가 생기면 여기 저절로 나타난다 — 적어 두는 일 없이» 라고 적혀 있다.
- **메일을 폴더로 옮기면 자동으로 따라간다** — 다음 회차에 새 폴더가 그 메일을 새 번호로 받아 오고, 옛 자리(받은메일함 등)에서는 `followGone` 이 빠진 것을 걷는다(`meta.gone`). 칸이 곧 폴더라서 «연결»을 따로 만들 필요가 없다.
- **열려 있는 화면이 서버 회차를 따라온다** — `mbLiveStart/mbLiveApply`(2026-10-10 대표 지시). 회차 기록(`mailbox/meta`)을 듣다가 바뀌면 뺀 메일을 빼고 새 번호를 받아 붙인다.

빠져 있던 것 (이번에 고친 것):
- **빈 새 폴더만 생긴 회차에는 열려 있는 화면이 폴더 목록을 다시 읽지 않았다.** `mbLiveApply` 는 폴더 목록(`loadMailFolders`)을 «뺀 메일이 있거나 새 메일이 온 회차»에만 다시 읽었다. 폴더만 만들었고 그 사이 다른 새 메일이 한 통도 없으면 옆줄에 안 나타났고, 새로고침(📥) 하거나 화면을 다시 열어야 보였다. (메일이 자주 오는 업무 시간에는 가려져 있었을 가능성이 크다 — 그래서 «가끔 안 보이는» 모양이었을 것으로 «추정»한다. 대표 화면에서 일어난 일을 재현해 본 것은 아니다.)

## 2. 바꾼 것 (화면: `pu-cards.html` 의 `mbLiveApply`)
- 서버 회차 기록의 폴더 수(`meta.folders`)가 «폴더 목록을 읽을 때의 값»과 달라졌으면(생기거나 없어졌으면) 폴더 목록을 다시 읽고 옆줄(`renderPCSide`)을 새로 그린다.
- ⚠ 폴더 «기록» 개수와 견주지 않고 **회차 기록끼리** 견준다 — 다음메일에서 지우거나 이름을 바꾼 폴더의 옛 기록이 서버에 남아 있으면(아래 3번) 개수가 늘 달라 회차마다 다시 읽게 되기 때문이다.
- 숫자가 아니면(처음·옛 기록·못 읽음) 견주지 않는다. 합치기 «전에» 견준다. 같은 변화는 «한 번만» 알아챈다.
- 메일을 읽는 중이면 옆줄만 새로 그리고 목록은 건드리지 않는다(읽던 자리가 튀지 않게 — 기존 규칙 그대로). 글을 치는 중도 같다.
- 보이는 모양·자리·글자는 바꾸지 않았다(대표 원칙: 기존 기능과 위치 유지). 서버는 건드리지 않았다.

## 3. 못 고친 것·모르는 것 — 대표 판단이 필요하다
- **다음메일에서 폴더를 «지우거나 이름을 바꾸면» 푸른 쪽에 옛 칸이 남는다(코드로 확인).** 서버는 «지금 있는 폴더»만 적고, 없어진 폴더의 기록(`folders/<slug>`·`msgs/<slug>`)을 걷는 곳이 없다(걷는 곳은 우리 앱의 «폴더 지우기·이름 바꾸기» 단추뿐 — `manageMailFolder`). 이름을 바꾸면 «옛 이름 칸(옛 메일 그대로)»과 «새 이름 칸»이 함께 보일 수 있다. 이번 요청(새 폴더 만들기)에는 없던 일이라 **고치지 않았다** — 지우는 일이 따라서, 어떻게 할지(숨기기·확인 뒤 걷기) 정해야 한다.
- **반영 속도는 최대 약 10분이다(업무 시간 07~22시).** 바로 보려면 메일함의 📥 새로고침. 서버 주기를 줄이는 것은 비용 문제라 건드리지 않았다.
- **손으로 지정한 담당자·칸 지정은 메일을 «옮기면» 새 번호로 바뀌어 이어지지 않을 수 있다** — 메일 한 통에 박은 담당자(`mailWhoMsg`)·한 통을 옮긴 쪽지(`mailPut`)는 `칸:번호` 열쇠이고, 다음메일에서 폴더를 옮기면 번호가 바뀐다. 코드로 열쇠 모양만 확인했고 «실제로 끊기는지»는 확인하지 못했다.
- 실서버의 폴더 목록(`mailbox/folders`)은 읽지 않았다 — 지금 화면에 11·12·13번 폴더가 실제로 들어와 있는지는 모른다.

- **폴더를 «한 개 지우고 한 개 만든» 회차나 «이름만 바꾼» 회차는 폴더 수가 그대로라 이 방식으로는 못 알아챈다**(자동 검토 지적, 낮음). 서버가 회차 기록에 폴더 목록의 «지문»을 함께 적게 하면 잡을 수 있지만 서버 함수 배포가 필요해 이번에는 하지 않았다. 그런 경우도 메일 변화가 있는 회차에는 목록을 다시 읽으므로 곧 따라온다.
