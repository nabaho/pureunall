# 주석 걷개를 «조각»에 쓰던 검사 48파일 — 277곳이 주석을 한 글자도 안 걷고 있었다

가지 `claude/wonderful-dijkstra-fc7ba2` · 2026-09-18

## 무엇이 문제였나

`tests/strip-comments.js` 의 `stripComments()` 는 주석을 **`<script>`·`<style>` 태그 «안»에서만**
걷는다. 그렇게 만든 까닭은 머리말에 있다 — 마크업의 `accept="image/*"` 에 든 별표 앞 빗금을
주석 시작으로 읽고 **673KB 중 230KB(34%)** 를 삼킨 사고가 2026-08-30 에 있었다.

**뒤집어 보면 태그가 없으면 한 글자도 안 걷는다.** 그런데 검사 48파일이 함수 «조각»과
«.js 파일»에 그대로 쓰고 있었다:

```js
const fn  = stripComments(cutFn(RAW, 'function autoReadPending('));   // ✗ 조각엔 태그가 없다
const IDX = stripComments(fs.readFileSync('functions/index.js'));     // ✗ .js 도 태그가 없다
```

두 방향으로 어긋난다. 둘째보다 **첫째가 훨씬 무섭다**:

| | 무슨 일이 벌어지나 |
|---|---|
| ① `assert.match(fn, /무엇/)` | **주석에 그 낱말이 있으면 코드에 없어도 통과한다** — 조용히 초록 |
| ② `assert.ok(!/옛길/.test(fn))` | 주석이 옛 이름을 «설명»만 해도 깨진다 (2026-09-18 `nas-connect-fail-help` 이 실제로 이렇게 깨졌다) |

## 고친 길 — 걷개 «자신»에게 문지기를 달았다

부르는 쪽 277곳을 다 고치는 것만으로는 다음 사람이 또 밟는다. 그래서 걷개에 문지기를 뒀다.

```
통째 HTML 문서(.html 을 통으로 읽은 것)   →  stripComments
그 밖의 모든 것(.js 파일 · 함수 조각 · CSS) →  stripJs      ← 이미 있던 함수다
.html 도 .js 도 받는 «읽기» 도우미        →  stripByName  ← 이번에 더했다
```

`stripByName(이름, 소스)` 는 **파일 이름으로** 고른다. 내용을 보고 짐작하지 않는다 —
`<script` 라는 글자는 HTML 을 «짓는» .js 안에도 있을 수 있어서, 내용으로 가르면
바로 그 파일에서 틀린다. 부르는 쪽은 이름을 이미 알고 있다.

`stripComments` 는 이제 **걷을 태그가 없는데 걷을 주석이 있으면** 그 자리에서 터진다.
«모양»이 아니라 «결과»를 본다 — 그 부름이 «아무 일도 안 하면서 한 것처럼 보일 때»만 운다.

⚠ `stripComments` 를 「태그가 없으면 JS 로 본다」로 바꾸지 **않았다.** 그러면 HTML 을 짓는
함수 조각(`accept="image/*"` 를 품은 것)에서 2026-08-30 사고가 되살아난다. 둘을 «가르고»
잘못 든 쪽에서 소리가 나게 했다.

## 실제로 무엇을 찾았나

**① 앞으로 조용히 통과할 수 있었던 자리 277곳** — 오늘 기준으로 «잘못된 초록»은 없었다.
고친 뒤 전체 검사가 그대로 통과한다. 즉 지금 코드는 규칙을 지키고 있다.
값은 «앞으로»에 있다: 이 자리들은 주석에 낱말 하나만 스쳐도 눈을 감았다.

그 «앞으로»가 얼마나 무서운지 실제로 재 봤다. `pu-photos.html` 에서 판독 문지기를
**통째로 지우고**, 같은 글자를 주석에만 남겼다:

```js
/* 전에는 readSkipWhy({ meta: job.meta }) 로 막았다 */
if (readQuotaOut) { renderReadAsk(); return; }     // ← 문지기가 사라졌다
```

| | `tests/photos-read-gate.test.js` 결과 |
|---|---|
| 고치기 전(`stripComments`) | **22 통과 · 0 실패** ← 문지기가 없는데 초록이다 |
| 고친 뒤(`stripJs`) | 21 통과 · **1 실패** ← 잡는다 |

「올렸는데 판독이 안 된다」는 이 저장소가 가장 여러 번 밟은 자리다. 그 자리를 지키라고
둔 검사가 **주석만 보고 통과하고 있었다.**

**② `tests/erp-backup-scan-index.test.js` — 진짜 코드 4,970자를 삼키고 있었다**

이 파일은 공용 걷개를 안 쓰고 **제 손으로 걷개를 적어** 두었는데, 그것이 마크업까지
주석으로 읽었다. `pu-erp.html` 5,058,598자를 놓고 재 보면:

| | 남은 양 | 삼킨 양 |
|---|---|---|
| 공용 걷개(옳다) | 4,460,718자 | 597,880자 (11.8%) |
| 제 손 걷개 | 4,455,748자 | 602,850자 (11.9%) |
| **차이 = 조용히 사라진 진짜 코드** | | **4,970자** |

2026-08-30 에 230KB 를 삼킨 것과 **같은 병**이다. 다행히 `pu-erp.html` 에는
`accept="image/*"` 가 없어 피해가 5KB 에 그쳤다. 공용 걷개를 쓰게 고쳤다.

**③ 제 손으로 걷개를 적어 둔 파일이 셋 더 있었다**
`fund-ui-structure` · `kcareer-hwp-name-fix` · `erp-backup-scan-index`.
사본은 본을 따라오지 않는다 — 셋 다 공용 걷개를 꺼내 쓰게 바꿨다.

## 되풀이를 막는 것 — `tests/strip-comments-guard.test.js`

⚠ 「stripComments 를 조각에 쓰지 마라」를 **글자로 찾지 않는다.** 그것은 모양을 못 박는
검사가 되어(CLAUDE.md 「검사를 쓰는 규칙」) 부르는 방식이 조금만 달라지면 헛돈다 —
실제로 부르는 길이 `cutFn`·`grab`·`조각`·`.slice`·변수로 받은 것 등 제각각이라
글자로는 어차피 다 못 찾는다(이번에도 세 갈래를 놓쳤고 문지기가 잡아냈다).

대신 문지기가 «살아 있는가»를 결과로 본다:

1. 조각을 넣으면 정말 소리를 내는가 — 주석에만 있는 낱말로 확인
2. 통째 HTML 은 그대로 지나가는가 — 헛소리를 안 하는가
3. 2026-08-30 사고(`accept="image/*"` 삼키기)가 되살아나지 않았는가
4. 걷개를 제 손으로 적어 둔 검사 파일이 없는가 ← **③을 이것이 찾아냈다**
5. **이빨** — 문지기를 실제로 떼어 내 위 검사들이 깨지는지 확인한다

조각에 `stripComments` 를 쓰는 검사는 **그 검사가 돌 때 그 자리에서** 터진다.
여기 목록을 손으로 늘릴 일이 없다.

## ⚠ 남은 것 — 걷개가 아직 «둘»이다

이 저장소에는 주석 걷개가 두 벌 있다. 이번에 손댄 것은 앞의 것뿐이다.

| | 어떤 것인가 | 쓰는 검사 |
|---|---|---|
| `tests/strip-comments.js` | 태그로 가른다. `stripJs` 는 **글자값을 모르는** 단순 걷개 | 약 200파일 |
| `tests/helpers/strip-comments.js` | **제대로 된 파서** — 글자열·정규식 안을 건드리지 않는다 | 14파일 |

```js

```
| 걷개 | 나온 것 |
|---|---|
| `helpers/주석걷기` | `var s = '<input accept="image/*">';` ← 지킨다 |
| `stripJs` | `var s = '<input accept="image` ← **삼킨다** |

즉 2026-08-30 사고가 «조각 안»에서는 아직 일어날 수 있다.
**오늘은 0건이다**(48파일을 계측해 재 봤다 — 아래). 조각들이 HTML 을 짓고 있지 않아서다.
하지만 `accept="image/*"` 를 품은 함수를 검사가 잘라 보는 날 조용히 되살아난다.

**다음 사람에게**: `stripJs` 가 `helpers/주석걷기` 를 부르게 하면 이 위험이 사라지고
걷개도 하나로 모인다. 이번에 안 한 까닭은 ① 277곳의 걷는 결과가 한꺼번에 바뀌고
② `helpers` 쪽 벗어남표(`\`) 처리에 확인할 것이 남아 있어서다 —
급하지 않지만 «알고 남겨 둔» 자리다. 문지기와 위 검사가 그동안 울타리를 지킨다.
