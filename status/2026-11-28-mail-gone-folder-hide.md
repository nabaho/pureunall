# 2026-11-28 · 다음메일에서 지우거나 이름을 바꾼 폴더 — 푸른 쪽 옛 칸 «숨기기» (mail-gone-folder-hide)

상태: 코드·검사 완료 · **서버 함수는 아직 안 올렸다**(합친 뒤 대표 승인을 받아 이름 찍어 올린다 — 아래 «배포») · 실서버·실제 화면에서는 **확인하지 못했다**
가지: claude/mail-gone-folder-hide
작업폴더: .claude/worktrees/mail-star-60bc62

대표 지시: 2026-11-28 「숨기기로 진행」 — 앞선 작업(2026-11-22 `status/2026-11-22-mail-new-folder-follow.md`, PR #3266)의 «남은 문제»에서 내가 물은 것에 대한 답이다. 「다음메일에서 지우거나 이름 바꾼 폴더의 푸른 쪽 옛 칸을 어떻게 할까요?」 → 숨기기.

## 1. 무엇이 문제였나 (코드로 확인, 실서버 자료는 읽지 않았다)
서버(`syncMailbox`)는 «지금 다음메일에 있는 폴더»만 `mailbox/folders/<slug>` 에 적었고, 없어진 폴더의 기록을 걷는 곳은 우리 앱의 «폴더 지우기·이름 바꾸기» 단추(`manageMailFolder`)뿐이었다. 그래서 다음메일에서 직접 폴더를 지우거나 이름을 바꾸면:
- 지운 폴더 → 푸른 분류 「업무별」 에 옛 칸이 계속 보이고, 통수·전체메일에도 옛 메일이 섞여 있었다.
- 이름 바꾼 폴더 → «옛 이름 칸»(옛 메일 그대로)과 «새 이름 칸»에 같은 메일이 두 번 보였다.

## 2. 바꾼 것 — «지우지 않고 숨김 표시만»
**서버** (`functions/mail-sync.js` · `functions/mail-box.js`)
- 한 회차에서 다음메일의 폴더 목록(거르기 «전» 전부)과 우리 기록을 견주어, 목록에 없는 폴더에 `gone`(숨김 표시 시각)만 적는다(`MB.vanishedFolders`).
- **폴더 기록·담긴 메일(`msgs`)·진행 표시(`sync`)는 지우지 않는다.** 같은 경로의 폴더가 다시 생기면 그 회차가 기록을 새로 적으면서 표시가 저절로 사라진다(되돌림).
- 안전장치: ① 목록에 **받은메일함이 없으면**(끊기거나 비어 온 응답) 아무것도 숨기지 않는다 ② 이미 표시한 것은 다시 적지 않는다(시각이 바뀌면 화면이 헛으로 다시 읽는다) ③ 스팸처럼 «안 가져오기로 한» 칸은 따로 걷는 길이 있어 건드리지 않는다 ④ 열 수 없게 된 «껍데기» 폴더도 목록에는 «있는» 폴더라 숨기지 않는다 ⑤ 실패해도 던지지 않는다(동기화는 계속).
- 본문 찾기(`searchMailbox`)가 «아는 폴더 전부»를 뒤질 때 숨긴 폴더를 뺀다(`MB.searchSlugs`) — 열 곳이 없어 「못 읽은 칸」만 늘던 것.

**화면** (`pu-cards.html`) — 모양·자리·글자는 바꾸지 않았다. 표시가 붙은 폴더를 아래에서 뺀다:
- 폴더 목록 `mbFolders()` → 업무별 칸(`mbBins`)·전체메일·통수 셈이 모두 같은 목록을 쓴다
- 사업장 메일 요약 셈 `mbSyncFolders()` (이름 바꾼 폴더의 같은 메일을 두 번 세지 않게)
- 담당자 「보는 사람 없는 칸」 점검 `mbBoxTodo()` (정해 둔 칸·셈에 온 칸 모두)

## 3. 일부러 건드리지 않은 것 · 한계 — 대표가 알아 둘 것
- **사용자가 직접 만든 푸른 분류 칸(저장된 칸)은 그대로 둔다.** 그 칸이 없어진 폴더에 이어져 있으면 담아 둔 옛 메일이 계속 보인다 — 사람이 만든 칸을 자동으로 건드리지 않는다.
- **숨긴 폴더를 «다시 보는» 화면은 없다.** 기록·메일은 서버에 그대로 있어 필요하면 꺼낼 수 있지만, 화면에서 되돌리는 단추는 만들지 않았다(같은 폴더가 다시 생기면 자동으로 돌아온다). 필요하면 알려 주시면 «숨긴 폴더 보기»를 만든다.
- (자동 검증 지적으로 고침 — 아래 5절) 이미 읽어 둔 표·씨앗에 든 옛 폴더의 메일은 폴더 목록을 읽을 때마다 읽어 둔 표에서 걷는다. 단 **사람이 만든 칸이 이은 폴더·손으로 옮긴 쪽지가 가리키는 폴더는 걷지 않는다**(사용자 자료). 그런 칸은 더 이상 갱신되지 않는 옛 메일만 보여 준다 — 안내가 필요할 수 있다.
- **일시적으로 폴더 목록이 «일부만» 오면**(받은메일함은 있는데 하위 폴더가 빠진 응답) 정상 폴더가 한 회차(업무 시간 10분) 동안 숨는다. 다음 회차가 기록을 새로 적으면서 표시가 풀린다(데이터 손실 없음). 「두 회차 연속 없을 때만 숨기기」로 더 조심할 수 있으나 숨김이 한 회차 늦어지고 상태가 늘어 이번에는 하지 않았다.
- 반영 속도는 서버 회차(업무 시간 10분마다)이고, 서버 함수를 올려야 시작된다. 올리기 전에는 아무것도 숨지 않는다(화면은 표시가 없으면 예전과 똑같다).
- 안내문 대장(`news-notice-log.js`)은 폴더 기록을 따로 읽는데 이번에 손대지 않았다 — 이름을 바꾼 폴더의 같은 안내문이 두 번 걸릴 수 있다(확인하지 않았다).
- 폴더 수가 같은 교체(한 개 지우고 한 개 만듦)는 열려 있는 화면의 «새 폴더 자동 갱신»이 못 알아채는 한계가 그대로다(2026-11-22 기록 3절). 이번 숨김 표시는 서버가 «목록 비교»로 정하므로 영향이 없고, 화면은 다음에 메일 변화가 있을 때나 다시 열 때 따라온다.

## 6. 배포 — 합친 뒤 대표 승인을 받는다
- **서버 함수 배포가 필요하다.** 최소: `syncMailbox`(예약 동기화에서 표시를 적음) · `pullMailbox`(수동 새로고침) · `searchMailbox`(본문 찾기). 같은 동기화를 먼저 돌리는 `mailContractSweep`·`runMailContractSweep` 도 올리면 같은 일을 한다(안 올려도 해롭지 않다 — 표시는 `syncMailbox` 가 적는다).
- 화면은 합쳐지면 웹 배포로 나간다. **화면이 먼저 나가도 해롭지 않다** — 표시가 없으면 예전과 똑같이 그린다.
- 올린 뒤 첫 회차에 «지금 이미 없는 폴더»에 표시가 한꺼번에 붙는다. 로그 줄 `syncMailbox 다음메일에서 없어진 폴더에 숨김 표시: N` 로 몇 개인지 본다 — **예상과 크게 다르면(옆줄이 갑자기 많이 줄면) 바로 알려 달라.**
