# 폰에서 글자가 작던 것 · 팝업에서 오른쪽이 잘리던 것

대표 지시 2026-09-26
「폰에서 글자가 작다. 그리고 팝업에는 오른쪽까지 확장해서 전체가 다 보이게 해라.」

편지를 700 → 980 으로 넓히면서 **두 가지가 따라오지 못했다.**

## ① 폰 — 980 고정이라 통째로 «줄여» 보여 줬다

폰 메일 앱은 폭이 넘치는 편지를 화면에 맞게 줄인다. 980 짜리가 375 폰에서는
**38% 로 줄어** 글자가 그만큼 작아진다. 넓혀서 얻은 것을 폰에서 잃고 있었다.

**고친 길 — 화면 크기별 규칙(@media).** 폰·웹메일에서만 칸을 쌓아 폭에 맞춘다.
★ **아웃룩은 @media 를 모른다** — 그래서 데스크톱 모습은 한 글자도 안 바뀐다.
★ **글자 크기는 안 건드렸다** — 줄이지만 않으면 14px 그대로가 폰에서 읽기 좋다.

실측(375px 폰):

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 편지 폭 | 980 (38% 로 줄여 보임) | **375 (안 줄인다)** |
| 본문 글자 | 14px × 0.38 ≈ 5px | **14px 그대로** |
| 자료 카드 | 세 칸이 짓눌림 | **한 장씩 쌓임 (361px)** |
| 가로 스크롤 | — | **없음** |

### ⚠⚠ 발송기에 «좁은 문»을 냈다 — 넓히지 말 것

발송기는 `<style>` 을 **속 글자까지 통째로 버린다**(`functions/mail-send.js`).
그래서 지금까지 화면 크기별 규칙을 쓸 수가 없었다. 이번에 **셋을 다 지킬 때만**
통과하는 문을 냈다:

1. **`@media` 블록 «안»**에 있는 규칙만 — 밖에 있으면 데스크톱까지 덮는다
2. 고르개가 **우리 반 이름(`.pu-…`)**일 때만
3. 값은 inline 과 **같은 잣대**(`STYLE_OK`) — `url()`·`expression()` 은 그대로 막는다

또 조건도 좁혔다: **화면 폭을 보는 것만**(`max-width`) 받는다. `@media print`·
`@media screen`·`min-width` 는 안 받는다.

⚠ **이 문을 넓히지 말 것.** 「받은 것 그대로 전달」로 **남의 편지 HTML 이 이 길로 들어온다.**
넓히는 순간 남의 CSS 가 우리 편지를 덮는다(글을 숨기거나 남의 서버 그림을 부른다).
검사가 남의 `<style>`·남의 반 이름·인쇄 규칙·`url()`을 모두 막는지 본다.

`class` 속성도 함께 열었다 — 규칙이 붙잡을 손잡이다. 값은 **`pu-` 로 시작하는 것만** 남긴다.

### ⚠ 하마터면 CSS 가 «글자로» 나갈 뻔했다

되살린 꾸밈을 **태그 거르개 «앞»**에 붙였더니, 거르개가 `<style>` 태그만 지우고
**속 CSS 를 글자로 남겼다** — 편지 맨 위에 `@media only screen…` 이 그대로 보인다.
지금은 거르개를 **지난 뒤**에 붙인다. 검사가 그 자리를 지킨다.

## ② 팝업 — 미리보기 틀이 700 에 굳어 있었다

편지는 980 인데 틀은 700 이라 **오른쪽이 잘렸다**(대표 화면: 팝업 아래 가로 스크롤).

⚠ **2026-09-12 에도 똑같은 일이 있었다**(680 → 780). 숫자를 두 곳에 적으면 되풀이된다.
그래서 이번엔 **숫자를 안 적는다** — 편지 짓는 층에서 읽는다
(`const 편지폭 = window.PuNewsTpl.전문넓이`). 팝업 창은 780 → **1060**.
