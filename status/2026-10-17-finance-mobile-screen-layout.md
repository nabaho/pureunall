## 무엇이 문제였나 (412px 실측 · 운영 코드 그대로 · 가짜 firebase·가짜 묶음)
- **출금 표만 폰 손질이 없었다** — 입금 표는 2026-08-23 에 카드로 바꿨는데 출금 표는 그대로라
  표 폭 753px(화면 386px). 대표 화면처럼 금액·카드·적요 셋만 보이고 옆으로 밀어야 했다.
- **적요마다 뒤에 「0」** — 은행 메모 0 이 아니었다(그건 이미 걷었다). 줄을 만들 때 `_hint: x.dupHint ? 1 : 0`,
  그릴 때 `row._hint && h(…)` — Preact 는 `0 && x` 의 0 을 글자로 그린다. **PC 에서도** 모든 줄에 붙어 있었다.
- 목록이 화면 절반 아래에서 시작 — 라디오 줄 2줄 · 단추 띠 3줄(안 눌리는 흐린 「📆 오늘」이 한 칸, ⚙ 혼자 셋째 줄) · 머리 2줄.
- 덤으로 찾은 흠 둘:
  - 출금 표가 «달 거르기 전» 목록(`expCardList`)으로 그려졌다 — 10월을 골라도 표에는 모든 달이 섞였다(머리는 「10월 N건」).
  - 「💸 출금 N건 등록」이 확인창에서는 **이 달** 건수를 묻고 실제로는 **모든 달**(`expAll`)을 등록했다.

## 고친 것
- 폰(≤640px)에서만:
  - 통장·카드·CMS → 알약(라디오는 투명하게만 — 자판·화면읽기로 그대로 고른다) · 「은행·나이스빌·확인·건」 접음 → 한 줄.
  - 단추 띠 첫 줄 = `📆 오늘(있을 때만) · 입금 · 출금 · ⚙`, 주 단추(「출금 N건 등록」/「모두 확정」)는 그 아래 통째 한 줄.
    「카테고리 자동」·「배운 것은 저절로 등록」·「저절로 확정」 스위치는 ⚙ 뒤로(넓은 화면은 그대로).
    좁을수록 그림 → 「도구」 → 「미처리」 낱말 순으로 접고 **숫자는 끝까지 남김**(≤440 · ≤380px, 뜻은 title).
  - 출금 머리 한 줄(안내 글 접음, 카드 칩이 있으면 칩만 둘째 줄).
  - 출금 표 = **카드 두 줄**: `☐ 번호 │ 날짜 적요 … 금액` / `│ 카드 [카테고리 고르개] 등록`. 줄 높이 59px 로 고르게(학습됨·등록 단추·선택 모두).
    날짜의 시각·카드 「승인」·「선택 필요」·✕ 만 접음(「취소」는 남김). 줄 안 고르개 13px·28px(공용 16px·42px 대신 — 찾기 칸 같은 «글자 넣는 칸»은 16px 그대로).
- 모든 화면:
  - 「0」 없앰(`_hint` 를 참/거짓으로 · 그릴 때 `!!`).
  - 카테고리 칸 — 고르개와 「학습됨 ×N」을 한 줄에(PC 에서 배운 줄만 두 줄이던 것 62 → 41px).
  - **☐ + 번호**(CLAUDE.md 대표 지시 2026-10-05) — 출금 표 맨 왼쪽에 ☐. 고르면 목록 위에 「✓ N건 선택 · 카테고리 한꺼번에 고르기 · 💸 고른 것 등록 M건 · 선택 풀기」.
    한꺼번에 고르기는 **고르기만**(저장 안 함), 등록은 건수를 묻는다. 보이는 줄만 센다. 달·탭·종류·거르기가 바뀌면 비운다.
  - 출금 표·카드별 건수를 달·오늘 거른 «뒤»에 만든다. 등록은 한 벌(`registerExpRows`) — 「출금 N건 등록」은 센 그 목록(`expList`)만.
- CSS 캐시 번호 `pu-erp.css?v=16 → 17`.
