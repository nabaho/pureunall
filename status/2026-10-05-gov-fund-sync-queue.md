# 2026-10-05 · 정부사업 컨설팅·기금관리 — 기기 사이 자료가 갈라지지 않게 (fix/gov-fund-sync-queue)

대표 지시: 「다른모든 프로그램에서도 데이터가 분리되지 않게 처리해라」

## 한 것

### gov-consulting.html (정부사업 컨설팅)
1. **밀린 저장 줄 `p_fbDirty`** — `fbPush`·`fbPushRecordDelta` 가 저장 «전에» 올릴 값을 이 기기에 적고,
   클라우드가 받았다고 답한 뒤에만 지운다(표 `tok` 가 같을 때만 — 그새 또 고친 것은 남는다).
   - 건별 칸(사업장·일정)은 바뀐 줄만(지운 것은 `row:null`), 통째 칸(담당자·환경설정 등)은 값 하나.
   - 붙는 순간(`onAuthStateChanged` → `fbFlushDirty()` 가 `fbSyncDown()` **보다 먼저**)·재연결(`.info/connected`)·`online` 에 자동으로 올린다.
   - 끊김 실패는 남기고, 권한 거절은 뺀다(다시 보내도 안 들어간다 — 화면에 따로 알림).
   - 저장 상태 글: 「연결되면 다시 저장하세요」 → 「기기에 저장 · 연결되면 자동으로 올림」.
   - `fbSyncDown` 은 내가 올리는 중인 칸을 덮지 않는다.
2. **증빙 사진 다시 올리기 줄 `p_evQueue`** — `evUpload` 가 먼저 적고 성공하면 지운다(사진은 IndexedDB 에 이미 있으므로 줄에는 일정·칸·쪽지만).
   켤 때·재연결·`online`·3분마다 `evQueueRetry`. 지운 사진(`evRemove`·IndexedDB 에 없음)은 줄에서 뺀다.
   - **`evAutoBacklog`** — 「이 PC 것 공용으로 올리기」를 켤 때 저절로 돈다. 실패 0 으로 끝나야 `p_evBacklogAt` 을 남기고 7일 쉰다.
   - 화면 왼쪽 아래 작은 표시(`#evSyncChip`) — 올리는 중/올림 완료(6초)/못 올린 N장(빨강, 누르면 다시).
3. **비정상 축소 띠 `#shrinkBanner`** — 안전장치(`_isBulkShrink`)는 그대로. 2초 토스트 대신
   「사업장 — 이 기기 N건 · 클라우드 M건」 띠를 맞춰질 때까지 남기고, [클라우드 기준으로 맞추기](확인 + 자동백업 먼저)·[잠시 닫기].
- `LS_VALID_KEYS` 에 `p_fbDirty`·`p_evQueue`·`p_evBacklogAt` 추가 — 안 넣으면 `cleanupLS` 가 켤 때마다 지운다.

### fund.html (기금관리)
4. **원본 서식 클라우드 보관** — 엑셀 원본(`setup`·`subsidy`·`contribx`)·원본 HWP(`hwp:*`)를
   `fund_erp/tpl_orig/{열쇠}`(본문 b64) + `fund_erp/tpl_orig_index/{열쇠}`(있는지·at·크기·이름)에도 둔다. `hwp:` → `hwp__`.
   - `tplPut`/`tplDel`/`tplGet`/`tplHas`/`tplSyncUp`. 화면 표시는 `tplHas`(파일 안 받음), 열기·채우기는 `tplGet`(없거나 다른 판이면 받아 옴).
   - 어느 판인지: `localStorage.fund_tpl_sync[열쇠]` = 받은/올린 판의 `at` · `'dirty'`(못 올림) · `'del'`(못 지움).
   - 옛 원본 옮기기: `start()` 5초 뒤·`online` 에 `tplSyncUp`. **클라우드에 이미 있으면 덮지 않는다**(먼저 옮긴 기기 것이 기준),
     이 기기 것은 `prev:열쇠` 로 IndexedDB 에 남긴다. 다른 곳에서 지운 것은 되살리지 않는다(역시 `prev:` 로 남김).
   - 색인을 못 읽으면(권한·끊김) 아무것도 안 올린다. 끊긴 채 켜면 4초 뒤 이 기기 사본으로 답한다(화면이 안 멈춘다).
   - `hwp_tpl`(표지 {{…}} 한글 틀)과는 따로다 — 그것은 채우기용 틀, 이것은 사람이 올린 원본 그대로.
   - **규칙 고칠 것 없음** — `fund_erp/*/*` 는 로그인한 직원 읽기·쓰기(workspace). 읽는 사람 범위 그대로(새로 보이게 되는 사람 없음).

## 배포 뒤 기기마다 할 일
- **정부사업 컨설팅**: 각 PC·폰에서 한 번 열고 로그인만 하면 된다.
  - 밀린 저장은 이번 판부터 적힌다 — **이 판 이전에 연결 전 저장으로 이미 덮여 사라진 것은 되살릴 수 없다.**
  - 증빙 사진이 든 PC 는 **켜 둔 채 15초 이상** 두면 옛 사진이 저절로 올라간다(왼쪽 아래 표시). 빨간 「못 올린 N장」이 남으면 인터넷·로그인 확인 후 눌러 다시.
  - 빨간 「이 기기와 클라우드 자료가 다릅니다」 띠가 뜨면 **누르기 전에 총괄관리자 확인** — 어느 쪽이 맞는지 사람이 판단할 일이다.
- **기금관리**: **원본 서식을 등록했던 PC·브라우저**에서 한 번 열고 로그인 → 5초 안에 「원본 서식 N개를 클라우드에 올렸습니다」.
  그 뒤 다른 브라우저에서는 「원본 없음」이 사라진다. 두 PC 에 서로 다른 원본이 있었다면 **먼저 연 PC 것이 기준**이 되고,
  뒤 PC 의 것은 그 브라우저 안 `prev:` 칸에만 남는다 — 그 PC 원본이 맞다면 서식 화면에서 다시 [등록]하면 된다.

## 남은 것 / 알려 둘 것
- 밀린 저장은 «마지막에 쓴 사람이 이긴다» — 며칠 끊겨 있던 기기가 붙으면, 그 사이 다른 기기가 같은 사업장·일정을 고쳤어도 이 기기 것으로 덮인다(줄 단위). 지금의 온라인 저장과 같은 규칙이다.
- 연결 전에 아주 많은 줄을 한꺼번에 고치면(대량 가져오기) 줄이 브라우저 저장소 한도(약 5MB, 앱들이 나눠 씀)에 걸릴 수 있다 — 그때 줄 적기만 실패하고 저장은 지금처럼 이 기기에 남는다.
- 실제 브라우저·실 Firebase 로는 돌려 보지 않았다 — vm 검사와 구문 검사까지. 배포 뒤 위 «할 일» 대로 한 번씩 확인 필요.
