# 2026-09-18 · 빨간 띠가 «없는 것»을 끄라고 시켰다 — 폭풍은 횟수가 아니라 «고름»으로 가른다

가지 `claude/login-start-screen-386qu2`

## 무엇이 있었나

대표님이 나스(192.168.0.21) 인증서를 브라우저에 받으시느라 그 주소를 열었다 닫았다 하시며
이알피를 몇 번 새로고침하셨다. 그러자 화면 위에 빨간 띠가 떴다 —

> ⚠ 이 탭이 3분 안에 3번 다시 켜졌습니다 (브라우저·확장이 새로고침, 마지막은 47초 전).
> 켤 때마다 자료를 전부 다시 받아 요금이 나갑니다 — **브라우저의 자동 새로고침 확장이나 탭 돌리기를 꺼 주세요.**

대표님은 끌 것을 찾으셨고, 없어서 「탭돌리기 꺼주세요 이것 처리해라」고 하셨다.
**끌 것이 없었다.** 화면이 시킨 일을 사람이 못 해서 나에게 넘기신 것이다.

## 먼저 가른 것 — 우리 코드가 스스로 새로고침한 것은 아닌가

주소에 `?v=1789718176560` 이 붙어 있어 앱이 스스로 다시 연 것을 의심했다. 아니었다.

- 앱 안에서 다시 여는 길은 모두 `location.replace(… ?v=…)` 다 → 종류가 `navigate` 로 찍힌다.
- 띠에 찍힌 종류는 `reload` 였다 → `location.reload()` 이거나 **사람의 F5·브라우저**다.
- `location.reload()` 를 바로 거는 곳은 `forceLogout`(퇴사·접속잠금)뿐 — 대표님은 해당 없다.

즉 **사람이 누른 새로고침**이었다. 앱 잘못이 아니고, 바깥 도구 잘못도 아니었다.

## 까닭 — 감지기가 «횟수»만 셌다

3분 안 3번이면 폭풍이라고 보았다. 그런데 새로고침을 손으로 세 번 누르는 것은 아주 흔하다
(인증서 받기·연결 시험·화면이 이상할 때). 횟수만으로는 사람과 기계가 갈리지 않는다.
이 감지기의 거짓 경보는 이것으로 **세 번째**다 — 9/17 저녁(화면 경로) · 9/18 낮(몰린 부팅) · 9/18 저녁(이것).

## 고친 것 — 기계는 «고르게» 켜고 사람은 못 그런다

| | 전 | 후 |
|---|---|---|
| 문턱 | 3분 안 **3번** | 3분 안 **5번** |
| 재는 것 | 횟수만 | 횟수 **와** 간격의 «고름» |
| 탭 눈의 몰린 부팅 | 그대로 셈 | 기기 눈처럼 5초 안은 한 번으로 접음 |
| 못 가릴 때 | 띠를 띄움 | **콘솔에만 남기고 안 띄움** |
| 띠의 말 | 「…꺼 주세요」(시키기만) | 「약 20초마다 고르게 — 사람이 누르면 이렇게 고르게 못 누릅니다」(근거 먼저) |

`gapStat()` — 부팅 간격의 가운뎃값을 잡고 모든 간격이 그 언저리(±35%, 최소 ±4초)에 들면 «고르다».
간격이 셋은 있어야 본다(=부팅 넷). 2분 반 넘게 뜸한 것은 고르더라도 폭풍으로 안 본다.

- 20초·20초·21초·19초·… → 고름 → 폭풍 (2026-09-17 진짜 자국이 이것이다, 그대로 잡힌다)
- 47초·9초·55초·15초·40초 → 제각각 → 사람 → **안 띄운다** (대표 화면이 이것이다)

`window.PU_BOOT` 에 `every`(잰 간격 초)·`even`·`rawCount` 를 함께 내보내, 이알피의
「자료 받기 멈춤」 덮개도 같은 근거를 말한다.
