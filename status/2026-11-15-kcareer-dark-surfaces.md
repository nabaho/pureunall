# 경력관리 — 어두운 테마 «공용 표면» (프로필 1장 밖 전 화면·창) (2026-11-15, 대표 «네, 고쳐 주세요»)

프로필 1장 화면(#3046) 밖에서 어두운 테마를 켜면 글자가 안 읽히던 것을 공용 규칙으로 고친다. 화면마다 따로 고치지 않고 «원인별 공용 규칙»으로 묶었다(kcareer.html 의 `어두운 테마 — 공용 표면` 블록, 메인 `<style>` 맨 끝).

## 원인 — 어두운 판은 «변수»만 밝게 바꿨는데, 밝은 바탕·짙은 글자가 하드코딩돼 있었다
측정(지어낸 자료, 어두운 판, 1280px): **화면 28개 + 머리줄·메뉴 + 창 39개에서 글자 대비 4.5:1 미달 948건.**
- 표 칸 글자색 `#1e293b` 하드코딩 → 바탕(`#1e293b`)과 같음 **1.00:1** (409건, 위촉장·사건·컨설팅·자격 등 표 화면 전부)
- 기본 단추 `.btn` 흰 바탕 + 글자는 `var(--text)`(밝음) 1.23:1 (약 350건)
- 번호 칩 `.id-chip`(#e2e8f0 바탕) 2.08:1 (114건) · 툴바·빈 칸·표 바깥 상자·칩·메뉴의 `background:#fff` 2.56:1 · OCR 칸 `#f8fafc` 1.18:1 · 인라인 밝은 바탕 상자
- 브랜드 글자색 변수(teal·red·amber·blue)가 어두운 카드 위에서 2.05~4.4:1
- 표 머리줄·호버 줄은 바탕 규칙이 `!important` 라 어두운 판 규칙이 졌고(흰색이 됨), `.topbar` 도 같음

## 고친 것(원인별 공용 규칙)
1. **브랜드 글자색 변수**를 어두운 판에서 밝은 값으로(`--teal:#4ade80` 등). `--navy` 는 안 바꾼다(흰 글자 단추의 «바탕»이 같은 값). 변수가 밝아져 «바탕»으로 쓰이던 곳(흰 글자 단추·삭제 단추 17곳)은 속성 선택자로 원래 짙은 값을 되박았다.
2. **종이 구역**(서식 채우기 `.kf-paper/.kf-sheet/#kfSheetWrap`, 이력서 용지 `.cv-sheet`, 한글 편집기, 프로필 종이)은 흰 바탕을 남기고 **안쪽 변수만 밝은 판 값으로 되돌렸다**(글자가 어두운 변수를 따라 밝아지지 않게).
3. **단추·표면**: 기본 단추·툴바·표·빈 칸·칩·메뉴·미리보기 판·OCR 칸 → 어두운 바탕+밝은 글자 한 벌. 폰(≤520px)은 표 바깥 상자가 투명(줄마다 카드)이라 표 바탕 규칙을 `min-width:521px` 로 가뒀다.
4. **표**: 칸 글자색·머리줄·호버 줄·번호 칩(`!important` 로 이김).
5. **인라인으로 박힌 것**: 짙은 글자색(호박·초록·빨강·파랑·남색·회색)은 밝은 계열로, 밝은 바탕(글자색 안 박은 것)은 어두운 바탕으로. 종이 안·자기 바탕을 따로 박은 칩·«밝은 안내줄»(#fbNotice 등) 안의 링크는 뺀다. JS 가 `style.cssText` 로 다시 쓰면 `color: #x`(공백)·`rgb()` 꼴이 되므로 셋을 다 본다.
6. 자잘한 글자색: `.firm-note`·`.at-warn`·`.ds-same.same`·`.rh-chip-*` 호박(짙은 글자 → 밝은), `.hy-tbl td.hy-y/hy-sum`·`#kcLock h2`·`.tag.purple` 남색 글자, `.tag.red`·`.fs-pill`·`.warn-banner`·`.cv-rowdel`·`.rh-warn` 밝은 칩 위 변수 글자, 입력 placeholder.
- 색은 팔레트 27색만 썼다(`tests/color-palette-apps.test.js`).
- 같이 고친 #3046 후속 «낮음» 2건: 사진 못 불러올 때 뜨는 빨간 경고줄(`var(--red)`, 어두운 판 4.35:1 → 변수가 밝아져 해결) · 용도 선택 상자 `aria-label`.

## 측정(직접) — 고친 뒤
어두운 판, **375·768·1280px 세 폭**에서: 화면 28개 + 머리줄·메뉴·그룹 탭 + 창 39개 **미달 0건(최저 4.83:1)**. 숨은 곳(`display:none` 인 안내줄·팝업·탭 칸 196~271곳, 글자 2,000여 줄)도 켜서 재 봐서 **0건**. 규칙 단위 점검(CSS 규칙 408개를 가짜 요소로 그려 «캐스케이드 뒤 최종 색»을 잼)에서도 남은 것은 글자 없는 막대·그림·종이 안(문맥 밖 탐침) 뿐. 전환 효과는 끄고 쟀다(안 끄면 전환 도중 값이 읽혀 틀리게 나온다). 눈으로도 위촉장 표 화면 확인.
- 밝은 판은 그대로: 이 블록은 전부 `html.dark` 안에만 있다(시험이 지킨다).

## 고치지 않은 것 / 알아 둘 것
- 측정은 **지어낸 자료**로 그려지는 상태만이다. 실제 자료로 처음 생기는 상태(예: 새 칩 종류)는 위 ② 시험이 «밝은 바탕을 하드코딩한 규칙»을 새로 만들 때 걸러 주지만, **JS 가 인라인으로 만드는 새 밝은 바탕**은 시험이 못 본다(⑧ 인라인 규칙이 흔한 꼴만 잡는다).
- `.kf-sheet`(서식 채우기 시트)·`.cv-sheet`(이력서 용지)·한글 편집기는 종이라 어두운 판에서도 흰 바탕이다 — 일부러.
- 종이 구역 안 «호버» 상태(`.cv-rowdel:hover` 등)는 밝은 판과 같은 값(3.9:1)이라 그대로 뒀다(원래 있던 문제).
- 폰 «한 화면» 맞춤 때 프로필 그림이 작게(27%) 나오는 것은 이번 일이 아니다(폰 규칙은 대표가 정함).
