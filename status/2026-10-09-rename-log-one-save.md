# 2026-10-09 이알피 — 약어 «과거까지» 바꾼 기록(renameLog)이 서버에 안 남던 것

- 실측: 일터 → 일터상생(과거까지 7건)은 번호·사본 모두 맞게 바뀌었는데, 유형의 renameLog 만 서버에 없었다.
  약어 저장(persistWith)과 기록 저장(bizTypeApply)이 잇달아 나가며 뒤의 것이 묻혔다.
- 고침: `bizTypeRenameRun` 은 유형 사전에 쓰지 않고 기록 한 줄만 돌려준다 → editType 이 번호를 «먼저» 바꾸고
  약어를 바꾸는 «같은 저장»에 `bizTypeRenameLogAdd` 로 얹는다. 고친 기록(hist)에도 「약어 과거까지 A → B」.
- 검사: `tests/biz-no-rename-all.test.js` ⑧.
- 실행 기록(대표 「세 가지 모두 실행」): ① 일터혁신 → 일터 합치기(스위트바이오 006·일신정밀 007, 개인입금 켬) ② 일터 → 일터상생 7건.
  옛 사본 세 곳(계약-2026-061 이케이·계약-2026-137 스위트바이오·진행기록 1건)은 id 로 진짜 번호를 확인해 손으로 맞춤.
  ③ 현클 → 현장클리는 이 고침 배포 뒤.
- ⚠ 사본을 고치면 「데이터 급감 차단: project_progress 40 → 1건」 창이 뜰 수 있다 — 서버는 40건 그대로였다(헛경보). 「현재 데이터 유지」.
