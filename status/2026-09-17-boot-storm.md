# 「계속 돈이 새고 있다」 — 서버 통신 기록으로 잡은 것: 한 PC 의 탭들이 20초마다 처음부터 다시 켜진다

대표 제보 2026-09-17 (폰 화면: 실시간DB ₩326/시간, 이 추세면 월말 ₩87,498)
가지 `fix/boot-storm-gate`

## 재는 길 — 추측을 끝낸 도구

`firebase database:profile --duration 180` — 3분간 서버가 실제로 무엇을 몇 번·몇 바이트 주고받았는지 기록한다.
(이 저장소에서 처음 쓴 도구다. 요금 문제는 **이것부터** 돌릴 것.)

## 기록이 말한 것 (165초)

| 내려간 자리 | 크기 | 횟수 |
|---|---|---|
| `/pucards/idx` (명함 색인) | 10.89 MB | ×9 |
| `/data/finance_income` (자문수입) | 8.50 MB | ×8 |
| `/work_erp/items` (업무관리) | 3.31 MB | ×8 |
| 모든 표의 `/u` 감시 · `/data` 얕은 읽기 | 작음 | **×8 씩** |
| **합계** | **24 MB / 165초 → 시간당 약 527 MB ≈ ₩700** | |

쓰기: `presence/…__P-001` ×16, `data/presence_hours/…/P-001` ×8.
`presence_hours` 는 **부팅 때 한 번만** 쓰는 것이라 — **한 PC(대표님, 기기번호 하나)에서 이알피가 3분에 8번 처음부터 다시 켜졌다.**
같은 시간에 기업정보함 9번·업무관리 8번. **세 앱 탭이 나란히 약 20초마다 새로고침되고 있었다.**

→ 켤 때마다 큰 표를 통째로 다시 받는다 = 요금. 켤 때마다 0.2초 얼어붙는다 = 깜빡임. **둘은 하나다.**
콘솔의 「첫 화면까지 67ms」(10:22:45) → 「62ms」(10:24:13) 두 줄도 88초 사이 두 번 부팅한 자국이었다.

## 지운 가설 (직접 재서)

- **캐시가 옛 판을 준다** — 대표 주소(`?sso=1&v=082fea5b`)를 그대로 받아 봐도 161 이 온다. ✗
- **새 버전 감지기가 핑퐁** — `version.json` sha·`pu-erp.html` ETag/Last-Modified·문서의 `pu-release` 도장을 각 8번 받아 봐도 **한 값으로 안정**, 셋이 서로 일치. ✗
- **앱끼리 표식 열쇠를 공유해 서로를 「새 버전」으로 읽는다** — 표식은 sessionStorage(탭별). ✗
- **이알피 ↔ 포털 튕김** — 포털은 `pucards/idx`·`work_erp/items` 를 읽지 않는다. 세 앱 각자의 부팅이다. ✗
- **명함 원본 284MB 가 통째로 내려온다** — 한 장씩만(`photos/{id}`) 꺼낸다. 기록에도 한 장(0.7MB)뿐. ✗

남는 것: **바깥에서 탭을 되풀이 새로고침하는 무엇**(자동 새로고침·탭 돌리기 확장 등).
정황: 콘솔마다 찍히는 확장프로그램 오류(`A listener indicated an asynchronous response…`), 밤에도 같은 자국.
⚠ 그러나 **아직 확정은 아니다.** 그래서 앱이 스스로 말하게 했다.

## 고친 것

### ① 부팅 폭풍 감지기 — `js/pu-version.js` (모든 앱이 싣는다)
같은 탭에서 이어지는 sessionStorage 에 부팅 시각을 남긴다. **3분 안 3번째 부팅부터** 폭풍으로 보고
- 콘솔에 `[부팅] reload · 직전 부팅에서 21초 · 이 탭에서 3분 안 4번 · 온 곳 …`
- 화면 위에 빨간 띠: 「이 탭이 3분 안에 N번 다시 켜졌습니다 … 자동 새로고침 확장이나 탭 돌리기를 꺼 주세요」
- `window.PU_BOOT = {count, since, type, from, storm}` 을 세운다.

★ **`type` 이 원인의 안팎을 가른다** — `reload` 면 브라우저·확장이 새로고침한 것, `navigate` 인데 온 곳이 우리 화면이면 앱 코드가 다시 연 것.
⚠ 2번은 폭풍이 아니다(F5 두 번은 사람). 3분 넘은 옛 부팅은 걷는다(아침 것이 저녁을 폭풍으로 만들지 않게).
⚠ `<button` 태그 글자를 쓰지 않는다 — `tests/deployment-gate.test.js` 가 이 파일에 그것이 없기를 못 박았다.

### ② 이알피 — 폭풍이면 무거운 받기를 «사람이 누를 때까지» 멈춘다 (`_erpBootStormGate`)
`fbInitialSync` 가 자료를 받기 **전**에 `PU_BOOT.storm` 을 본다. 폭풍이면 덮개를 띄우고 「자료 받기 계속」을 누를 때까지 기다린다.
- 20초마다 다시 켜지는 탭은 사람이 쓰는 탭이 아니다 — 그런 탭이 917KB·2.8MB 를 매번 받는 것이 요금의 정체였다.
- 화면은 이 기기의 지난 사본으로 그대로 보인다(막히는 것은 «서버에서 새로 받기»만).
- 한 번 누르면 그 세션은 다시 묻지 않는다 — 진짜 쓰는 사람을 괴롭히지 않게.
- 돌려주는 것은 «이어가는 약속»이라 부르는 쪽(`_startFbSync`) 흐름은 그대로다.

### 캐시 번호
`js/pu-version.js` 를 고쳤으므로 부르는 21개 화면 `?v=3 → ?v=4`.

## 안 고친 것 — 왜

- **기업정보함 `idx` 1.2MB·업무관리 `items` 3.3MB 도 부팅마다 통째로 받는다.** 문은 이알피에만 달았다 —
  두 앱의 첫 받기 흐름은 이번에 손대지 않았다(다른 앱의 심장이라 따로 봐야 한다). 띠는 세 앱 모두에 뜬다.
- **부팅 한 번의 값 자체**(자문수입 917KB 를 매 부팅 통째로)는 구조다 — 건별 구독도 «첫 받기»는 통째다.
  지난 사본에서 «바뀐 것만» 이어받는 설계는 큰 일이라 따로.
- `backfillIdx` 가 색인 **개수를 세려고** 1.2MB 를 통째로 받는다(`once('value')` 뒤 `Object.keys().length`) — 낭비다. 따로.

## 재검증 (같은 날 저녁, 대표 지시 「다시 검증해 봐라」) — 문이 «한 번도 안 닫혔다»

가지 `fix/boot-storm-device-eye` · 이알피 BUILD_SEQ 163 · `pu-version.js?v=4 → ?v=5`

### 잰 것
- 서버 상태: 새 껍데기 접속 0 · 새 장애알림 0 · `appBuild.seq` 162 · staff_colors 마지막 쓰기 22시간 전. ✔
- 배포된 화면을 브라우저로 직접 세 번 새로고침 → 콘솔 `[부팅]` 줄·빨간 띠·이알피 덮개와 단추 **모두 동작**. ✔
- **그런데** 배포 1시간 뒤 `database:profile` 165초를 다시 재 보니 **그대로**:
  `/pucards/idx` 10.89MB×8 · `/data/finance_income` 8.51MB×8 · `/work_erp/items` 3.31MB×10 · 합계 23.62MB(전 24.17) · **부팅 자국 8번/165초(전 8번)**.

### 까닭 — 감지기가 «탭»만 봤다
첫 눈은 sessionStorage 다. **부팅마다 새 탭이 열리면 sessionStorage 는 매번 빈다** → 감지기는 늘 「이 탭의 첫 부팅」만 보고, 폭풍을 못 보니 이알피 문도 안 닫힌다.
같은 탭을 새로고침하는 내 브라우저 시험은 통과하고, 대표 PC 의 실제 폭풍은 빠져나간 것이다. (검증 없이 「고쳤다」고 했으면 그대로 돈이 새고 있었다.)

### 고친 것 — 두 번째 눈 `noteBootDevice` (`js/pu-version.js`)
- localStorage `pu_boot_dev_v1` 에 **이 기기·이 화면 경로별** 부팅 시각을 남긴다. **3분 안 5번째부터** 폭풍(`PU_BOOT.devStorm`).
- 4번까지는 참는다(F5 몇 번·포털이 앱을 여는 것). 화면 경로로 갈라 세어 **앱 넷을 연달아 여는 것은 폭풍이 아니다.** 3분 넘은 것은 걷는다.
- 첫 눈(탭)은 그대로 sessionStorage 만 본다 — 탭 열 개를 열기만 해도 폭풍이 되지 않게 두 눈을 **다른 함수**에 두었다.
- 콘솔 `[부팅]` 줄에 「이 기기의 이 화면 3분 안 M번」이 붙고, 기기 눈만 걸리면 띠가 **「매번 새 탭으로 열림」**이라고 말한다 — 원인을 찾는 사람에게 «탭이 새로 열리고 있다»는 것이 곧 실마리다.
- `PU_BOOT = {count, devCount, since, type, from, storm, tabStorm, devStorm}`. 이알피 문은 `storm` 을 보므로 손댈 것 없이 함께 닫힌다.

### 이알피 덮개 문구도 고쳤다
기기 눈만 걸린 폭풍이면 `PU_BOOT.count` 는 1이라 덮개가 「3분 안에 1번 다시 켜졌습니다」라고 **거짓말**을 하게 되어 있었다 → 기기 수를 쓰고 「이 화면이 매번 새 탭으로 계속 열리고 있어」라고 말한다.

### 검사 — 13건 (6건 추가) · 이빨 확인 7가지 모두 물었다
⑧ 새 탭 5번 → 폭풍·띠 「매번 새 탭」 · ⑨ 4번은 참는다 · ⑩ 경로별 · ⑪ 3분 걷기 · ⑫ 두 눈은 다른 함수 · ⑬ 이알피 덮개는 기기 수와 «새 탭»을 말한다.
부러뜨린 것: 문턱 5→99 · 경로 안 가름 · 3분 안 걷음 · 기기 눈을 폭풍에 안 섞음 · 띠 문구 · 덮개가 기기 눈 무시 · 덮개가 탭 수만 — 다 걸렸다.

### 이번에도 확정이 아닌 것
이 문이 닫히는지는 **배포 뒤 `database:profile` 을 다시 재야** 안다(부팅 자국 8번/165초가 줄어야 한다).
그래도 부팅 자국이 그대로면 «부팅마다 localStorage 까지 비는 환경»(시크릿 창·프로필 초기화·다른 브라우저)이다 — 그때는 코드가 아니라 대표 PC 의 확장·자동화를 직접 봐야 한다.
대표께 부탁: 콘솔 `[부팅]` 줄 한 줄(reload 인지 navigate 인지·탭 수와 기기 수)과 `chrome://extensions` 의 자동 새로고침·탭 돌리기 확장 여부.
