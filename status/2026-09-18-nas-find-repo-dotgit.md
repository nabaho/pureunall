# 2026-09-18 · 찾기가 «배포본»을 잡았다 — 그리고 붙여넣을 것까지 손에 쥐어 준다

가지 `claude/login-start-screen-386qu2`

## ① 찾기가 엉뚱한 폴더를 잡았다

대표님이 한 줄을 붙여넣으시자 이렇게 나왔다 —

```
Error: Cannot find module 'C:\Users\fair0\Documents\pu-deploy\scripts\nas-backup-deploy.js'
```

`pu-deploy` 는 **배포 결과물 폴더**다. 거기에도 `pu-erp.html` 이 있고 `scripts` 도 있다.
내 찾기 조건이 「`pu-erp.html` 이 있고 옆에 `scripts` 가 있으면 저장소」였다 — **허술했다.**

**진짜 조건은 `.git` 이 있는가다.** 우리가 하려는 것이 `git pull` 이므로 그것이 조건이다.

| | 전 | 후 |
|---|---|---|
| 찾는 조건 | `pu-erp.html` + `scripts` | `pu-erp.html` + **`.git`** |
| 못 찾았을 때 | 「클로드에게 보여 주세요」 | **`git clone …` 을 함께 적는다** |

## ② 나스에 붙여넣을 것을 «완성해서» 손에 쥐어 준다

대표님이 「나스 어디에 넣나」고 물으셨다. 자리를 알려 드리는 것만으로는 부족하다 —
스크립트를 찾아 열고 두 줄을 고쳐 넣는 일이 남는다. 그것까지 없앤다.

올리기가 끝나면 **완성된 나스 스크립트(열쇠·주소가 이미 들어간 것)를 클립보드에 넣는다.**
대표님은 DSM 「사용자 정의 스크립트」 칸에서 **Ctrl+V** 만 하시면 된다.

⚠★ **파일로 안 남긴다.** 클립보드는 잠깐 있다 사라지지만 파일은 남는다 —
열쇠가 든 파일 하나면 백업 전부를 받아 갈 수 있다.
`clip` 이 없는 자리(윈도우가 아닐 때)에서는 화면에 통째로 찍어 «그래도 손에 쥐어» 준다.

## 나스 자리 (대표님께 드린 안내)

```
DSM → 제어판 → 작업 스케줄러 → 생성 ▾ → 예약된 작업 → 사용자 정의 스크립트
  일반    : 작업 이름 「푸른이알피 백업」 · 사용자 root
  일정    : 매주 · 월요일 · 03:00
  작업 설정: 「사용자 정의 스크립트」 칸에서 Ctrl+V
```
