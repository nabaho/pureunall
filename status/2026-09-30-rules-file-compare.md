# 2026-09-30 · 규정관리 — 두 파일 견주기(신구대조) (rules-file-compare)

목업 ③(파일끼리 신구대조) 대표 승인 「네」(추천대로 세 가지).

## 한 일
- 「⋯ 참고」 서랍에 「📑 두 파일 견주기」. 옛 파일(지금 신고된 것) ↔ 새 파일(회사가 고쳐 온 것)을 조 단위로 견준다.
  두 파일 모두 브라우저 안에서만 읽는다(kordoc 읽개). 견주기만 할 때는 어디에도 올리지 않는다.
- 짝짓기는 번호가 아니라 제목이 먼저(`js/pu-rules-filecmp.js`) — 한 조만 끼우거나 빼도 뒤가 다 밀리기 때문.
  갈래: 바뀜 · 새 조 · 없어짐 · 번호 바뀜 · 같음. 바뀐 조는 낱말 단위로 칠한다(15일→12일 이면 숫자만).
- 기본 보기 「글이 달라진 것」 은 번호만 밀린 조를 뺀다(표준규칙에서 한 조 빼 보니 57개가 밀려 덮었다).
- 바뀐 조·새 조에만 검토 기준을 돌려 «위반 의심» 을 곁에 단다. 옛 글에도 있던 것은 흐리게.
- 「신구대조표 한글로 받기」(.hwpx, 실패 시 .doc).
- 「이 차이로 새 회차 만들기」 — 옛 파일을 보통 올리기 길(loadFile)로 원본 삼아 검토를 돌리고,
  바뀐 조 = 개정, 새 조 = 앞 짝 조 뒤 신설, 없어진 조 = 삭제 제안으로 건다. 결정은 비워 둔다(노무사가 한 건씩).
  번호만 바뀐 조는 넣지 않는다 — 새 파일이 번호를 다시 매겼으면 「전부개정」 을 고르라고 알린다.
