# 2026-09-20 step2-share — 3걸음(나): 구글에 «쓰는» 길을 옮긴다

대표 지시 「옮긴다」 — 3걸음 끝에 여쭌 「구글 쓰기를 옮길까 없앨까」에 대한 답.

## 살펴보니 더 큰 것이 걸려 있었다

구글 쓰기 얼개가 이알피 **법인 대시보드 안**에만 있었다. 4걸음에서 그 화면을
걷어내면 **둘이 함께** 죽는다 —

1. 우리 일정을 지울 때 구글 쪽 일정도 지우는 일 — **지금 이어진 근태가 30건**(실측)
2. **보수총액신고 Gmail 자동발송** — 달력과 아무 상관없는 기능인데, 로그인 토큰을
   그 화면이 받아 두는 것에 얹혀 있었다

②는 여쭐 때 몰랐던 것이다. 그래서 토큰 «받아 두는 자리»까지 통째로 밖으로 뺐다.

## 무엇을 했나

- **`js/pu-gcal-auth.js`(새 파일)** — 로그인·토큰·API 부르기를 한 곳에.
  이알피가 데어 가며 얻은 규칙을 그대로 옮겼다: 로그인 전엔 안 부름 · 401 본문을
  자료인 척 넘기지 않음 · 200+error 도 실패 · 204 는 성공 · 만료 1분 전은 죽은 것.
- **`pu-erp.html`** — 그 모듈을 쓰도록 바꾸고, **토큰 받는 자리를 대시보드 «밖»으로**
  옮겼다. 이제 4걸음에서 달력을 지워도 Gmail 발송이 살아 있다.
- **`pu-cal.html`** — 이어진 건을 지울 때 **구글 쪽을 먼저 지운다**. 못 지우면
  「⚠ 구글 쪽은 못 지웠습니다」라고 **분명히 말한다**(이알피가 여기서 데었다 —
  안 지워졌는데 「삭제됨」이라고 했다). 「🔐 구글 로그인」 단추는 **이어진 건이 있고
  아직 로그인 안 했을 때만** 뜬다.

## ⚠ 대표님이 한 번 해 주실 것 (구글 콘솔)

푸른 캘린더에서 구글 로그인을 하려면 **되돌아올 주소를 구글 콘솔에 등록**해야 합니다:

```
https://nabaho.github.io/pureunall/pu-cal.html
```

Google Cloud 콘솔 → 사용자 인증 정보 → OAuth 클라이언트 → 승인된 리디렉션 URI 에 추가.
(제가 들어갈 수 없는 곳입니다 — 파이어베이스 콘솔과 다릅니다.)

**등록 전에도 안전합니다** — 등록 안 된 채로 누르면 구글이 막고, 지우기는 「구글 쪽은
못 지웠습니다」로 솔직히 알립니다. 이알피에서 로그인하고 오면 같은 창의 토큰을 그대로 씁니다.

## 검사

새 `tests/gcal-auth.test.js` **15개** — 가짜 응답으로 401·200+error·204·본문깨짐을
하나씩 먹여 본다. 이빨 확인: 「실패를 값으로 넘기지 않기」를 되돌리면 넷이 걸린다.

⚠ `erp-gcal-guard` 는 **살렸다**(지우려던 것에서 바뀜). 상자에 공용 모듈을 «진짜로»
넣어 이알피의 길이 끝까지 도는지 그대로 본다. 「토큰 판정」 검사만 뜻을 고쳤다 —
옛 구현 한 줄을 글자로 박아 두어 옮기자마자 깨졌는데, 지킬 것은 생김새가 아니라
«판정이 한 곳인가»다.

관련 **979개 통과**.
