# 사번·로그인 아이디를 화면 어디에도 안 적는다 (2026-10-25)

대표 결정: 「푸른통합시스템 전체에 사람이름과 고유번호가 있다. 사람이름은 화면에 보여도 문제가 없는데
모든 로그인 상황에서 사번이 드러나면 로그인에 해킹이 가능하다. 따라서 푸른통합시스템에 모든 사번은
로그인할 경우 모두 안 보이게 해달라.」 → 「이름만 있어야한다.」
(사번에서 로그인 아이디가 그대로 만들어진다 — P-001 → p001@pureun.kr. 그래서 «로그인 이메일»도 같은 취급.)

이전 결정(2026-08-10·09-12 「사번은 절대 접지 않는다」)은 이 결정으로 뒤집힌다.

## 어떻게 막았나 (두 겹)
1. **원천 고치기** — 이름을 못 찾았을 때 사번·이메일 앞부분을 «대신 적던» 모든 자리를 이름·빈 글자·「이름 미확인」으로.
   머리글·말풍선·고르는 목록·알림·토스트·인쇄/엑셀 글자·구글 캘린더 설명·보안 알림·카카오 알림·공개 이음 명단.
2. **안전망** `js/pu-sid-guard.js` — 직원 화면 25쪽에 실려, 놓친 사번·로그인 이메일 글자를 화면에서 사후에 닦는다.
   (입력칸 value·내려받는 파일·서버가 만드는 글자는 못 닦는다 → 그쪽은 원천에서 고쳤다.)

- 로그인 화면: 예시 아이디(p001@…) 걷음, «저장된 아이디»는 손대기 전까지 점으로 가림(포털·이알피).
- 서버(functions): gcal-proxy(일정 설명 「푸른 담당」 — 이름 모르면 줄째 뺌) · login-security(보안 알림 글 이름) ·
