# 컨설팅보고서 — 회차 기록·기준 점검 (2026-10-12, 설계 2-B)

설계 `docs/superpowers/specs/2026-10-12-gov-report-rounds-design.md` · 계획 `docs/superpowers/plans/2026-10-12-gov-report-rounds.md`

## 만든 것
- **기록 모듈**(`js/pu-gov-report-track.js`): 회차 기록 `rd`(형태·시간·인원·사진/서명지 확보·MD·종류)를 읽고 자르고 이어받는다(`normRd`·`nextRd`, 지우는 길 없음).
- **기준 점검 모듈**(`js/pu-gov-report-criteria.js`, 순수): 회차 인정/미달 + 사유, 업체 합계 — 일터혁신(회의 120분·참석 3명·사진·서명지·대면 70%), 산업일자리(비대면 보고서 4MD·자료조사 2MD 한도).
- **화면**(`gov-report.html`): 일터혁신 «회차별 수행보고서»·산업일자리(능률) «MD별 수행일지» 칸 창에 «회차 기록» 입력과 «기준 점검» 구역(알림일 뿐 제출을 막지 않는다).
- **규칙**: `scal_docs/$co/$rid/items/$key/rd`(생성기 + 규칙 JSON 두 개). 한계는 모듈과 같다(검사로 못 박음).

## 쓰는 곳
- 서류 줄 하나 `.set`(`grSaveCell`) 한 곳 — `rd` 가 그 줄의 새 자식. **`rd` 규칙은 게시해야 저장된다**: 게시 전에는 `rd` 가 든 저장만 줄의 `$other:false` 때문에 거절된다(`rd` 없는 저장은 그대로).
- 게시 후: `docs/firebase-rules-콘솔원문-<날짜>.json` 갱신 + `tests/photos-staff-share.test.js` 의 `PENDING` 비움.

## 못 한 것 · 확인 필요
- **실제 로그인 화면 확인 안 함**(가짜 DB 로만 검사). 규칙의 `%` 연산(정수·0.5 단위 검사)은 이 저장소 규칙에서 처음 쓰는 식이라 **게시할 때의 문법 검사가 실제 확인**이다.
- 유형별 방문 인정 회수 목표(자문 2·4 / 전문 4·8·12 / 심화 8·12·16)는 계산하지 않는다 — 유형 입력이 없어 계획 회차 수와 견주어 보여 주기만 한다.
- 산업일자리 충남 지원센터·간단형 사업의 점검, 사진·서명 파일 보관, 제출 막기는 만들지 않았다.
- 기준 수치와 «방문/보고서/자료조사» 글은 정리본 기준 초안이다 — **노무사 확인 필요**.
- 대면 비율 표시는 «대면 a/b (정수 내림 %)» — 기준 판정은 정수 비교라 정확하다.
