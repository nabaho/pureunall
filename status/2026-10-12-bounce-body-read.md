# 2026-10-12 · 반송 안내 메일의 «본문»까지 읽어 갈래·실패 주소를 판정

대표 「추천대로」(10/12) = 직전 제안 «본문까지 자동으로 읽게 만들 수 있는데, 만들까요?» 에 대한 답으로 이해하고 진행.
(해석이 틀렸으면 대표가 바로잡는다 — 틀리면 PR 은 되돌린다.)

## 왜
`newsletterBounceScan`(매일 09:00)은 반송을 «제목 + 본문 앞 140자»로만 가른다. 가비아 하이웍스 `failure notice: To - '…'`·고객사 메일서버 `[발송실패 안내] …` 는 사유가 «본문 HTML» 에 있고 원본 편지는 `message/rfc822` 첨부라
- 미리보기는 비었거나 우리 편지 글 → «까닭 모름»(코디스 대표자: 실제로는 메일함 용량 초과 = 일시)
- 받는 주소가 제목·미리보기에 없으면 명단 주소로 못 맞춰 «기록조차 안 남음»(충남사회서비스원 대표자: 실제로는 `501 RCPT TO: user unknown` = 없는 주소)
→ 10/12 아침에 사람이 원문을 열어 읽고 손으로 정리했다.

## 설계
- 새 모듈 `functions/news-bounce-body.js`(순수 + 읽기 주입) — 후보 고르기 → 본문 읽기(IMAP, 읽기만) → 판정 → 기존 `반송모으기` 에 «판정»을 실어 보냄.
- 후보 = 보낸 뒤 받은 메일 중 «반송 같은데 까닭 모름 / 주소 못 맞춤» 이거나 «기계 반송 꼴인데 제목 낱말이 달라 못 알아본 것»(예: `발송실패` 는 붙여 쓴 꼴). 한 번에 12통까지.
- 본문 글 = HTML 을 글로(`html글`) → 인용·원본 표지에서 자르고 앞 1500자만. 원본 편지(.eml 첨부)는 읽지 않는다 — 우리 편지 글에 낚이지 않게.
- ⚠ 자동으로 명단에서 빼는 것은 «확실한 근거»(user unknown · no such user · 5.1.1 · RCPT TO … unknown 등)가 있을 때만. 애매한 «없는 주소»는 «모름»으로 내려 사람이 본다.
- 읽기에 실패해도(IMAP 끊김·메일 없음) 스캔은 그대로 돈다 — 기존 판정만으로.
- `news-watch.js 반송모으기` 는 줄에 `판정` 이 실려 있으면 그것을 쓴다(없으면 예전 그대로).
