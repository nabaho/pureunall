# 경력관리 증명서 보관함 표에 «☐ 고르기 칸 + 번호» (2026-11-14)

PR #3025(인사관리 증명서 당겨오기)에서 «전부터 있던 규칙 위반»으로 남겨 둔 일 — CLAUDE.md 「자료 목록의 맨 왼쪽은 ☐ 고르기 칸 + 번호」(`docs/규칙/고르기칸-번호.md`)를 증명서 표(`_cdTable`)에 채웠다.

## 한 일 (`kcareer.html`)
- `_cdTable`: 맨 왼쪽 **☐ + №** 칸(`th.rownum-h` · 줄마다 `td.rownum`) — 번호는 «지금 보이는 순서»(거르거나 순서가 바뀌면 다시 매김 · 기록에 저장하지 않음 · 열쇠로 쓰지 않음). 머리줄 ☐ 는 지금 보이는 줄 전체. ☐ 의 값은 줄의 `id`, 이름표(`aria-label`)는 «종류 날짜 고르기».
- 고르기 줄(«N건 선택» · 전체 선택 · 선택 해제 · ⬇ 선택 내려받기 · 🗑 선택 삭제)을 `_dsSelBarHtml(domain)` **한 함수**로 뽑아 카드 보관함(이력서·프로필·비용 서류)과 증명서 표가 같은 줄을 쓴다(복사본 없음). 고르기만으로는 아무것도 안 바뀐다.
- 고르기·끌어 고르기·삭제는 카드 보관함이 쓰던 길 그대로(`docSelSync`·`docSelAll`·`bindDragSel`·`docSelDel` → `_docTrashIds`): **건수를 묻고(휴지통으로) 한 번에 저장**, 지운 줄은 물리 삭제가 아니라 휴지통(30일 안에 되살림). `docSelSync` 는 표 줄(`tr`)에도 «고른 바탕»을 칠하게 넓혔다.
- 다시 그리면 고른 것이 비워진다(검색·거르기를 바꿔도, 화면을 떠났다 돌아와도) — 번호도 다시 매겨진다. 고른 것을 어디에도 저장하지 않는다.
- 직원 «보기 전용»(`body.kc-staff`)에서는 다른 표처럼 ☐·번호 칸·고르기 줄이 감춰진다 → #3025 에서 넣은 «첫 칸 유지» 예외(`body.kc-staff #cdBody …:first-child`)를 걷었다(첫 칸이 이제 번호 칸 — 종류·발급번호는 둘째 칸이라 남는다). 취소된 줄의 옅은 글자색 규칙은 `td:nth-child(n+3)` 로 옮겼다(번호·종류 칸은 또렷하게).
- 어두운 판: `.sel-bar`(고르기 줄)와 `.dt tbody tr.sel-on`(고른 줄)이 밝은 바탕(#f8fafc)에 밝은 글자가 되어 읽히지 않던 것(대비 1.18:1)을 한 곳에서 맞췄다 — **모든 목록의 같은 옷**이라 다른 목록의 어두운 판도 좋아진다. 밝은 판 모양은 그대로.

## 폰·PC
- PC(1366)·폰(375): ☐ + № 가 카드 첫 줄(☐ 24px)에 선다(공용 `.dt td.rownum` 카드 규칙) · 한 칸은 한 줄 · 직원 보기 확인 · 어두운 판 대비 5.7:1 이상.
- PC 에서 표 모양은 #3025 에서 이미 공용 표 옷(`.dt`)으로 바뀌어 있었다 — 이번에 더한 것은 맨 왼쪽 두 칸(☐·№)과 표 위 고르기 줄뿐이다.
