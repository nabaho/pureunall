## 그 하나가 무엇을 망가뜨렸나 (`dbSet` 안)

```js

…
if(!curArr.every(function(x){ return x && x.id; })) return;             // ← 트랜잭션 매번 중단
…
```

1. **안전 병합이 늘 꺼진다** → 「⚠ 병합 실패 — 서버 최신으로 갱신했습니다」 경로로 빠진다
2. **객체형 변환이 안 된다** → 서버가 영영 «배열»
3. → `_fbObjForm['finance_income']` 이 false → **칸별(건별) 저장이 영영 안 켜진다**
4. → 자문수입을 한 번 고칠 때마다 **1MB 를 읽고 1MB 를 통째로 다시 쓴다**

「🧹 자문수입 중복 541건 자동 정리됨」 토스트도 같은 뿌리다 — 병합이 안 되니 통째
덮어쓰기·되받기가 되풀이되며 브라우저 안에서만 중복이 쌓였다(**서버에는 중복 0건**).

## 고친 것 — «조용히 느려지지 않게»

자기점검(부팅)에서 id 없는 기록을 세고, 있으면 **무엇이 문제인지까지 말한다**:
> ⚠️ 자문수입에 id 없는 기록 1건
> 이 표는 저장할 때마다 «통째로» 주고받고 있습니다 — 화면이 멈추는 원인입니다.

⚠ **자동으로 안 지운다** — 돈이 걸린 자료다. 세고 말하기만 한다(검사 ③ 이 이것을 못 박는다).

## 되돌리지 말 것

- ⚠⚠ **「모두 id 가 있을 때만 병합」 문턱을 풀지 말 것.** 풀면 id 없는 항목이
  병합에서 통째로 사라진다 — 느린 것보다 «사라지는» 것이 훨씬 나쁘다.
  느린 것은 «자료를 고쳐» 푸는 문제이지 문턱을 풀어 푸는 문제가 아니다.
- `dbUpsert` · `dbPatch` 의 id 검사도 그대로 — 새 껍데기가 못 들어오게 막는 그물이다.
