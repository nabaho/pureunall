# 컨설팅 드래그앤드롭이 안 되던 뿌리 — 카드 «순서 바꾸기»가 안쪽 줄 끌기를 취소하고 있었다

대표 제보 2026-09-16 「ERP 일정표 컨설팅 드래그앤드롭이 되지 않습니다!」
가지 `fix/drow-drag-eaten` · 고친 곳 `gov-consulting.html` (컨설팅일정, 대시보드 줄 끌기)

## 뿌리

2026-09-09 에 사업장 카드에 **「끌어서 순서 바꾸기」**가 붙었다(대표 지시 「기업순서를 바꿀수 있게 … 마우스로 드래그해서」).
그때 카드에 이런 것이 생겼다:

```js
card.draggable = true;
card.ondragstart = e => {
  if(!e.target.closest('.dcard-grip')){ e.preventDefault(); return; }   // ← 손잡이 아니면 취소
  ...
};
```

카드가 아무 데서나 잡혀 끌려다니지 않게 하려던 것이다. 그런데 —

- 컨설팅 줄(`.drow`)은 그 **카드 «안»**에 있다 (`.dcard > .dcard-rows > .drow`, 6501줄)
- `dragstart` 는 **버블한다**

그래서 줄에서 끌기를 시작하면
① 줄 핸들러가 먼저 돌아 `dragItem` 을 채우고 → ② 곧바로 **카드 핸들러가 버블로 받아 `preventDefault()`** 를 부른다.
**끌기가 그 자리에서 취소된다.** 달력으로 끌어다 놓는 길이 그날부터 막혀 있었다.

### 브라우저에서 실제로 재현해 확인했다

같은 겹침을 만든 쪽지 화면을 띄워 재 보았다:

```
① 줄 핸들러가 먼저 돌았다
② 카드 핸들러가 돌았다. e.target = .drow
   → preventDefault() 를 불렀다
★ 끌기가 취소됐나: true      ← 지금 코드
★ 끌기가 취소됐나: false     ← 고친 뒤
```

## 고친 것 — 한 줄

줄의 `ondragstart` 첫머리에 `e.stopPropagation()`.
**카드 쪽은 안 건드렸다** — 손잡이 끌기는 멀쩡히 돌고 있다. 안쪽 끌기가 바깥으로 새지 않게 막는 것이 옳은 자리이고,
일정 칩(`bindChipDrag`)도 같은 까닭으로 이미 그렇게 한다.

## ⚠ 다음 사람이 밟을 자리

- **바깥 것을 끌 수 있게 만들 때는, 그 «안»에 이미 끌리는 것이 있는지 먼저 본다.**
  `dragstart` 는 버블하고, 바깥에서 `preventDefault()` 하면 안쪽 끌기가 통째로 죽는다.
  안쪽에서 `stopPropagation()` 으로 막는 것이 바른 자리다.
- 이번에 **검사가 못 잡았던 까닭**: `tests/gov-dash-order.test.js` 는 카드 순서 규칙만 못 박고
  «안쪽 줄 끌기가 살아 있는가»는 한 줄도 안 봤다. 새 기능이 옆 기능을 죽여도 초록불이었다.
  → 그 파일에 **돌려 보는** 검사를 넣었다(가짜 DOM 에서 버블을 실제로 태워 `defaultPrevented` 를 잰다).
- 「글자로만 견주는 검사」의 한계도 드러났다 — 토막을 잘라 «돌려» 보니 닫는 `);` 가 빠져 구문 오류가 났다.
  글자만 볼 때는 아무도 몰랐다.

## 검사

`tests/gov-dash-order.test.js` 에 2건 추가 —
① 컨설팅 줄을 끌면 취소되지 않고 `dragItem` 이 담긴다 ② 카드 순서 바꾸기는 그대로 살아 있다(손잡이 밖은 여전히 막는다).
이빨 확인 **6/6** (고침 빼기 · 너무 늦게 막기 · 꺼 두기 · 카드 막기 없애기 · 카드 못 끌게 하기 · dragItem 안 담기 — 모두 걸린다).

## 짚어 둘 것 — 푸른이알피(pu-erp) 쪽은 «원래 없다»

찾다가 확인한 것: 푸른이알피의 달력들(내 캘린더·법인 대시보드)에는 **컨설팅이 아예 안 올라간다.**
- 「내 캘린더」는 일부러 뺐다(「사건/컨설팅/출퇴근은 내 캘린더에 표시 안 함」).
- 법인 대시보드는 사건 마감·단계 기한만 올리고 그것도 `draggable:false` 다(계산된 값이라 일부러).
- `moveCalendarEvent` 에 `eventType === 'cons'` 분기가 있지만 그 이름표를 **만드는 곳이 한 곳도 없다** — 7월부터 죽은 코드다.

즉 이알피 달력에서 컨설팅을 끄는 기능은 «고장 난» 것이 아니라 **한 번도 없었다.**
필요하시면 만들 수 있으니 말씀해 주십시오(이번 고침에는 안 넣었다 — 제보하신 것과 다른 일이다).
