# 2026-11-15 푸른메일 열기 속도 개선 + 메일 회의·강의·기관조사 일정 자동 등록·병합

## 1. 푸른메일 열기 속도 개선 (`pu-cards.html`, `functions/mail-sync.js`)
- **원인**:
  1. 다음메일은 자체 서버에서 이미 파싱된 본문 DB를 바로 내려주지만, 푸른메일은 실시간DB 용량·비용 보호를 위해 본문을 저장하지 않고 클릭 시 서울 Cloud Functions(`readMailMessage`) → 다음 IMAP 조회·파싱 → 미국(`us-central1`) RTDB 읽음 표시를 거쳤다.
  2. 본문이 도착하기 전 0.4~0.7초 동안 `본문을 가져오고 있습니다…` 빈 화면만 보였고, 보낸이 칸(`.who`)에는 마우스 호버 미리 받기가 없었으며 클릭(`mouseup`)이 끝난 뒤에야 요청이 출발했다.
- **개선**:
  1. **0ms 즉시 본문·첨부 미리보기(`mbLoadingBodyHtml`)**: 클릭 즉시 목록에 이미 받아 둔 앞부분 글(`row.p`)과 첨부 파일명(`row.an`)을 먼저 펼쳐 보여 주고, 전체 서식 HTML이 도착하면 매끄럽게 교체.
  2. **누르는 순간(`mousedown`) + 보낸이 호버 + 상위 안 읽은 메일 자동 미리 받기(`mbPressPeek`, `mbPrefetchTop`, `MB_HOVER_MS = 70`, `MB_BODY_KEEP = 60`)**: 손가락을 떼기 전부터 본문을 받아 체감 지연을 제거.
  3. **서버 그릇 메모리 캐시(`_msgBodyCache`, 5분·40통 상한) + 읽음 표시 병렬화(`{ write: !peek }`)**: 미리 받아 둔 통이나 직원이 방금 연 통은 IMAP 재왕복·재파싱 없이 즉시 응답하고, `\Seen` 표시와 RTDB `r=1` 기록을 본문 읽기와 병렬화.

## 2. 메일 일정(회의·강의·기관조사 등) → 푸른캘린더 & 구글 공용 캘린더 자동 등록·병합 (`js/pu-cal-capture.js`, `functions/cal-inbox.js`, `functions/rules-collect-redact.js`, `functions/mail-sync.js`, `scripts/make-firebase-rules.js`, `pu-cal.html`, `pu-cards.html`)
- 받은메일함에 새로 들어온 일정 메일에서 본문뿐 아니라 **첨부 공문(`.pdf`, `.hwp`, `.hwpx`, `.docx`)** 안의 일시·도로명 주소·담당자 이름·전화번호·안건을 읽어(주민등록번호·계좌·신분증은 가리고 원본 바이트 전송 없이) AI 초안을 생성.
- 검증된 발신자(공공·교육·연구기관 도메인 또는 등록 거래처·명함·공단연락처 + 메일 인증 통과)가 보낸 날짜 확정 일정(`date >= today`, `[마감]` 제외, 외부 URL 자동 제거)을 **푸른캘린더(`data/my_schedules/v`)와 구글 공용 캘린더(`GCAL_CAL_ID`)에 자동 등록**.
- **동일 시간(또는 같은 날·같은 기관/회의명) 기존 일정 원자적 자동 보강**: 이미 같은 시각에 대표님(`P-001`) 회의가 적혀 있으면 중복 생성하지 않고 트랜잭션으로 기존 일정을 직접 고쳐 상세 주소·담당자 연락처·회의 내용을 채워 넣음(기존 메모·종료시각 보존).
- 제출 기한(`[마감]`) 및 미등록 외부 발신자 건은 푸른캘린더 `📥 일정 후보`에 남겨 검토 후 반영하며, 설정 스위치·한도(`cal_inbox/cfg`)는 총괄관리자(`ADMIN`) 전용 경로로 격리·잠금.
