# 경력관리 휴지통 «일괄 반복문 넷»도 한 번에 담기 + `.dt` 표 가로 넘침 재기 (2026-11-16)

PR #3047 이 증명서 보관함 표(`_docTrashIds`)만 `kcTrashPutMany` 로 바꾸고 «결과가 달라질 수 있는 자리마다 검사·가짜 환경이 달라 별도»로 남겨 둔 일(`status/2026-11-15-kcareer-select-trash-hardening.md` ③, `status/2026-11-15-kcareer-drag-start-state.md`)을 이어서 했다.

## 한 일 (`kcareer.html`)

건마다 `kcTrashPut` 을 불러 휴지통 «전체를 읽고 쓰기»를 N번 하던 반복문 네 곳을 `kcTrashPutMany`(한 번 읽고 한 번 쓴다) 한 번으로 바꿨다. 짓다가 걸리면 아무것도 안 바뀐다.

| 자리 | 함수 | 무엇을 지우나 | 전에는 |
|---|---|---|---|
| ① | `careerDelAll` | 「이 화면 전체 삭제」(수백 건일 수 있음) | 건마다 휴지통 저장 N번 |
| ② | `careerDelSelected` | 「골라 삭제」 | 같음 |
| ③ | `bizSelDel` | 사업 골라 삭제 | 같음 |
| ④ | `rhDraftTrashSel` | 작성 중 서류 골라 버리기 | 같음 + 열어 둔 자리 표시를 «담기 전에» 지움 |

- **순서·줄 모양은 그대로** — 마지막 건이 맨 위(`kcTrashPut` 과 `_kcTrashEntry` 한 곳을 같이 쓴다). 확인창·알림 문구·휴지통 줄의 `store`·`page`·`what` 도 전과 같다.
- ③ 사업: «되살리기» 손잡이는 전과 같이 «마지막으로 담은 줄»이다(`es[es.length-1]`). 바꾸지 않았다 — 아래 «안 고친 것» 참고.
- ④ 작업 중 서류: 열어 둔 자리 표시(`_rhDraftId`)는 «담은 뒤에» 지운다. 담다가 걸리면 열어 둔 자리가 그대로여야 한다. 알림의 «N건»은 «실제로 담은 건수»(목록에서 그새 사라진 번호는 건너뜀).
- 손댄 기존 검사 넷(코드 모양이 바뀐 만큼): `kcareer-draft-select.test.js`(가짜 `kcTrashPut` → `kcTrashPutMany`, 담은 «횟수»도 센다) · `kcareer-navcount-run.test.js`(같음) · `kcareer-html.test.js`·`kcareer-trash.test.js`(`kcTrashPut(` → `kcTrashPut(Many)?(`).

## `.dt` 표 가로 넘침 — 잰 것(고치지 않았다)

가짜 파이어베이스 + 지어낸 자료(`tools/phone-audit/seeds/career.js`)로 29개 화면을 하나씩 열어, 보이는 `.dt` 상자마다 «표 폭 > 상자 폭»을 쟀다(내장 브라우저, 폭마다 새로 불러서). 보이는 `.dt` 상자 18개 중 줄이 있는 것은 8개(나머지 10개는 지어낸 자료에 줄이 없어 빈 표 — 재지 못한 것). ⚠ 지어낸 자료 기준이라 실제 자료의 긴 글자·많은 칸에서는 더 넓을 수 있다.

| 폭(px) | 상자보다 넓은 표 |
|---|---|
| 1366 | 없음 |
| 1280 | 위촉장(989 대 963) 한 곳 — 상자 밖으로 26px 삐져나오지만 화면은 안 구른다 |
| 1160 | 위촉장(989 대 843) — 그때 `main` 이 좌우로 110px 구른다 |
| 1024·768 | 위촉장(989) · 사업(795) · 자문(805) 세 곳 |
| 600 | 위촉장·자격·수료·표창·교육·경력·사업·자문 여덟 곳(642~996px) |
| 375 | 없음(폰 카드 모양) |

- `.dt` 자체는 `overflow-x:visible` 이라(머리행 틀고정 때문 — 위 `.dt table` 주석) 넘친 표는 상자 안에서 구르지 않고 **`main` 이 좌우로 구른다**. 1024px 위촉장 표는 `main` 이 246px 구른다.
- **이 폭 띠(521~1280px)의 위 표들은 ☐ 칸이 왼쪽에 안 붙어 있다.** 1024px 에서 `main` 을 끝까지 굴리면 줄마다 ☐ 와 머리줄 «전체 선택 ☐» 가 화면 밖으로 나간다 — #3047 이 증명서 표(`#cdBody`)에만 한 «☐ + № 칸 붙들기»(`position:sticky;left:0`)와 같은 문제다. 줄 바탕·고른 줄·지나가는 줄·어두운 판을 표마다 맞춰야 해서 이번에는 재기만 했다. 고친다면 `#cdBody` 규칙을 공용 `.dt` 쪽으로 넓히는 일이다 [결정 필요].
- 폭 띠 밖(PC 1366 이상·폰 375)에서는 문제가 없었다. 태블릿 실기기 터치는 보지 못했다.

## 안 고친 것 (이번 일 밖 — 전부터 있던 것)

- **`careerDelAll`·`careerDelSelected` 알림의 «↩ 되살리기» 손잡이가 아무것도 못 되살린다** — `kcUndoBar(msg, null)` 처럼 번호(`tid`)도 `fn` 도 안 줘서, 눌러도 `kcTrashRestore(null)` → «휴지통에서 찾지 못했습니다». 코드를 읽어 안 것이고 화면에서 눌러 보지는 않았다. 고치려면 `_docTrashIds` 의 «여러 건 되돌리기»처럼 담은 줄 전부를 되살리는 `fn` 을 줘야 하는데, 「전체 삭제」(수백 건)는 건마다 되살리면 저장이 N번이라 일괄 되살리기가 따로 필요하다.
- **`bizSelDel` 의 «되살리기» 는 마지막으로 담은 한 건만 되살린다**(알림은 «사업 N건») — #3029 에서 증명서 표에 고친 것과 같은 모양. 위 일괄 되살리기와 함께 공용 헬퍼로 묶는 게 맞다.
- 위 «☐ 칸 붙들기» 넓히기.
- **휴지통 «저장 실패»는 막지 못한다**(자동 검증 보안 쪽 지적 — 중간, 새 회귀 아님): `kcTrashPutMany`(와 전부터 `kcTrashPut`)는 `set` 이 «못 담았다»(`LS.set` 실패·예외는 `set` 안에서 삼켜진다, `set._lastOk===false`)는 것을 모른 채 줄을 돌려준다. 그래서 이 기기에 휴지통이 안 담긴 채로 원 자료를 빼고 «옮겼습니다»라고 알릴 수 있다(검토 쪽 가짜 환경에서는 휴지통 쓰기가 `false` 일 때 원 자료 0건·휴지통 0건을 재현). 이번에 «짓다가 걸리면 아무것도 안 바뀐다»고 한 것은 이름표를 짓다가 던진 경우뿐이고 **저장 자체의 실패까지 원자적인 것은 아니다.**
  - 안 고친 까닭: 제대로 막으려면 `_feeSaved`(`set._lastOk` + 기본 저장소 KV 의 `flush`·오류 횟수까지 본다)처럼 «기다려서» 확인한 뒤에야 원 자료를 빼야 한다 — 지우는 길 전부(`delRec`·`_docTrashIds`·위 넷 등)가 비동기로 바뀌는 일이다. `set._lastOk` 만 보는 반쪽 가드는 localStorage(보조 저장) 가 가득 찬 것만으로 삭제를 막는 새 문제를 만들 수 있고 KV 쪽 실패는 못 잡는다. 따로 결정·구현하는 게 맞다 [결정 필요].
