# 2026-09-13 · 서고 — 「개정전」이 「개정본」으로 갈리던 것

- PR: 이 가지
- 대표 지시: 「1」 (= 서고에 첫 자료 넣기)

## 왜 이걸 먼저 했나

서고는 **한 번도 안 써 본 길**이다(살아 있는 DB 에 `rules_mgmt/casebook` 이 없다).
대표가 10년치를 떨어뜨리기 «전»에 내가 먼저 돌려 봤다 — 중간에 막히면 시간만 버린다.
⚠ **업체 자료를 안 썼다.** 노무법인 폴더에 흔한 파일 이름 모양을 손수 지어 돌렸다.

## 나온 것 — 하나는 위험했다

| 파일 이름 | 갈린 것 | |
|---|---|---|
| `신구대조표_2019.hwp` | 대조표 | ✔ |
| `취업규칙 변경신고서.hwp` | 신고서 | ✔ |
| `근로자 의견청취서.hwp` | 의견 | ✔ |
| `취업규칙_○○_2022_개정안.hwp` | 개정본 | ✔ |
| **`개정전_취업규칙.hwp`** | **개정본** | **✖ 뒤바뀜** |
| `회의록`·`붙임1`·`스캔본` | 확인 필요 | ✔ (사람이 봐야 한다) |

14개 중 10개를 스스로 가리고 4개를 「확인 필요」로 올렸다 — 거기까지는 설계대로다.

## ★★★ 뿌리 — 「개정」이 「개정전」보다 먼저 걸렸다

```js
{ role: 'after',   words: ['개정안', '개정', '최종', '(신)'] },
{ role: 'before',  words: ['현행', '기존', '(구)'] }      ← 아래라 차례가 안 온다
```

`개정전_취업규칙` 은 **「개정」** 에 먼저 걸려 `after`(개정본)가 됐다.
`before` 의 단서(현행·기존·(구))에는 「개정전」 꼴이 아예 없었다.

★ **왜 큰가** — 개정 «전» 문안이 개정 «본» 자리에 담기면
신구대조표가 **거꾸로** 그려지고, 조문 검색·사례집이 **옛 문구를 지금 것으로** 내놓는다.
빈칸은 눈에 띄지만 **뒤바뀐 값은 아무도 못 찾는다.**

## 고침

`before` 를 `after` «위»로 올리고 「전」 꼴을 다 넣었다 —
`개정전 · 개정 전 · 변경전 · 변경 전 · 종전 · 현행 · 기존 · (구)`.
`after` 에는 「개정후」를 더했다.
⚠ **대조표는 여전히 맨 위다** — 「개정전후 신구대조표」는 대조표다(검사가 지킨다).

## 안 바꾼 것

`취업규칙.hwp` 처럼 단서가 없는 것이 「확인 필요」로 가는 것은 **일부러 그렇게 한 것**이다
(설계서 §4 · 기존 검사가 못 박고 있다). 추측해서 넣으면 수백 건 중 어느 것이 틀렸는지
아무도 못 찾는다. 회차마다 본문 파일이 한 번씩 확인 필요로 올라오지만, 그 화면은
**확인 필요분을 맨 위에** 둔다.
