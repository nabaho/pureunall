## 찾은 것 — 다섯, 전부 고쳤다

### ★★ ① 이번 달·지난 달이 «점 모양 날짜»를 통째로 빠뜨렸다

입력 칸(`autoDate`)은 일자를 **「2026.09.18」(점)** 으로 저장한다 — 캡쳐 속 실제 건이 그 모양이다.
달을 가르는 코드는 앞 일곱 글자를 «그대로» 「2026-09」(줄표)와 견주었다.

| 화면 | 고치기 전 | 실제 |
|---|---|---|
| 한눈에 「이번 달」 | **45,000원** | 345,000원 (점 모양 300,000원이 빠짐) |
| 정산 「지난 달」 | 「이 기간에 기록이 없습니다」 | 2건 1,680,000원 |

한눈에 한 화면 안에서도 모순이었다 — 「이번 달 45,000원」 바로 아래 최근 내역에는 10월 건이
300,000원 + 45,000원으로 찍혀 있었다. **대표님 화면의 실제 건(2026.09.18, 1,600,000원)이 바로 이 경우**라,
정산 「지난 달」은 비어 보였을 것이다.

**왜 검사가 못 잡았나** — 검사 자료가 전부 줄표(`올해 + '-01-05'`)였고, 이번 달·지난 달 길은 아예
안 돌렸다(올해·전체만). 그래서 **초록인데 화면은 틀렸다.**

**고침** — 일자를 읽는 곳을 `_feeYMD` 한 곳으로 모았다(점·줄표·빗금·여덟 자리·「년월일」).
이번 달 합계·월별 막대·정산 기간·«마지막»·최근 순이 모두 거기서 읽는다.
⚠ 일자를 글자 조각(`slice`)으로 자르지 말 것.

### ② 「마지막」·「최근 내역」 차례가 점과 줄표가 섞이면 어긋났다
글자로 견주면 점(`.`)이 줄표(`-`)보다 커서 10월 9일(줄표)이 10월 5일(점)보다 아래로 갔다 → 날짜 열쇠(`_feeKey`)로 견준다.

### ③ 옆줄 「비용 목록」 숫자가 목록보다 적었다
옆줄은 `meetfee` 한 통만 세는데 목록은 `meetfee + etcfee` 두 통을 모은다 → 목록 4건·옆줄 3건.
(대표님 화면은 기타비용이 비어 있어 우연히 맞아 보였다.) `navCount` 가 `cfg.stores` 를 따라 두 통을 센다.

### ④ 비용 목록 줄이 글자를 감싸지 않았다 (이번 일 전부터 있던 것)
내용·지출처는 **OCR 로 읽은 영수증 글자가 그대로 들어오는 칸**인데 `${r.content}` 를 날것으로 그렸다.
`<img onerror=…>` 같은 글이 있으면 화면에서 그대로 실행됐다. 다른 목록은 이미 `escapeHtml` 로 감싸고 있었다.
CSV 로 가져온 번호에 `'` 가 있으면 동의서 단추도 깨졌다 → `_jsAttr`.

### ⑤ 어두운 판에서 새 화면이 «안 보였다» / 폰에서 정산 표가 잘렸다
- 큰 숫자 셋(합계·이번 달·건수)·칸 제목·구분별 막대가 글자색 = 바탕색이었다(대비 차 0.00).
  새 CSS 가 글자·막대에 `var(--navy)` 를 썼는데, 어두운 판에서도 `--navy` 는 짙은 남색 그대로다.
  → 글자·막대는 `var(--ink)`(어두운 판에서 밝게 뒤집힘, 밝은 판에서는 `--navy` 와 같은 색 — 모습 그대로).
- 정산 표는 여섯 칸이라 폰 폭(375)보다 넓다(실측 469) — 맨 오른쪽 「입금계좌」가 잘려도 밀어 볼 길이 없었다
  → 감싸는 칸이 옆으로 밀린다. 한눈에는 폰에서 문제없었다(2열·1열로 접힘, 넘침 0).

## 검사 — 「진짜 모양」으로

`tests/kcareer-fee-dates.test.js` 새로 8개. 못 박은 규칙:
- 어떤 일자 모양이든 같은 달로 읽는다(점·줄표·빗금·여덟 자리·「년월일」·여섯 자리, 읽을 수 없으면 빈 값)
- **시계를 고정**해 이번 달·지난 달을 돌린다 — **1월에는 지난 달이 «지난해 12월»** (해 넘김)
- 한눈에 «화면 전체»를 돌려 이번 달 숫자·최근 순·월별 막대를 읽는다
- 합친 표에서 **기타비용 줄은 «자기 통»**으로 동의서를 만든다(안 그러면 만든 날이 남의 통에 적힘)
- 옆줄 숫자는 두 통을 센다 · 줄은 글자를 감싼다 · 새 화면 CSS 에 `var(--navy)` 글자 없음 · 정산 표 밀기

⚠ 옛 검사 하나(`kcareer-html` 「📨 동의서 버튼」)의 정규식이 «첫 닫는 괄호»에서 끊겨,
값을 `_jsAttr(…)` 로 감싸자(안쪽 괄호) 깨졌다 → 속성 끝(`)"`)까지 보게 고쳤다. 지키는 규칙은 그대로다.

**고장 넣기** — 되돌려 걸리는지 열여섯 자리를 돌렸다. 처음엔 둘이 안 걸렸다:
최근 순을 글자로 견주는 자리(그리기 함수 안이라 부분 함수 검사가 안 닿음 → 화면 전체를 돌리는 검사를 더함),
저장소를 안 넘기는 자리(→ 합친 표 규칙을 직접 돌려 더함). 지금은 **열여섯 모두 걸린다.**

## 안 고친 것 — 대표님이 정하실 것 둘

1. **「이번 달」·월별 막대를 눌러도 그 달이 아니라 «한 해 전체»로 간다** (실측: 이번 달 누르니 4건, 9월 막대 누르니 4건 — 9월은 2건).
   비용 목록에 «월 고르개»가 없어서다. 눌러지는 것처럼 보이는데 속이는 셈이라 정해야 한다 —
   (가) 비용 목록에 「전체 월」 고르개를 더한다(추천) (나) 이번 달·월 막대는 눌러도 아무 일 없게 (다) 지금처럼 두고 「(그 해 전체)」를 적는다.
2. 한눈에·정산이 «이름 글자»로 묶는다(지출처 「홍길동」). 같은 사람이 「홍 길동」으로 적히면 두 곳으로 갈린다.
   온톨로지 규칙은 이름을 «관계 열쇠»로 쓰지 말라는 것인데 여기는 보여 주려고 합치는 셈이라 위반은 아니다 —
   다만 사람 번호(sid)로 잇는 길은 이 화면에는 없다. 쓰다가 갈리는 것이 보이면 그때 정한다.
