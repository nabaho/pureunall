# 2026-11-19 — AI 부름: 은퇴 모델 교체 · 보내기 전 개인정보 가림 (`claude/ai-model-mask`)

## 왜
- 대표가 «구독에 딸린 무료 API 크레딧» 으로 무엇을 할 수 있나 물어, 푸른토탈시스템의 AI 연결 지점을 훑다가 발견했다.
- **은퇴 모델**: 푸른이알피 상담 AI 요약은 `claude-sonnet-4-20250514` 하나만 썼는데, 이 모델이 **2026-06-15 에 은퇴**했다. 그 뒤로 이 단추는 늘 실패했을 가능성이 크다(실제 프록시 호출은 하지 않아 확인하지 못함). 업무관리·기금관리의 두 번째(폴백) 모델도 같은 모델이라 폴백이 죽어 있었다. 포털 챗봇의 보조 길도 같다.
- **개인정보**: 상담 AI 요약·업무관리 AI 초안/인터뷰/지식 뽑기/지식 묻기·기금 AI 가 의뢰인 이름·전화·주민번호를 가리지 않고 바깥 AI(Anthropic)로 보내고 있었다. 회사 원칙은 «외부 서비스에 고객 실명·주민번호를 넣지 않는다» 이다.
- 대표 「여기서 고쳐줘」(은퇴 모델 교체와 개인정보 가림부터).

## 한 것
- **새 가리개 `js/pu-ai-mask.js`**
  - 이미 아는 값(상담자·업체·의뢰인·상대기관 담당·우리 담당자)과 모양으로 아는 번호(주민·외국인번호·카드·사업자번호·계좌·전화·전자우편)를 `[의뢰인1]`·`[전화1]` 같은 꼬리표로 바꿔 보낸다.
  - 답이 오면 **브라우저 안에서** 진짜 값으로 되돌린다. 그래서 초안에는 진짜 이름이 들어 있다.
  - 가린 뒤에도 주민번호 꼴이 남아 있으면 `PuRrnMask.maskRrnInText` 로 한 번 더 지운다(마지막 문지기).
  - 뒤돌아보기(lookbehind)는 쓰지 않았다. 옛 사파리에서 터지기 때문이다.
- **업무관리(`work.html`)**: `aiCall(system,userText,known)`
  - 가리개가 없으면 **보내지 않는다.**
  - `aiKnown(id)` 가 업체·의뢰인·상대담당·담당자·기록 작성자를 넘긴다.
  - 모델은 `['claude-opus-5-5','claude-sonnet-5-5']`. Opus 5.5 가 Opus 5 보다 싸다.
  - 안전 기준으로 거절(`stop_reason:'refusal'`)되면 까닭을 밝히고 다음 모델로 넘어간다.
  - AI 동의 문구를 «무엇을 가리고 무엇은 못 가리는지» 에 맞게 고쳤다.
- **기금관리(`fund.html`)**
  - `aiCall` 에 같은 가림을 넣었다. 서식 고치기는 AI 가 고른 «찾을 글» 을 되돌린 뒤 찾으므로 그대로 맞는다.
  - 모델은 업무관리와 같은 목록이다.
  - `max_tokens` 를 2000 → 4000 으로 올렸다. 새 모델은 생각(thinking)도 이 안에서 쓴다.
- **푸른이알피(`pu-erp.html`) 상담 AI 요약**
  - 상담자·연락처와 번호를 가리고, 요약을 되돌려 저장한다.
  - 모델 `claude-sonnet-5-5`, `max_tokens` 800 → 2000.
  - 프록시 오류(`d.error`)와 거절을 따로 알린다.
- **포털 챗봇(`js/pu-chatbot.js`) 보조 길**
  - 모델만 `claude-sonnet-5-5` 로 바꿨다. 질문은 이미 `maskPersonal` 로 가리고 있다.
  - `max_tokens` 1100 → 2000, 거절 안내를 더했다.
- **문서 `docs/AI-프록시-만들기.md`**
  - 새 모델·`max_tokens` 를 반영했다.
  - Worker 는 `model`·`max_tokens`·`system`·`messages` 만 넘겨서 생각 양(`effort`)이나 서버 쪽 `fallbacks` 를 앱에서 정할 수 없다는 점을 적었다.
  - 거절 응답과 «가려서 보낸다» 절을 더했다.

## 검사
- 새 검사
  - `tests/ai-mask.test.js`: 가림·되돌림·조각 이름·전화와 계좌 구분·뒤돌아보기 금지, 세 앱이 싣고·거치고·없으면 멈추는지.
  - `tests/ai-models-not-retired.test.js`: 배포되는 앱(최상위 html·js·functions)이 은퇴 모델을 부르지 않는지.
- **모델 이름을 박던 검사를 «규칙» 으로 바꿈**
  - `ai-proxy-doc`: 코드의 모델·max_tokens 가 문서에 있는지, 이알피는 한 모델만 쓰는지.
  - `fund-ai-edit`: 업무관리와 같은 목록인지.
  - `work-ai-timeout`: 바꿔 걸 모델이 둘 이상인지.
  - `erp-fetch-timeout`·`erp-ai-proxy`: 함수 앞 몇천 자만 자르던 것을 함수째 집고, 저장 자리는 `upd('summary',` 로 찾게 했다.
- 브라우저(가짜 파이어베이스, 바깥 요청은 가로챔)
  - 업무관리 `aiCall`: 보낸 글에 꼬리표만 있고 답은 되돌려졌다. 거절 응답이면 둘째 모델로 넘어갔다. 가리개를 빼면 보내지 않았다.
  - 기금 `aiCall`: 꼬리표로 고른 «찾을 글» 이 원문으로 되돌려졌다.
  - 이알피: 가리개가 실린 것만 확인했다. 상담 창의 AI 요약 단추를 눌러 보지는 못했다.

## 남은 것 / 못 한 것
- **기록 본문 속 «넘겨받지 못한» 다른 사람 이름·주소는 못 가린다.** 모양으로 알 수 없기 때문이다. 동의 문구와 문서에 적었다.
- **경력관리(`kcareer.html`)**
  - 아직 브라우저에서 API 키로 Claude 를 바로 부른다. 키는 localStorage 와 RTDB `_secrets` 에 있다.
  - 증명서 **사진**을 보내므로 이 글자 가리개로는 못 가린다.
  - 모델 `claude-haiku-4-5` 는 은퇴하지 않아 이번에는 손대지 않았다. 서버 문으로 옮기는 일은 따로 해야 한다.
- **Claude 프록시(Worker)는 여전히 증표가 없다.** 주소가 새면 누구나 쓸 수 있다. Console 월 상한을 꼭 걸어야 한다. 잠그는 일(로그인 토큰 검사 또는 Functions 문)은 따로 해야 한다.
- `tools/pureun-ai/`(내 PC LLM 라우터)도 은퇴 모델 `claude-opus-4-1` 과 곧 은퇴할 `claude-sonnet-4-5`(2026-11-30)를 쓴다. 배포되지 않는 도구라 이번 범위에서 뺐다.
- 실제 프록시로 새 모델을 불러 보지는 않았다(돈이 나간다). 배포 뒤 상담 AI 요약을 한 번 눌러 확인해야 한다.
