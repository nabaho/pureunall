# 2026-09-27 staff-pick-color — 담당자가 «제 색»을 스스로 고른다

대표 지시 — 「담당자들이 자기 색을 스스로 선택할 수 있게 해달라. 본인 이름 클릭시 색깔
선택할 수 있게 다양한 색 준비하고, 만약 색이 중복되는 경우 다른 사람과 중복되어
사용할 수 없다고 창이 나오게 해라.」 목업 뒤 「추천대로」.

## ★ 먼저 걸린 것 — 고를 색이 «열한 가지»뿐이었다

사람 색은 **구글 일정 색 11가지**에서만 왔다. 그런데 **현직이 10명**이다.
「남이 쓰는 색은 못 쓴다」로 하면 **남는 색이 하나**뿐이라 — **고를 수가 없다.**
색을 안 늘렸으면 이 기능은 만들어도 뜻이 없었다.

→ 이알피가 외부 협력자에게 쓰던 **사람 구분색 24**를 함께 낸다.
**어느 둘을 집어도 눈에 다르게 보이도록 «재서» 짠 것**이라 마침 이 일에 맞다.
합쳐 **35가지**(구글 11 + 24, 겹치는 값은 앞엣것만).

⚠ `pu-erp.html` 의 `EXT_COLOR_CANDIDATES` 와 **같은 값**이다. 한쪽만 고치면
같은 사람이 두 앱에서 다른 색이 된다 — 검사가 두 파일을 맞대 본다.

## 무엇을 만들었나

| | |
|---|---|
| **여는 법** | **내 칩을 누르면** 색 고르개가 열린다. 내 칩에는 파란 고리를 둘러 「이게 나」를 알린다 |
| **남의 칩** | **그대로 거르개**다 — 남의 색은 내가 못 고친다(서버도 막는다) |
| **거르개** | 내 칩으로는 못 거니까, 고르개 맨 위에 「📋 내 일정만 보기」를 두었다 |
| **남이 쓰는 색** | **빗금 + 이름 두 글자**를 미리 보여 준다. 숨기면 「왜 이 색은 없지」 하고 찾는다 |
| **겹치면** | **창**이 뜬다 — 「⛔ 이미 쓰는 색입니다 · 김철수 님이 쓰고 있습니다」 |
| **그만둔 사람 색** | **안 잠근다** — 안 쓰는 색까지 잠기면 고를 것이 줄어든다 |

## 저장 — «내 칸 하나»만

`PuCalWrite.saveMyColor(sid, 색)` 를 새로 만들었다. `data/staff_colors/v/<사번>` 한 칸만 적는다.

⚠ 기존 `saveColors` 를 **쓰지 않는다**. 그것은 `data/staff_colors` 를 **통째로** 갈아 끼운다 —
① 서버 규칙이 통째 쓰기를 관리자에게만 허락하므로 직원이 부르면 **거절**당하고,
② 통째로 쓰면 **내가 보던 색표**를 그대로 올려 그사이 남이 고친 색을 **덮는다**.
⚠ `u`(시각)는 안 건드린다 — 읽는 쪽이 `v` 만 보고, 열어 두면 아무나 흔들 수 있다.

## 서버 규칙 — 고쳐서 **올렸다**

```
data/staff_colors
  .read   직원 누구나      (그대로 — 남의 색을 봐야 «겹치는지»를 안다)
  .write  관리자·위임관리인 (그대로 — 통째로 갈아 끼우는 일은 관리자 몫)
  v/$sid
  ├ .write    관리자·위임관리인 «또는» uid_roles 의 제 사번과 같을 때
  └ .validate #rrggbb 여섯 자리만
```

**누가 무엇을 할 수 있게 됐나:** 직원 10명이 **제 칸 하나**를 쓸 수 있게 됐다.
남의 칸은 여전히 못 건드린다. 읽기는 전과 같다 — **새로 보이게 된 칸은 없다.**

⚠ `.validate` 를 붙인 까닭: 없으면 아무 글자나 들어와 **그 사람 칩이 통째로 안 보인다.**
화면 검사로는 못 막는다 — 서버가 막아야 한다.
⚠ `uid_roles` 10칸 모두 `sid` 가 있는 것을 **먼저 확인하고** 올렸다(없으면 그 사람은 제 색도 못 고친다).

올린 결과: 새로 1개(`/data/staff_colors/v`) · 바뀜 0 · 사라짐 0 · 콘솔 확인 일치.
