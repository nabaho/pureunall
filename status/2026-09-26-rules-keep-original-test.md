# 2026-09-26 · 취업규칙 ③ 원본 살려 고치기 — 가능성 시험 (통과)

> 대표 지시: 「표준취업규칙으로 해봐라」 — 목업 ③(원본 모양 그대로)을 만들기 전 시험.
> 시험 파일: 고용노동부 「표준취업규칙(2026년, 배포).hwp」(공개 문서, 164쪽). 사업장 실제 파일은 쓰지 않았다.

## 결론 — .hwp 를 «원본 형식 그대로» 고쳐 저장하는 길은 된다

브라우저에 이미 있는 한글 엔진(vendor/rhwp-core, 0.7.19)으로 원본을 열어 고치고 `exportHwp()` 로 저장한 뒤,
**진짜 한글 프로그램**(자동화)으로 열어 PDF·본문 글자를 뽑아 원본과 견줬다.

| 확인 | 결과 |
|---|---|
| 한글에서 열림 | ✓ (원본·고친 .hwp·고친 .hwpx 셋 다) |
| 쪽수 | 원본 164 = 고친 .hwp 164 |
| 본문 글자 비교(한글이 뽑은 2,346줄) | **고친 곳 14줄만** 다름 — 나머지는 한 글자도 안 바뀜 |
| 글꼴 | 19종 그대로 |
| 속 조각(요약정보·미리보기·스크립트) | 전부 그대로. 파일이 284→197KB 로 준 것은 압축 차이뿐(풀면 문서정보 0바이트 차이) |
| 엔진 자기검증 `exportHwpVerify()` | recovered:true |

시험한 편집 다섯 가지(모두 됨):
① 글자 바꾸기(표 칸 안) ② 항 끼워 넣기(문단 쪼개기) ③ 조 신설(표에 줄 넣기 + 조문·해설 칸)
④ 조 삭제(「제25조 삭제 <날짜>」, 뒤 조 번호 안 밂) ⑤ 문단형 조문에 항 끼워 넣기

## 걸린 것 — 만들 때 반드시 넣을 것

1. **새 글자는 옆 조문의 글자 모양을 복사해 입혀야 한다.** 안 하면 새 글자가 빈 문단의 «굵은 조 머리» 모양을
   물려받아 통째로 굵게 나온다(표준취업규칙은 빈 문단이 109번=굵게). 조 머리·본문·해설 꼬리표·해설 본문의
   모양 번호를 **그 문서에서 그때그때 읽어**(`getCellCharPropertiesAt`/`getCharPropertiesAt` → `setCharShapeIdInCell`/`setCharShapeId`)
   입혔더니 원본과 똑같아졌다. ⚠ 번호를 박지 말 것 — 사업장 문서마다 다르다.
2. **.hwp 를 .hwpx 로 바꿔 저장하면 안 된다.** 한글 본문 비교에서 160줄이 달라졌다 —
   「작성·변경」→「작성· 변경」 같은 **띄어쓰기가 멋대로 생기고**, 모아찍기(한 장에 두 쪽) 인쇄 설정도 빠졌다.
   → 목업 ③ 결정 「원본과 같은 형식으로 저장」이 맞다(.hwp 는 .hwp, .hwpx 는 .hwpx).
3. 새 항은 **바로 앞 항의 문단 모양**을 따른다. 앞 항이 한 줄짜리면 들여쓰기(내어쓰기)가 없는 모양이라
   새 항 둘째 줄이 왼쪽 끝에서 시작한다 → 같은 조의 «여러 줄짜리 항» 모양을 골라 입힐 것.
4. 칸 번호는 표에 줄을 넣으면 밀린다 → 칸은 늘 **조 머리 글자로 찾는다**(`searchAllText`), 번호를 들고 다니지 않는다.
5. 표준취업규칙은 본문이 **큰 표 한 장**(왼쪽 조문·오른쪽 해설)이다. 사업장 취업규칙은 대개 문단형이다 — 두 길 모두 필요.

## 남은 일
- ③ 실제로 만들기(목업 ③ 승인: 원본과 같은 형식 · 제목이 다른 조는 사람이 고름).
- 한글 자동화 보안 모듈이 이 PC 에 등록 안 돼 있다(`module registered: False`) — 그래도 파일은 열렸다. 검증용일 뿐 앱에는 상관없다.
