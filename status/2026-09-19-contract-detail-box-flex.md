# 2026-09-19 · 계약금·잔금 「종류별 세부설정」 박스 — CSS Grid에서 flex 로

- 가지: `feat/contract-6col-relabel` (같은 PR 에 이어 담음 — 대표 지시 「나머지도 모두해라」)
- 앞선 걸음: [2026-09-19-contract-6col-relabel.md](2026-09-19-contract-6col-relabel.md) —
  기업정보·계약정보·담당자 탭을 6칸으로 바꾼 것. 그 PR 에서 「종류별 세부설정」
  박스(계약금·잔금)는 **계산 로직이 얽혀 있어 더 신중히 다룰 별도 작업**으로 미뤄 뒀었다.

## 대표 지시·승인

「이부분도 한줄로 넣어라 가급적 설명되는것은 한줄에 모두 셀과 내용을 모두 해야
혼란이 없다」 — 목업 `contract-detail-box-v2.html` 로 승인받음(스크래치패드에 남아 있었다):
컨설팅계약 4줄→2줄, 사건계약 2줄→1줄, 기금관리는 1줄 그대로.

## 왜 «더 신중히»가 필요했나

세부설정 박스는 이전까지 CSS Grid(6열, `gridTemplateColumns:'90px 1fr 60px 120px auto auto'`)로
짜여 있었고, 칸을 `h('span')` 빈 칸으로 채워 자리 수를 맞추는 방식이었다 — 칸 개수가
정확히 6의 배수가 아니면 뒤따르는 칸이 전부 밀리는 깨지기 쉬운 구조였다. 이 그리드에는
계약금·부가세·일수(컨설팅만)·잔금/성공보수·부가세·CMS 가 얽혀 있고, 관련 검사만
`tests/contract-vat-brief-cms.test.js`·`tests/clinic-days-fee.test.js`·`tests/contract-new-today.test.js`
셋이 «격자 열 수를 실제로 세는» 방식으로 짜여 있었다 — 레이아웃을 바꾸면 이 검사들이
전부 다시 짜여야 했다.

## 무엇을 바꿨나

1. **레이아웃을 CSS Grid → flex 로.** `.pu-kbox`(박스)·`.pu-krow`(줄)·`.pu-vatpill`
   (부가세포함 알약)·`.pu-toggle2`(원/% 토글)·`.pu-calc`/`.pu-goBtn`/`.pu-okTag`
   (일수 계산 띠) 를 `css/pu-erp.css` 에 새로 추가. flex 는 칸이 늘거나 줄어도 그
   줄 안에서 자연히 다시 채워지므로, 그리드 시절의 «칸 개수를 정확히 맞춰야 한다»는
   깨지기 쉬운 제약이 아예 없어졌다.
2. **컨설팅**: 줄1(계약금·부가세·업무요약) + 줄2(일수 있으면 일수·셈 문구·단추,
   그리고 늘 잔금·부가세). 「계약금 줄과 일수 계산 줄은 다른 이야기」라 한 줄로 안
   합쳤다(대표 지시 문구 그대로).
3. **사건·기타**: 착수금과 성공보수를 «한 줄»에 함께 — select·착수금·부가세·업무요약·
   성공보수·원%토글·부가세.
4. **기금**: 그대로 1줄, 모양만 새 클래스로.
5. **`vatPill(checked, field, label)` 헬퍼 새로 만듦** — 계약금·잔금·기금 세
   체크박스가 각자 따로 갖고 있던 「체크박스+말풍선 안내」 코드를 한 함수로
   묶었다(중복 제거). 부르는 자리는 `vatPill(f.contractFeeVatIncluded,
   'contractFeeVatIncluded', ...)` 처럼 «읽는 칸 이름»과 «쓰는 칸 이름»을 문자로
   함께 넘긴다.
6. **`briefInput(kv)` 헬퍼로 업무 요약 칸을 단순화** — 옛 `briefCell()`/`briefRow()`
   (격자 자리를 지키려고 있던 함수, 값이 없어도 빈 칸을 그려야 했다)를 걷어냈다.
   flex 라 값이 없으면 그냥 `null` 을 돌려도 된다 — 자리 채우기 자체가 필요 없어졌다.

## 검사 — 그리드 열 세기를 «실제로 그려 보고 줄 구조를 보는» 방식으로

| 파일 | 무엇이 깨졌었나 | 무엇으로 다시 짚었나 |
|---|---|---|
| `contract-vat-brief-cms.test.js` | 「격자는 6열」·「업무요약이 1~2열」 같은 gridColumn 검사 전부 | `.map()` 식을 실제로 vm 에서 돌려 종류별 박스가 `pu-kbox`·`pu-krow` 인지, 어느 줄에 무슨 칸이 있는지를 본다 |
| `clinic-days-fee.test.js` (⑧-2·⑧-3) | 「span 합이 24, 24+6+6」 같은 gridColumn 합산 | row2(잔금 줄)의 실제 자식 개수(단가 없으면 2개, 있으면 8개)로 |
| `contract-new-today.test.js` | 「부가세 체크박스 8곳」 문자 개수 | vatPill 로 묶이며 3곳이 함수 정의 하나로 합쳐져 8→6이 됨(뜻은 그대로) — «호출 횟수(4)」로 다시 잼 |

**★ 이빨 확인(뮤테이션)으로 진짜 구멍 하나를 찾아 고쳤다** — `vatPill(f.contractFeeVatIncluded,
'contractFeeVatIncluded', ...)` 에서 둘째 인자(쓰는 칸 이름)만 `'wrongField'` 로 바꿔
돌려 봤더니 **처음 짠 검사는 못 잡았다**(첫 인자 `f.xxx` 개수만 셌지 둘째 인자까지
견주지 않았다 — 복붙 실수로 「읽는 칸」과 「쓰는 칸」이 어긋나도 통과했을 것이다).
`vatPill(f\.(\w+),\s*'(\w+)'` 로 두 인자를 함께 잡아 실제로 같은 이름인지 견주는
검사를 추가해 다시 뮤테이션했더니 즉시 걸렸다. 최종 확인 후 원본으로 복구.
