# 2026-09-18 · 비밀번호가 빈 채로 「주 1회 자동 백업 활성화됨」이라 했다

가지 `claude/login-start-screen-386qu2`

## 무엇이 있었나

화면 맨 위에 스스로 재고 답하는 칸을 붙여 드렸는데(#1420),
대표님 화면에는 **그 칸이 아예 안 떴다.**

같은 화면을 보니 **NAS 비밀번호 칸이 비어 있었다.** 저장된 설정에 비밀번호가 없다.
내가 넣은 걸러내기 —

```js
if(!cfg.host || !cfg.user || !cfg.pass) return;   // 설정이 없으면 안 잰다
```

— 가 그대로 물러섰고, **화면은 아무 말도 안 했다.**

## 더 아픈 것

그 바로 위 초록 띠는 그대로 이렇게 말하고 있었다.

> 🔄 **주 1회 자동 백업 활성화됨**
> 아직 자동 백업이 실행된 적 없습니다 (앱 열 때 자동 실행)

비밀번호가 없어 **한 번도 돌 수가 없었는데** 「활성화됨」이라고 한다.
**조용한 것이 거짓말이 되는 자리**다 — 이 저장소가 여러 번 밟았다.

## 왜 비어 있었나

넣고 「🔌 연결 테스트」만 누른 뒤 **「💾 설정 저장」을 안 누르면 그대로 사라진다.**
화면이 그 사실을 «미리» 말한 적이 없다.

## 고친 것

| | 전 | 후 |
|---|---|---|
| 빈 칸일 때 | 조용히 물러섬 | **무엇이** 비었는지 이름으로 말함 (「NAS 비밀번호 칸이 비어 있습니다」) |
| 저장 안내 | 없음 | 「넣으신 뒤 «반드시» 「💾 설정 저장」을 — 안 하면 떠나는 순간 사라집니다」 |
| 자동 백업 띠 | 언제나 「활성화됨」 | 못 도는 상태면 **「자동 백업이 «꺼져» 있습니다 — 돌 수가 없습니다」** |
| 저장 단추 | 「💾 설정 저장」 | 안 저장된 변경이 있으면 **빨강 + 「(아직 저장 안 됨)」** |
| 빈 칸일 때 할 일 | 없음 | 〔지금 바로 되는 길〕 백업 파일 다운로드 |

## 남은 일 — 대표님께 드릴 말

1. **NAS 비밀번호 칸에 비밀번호를 넣고 「💾 설정 저장」**을 누르십시오. 이것이 첫 단추다.
2. 그러면 화면이 스스로 재고 맨 위에 답을 씁니다 — 그 칸만 찍어 보내 주시면 된다.
3. 아이디가 `admin` 으로 되어 있다. DSM 이 「admin 은 무차별 대입에 취약하니 비활성화하라」고
   경고하는 그 계정이다. 나스에 `pureun_backup` 계정이 이미 있으니 그것으로 바꾸는 편이 낫다
   (단, 그 계정은 「응용 프로그램 권한」에서 **거부**로 되어 있어 먼저 풀어야 한다).
