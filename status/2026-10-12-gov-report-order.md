# 컨설팅보고서 UI 재정리 4단계: 사업 순서 · 끌어서 바꾸기 · 업체 □ 번호 · 전체 폭 · 왼쪽 사업 대시보드 (2026-10-12~13)

계획 `docs/superpowers/plans/2026-10-12-gov-report-order.md`. 대표 지시: 「푸른이알피의 사업단위로 정렬하고 업체는 항상 ㅁ와 넘버링」·「사업은 마우스로 아래위 드래그」·「화면이 짤렸다」·「사업은 왼쪽으로 대시보드로, 좌우로 넓게 모든 화면 사용」.

## 만든 것
- **사업 순서 = 푸른이알피 순서**: 진행 사업도 업체 수 정렬을 없애고 이알피 «컨설팅 사업»의 순서(`sortOrder` → 이름)를 따른다. 현황판 표도 사업 묶음 순서로 정렬.
- **끌어서 순서 바꾸기**: 왼쪽 사업을 마우스로 끌어 같은 묶음 안 위·아래로. 저장은 새 DB 칸 `scal_bizOrder/main`(`{list:'코드,코드', by?, at}`, 한 문서 `.set`) — 모두가 같은 순서를 본다. **쓰기는 관리자·위임관리인만**(직원은 거절 → 원래 순서로 복귀 + 안내). 외부 글자·파일을 떨어뜨려도 무시(전용 끌기 형식 확인).
- **업체 □ 번호**: 현황판 표·서류 체크표·사업 대시보드 업체 줄에 `□ 1, □ 2 …`(CSS 카운터 — 글자는 안 바꿈). 현황판 표는 사업이 바뀌면 1부터 다시.
- **전체 폭**: 가운데가 눌리던 원인 `main{max-width:1280px}` 제거 → 화면 전체 사용. 1500px 아래는 2열(오른쪽 패널은 아래), 1100·900px 규칙은 그대로.
- **왼쪽 = 사업 대시보드**: 요약 줄(진행 사업·업체·막힘) + 사업 카드(이름 줄바꿈·(수행기관)·종류·업체 N곳·단계 막대·막힘/기한 딱지). 왼쪽 패널은 스크롤해도 따라온다(sticky).
- 순수 모듈 `PuGovReportNav` 에 `parseOrder`·`rankMap`·`reorder`·`orderEntry` 추가.

## 규칙
- `scal_bizOrder` 새 규칙(추가만 — 새 1·바뀜 0·사라짐 0): 읽기 직원, `main` 쓰기 MGR, `list` ≤ 4000자·글자 꼴, `$other` 거절. **게시 완료 2026-10-13**(문법 검사·다시 읽어 같음 확인) — 콘솔 원문 `docs/firebase-rules-콘솔원문-2026-10-13.json`. `PENDING` 비움.

## 알아 둘 것
- 폰 터치로는 끌 수 없다(마우스 전용). Firefox 에서는 버튼 끌기가 안 될 수 있다 — Chrome·Edge 는 됨.
- 끌어서 정한 순서에 없는 새 사업은 목록 뒤쪽에 이알피 순서로 붙는다.
- 요약 줄의 «업체 M» 은 사업별 합계(한 업체가 두 사업에 걸리면 두 번 센다). 막힘이 붉은 숫자와 딱지로 두 번 보인다(의도).
- 합성 자료로 모양만 확인. **실제 로그인 화면·실제 끌기는 확인 못 함**.
