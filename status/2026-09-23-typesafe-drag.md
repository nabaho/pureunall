가지: `claude/login-start-screen-386qu2`

> 「팝업창 마우스로 이동가능하게 해줘」

## 먼저 — main 을 받아 합쳤다

이 기능(`js/pu-typesafe.js`)은 **다른 방이 PR #1572 로 넣은 것**이라 내 가지에 없었다.
내 가지가 **185 커밋** 뒤처져 있었다. `git merge origin/main` —
충돌은 `chwieop.html` 한 곳, 캐시 번호가 서로 달랐다.
내 것(`pu-gate ?v=3`)과 저쪽 것(`ontology ?v=31`·`write ?v=3`)을 **둘 다** 살렸고,
싣는 모든 곳의 번호가 갈리지 않았는지 기계로 확인했다.

## 무엇을 했나

머리줄(제목·설명이 있는 줄)을 잡고 끌면 창이 따라온다.

| | |
|---|---|
| 잡는 곳 | 머리줄 — `cursor:move` 로 «잡을 수 있음»을 보여 준다 |
| 마우스·손가락 | `pointer` 하나로 둘 다 받는다(따로 적지 않는다) |
| 옮긴 자리 | **기억한다** — 열 때마다 가운데로 돌아가면 옮긴 뜻이 없다 |
| 화면 밖 | **못 나간다** — 열 때·창 크기 바뀔 때 안으로 당긴다 |

## ★ 왜 `transform` 인가 — `left/top` 이 아니다

이 창은 바깥 칸의 `flex` 가 **가운데로 세워 준다.**
`position/left/top` 으로 옮기면 그 가운데 세우기와 **싸운다** —
글이 길어지거나 창 크기가 바뀔 때마다 자리가 어긋난다.
`transform` 은 「세워진 자리에서 얼마나 밀지」만 말하므로 그 위에 **얹을 수 있다.**
검사 ⑤ 가 `position/left/top` 으로 되돌아가는 것을 막는다.

## 세로 막이는 «바닥»이 아니라 «머리줄»을 본다

창이 화면보다 길 수 있다. 바닥을 기준으로 막으면 긴 창은 아래로 못 내린다.
그런데 정작 중요한 것은 **머리줄이 보이는가**다 — 머리줄을 못 잡으면 **다시 못 옮긴다.**

## 검사 — 글자를 안 보고 «끌어 본다»

`tests/typesafe-drag.test.js` **6건**. 끌기 대목을 떠서 가짜 손잡이에 실제로
`pointerdown → pointermove → pointerup` 을 쏘아 본다.

- 60·40 만큼 끌면 창이 그만큼 따라오는가
- **놓은 뒤에도 따라오면 안 된다**(창이 마우스에 붙어 다닌다)
- **다시 잡으면 그 자리에서 이어서** 끌어야 한다(0부터 세면 창이 튄다)
- 닫기 단추를 누른 채 흔들려도 창이 안 옮겨진다
- 네 방향 모두 화면 밖으로 안 나간다

**돌연변이 7회 전부 걸린다.**

### ⚠ 돌연변이가 «구멍»을 하나 더 잡았다

처음엔 6회 중 **하나가 안 걸렸다** — 「끌기를 창에 아예 안 붙인다」.
까닭: 검사들이 끌기를 **직접 불러서** 쓰다 보니, 만드는 자리(`make`)에서
**안 붙여도 전부 초록**이었다.
**「잘 도는 부품」과 「그 부품이 달려 있는 것」은 다른 말이다.**
붙였는지, 그리고 «머리줄에» 붙였는지를 보는 검사를 더했다.

### ⚠ 내 대역이 틀려 «거짓 실패»를 한 번 봤다

화면 밖 당기기를 검사하며 자리를 **안 씌우고** 당겼다. 실제 흐름은
「끄는 동안 자리적용 → 놓을 때 안으로당기기」다. 대역이 틀려 「안 당겨진다」고 나왔다.

## 남의 검사 아홉이 깨졌다 — 가짜가 실물보다 «모자랐다»

`typesafe-consent-gate`·`typesafe-local-redact` 의 가짜 요소에
`getBoundingClientRect` 가 없었다. 자리를 재는 코드가 들어오자 **기능이 멀쩡한데** 깨졌다.
코드에 방어를 넣어 덮지 않고 **가짜를 실물에 가깝게** 고쳤다 —
가짜는 실물에 없는 것을 더하지 말되, **실물에 있는 것을 빠뜨려도 안 된다.**
