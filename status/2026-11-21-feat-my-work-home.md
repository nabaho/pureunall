# 2026-11-21 · 📋 «내 업무»는 업무관리 한 곳 — 포털 머리줄 단추 · 이알피 「나의 업무」 2단계 (`feat/my-work-home`)

대표 물음: 「나의 업무와 업무관리는 중복되는 것 같은데 어떻게 하는 게 좋은가 … 업무관리를 어떻게 더 관리하는 게 좋은지」
→ 검토(1단계 9/27 «기록은 업무관리 한 곳» 이후 남은 겹침 = «목록»·«업무 만들기») → 「추천대로 하고 … 로그인하면 자기 업무 위주로 …
개별 로그인했던 사람이 정확하게 한 번에 보고 클릭해서 자기 업무만 확인할 수 있게」.

## 검토에서 잰 것 (코드 기준, 서버 자료는 안 읽음)
- 같은 사람 목록이 두 벌 — 이알피 「내 프로젝트」(대표 41건) ↔ 업무관리 「내 업무」(46건). 어느 쪽이 맞는지 모름.
- 이알피 「+ 일반업무」(`data/my_work_items`)·「+ 업무케이스」(`data/biz_cases`)·「오늘 할일」(`my_todos`)은 **이알피에만 있는 섬** —
  업무관리·검색·인수인계·캘린더 어디서도 안 읽는다(work.html 에 그 자리 이름이 0번). 두 종류 목록도 거의 같다.
- ★ 「내 프로젝트」 표의 **머리줄·본문 칸 순서가 어긋나 있었다** — 머리 «담당·진행률·최근 기록» ↔ 본문 «최근 기록·담당·진행률».
  화면의 «담당» 칸에 «—», «진행률» 칸에 «주»가 찍힌 까닭. 진행률은 넣을 곳이 없어 늘 0%.

## 바뀐 것
- **포털(enter.html)**: 업무관리가 자료함 타일이 아니라 **머리줄 맨 앞 «📋 내 업무» 단추**(head 앱, 캘린더와 같은 틀).
  누르면 업무관리 「내 업무」(로그인한 사람 것만). 단추에 «진행 N · 임박 N · 할 일 N»(PC) / 급한 수 딱지(폰).
  폰(≤520px)에서 머리줄이 두 줄이 되어 챗봇 단추도 그림(🤖)만 둔다(380px 구간과 같은 꼴, 접근성 이름·말풍선은 그대로).
- **숫자 한 줄** `work_erp/mysum/{로그인 UID}` (`js/pu-mywork.js`) — 업무관리가 「내 업무」를 그릴 때 **자기 몫만** 적는다(이번 주를 볼 때만,
  바뀐 것이 없으면 안 적음). 진행은 머리 숫자와 같은 셈(이관 계약·자문 뺌), 임박·할 일은 **날짜로** 남겨 읽는 쪽이 오늘 기준으로 다시 센다.
  포털·이알피는 이 한 줄만 읽는다(업무 목록 통째를 안 읽는다). 없거나 14일 넘게 묵었으면 숫자를 안 보인다(못 받음 ≠ 0건).
  읽기는 `work_erp` 그대로(로그인 직원) — 더 넓게 공개되는 칸 없음(날짜·건수뿐). 쓰기는 «본인 UID 자리만»으로 좁히는 규칙을 더했다(아래).
- **이알피 「나의 업무」(pu-erp.html)**: 「내 프로젝트」 표를 걷고 «📋 내 업무 — 업무관리» 칸으로 —
  숫자(누르면 업무관리가 그 건만 거른 채 열림 `#f=due|next|nolog`) · 「＋ 새 업무」(`#new`) · 「업무관리에서 열기 →」.
  **조용히 감추지 않는다** — ① 내 담당인데 업무관리에 연결 안 된 업무 → 「업무관리로 가져오기 →」(`#peimport`, 기존 주담당 연결 창)
  ② 이알피에만 있는 일반업무·업무케이스 → 「업무관리로 옮기기 →」(`#erpmove`). 업무관리 목록을 못 읽으면 ①②를 세지 않는다.
  「+ 일반업무」「+ 업무케이스」 단추는 없앴다(끝난 일반업무 보관함·복구는 그대로). 안 쓰이게 된 `wsOpen` 지움.
- **업무관리(work.html)**: 「📦 이알피 일반업무·업무케이스 옮기기」 창 — 원본은 읽기만, 끝난 것·휴지통·이미 옮긴 것 뺌,
  ☐+번호, 한 번의 update. 옮긴 줄 = `mv:{store,id}` + `entityType:'Task'`·`id`·`createdAt`·`updatedAt`.
  ⚠ `src:'puerp'`·`ref` 는 안 붙인다(붙이면 이알피 종료 동기화가 원본을 건드린다). 업체는 `companyId` 있을 때만 `co_id`.
  담당 이름만 있는 옛 자료는 명부에서 **이름이 하나뿐일 때만** 사번. 원본 내용·결과 전문은 서랍 옛 메모(`pe_notes`)에.
- 길잡이 챗봇 안내: 자료함(6개) · «📋 내 업무» 머리줄 단추.

## 외부 검토(ow review 1회차 — 검증 Gemini 4 argon high · 보안 Codex) 반영
- [높음] 768px 태블릿에서 로그아웃이 화면 밖으로 17px → ≤900px 에서 챗봇 단추도 그림만(머리줄 단추들과 같은 꼴). 1366·1024·768·411·360 재어 화면밖 0.
- [중간·보안] 숫자 한 줄을 남이 덮을 수 있음(+사번 치환 겹침) → 열쇠를 **로그인 UID** 로, 규칙 `work_erp/mysum/$uid` «본인만 쓰기 + 모양 검사»
  (`scripts/make-firebase-rules.js` → 적용본 다시 만듦). 에뮬레이터 `tests/work-mysum-rules.emulator.mjs` 새 규칙 14/14, 옛 규칙에선 ★6개 통과(구멍 확인).
  열쇠에 못 쓰는 글자가 오면 바꿔 쓰지 않고 자리를 안 만든다(겹침 방지).
- [중간·보안] 동명이인이 «내 것»에 섞임 → 옮기기 후보는 사번으로만 «내 것»(`mvMine`). 사번 없는 옛 자료는 관리자 화면에서만.
- [중간·보안] 원본 전체를 받아 거르고 연락처·상세를 복제 → **해당 없음으로 판단**: `data/my_work_items`·`data/biz_cases` 는 규칙상 이미 `$other`
  (로그인 직원 읽기·쓰기)이고 `work_erp` 도 같은 범위 — 더 넓게 공개되지 않는다(온톨로지 «원본보다 넓게 공개 금지» 지킴).
- [중간] 딱지 키보드 조작 → role·tabIndex·Enter/Space. 옮기기 창 ☐ 를 label 로 감싸 24px 넘게·aria-label·th scope·결과 줄 aria-live.
- [중간] 대비 → 새 칸의 흐린 글자 #94a3b8→#64748b, 주황 단추·숫자 #d97706→#854d0e. ⚠ 이알피 어두운 테마의 흰 바탕 고정은 기존 위젯과 같은 꼴이라 손대지 않음.
- [낮음] 1000번 넘는 관리번호 잘림 고침 · 한국어 줄바꿈(keep-all) · 떠 있는 단추 겹침·전역 창 role=dialog 는 기존 공용 부품이라 이번엔 안 고침.
- ⚠ **규칙은 아직 안 올렸다** — 처음엔 «사라질 규칙 7개(/app_owner·/datahub*)»로 멈췄고(그 사이 #3225·#3226 이 합쳐져 최신 main 위로 다시 쌓음),
  이제는 «사라질 규칙 1개(/edulib/cats)»로 멈춘다 — 열린 PR #3227(강의자료)이 콘솔에 먼저 올리고 아직 안 합친 것이다(우회하지 않음).
  #3227 이 합쳐진 뒤 `node scripts/rules-deploy.js --deploy` → 콘솔 원문 새 판 → `photos-staff-share` 의 PENDING 비우기(다음에 규칙을 올리는 방이 함께 올려도 된다 — 만들개 전체가 나간다).
  그 전까지 숫자 한 줄은 지금 규칙($k — 로그인 직원 쓰기)으로도 저장된다(기능은 돈다, «본인만·모양 검사»가 아직 안 걸렸을 뿐).

## 외부 검토 2회차 반영 (검증 Gemini: 문제 0 · 보안 Codex: 높음1·중간2·낮음1)
- [높음] 패치가 main 의 app_owner·datahub 규칙을 지움 → 검토 사이 main 에 합쳐진 것이었다. 최신 main 위로 다시 쌓고 적용본을 만들개로 다시 만듦.
- [중간] 두 창이 동시에 옮기면 업무가 둘 → 옮긴 업무 열쇠를 원본에서 정한 이름(`MV-W-<id>`·`MV-B-<id>`)으로 — 같은 자리에 써져 한 줄만.
  (관리번호를 동시에 같은 번호로 받을 수 있는 것은 «＋ 새 업무»(genNo)와 같은 기존 방식이라 그대로.)
- [중간] 숫자 한 줄의 모양을 n·at 만 봄 → 아는 칸만($other 거부)·건수 0~10만·날짜 목록 999번째까지 «YYYY-MM-DD» 만. 에뮬레이터 21/21, 옛 규칙에선 ★11개 통과(구멍 확인).
- [낮음] 에뮬레이터 시험이 모든 실패를 «거부»로 셈 → 401·403 만 거부, 나머지는 «오류», 자료 심기 실패면 멈춤.
