# 경력·실적 표들도 «☐ + №» 칸을 왼쪽에 붙들기 — 태블릿·좁은 노트북 폭 (2026-11-22)

PR #3122 의 기록(`status/2026-11-16-kcareer-trash-putmany-rest.md`, «`.dt` 표 가로 넘침 — 잰 것»)이 남긴 일이다. #3047 이 증명서 표(`#cdBody`)에만 한 «☐ 칸 붙들기»를 «☐ 칸이 있는 모든 공용 표(`.dt`)»로 넓혔다.

## 무엇이 틀렸나 (가짜 환경에서 재 봄)

폭 521~1280px 에서 표가 상자보다 넓으면 줄마다 ☐ 와 머리줄 «전체 선택 ☐» 가 왼쪽으로 밀려 화면 밖으로 나갔다. 1024px 위촉장 표는 `main` 이 127px 구르면 ☐ 칸의 왼쪽이 -90px 였다. 어느 상자가 구르는지는 폭에 따라 다르다 — 1024px 에서는 `main`(`.dt` 는 `overflow-x:visible`), 600px 에서는 `.dt` 자신(`overflow-x:auto`)이었다(그 사이 어느 폭에서 바뀌는지는 재지 않았다). 붙들기(`position:sticky;left:0`)는 «가장 가까운 스크롤 상자» 안에서 돌기 때문에 둘 다 된다(아래 실측).

## 고친 것 (`kcareer.html` CSS 한 덩어리)

- `#cdBody` 에만 걸려 있던 규칙을 «☐ 가 든 칸» 일반 규칙으로 바꿨다(같은 폭 띠 `@media (min-width:521px) and (max-width:1280px)`):
  `.dt thead th.rownum-h:has(input[type=checkbox]), .dt tbody td.rownum:has(input[type=checkbox]){position:sticky;left:0}` + 머리줄 모서리 칸은 `z-index:6`(머리줄 5 위) + 줄 칸은 `z-index:2`·`background:var(--card)`(비치지 않게)·오른쪽 가는 줄 + 지나가는 줄·고른 줄·살필 줄(`row-warn`)은 줄 바탕을 `inherit` + 어두운 판의 고른 줄 왼쪽 파란 띠.
- 증명서 표는 같은 규칙을 일반 쪽으로 받는다(그 안에 따로 있던 `#cdBody` 규칙은 지웠다 — 같은 일을 두 곳에 두지 않는다).
- **«☐ 가 든 칸»에만** 건다(`:has(input[type=checkbox])`) — № 만 있는 보기용 표(설정의 계좌·법인 서류 등)는 그대로다. `:has` 를 모르는 브라우저는 이 규칙을 통째로 건너뛰고 표는 예전 그대로다(이 파일은 이미 `:has` 를 쓰고 있다).
- **머리 칸은 «그 표의 줄에 ☐ 가 있는가»로 정한다**(`.dt:has(tbody td.rownum input[type=checkbox]) thead th.rownum-h`) — 머리 칸에 ☐ 없이 글자(「☐ №」)만 있는 표(사업 서류 찾기 `#bizDocBody`·프로필 고르기 창 `#p1PickTbl`)도 줄 칸과 같이 붙들어야 머리글이 어긋나지 않는다(자동 검증 지적 — 처음엔 머리 칸 자신의 ☐ 로 정해 줄 칸만 붙들렸다).
- 지우려고 «묻는 중»인 줄(`tr.kc-dying`)도 줄 바탕을 따르는 목록에 넣었다(자동 검증 지적 — 그 줄의 ☐ 칸만 흰색으로 남았다).
- 폰 카드(≤520px)·1280px 를 넘는 PC 는 그대로다(띠 밖).

## 확인한 것

가짜 파이어베이스 + 지어낸 자료(`tools/phone-audit/seeds/career.js`)로, 내장 브라우저에서 `main`(또는 `.dt`)을 «끝까지 굴린 뒤» ☐ 칸의 왼쪽 위치를 쟀다.

| 폭 | 결과 |
|---|---|
| 1366 | 줄 칸 `position:static`(붙들지 않음)·표가 상자 안에 들어와 구르지 않음 — 전과 같음 |
| 1160 | 붙듦이 걸려 있으나 이 자료에서는 `main` 이 구르지 않아(`main` 폭 915 = 안쪽 915, 표가 여백 안에서 끝남) 달라지는 것 없음. 1280px 는 따로 재지 않았다 |
| 1024 | 위촉장(`main` 127px 구름)·사업(54px)·자문(63px): 끝까지 굴려도 ☐ 칸 left **0**(붙들림) — 전에는 위촉장 -90. 자격(구르지 않음)은 그대로 37 |
| 600 | `.dt` 가 스크롤 상자: 위촉장 301px·사업 231px·자문 242px … 끝까지 굴려도 ☐ 칸·머리줄 left **0**(붙들지 않던 칸이라 전에는 스크롤한 만큼 밀려 나갔을 것 — 600px 의 고치기 전 값은 따로 재지 않았다) |
| 375(폰 카드) | `position:static`·머리줄 숨김(카드 모양)·가로 넘침 0 — 전과 같음 |

- 바탕: 보통 줄 ☐ 칸 `rgb(255,255,255)`(밝은 판) · `rgb(30,41,59)`(어두운 판, `var(--card)`). 고른 줄(`sel-on`)·살필 줄(`row-warn`)의 ☐ 칸은 줄 바탕과 «같다» — 밝은 판 `rgb(248,250,252)`, 어두운 판 고른 줄 `rgb(30,41,59)`·살필 줄 `rgb(71,85,105)`; 어두운 판 고른 줄의 왼쪽 파란 띠 유지.
  ⚠ 내장 브라우저는 «창이 숨김»이면 CSS 전환이 안 돌아 줄 바탕색이 전환 시작값(투명)에 머문다 — `*{transition:none!important}` 를 심고 쟀다(처음엔 이것 없이 재서 «투명»으로 나왔다).
- 증명서 표(`#cdBody`)도 일반 규칙을 받는다: 줄·머리 칸 `sticky`, 머리 `z-index:6`·줄 `2`, 바탕 흰색.
- 스크린샷(1024px, 끝까지 굴림): ☐ + № 칸이 왼쪽 가장자리에 흰 바탕으로 남고 툴바·표 나머지는 밀려 간다.
- 새 검사(`tests/kcareer-select-trash-hardening.test.js` ④ 묶음을 일반 규칙에 맞게 다시 씀, 여섯 — 자동 검증 뒤 «머리 칸 글자만 있는 표도 같이 붙든다»를 더함): ① 폭 띠 — 폰 카드 폭 위·1366px 아래·1024px 포함, 띠 밖에서는 어느 칸도 `sticky;left:0` 이 아님 ② «☐ 가 든 칸»에만(№ 만 있는 표 제외) ③ 바탕·`z-index`(머리 모서리 > 머리줄 > 줄 칸)·지나가는/고른/살필 줄 `inherit`·어두운 판 띠 ④ 이 규칙을 받는 표(경력·실적 `renderCareer`·사업 목록 `renderBizList`·증명서 `_cdTable`)가 실제로 «머리줄 ☐ + №» / «줄마다 ☐ 칸» 모양을 갖는다 ⑤ 직원 «보기 전용» 숨김 규칙 유지.
- 고장 넣기: 처음 11가지 중 10가지(나머지 1가지는 앵커 오류), 자동 검증 뒤 고친 규칙으로 다시 12가지 모두 잡음(지우려는 줄 inherit 뺌 · 머리 칸 규칙을 «머리 칸 안의 ☐» 로 되돌림 · 살필 줄 inherit 뺌 · 줄 칸 규칙이 ☐ 를 안 요구 · 폭 띠가 폰 카드 폭/PC 폭까지 · 머리 모서리 `z-index` 낮춤 · 바탕 뺌 · 어두운 판 띠 뺌 · 띠 밖에서도 붙듦 · 사업 목록·경력·실적 표의 ☐ 칸 이름이 바뀜). 나머지 1가지는 앵커를 잘못 잡아 «같은 내용의 다른 고장»이 이미 잡았다.

## 안 고친 것 · 못 한 것

- **줄에 ☐ 가 없는 줄**(☐ 칸이 있는 표 안에서 일부 줄만 ☐ 없이 번호만인 드문 경우)은 붙들리지 않는다 — 열이 어긋나 보일 수 있다. 이 저장소의 ☐ 표에서는 그런 줄을 찾지 못했다 [확인 필요].
- 같은 폭 띠의 **다른 넘침**(예: 긴 기관명이 칸을 밀어 표가 넓어지는 것 자체)은 이번 일이 아니다 — 이 규칙은 «넘칠 때 ☐ 가 안 사라지게»일 뿐 표를 줄이지 않는다.
- 실제 대표 화면(진짜 자료)·실기기(태블릿 터치)에서는 확인하지 못했다. 내장 브라우저는 사람 손이 아니라 `scrollLeft` 를 직접 바꿔 쟀다. 지어낸 자료 기준이라 실제 자료의 긴 글자·많은 칸에서는 구르는 폭이 다를 수 있다.
