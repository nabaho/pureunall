# 2026-10-19 · 메일을 눌렀는데 기업정보함으로 «들어가 화면이 바뀐다» — 메일 문 안에서 새던 길을 막음

대표 지적(폰 화면 캡처 셋): 「메일함에 클릭했는데 왜 기업 정보함으로 들어가서 화면이 바뀌냐? … 메일함 기업 정보함 연결되어 있는 거 제대로 다 정리해 달라」

## 왜 그랬나
`pu-cards.html` 한 파일에 문이 둘이다(기업정보함 · 푸른 메일 `?view=mail`). 메일 문 안에서 «기업정보함 쪽 화면»으로 새는 길이 다섯이었다.

| # | 새던 곳 | 증상 |
|---|---|---|
| ① | 폰 메일 «읽기» | 목록(.dmm)은 화면을 통째로 덮는 검정 앱 차림인데 읽기는 그 «아래» 흐름 속에 그려져, 누르는 순간 기업정보함 머리줄·흰 바탕이 드러남 (캡처 둘째 장) |
| ② | 머리줄 이름 | 메일 문에서도 「기업정보함」 (탭 제목·홈 화면 이름은 이미 「푸른 메일」) |
| ③ | 「‹ 목록」 · 「← 목록으로」 | 메일 화면 4곳이 «명함 목록»으로 나감 |
| ④ | 「‹ 기업정보함으로」 | 메일 문에서 누르면 주소·제목은 메일인데 내용만 명함인 «섞인 문» |
| ⑤ | 폰 서랍 「⚙️ 환경설정」 | 기업정보함 설정으로 감 (PC 옆줄은 2026-08-29 에 메일 설정으로 고쳤는데 폰 서랍만 빠짐) |

## 한 것 (`pu-cards.html`)
- 읽기를 목록과 같은 전체 화면 덮개(`.dmr`)에 담음. 맨 위(‹ 목록·▲·▼·🖨)는 붙어서 스크롤해도 따라오고 «첫 줄», 답장·삭제 같은 일은 그 아래 줄.
- 메일 문의 머리줄은 「푸른 메일」 — `<head>` 가 붙이는 `html.maildoor` + CSS 만(스크립트를 마크업 사이에 끼우지 않음).
- `mailBack()` 새로 — 메일 문이면 메일함, 기업정보함 문이면 예전 그대로. 「목록으로」 단추 4곳이 이것을 부름.
- `closeMailPage()`(나가는 길)는 메일 문에서 «문을 바꿈» (`pu-cards.html` 로 이동, 쓰던 편지는 임시저장하고).
- 폰 서랍 ⚙️ 환경설정 → 메일 설정(`openMailSetPage`).

## 검사
- 새 `tests/mail-door-stays-in-mail.test.js` — 읽기 덮개 · 층 · 붙는 맨 위줄 · 머리줄 이름(CSS 로만) · mailBack · 나가는 길 · 서랍 설정.
- «지금 값/글자 모양»을 박았던 옛 검사 4개를 규칙으로 되겨눔(`cards-phone-mail` mmback 함수 이름 · `mail-att-preview` 붙어 있는 글자 · `mail-daum-box-screen` 서랍 환경설정).
- 전체 2187개 파일 묶음으로 돌려 전부 통과.
- 화면은 진짜 Edge(375px 틀)로 «전/후»를 같은 장면으로 그려 확인(머리줄이 안 드러남·목록 단추 첫 줄·「푸른 메일」).

## 남은 일 / 모르는 것
- 진짜 로그인·메일 자료로 폰에서 눌러 본 것은 아님(하네스는 실제 CSS + 읽기 화면 모양을 손으로 지은 것). 배포 뒤 폰에서 한 번 눌러 확인 필요.
- 메일 문의 «덮개 없는» 화면(쓰기·보낸·예약·자료함)은 머리줄이 남는다(이름만 「푸른 메일」). ☰·🔍 은 기업정보함 것(메뉴·명함 찾기) — 이번에 손대지 않음.
- 메일 → 「📥 메일 연락처」(연락처 정리)·「📷 사진첩으로」는 일부러 기업정보함/사진첩으로 건너가는 길이라 그대로.
