# 2026-11-15 · 서비스워커 «자리 다툼» 고침 — 이알피 공유 받기를 통합 일꾼(pu-sw.js)으로

푸른캘린더 캡처 공유(PR #3079, `status/2026-11-15-cal-share-image.md`)를 만들다 발견한 문제의 뒷일.

## 무엇이 문제였나
- 서비스워커(폰 «공유 받기»를 받는 일꾼)는 한 자리(scope)에 하나만 산다. `/pureunall/` 의 앱들은 통합 일꾼 `pu-sw.js` 를 «함께» 등록하기로 약속했다(`pu-sw.js` 머리말).
- 이알피(`pu-erp.html`)만 자기 일꾼 `pu-erp-sw.js` 를 같은 자리에 등록했다. 나중에 연 앱의 일꾼이 앞의 것을 밀어내므로
  - 이알피를 연 뒤 → 기업정보함·사진첩·급여데이터함·문서뷰어의 폰 «공유 받기»가 죽고
  - 다른 앱을 연 뒤 → «공유 → 푸른이알피»가 죽었다.
- 지키던 검사(`tests/portal-install-app.test.js` 의 `rootWorkersOf`)는 포털·설치·기업정보함 «세 화면»만 보아 이알피를 몰랐다.

## 고친 것
- `pu-sw.js` — 이알피 갈래 `takeErp` 를 더했다. POST `/pu-erp.html` 로 온 사진(칸 이름 `photos`, `pu-erp-manifest.json` 과 짝)을 사진첩 몫과 «같은» `keepPhotos`(IndexedDB `pu-photos-share`/`inbox`/1)에 넣고 같은 폴더의 `pu-photos.html?share=1` 로 303. 한 장도 없으면 `?share=none`, 읽다 깨지면 `?share=err`(사진첩 화면이 알린다). 캐시 없음. 다른 앱 갈래는 손대지 않았다.
- `pu-erp.html` — `pu-sw.js` 를 등록한다(https 에서만, 실패해도 이알피는 열린다 — 그대로).
- `pu-erp-sw.js` — **지우지 않고** `importScripts('pu-sw.js?from=erp-sw-20261115')` 한 줄짜리 껍데기로 바꿨다(꼬리표는 처음 갈아탈 때 폰 캐시의 옛 `pu-sw.js` 를 집지 않게 — 자동 검토 낮음 지적). 까닭:
  1. 이미 이 일꾼이 깔린 폰이 있다. 브라우저는 깔린 일꾼 파일을 때때로 다시 받아 보고, 바뀌었으면 그 자리에서 갈아 끼운다 → 그 폰은 아무 화면을 안 열어도 통합 일꾼과 똑같이 모든 앱 공유를 받게 된다.
  2. 배포 직후 브라우저에 잠깐 남은 옛 `pu-erp.html` 이 이 파일을 다시 등록해도 통합 일꾼과 똑같이 움직여 다른 앱 공유가 안 죽는다.
  3. 옛 몫을 따로 들고 있지 않는다 — 옛 껍데기들(`pu-photos-sw.js` 등)은 옛 코드를 들고 있다가 통합 일꾼과 갈라졌다(`tests/photos-share-target.test.js` 머리말).
  - 지웠다면: 1의 폰은 새 이알피나 다른 앱을 열 때까지 옛 일꾼(이알피 공유만 받음)으로 남는다. 다 갈아탄 것이 확실해지면 지워도 된다.
- 낡은 설명 고침: `pu-erp-manifest.json` 주석, `pu-cal.html`·`pu-cal-share-sw.js` 머리말(«두 일꾼이 번갈아 차지한다» → 이제 통합 일꾼 하나), `tests/cal-share-target.test.js` 실패 문구.
- 참고: 옛 이알피 일꾼은 사진첩 함을 «열쇠 칸(id) 없이» 만들 수 있었다. 사진첩 화면은 `getAll()` 로 통째로 꺼내므로 어느 쪽이든 그대로 읽힌다 — 손댈 것 없음.

## 검사
- 새 `tests/sw-one-root-worker.test.js` — 규칙: «scope 를 좁히지 않은 일꾼 등록은 어느 화면이든 `pu-sw.js`».
  - 저장소의 모든 html·js(검사·참고본·작업 사본 제외)에서 `serviceWorker.register(` 를 «빠짐없이» 읽는다. 못 읽는 꼴이면 실패.
  - 뿌리(`/pureunall/`)를 덮는 등록은 모두 `pu-sw.js`. 좁힌 등록(웹푸시 `push/`, 캘린더 `./cal-share/`)은 예외 — 좁힌 척 `'./'` 를 주면 잡는다.
  - 공유를 받는 앱(manifest `share_target`)마다 그 주소를 맡게 될 일꾼을 vm 으로 켜서 공유 POST 를 보내 «받는지» 본다(한 자리에 일꾼이 둘이면 둘 다).
  - 잣대 자체를 11가지 꼴로 시험하는 칸을 함께 둔다(틀린 꼴은 잡고, 통합 일꾼·좁힌 등록·하위 폴더 등록은 통과).
- 새 `tests/erp-share-target.test.js` — 일꾼을 vm 으로 통째로 켜서: 이알피 공유 → 사진첩 화면이 꺼내는 함(`pu-photos.html` 의 `SHARE_IDB` 에서 읽음)에 담기고 사진첩 화면 `?share=1`(깃허브 주소·localhost 둘 다) · none · err · GET 안 건드림 · 다른 앱(사진첩·급여데이터함·문서뷰어·기업정보함)은 제 함에만 담김 · 옛 `pu-erp-sw.js` 자리에서도 모든 앱 공유를 받음.
- 공용 도구 `tests/lib-sw-boot.js` — 일꾼 파일을 vm 에 켜는 가짜 IndexedDB·캐시·`importScripts`.
- 고장 9가지를 일부러 넣어 모두 잡힘: 이알피가 옛 일꾼 등록 · 옛 껍데기 등록 · 이알피 갈래 끔 · 칸 이름 틀림 · 다른 함에 담음 · 이알피로 돌려보냄 · 껍데기가 옛 몫만 듦 · 다른 앱이 scope `./` 로 새 일꾼 등록 · 사진첩 갈래 끔.
- 자동 검토(`ow review`, 검증 Antigravity gemini · 보안 Antigravity claude — codex 사용률이 높아 바뀜): 높음·중간 없음, 낮음 4건.
  고친 것: 껍데기의 캐시 틈(위 꼬리표) · 첫 공유 실패 안내(아래) · 검사 빈틈 둘 — 가짜 IndexedDB 가 «판 번호·함 이름»까지 적고 사진첩 화면 값과 맞춰 본다, 다른 이름으로 부른 등록(`const sw = navigator.serviceWorker; sw.register(…)`)과 아직 git add 안 한 새 화면도 잡는다.

- 새 확인 칸에도 고장 5가지(판 번호·함 이름 어긋남, 별칭 등록, git add 안 한 새 화면, 껍데기가 딴 파일 부름)를 넣어 모두 잡힘.

## 사람이 할 일 (배포 뒤, 안드로이드 폰)
1. 폰 크롬에서 이알피를 한 번 연다(새 일꾼이 등록된다).
2. 갤러리에서 사진 하나 → 공유 → **푸른사진첩**(또는 기업정보함) → 사진첩에 담기는지. (예전에는 이알피를 연 다음엔 여기서 죽었다)
3. 사진첩을 연 다음, 사진 → 공유 → **푸른이알피** → 사진첩 화면으로 넘어가 담기는지.
- 배포 직후 «첫 공유» 한 번은 안 될 수 있다 — 폰에 남아 있던 옛 일꾼이 그 공유 뒤에 새것으로 갈아 끼워진다. 안 되면 한 번 더 해 본다(예전에도 그 상태에서는 안 되던 것이라 나빠진 것은 아니다).
- 내장 브라우저는 서비스워커 등록을 막아 두어 일꾼의 실제 POST 받기는 화면으로 못 봤다 — vm 검사로만 확인.
- 아이폰은 웹앱을 공유 목록에 못 올린다(애플 정책) — 안드로이드 전용.
