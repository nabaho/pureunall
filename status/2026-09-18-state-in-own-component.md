# 2026-09-18 · 내가 환경설정을 통째로 죽였다 — 상태 칸을 «남의 집»에 선언했다

가지 `claude/login-start-screen-386qu2`

## 무엇이 있었나

나스 설정에 「지금 상태」 칸을 붙이며 `var 진단S = useState(null)` 을 넣었다.
그 줄이 **엉뚱한 컴포넌트**(「🔬 데이터 진단」, 37,500줄께)에 들어갔다.
쓰는 곳은 41,000줄께의 `NasBackupSettings` 였다. 배포되자 —

> ⚠ **env/settings 렌더링 오류**
> `진단 is not defined`

화면 하나가 아니라 **환경설정 전부**가 안 열렸다.

## 까닭

고칠 자리를 «첫 번째로 닮은 줄»로 찾았다. 이 파일에는

```js
var busyS = useState(false); var busy = busyS[0]; var setBusy = busyS[1];
```

가 **두 곳**(37,492 · 41,072)에 있다. 첫 번째가 남의 집이었다.

⚠ **이 세션에서 같은 실수를 두 번 했다.** 앞서 `doRestore` 를 첫 번째 것으로 잡아 2,400줄을 지웠다.
그때는 「앞으로 조심하겠다」로 넘겼다. **사람이 조심하는 것으로는 안 막힌다.**

## 왜 검사가 못 잡았나

같은 날 새로 쓴 검사 13개가 `NasBackupSettings` 를 떼어내 **«쓰는 쪽»만** 봤다.
«선언이 그 안에 있는지»는 아무도 안 봤다 — 코드는 문법상 멀쩡하고, **터지는 것은 화면을 그릴 때**다.

## 고친 것

1. `진단S` 를 제자리(`NasBackupSettings`)로 옮겼다.
2. **`tests/state-declared-in-own-component.test.js`** — 기계로 막는다.
   `var 아무개S = useState(…)` 로 만든 칸의 `set아무개` 는 **그것을 만든 컴포넌트 안에서만** 불린다.
   4개 앱(이알피·명함첩·업무관리·사진첩)을 함께 본다.
3. 검사를 만들다 **진짜 흠 하나를 잡았다** — 아래.

### 곁들여 잡은 것 · 종료관리에서 오른쪽 클릭하면 터졌다

`ClosedManagement` 의 표 줄에 `onContextMenu` 가 있는데 `setCtxMenu` 를 불렀다.
그런데 **이 화면에는 그 상태 칸도, 띄울 메뉴도 없다** — 다른 화면에서 옮겨 붙을 때 딸려 온 것이다.
그래서 종료관리 표에서 오른쪽을 누르면 브라우저 기본 메뉴도 안 뜨고 그 자리에서 터졌다.
메뉴를 새로 만들지 않고 **손잡이를 뗐다** — 이제 기본 메뉴가 정상으로 뜬다.

## 검사를 만들며 밟은 자리 셋 (다음 사람을 위해)

| 밟은 것 | 어떻게 드러났나 |
|---|---|
| 한글 이름 앞의 `\b` | 자바스크립트 `\b` 는 **ASCII 기준**이라 「` var set진단`」에서 경계로 안 쳐준다 → 한글 상태 칸을 통째로 **못 보는 눈먼 검사**가 됐다 |
| «첫 임자»를 정해 두고 견줌 | 같은 이름(`setQuery`)을 저마다 «따로» 만든 컴포넌트가 **24개**다 → 둘째부터 전부 거짓 경보 |
| 선언이 늘 `var` 로 시작한다는 짐작 | `var qs=useState(''),query=qs[0],setQuery=qs[1]` — **쉼표로 이어지는** 꼴이 있다 |
| 조각에 주석이 살아 있음 | 내가 쓴 주석의 「실행 로그」가 코드로 읽혀 순서 검사가 거짓으로 깨졌다 → 조각에는 `stripJs` |
