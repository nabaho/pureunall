# 문서(급여명세서·급여대장·인사기록카드)의 사번 숨기기 (대표 2026-10-31 「사번은 숨겨라」)

2026-10-25 에 화면에서 사번을 걷을 때 문서는 «법적 기재 사항 확인 전»이라 남겨 뒀다. 10/31 대표가 문서도 숨기라고 결정했다.

## 법 확인 (국가법령정보센터 원문을 직접 읽음 · 시행 2025.10.23)
- 근로기준법 시행령 **제27조의2 제1호**(임금명세서): 「근로자의 성명, 생년월일, 사원번호 등 근로자를 특정할 수 있는 정보」 → 사원번호는 «예시».
- 같은 시행령 **제27조 제1항**(임금대장): 제1호 「성명」 · 제2호 「생년월일, 사원번호 등 근로자를 특정할 수 있는 정보」(사용기간 30일 미만 일용직은 2호 생략 가능, 제2항) →
  임금대장은 성명 외에 «특정 정보» 한 가지가 더 필요하다. 사번을 빼면 그 자리를 **생년월일**(직원 정보 u.birthDate)로 채워야 요건이 유지된다.

## 한 일
- 사번 글자를 뺀 자리(pu-erp.html): ① 명세서 HTML(PDF·메일·시험발송) ② 명세서 일괄 출력 ③ 급여대장 CSV(머리·줄) ④ 명세서 mailto 글 ⑤ 명세서 한글(HWPX) ⑥ 명세서 화면 칸
  ⑦ 인사기록카드 머리(이름 줄 아래 «사번 · 직책 · 소속» → «직책 · 소속») ⑧ 급여 겹친 달 관리 화면.
- 사번 자리는 `erpDocBirth(u)` — 생년월일, 값이 없으면 **빈 글자**(사번·이메일·이름으로 대신 채우지 않는다). mailto 글은 값이 있을 때만 줄을 만든다.
- **CSV 가져오기 왕복**: 내려받은 `급여대장_YYYY-MM.csv` 를 고쳐서 다시 가져오던 길(📥 CSV)이 사번 칸에 기대고 있었다. 사번 칸이 «있으면» 예전처럼 사번만 본다.
  사번 칸이 «없는» 파일은 `payCsvFindUser` — 이름과 생년월일이 «둘 다» 같은 «한 사람»만 맞춘다(이름만·생년월일 빈 것·동명이인은 맞추지 않음). 못 맞춘 줄 수를 알림에 적는다(조용히 빠지지 않게).
- 안 건드린 것: 급여 «가져오기»의 사번 열쇠(CSV 가져오기 사번 칸이 있는 경우·엑셀 급여대장 가져오기의 주민번호/이름 맞춤) · 값·DB 경로·열쇠(사번 그대로) · 고객사 급여관리(payroll-os.html — 고객사 자체 번호라 범위 밖).
- 서버(functions/): 급여명세서 메일 본문·제목은 이미 이름뿐 — 고칠 것 없음. 실제 메일 발송은 하지 않았다(대표 승인 범위 밖).

## 알아 둘 것 (대표에게 알림)
- 서버 직원 정보(user_accounts) 실측: 퇴직 제외 10명 중 **생년월일이 빈 직원 1명**(이름은 대표 보고에만 — 저장소엔 안 적는다) → 그분 명세서·급여대장 줄은 생년월일 칸이 빈칸이다. 근로자명부에서 입력하면 문서에 나온다.
- **퇴직자 22명은 전원 생년월일이 비어 있다** → 과거 달 급여대장 CSV·명세서를 다시 뽑을 때 그분들 줄은 성명만 나온다(임금대장 제2호 «특정 정보»가 비는 셈). 필요하면 근로자명부에 입력 — 주민번호에서 자동으로 뽑지는 않는다(주민번호는 기록에 안 옮긴다).
