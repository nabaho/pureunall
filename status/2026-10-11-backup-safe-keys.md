# 2026-10-11 · 서버 백업이 통째로 실패하던 것 — 칸 이름의 「#」 (fix/backup-safe-keys)

- 증상: 「🔴 백업을 저장하지 못했습니다 — 주민번호를 잠글 열쇠를 얻지 못했습니다 — update failed: … invalid key (bank|expense|2026-04-06|800|03월문자수수료 14:10#1) … bank_ledger_draft.expCat」
- 원인: 거래내역 임시 저장(bank_ledger_draft, 이 PC 작업분)의 칸 이름에 `#`(같은 날 같은 금액 둘째 줄 표시)가 있다.
  실시간DB 는 칸 이름에 `. # $ / [ ]` 를 받지 않아 백업 «전체»가 거절됐다. 문구는 잠금 실패로 잘못 적혔다.
- 고침: 두 백업 길(매일·수시)이 지나는 erpSealSnap 이 칸 이름을 `~k~`+인코딩으로 바꿔 싣고,
  모든 되살리기가 지나는 erpUnsealSnap 이 원래대로 푼다(옛 백업은 그대로 지나감). 작업 자료 자체의 열쇠는 안 바꾼다.
  서버 저장 거절은 «서버 저장 실패»로 따로 알린다.
- 검사: tests/backup-safe-keys.test.js (옛 코드에서 3건 실패) · 백업·나스·주민번호 잠금 묶음 276 통과.
- 확인할 것: 배포 뒤 다음 자동 백업(하루 1회)이 성공하는지 — 환경설정 › 백업 또는 serverBackupsIndex 의 오늘 날짜.
