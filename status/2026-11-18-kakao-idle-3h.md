# 2026-11-18 — 자동 로그아웃: 아이디·비번 1시간 / 카카오 3시간 (둘 다 작업 중이면 연장)

대표 지시: 「단순 비번·아이디로 로그인할 경우 1시간 제한 걸리고 계속 작업 시에는 시간이 연장되어 가지만,
카카오톡 로그인의 경우 3시간으로 하고 계속 작업 중인 경우 안 끊기게 해 달라」

## 한 일
1. **판정을 공용 부품 한 곳으로 — `js/pu-active.js`**
   - `PuActive.limitMs(기본값)` — 아이디·비번(그 밖 모두)은 포털 설정 시간(비우면 60분), 카카오는 3시간.
     포털 설정이 3시간보다 길면 카카오도 설정을 따른다(더 짧게 하지 않는다).
   - 카카오인지는 **서버가 서명한 인증표의 `kakao: true`**(`functions/kakao.js` 가 넣는다)로 가린다.
     결과를 `localStorage.pu_login_via = {uid, via, at}` 에 적어 모든 앱이 같은 값을 본다.
   - 다른 사람이 남긴 표시(uid 다름)는 믿지 않는다(공용 PC). 더 새 로그인의 표시를 옛 것이 덮지 않는다.
   - «움직였다» 적기(`mayMark`)도 같은 시간을 쓴다 → 카카오 사용자는 캘린더·사진첩 등에서 1시간 넘게 일해도 기록이 이어져 안 끊긴다.
2. **자동 로그아웃을 거는 다섯 화면이 그 판정을 묻는다** — 포털(`enter.html`)·이알피(`pu-erp.html`)·
   정부사업일정(`gov-consulting.html`)·기업정보함(`pu-cards.html`)·규정관리(`rules.html`).
   각 화면에 `pu-active.js` 를 싣고, 남은 시간·로그아웃 판정을 `idleLimit()`(= `PuActive.limitMs(LIMIT)`)로 잰다.
   남은 시간 배지(⏱)도 카카오면 3시간부터 센다.
3. **포털은 로그인 직후 어떻게 들어왔나를 적는다** — 비번 로그인 → `password`, 카카오 → `kakao`
   (인증표 확인 전에도 바로 맞는 시간이 걸리게).
4. 포털 ⚙ 설정의 「자동 로그아웃 시간」 안내에 «카카오 로그인은 3시간» 한 줄.
5. `pu-active.js` 캐시 번호를 v=2 로 올렸다(싣는 화면 모두).

## 그대로 둔 것
- 「이 기기에서 로그인 유지」(`pu_portal_auto=1`)를 켠 기기는 지금처럼 자동 로그아웃을 하지 않는다.
- 판정은 브라우저 안 편의 장치다 — 서버 쪽 세션 시간은 바꾸지 않았다(원래 없었다).

## 검증
- 새 검사 `tests/idle-logout-kakao.test.js` (10) — 고장 14가지를 일부러 넣어 모두 잡는 것을 확인.
- 전체 검사 30,901건 — 실패 1건(`authsync-global-logout` 이 옛 글자 `>= LIMIT` 를 박아 둠)을 «판정 뒤 신호를 내나»로 고쳐 통과.
- `ow review`(기능 검증·보안 모두 Claude 가 맡음 — 기본 담당 사용률 초과로 자동 전환): 둘 다 통과, 높음·중간 없음.
  낮음 지적 중 둘을 고쳤다: ① 로그인 때를 기기 시계 대신 서버 시각(`lastSignInTime`)으로 적어 시계가 틀린 PC 에서도 순서가 맞게,
  ② 인증표 읽기 실패 뒤 매초 재시도하지 않고 1분 쉼. 남긴 것: 로그아웃 때 `pu_login_via` 를 지우지 않음
  (다른 사람이 로그인하면 uid 가 달라 무시되고, 같은 사람은 인증표로 곧 바로잡힌다).
  사용자가 제 브라우저에서 표시를 손으로 바꾸면 3시간이 되지만, 자동 로그아웃은 원래 브라우저 쪽 장치라 새 구멍이 아니다
  (「로그인 유지」로 이미 끌 수 있다). 서버 쪽 세션 만료가 필요하면 별도 일이다.
- 내장 브라우저(내 컴퓨터 임시 서버)에서 포털을 열어 `PuActive.limitMs()` 가 표시 없음 60 · 비번 60 · 카카오 180 · 설정 480이면 480(분)으로 답하는 것을 확인.
- ⚠ 실제 카카오 로그인으로 3시간 배지가 뜨는 것은 배포 뒤 확인이 필요하다.
