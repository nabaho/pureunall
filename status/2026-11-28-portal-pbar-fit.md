# 포털 머리줄 «맞춤» — 1024px 등 PC 중간 폭에서 로그아웃·내 메뉴가 화면 밖으로 나가던 것 (2026-11-28)

발견: «내 업무» 첫 안내(#3269) 작업 중 포털을 여러 폭으로 재다가 1024px 에서 `#logoutBtn`·`#meBtn` 이 화면 밖(화면밖 2)으로 나간 것을 찾음.

## 원인 — 커밋을 차례로 다시 재서 밝힘 (`tools/phone-audit` portal, 지어낸 자료)
| main 시점 | 1024px 화면밖 |
|---|---|
| `e37b9818e` (11-21, «내 업무» 단추 전) | 0 |
| `eb96ae6af` (#3228 «📋 내 업무» 머리줄 단추 합침 직후) | **2** |
| `9dda9931b` (#3269 첫 안내 합침 직후) | **2** |
| `663a886d6` (지금 main — #3272 가 「✨ TypeSafe 검토」 단추를 걷음) | 0 (지어낸 자료 기준, 남은 틈 몇 px) |

- 즉 «내 업무» 단추(머리줄 한 칸 ≈190px)가 들어오며 넘쳤고, TypeSafe 단추가 빠져 지어낸 자료로는 겨우 들어왔다.
- 그런데 **대표 PC 는 내 메뉴 단추 안에 «₩000,000 이번 달»(사용액)이 붙는다**. 점검 씨앗에 사용액을 넣고 재니 지금 main 에서도 1100·1024·960·920·901px 에서 로그아웃(960 이하는 내 메뉴까지)이 화면 밖이었다.
- 머리줄은 «한 줄»(대표 2026-08-20)이라 접히지 않고 옆으로 넘친다. 폭으로 끊는 `@media` 만으로는 사용액·«서버 연결 끊김» 글자·숫자 자릿수·새 단추에 따라 또 넘친다.

## 한 일
- `enter.html` CSS: `@media(min-width:901px)` 안에 맞춤 단계 `.pbar[data-fit~="1"|"2"]`.
  - 1단계: 챗봇 글자(🤖만 — 이름은 aria-label·title)·아바타·«이번 달» 글자를 접고 사이를 13→8px. 셋 다 폰·태블릿이 이미 접는 것이다.
  - 2단계: 머리줄 단추(내 업무·캘린더)를 그림 + 딱지로 — 태블릿(≤900px) 규칙과 «같은» 모양.
- `enter.html` JS: `pbarFit()`·`pbarFitWatch()` — 머리줄 «보이는 직계 자식» 전부의 오른쪽 끝을 화면 오른쪽 끝(−8px)과 견주어 가장 덜 접는 단계를 고른다. 넘치지 않으면 `data-fit` 를 지운다(1366px 대표 화면은 그대로).
  포털을 그린 뒤(`renderPortal`)·창 크기·머리줄 안 바뀜(MutationObserver — 숫자·사용액·연결 상태·단추 켜고 끔)·글꼴 받음 때 다시 잰다. 떠 있는 창(내 메뉴·첫 안내) 안의 바뀜은 무시하고, `data-fit` 는 지켜보지 않아 되풀이가 없다. 단계가 바뀌면 «내 업무» 첫 안내 화살표를 다시 맞춘다.
  ≤900px 은 손대지 않는다(`data-fit` 를 지움 · CSS 도 PC 구간 안에만).
- `tools/phone-audit/seeds/portal.js`: 이번 달 사용액(`billing/current`)을 넣어 대표 머리줄 폭으로 재고, 연결이 끊긴 머리줄 화면 `pbar-offline` 을 더함.
- 새 검사 `tests/portal-pbar-fit.test.js` (6) — PC 구간에만 · 경계가 태블릿 규칙·JS 와 맞물림 · 마지막 단계 = 태블릿 모양 · 눌러야/읽어야 하는 것은 안 감춤 · «재서» 고름(직계 자식 전부·떠 있는 창 뺌·다시 재는 때) · 가짜 머리줄로 단계 고르기 돌려 봄 · 씨앗이 가장 넓은 머리줄로 잼.
  저장소 밖 사본에서 맞춤 코드를 10가지로 망가뜨려 모두 잡는 것을 확인(기준선 통과).

## 잰 값 (고친 뒤, 사용액 있는 씨앗)
- `node tools/phone-audit/run.mjs portal --widths=1366,1200,1100,1024,960,920,901,900,768,411,360` — 첫 화면·오케스트레이션 창·내 업무 첫 안내 모두 **화면밖 0**.
- `--view=pbar-offline`(연결 끊김) 1366·1200·1024·960·901 모두 화면밖 0 — 901px 에서 2단계(그림+딱지)로 들어감, 1366 은 단계 없음.
- 고치기 전·뒤 갈무리: 1366·1200·768·360 은 바이트까지 같음. 411·900 은 찍을 때마다 몇 점씩 흔들려(같은 코드로 다시 찍은 411 이 고치기 전 것과 해시 일치) 모양 변화 아님.
