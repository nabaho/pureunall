# 컨설팅보고서 — 대형 사업 단계 체크표 (2026-10-11, 설계 2-A)

설계 `docs/superpowers/specs/2026-10-11-gov-report-big-stages-design.md`(#2536 합쳐짐) · 계획 `docs/superpowers/plans/2026-10-11-gov-report-big-stages.md` · 구현 PR 예정

## 만든 것
- **기록 모듈**(`js/pu-gov-report-track.js`): 단계 종류 `plat`(플랫폼 입력)·`report`(보고서), 항목 단위 줄 키 `keysForItem`(once·회차·월 — 키는 규칙 식·20자 한도 안), 단계 칩 `bigCells`, `nextStage`(첫 미완 단계), `blockedOf`.
- **서류 틀 모듈**(`js/pu-gov-report-docs.js`): 대형 3종 항목에 입력 순서 체크 글(`steps`)·안내(`note`), `monthsFor`, `docsTable` 대형 분기(단계 열·칩·다음 단계), `trackRows` 대형 분기, `blockedAlerts`(기록에서 직접 «막힌 단계» 목록).
- **화면**(`gov-report.html`): 대형 사업을 고르면 단계 열 표 · 단계 칸을 누르면 기존 칸 창(상태·완료일·메모·받은 서류 연결, 회차 서류는 «서류» 고르기, 월별 서류는 `YYYY-MM` 이름) · 서명 단계는 설계 1 의 서명 요청 메일 초안 · 플랫폼 단계는 입력 순서 체크 글 · ⏰ 「막힌 단계」 알림.

## 쓰는 곳
- **바뀌지 않았다**: `scal_docs/{업체}/{rid}/items/{키}` 줄 하나 `.set`(`grSaveCell`) 한 곳. **새 규칙·게시 없음** — 줄 키 규칙(`^[a-z]+(:[0-9]+)?$`·20자)에 대형 3종 모든 키가 맞는지 검사로 못 박았다. AI·메일 자동 발송 없음.

## 설계서와 달라진 점
«막힌 단계» 알림은 현황판 줄이 아니라 `blockedAlerts` 가 기록에서 직접 만든다(대형 사업은 현황판 줄이 없는 경우가 많다). 설계서 §3·§4 도 같이 고쳤다. `alertsExtra.blocked`·`trk.blocked` 는 남겼지만 화면은 쓰지 않는다.

## 못 한 것 · 확인 필요
- **실제 로그인 화면 확인 안 함** — 단계 표·칸 창·알림은 가짜 DB 로만 검사했다. 대표 PC 에서 일터혁신 사업 한 곳으로 단계 기록·읽기·삭제를 확인해야 한다.
- 회차 기록(형태·시간·참석자·사진·서명지)과 기준 점검(2-B, 새 자료 칸·새 규칙 필요 — 대표 승인), 장별 AI 초안(2-C), 기한, 플랫폼 자동 입력(Aside)은 만들지 않았다.
- 월별 서류 키는 «계약 기간의 달 순서»(위치) — 계약 기간을 고치면 기록의 달이 밀린다.
- 단계 체크 글·증빙 안내는 정리 파일(2026-10-09) 기준 초안이다. **노무사 확인 필요**(`DOC_PLANS` 대형 항목 `steps`·`note`, 일터혁신 플랫폼 입력 순서 포함).
- 사업 목록을 못 읽었을 때 «막힌 단계» 개수는 0 으로 보인다(기록을 못 읽었을 때만 「?」).
