# 한글 편집기 자동 저장 (2026-11-01)

가지: `feat/hangul-autosave` (origin/main 에서 새로 땀)

## 한 일
- 열어 둔 문서(끌어다 놓은 파일 포함)를 이 컴퓨터의 브라우저(IndexedDB)에 복구용 사본으로 계속 저장. `hangul/js/autosave.js`(신규 v1), `app.js` v9(`pu:dirty`·`pu:doc`·`pu:leave` 알림, 파일 메뉴 «자동 저장된 문서…»), `app.css` v6, `hangul.html`.
- 저장 시점: 파일을 열자마자, 고친 뒤 2.5초 쉬면, 탭을 바꿀 때, 창이 가려지거나 닫힐 때. 상태 표시줄에 «자동 저장됨 시:분:초».
- 다시 열 때: 빈 문서뿐이면 «이전에 작업하던 문서 N개…» 안내, 파일 → 자동 저장된 문서…에서 열기·지우기·모두 지우기. 열면 저장 전(*) 상태로 이어서 같은 사본에 저장.
- 원본 파일은 건드리지 않음(다른 이름의 사본만). 20개·14일 넘으면 오래된 것부터 삭제. 배포용(읽기 전용) 문서는 보호를 우회하지 않도록 저장하지 않음.

## 확인 (1460px 가상 화면, 로컬 서버)
42쪽 문서(공공기관 편람)를 열면 1.5MB 사본이 저장됨 → 글 한 줄 추가 후 2.5초 뒤 «저장 전 상태» 사본 갱신 → 저장 없이 강제 새로고침 → 안내 문구와 목록 표시 → «열기» → 42쪽, 추가한 문구 포함, 탭에 * 표시. 오류 0.

## 알아 둘 점·[확인 필요]
- 복구 사본은 한/글 파일(.hwp)이 아니라 HWPX 로 저장됨 — 편집기가 못 읽는 개체는 사본에서도 빠짐(열 때 «지원하지 않는 개체» 안내와 같은 범위).
- 실제 PC가 갑자기 꺼지는 경우(전원 차단)는 시험하지 못함. 브라우저 «사이트 데이터 삭제»·시크릿 창에서는 저장되지 않음.
- 개인 정보가 든 문서의 사본이 이 PC 브라우저에 남으므로, 공용 PC에서는 쓰고 나서 «모두 지우기».
