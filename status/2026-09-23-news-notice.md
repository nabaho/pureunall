# 뉴스레터 관리 — 「안내문」 (뉴스레터가 아닌 한 건 집중 편지)

대표 지시 2026-09-23
「뉴스레터 이외에 비정기적인 자료를 푸른노무법인 이름으로 뉴스레터가 아닌 내용으로
 집중해서 확인하라는 의미로 보내고 싶은데 이부분도 반영해라」

대표 결정(목업을 보시고): **그대로 · ✅「확인했습니다」 단추는 뺀다 · 문의는 사업장별 담당 노무사.**
(목업 파일은 저장소에 두지 않는다.)

## 무엇

뉴스레터 관리에 **「안내문」 탭**. 제목 · 이것만 확인해 주십시오(한 줄에 하나) · 회신 기한 ·
본문 · 자료(파일 올리기 / 링크) · 받는 곳(뉴스레터 명단 전체 / 골라서) · 크게 보기 · 시험 발송 · N곳에 보내기.

편지는 **뉴스레터와 생김새부터 다르다** — 남색 띠 · 「확인 요청」 딱지 · 꼭지 없이 한 건 ·
제목 「[푸른노무법인 안내] … — 9월 30일(수)까지 확인 부탁드립니다」.

## 어디에 무엇이

| 것 | 자리 |
|---|---|
| 편지 짓개 | `js/pu-news-notice.js` (빛깔은 `Tpl.색` 을 빌린다 — 팔레트 두 벌 금지) |
| 안내문 자료 | `newsletter/notices/{번호}` — 회차(주차)와 **따로**. 지난 회차·미열람 셈에 안 섞인다 |
| 보내기 | `sendBulkMail` 의 **`noticeSend` 갈래** — 총괄관리자만 · 서버 잠금(NL) · 번호 꼴만 |
| 담당 끼우기 | `mail-bulk` `staff` → `{담당문의}` = 「담당 홍길동 · 」 또는 빈 글자 |
| 자료 파일 | 창고 `newsletter_files/` · 받는 분은 `newsView?file=<32자리>.<확장자>&n=<이름>` 로 **내려받기** |

## ⚠ 다음 사람이 알아야 할 것

- **담당은 업체관리 주담당(`managerMain`) 사번 → 직원 명부(`data/user_dir`) 이름.** 이름으로 짐작하지 않는다.
  못 찾으면 비운다 → 문의 줄에 법인 대표 번호만 남는다(지어내지 않는다).
- **「노무사」 직함을 붙이지 않는다** — 주담당이 노무사가 아닌 직원일 수 있다. 틀린 직함보다 이름만이 낫다.
- **전화번호는 법인 대표 번호만** — 명부에는 연락처가 일부러 빠져 있고, 개인 번호를 거래처에 뿌리지 않는다.
- ⚠⚠ **사람이 쓴 `{ }` 를 막는다.** 발송기의 fill 은 `{무엇}` 을 모두 자리로 읽어 비운다 —
  안 막으면 「{주의}」가 편지에서 조용히 사라진다. 서식은 `&#123;`, 평문·제목은 전각 `｛｝`.
  편지 안에서 발송기가 읽을 자리는 **`{담당문의}` 딱 하나**다(검사가 센다).
- 두 번 보내기는 **서버가** 막는다(뉴스레터와 같은 NL 잠금). 같은 요청을 다시 물으면 «그때 결과»를 준다.
  안내문 갈래는 뉴스레터 갈래 **앞**에 서서 끝나면 `return` 한다 — 안 돌아서면 대기열이 두 번 걸린다.
- 추적(열람·클릭)은 **안 한다** — 확인 단추를 빼기로 해서 받는이 대장·보냄표·링크들을 안 쓴다.
- 자료는 **붙이지 않는다**(2026-09-13 뉴스레터 결정과 같은 까닭 — 143곳 × 크기).
  서버 문은 `attachment` + `octet-stream` + `nosniff` 로 준다 — 우리 주소 안에서 문서가 열리지 않게.
  받는 확장자(pdf·hwp·hwpx·doc·docx·xls·xlsx·ppt·pptx·jpg·png)는 화면과 서버가 **같아야** 한다(검사).
  html·svg·js·zip 은 안 받는다.
- 창고 규칙 `newsletter_files` — 읽기 false, 20MB. 온톨로지 INFRA_ROOTS 에 **창고 자리라고 밝혀** 적었다.
