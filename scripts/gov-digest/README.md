# 정부사업신청 «매일 카톡 요약»

대표 지시 2026-11-22 「정부 지원사업 관련해서 카카오톡으로 매일 받고 싶다 — 내 개인톡으로. 다 주는 것은 필요 없고 수의계약 제외하고
필요할 만한 것들, 컨설턴트 모집도 대전·충청 지역 것, AI 사업은 전국, 노무사가 직접 하거나 노무 프로그램으로 충분히 가능한 사업으로」
→ 보내는 길은 **카카오 공식 «나에게 보내기»** (대표 «공식 방식으로» 2026-11-22).

서버가 모은 공고(`gov_feed/rows`, 07:40)·기관 게시판 모집 글(`gov_watch/hits`, 07:20)을 읽어 추리고 → **«새로 걸린 갈래마다 한 통»**을 «나에게 보내기»로 보낸다.
공식 방식은 받는 사람이 **토큰 주인(대표)뿐**이라 엉뚱한 방으로 갈 수 없고, PC 가 꺼져 있어도 서버가 보낸다.

## 무엇을 보내나 (규칙은 `functions/gov-digest.js` 맨 위 `RULES`)
| 갈래 | 들어가는 것 | 안 들어가는 것 |
|---|---|---|
| 🧑‍💼 충청 모집 | 대전·세종·충남·충북(충청 공통 포함) 기관 게시판의 컨설팅·자문·심사위원 모집 · **공인노무사회 게시판** 모집(지역 없어도, 제목에 다른 지역이 있으면 빠짐) | 다른 지역 모집 · 주민자치센터 같은 일반 «강사 모집»(제목에 노무·노동·근로·임금·고용·인사·괴롭힘·안전보건… 이 있으면 들어감) · 행사 안내 · 후보 추천 · 법인 위탁 운영·임원 공개모집 |
| 📋 노무 공고 | 노무 핵심 낱말(노무·노사·임금·일터혁신·조직진단·취업규칙·직장내괴롭힘·위험성평가 …)이 걸린 공고 · 충청권 공고(찾는 말이 하나는 걸려야 함) | 약한 낱말(인사·고용·컨설팅)만 걸린 전국 공고 · **우리 지역이 아닌 지역 제한 공고** |
| 🤖 AI 사업 | AI 도입·전환 · HR플랫폼 · 스마트서비스 · AI/클라우드 바우처 — 지역으로 거르지 않는다(전국) | 스마트공장 · 교육 과정 운영(부트캠프·강사) 용역 |
| 모든 갈래 | | **수의계약** · 마감 지난 것 · 같은 공고의 고침판·재공고(한 줄만) · 마감 없는 채 공고 후 90일이 넘은 것 |

- **새로 걸린 것만** 보내고, 마감이 3일 안으로 다가온 줄은 **한 번만** 더 알린다(⏰). 새 것이 없는 날은 아무것도 안 보낸다.
- 카톡 글은 **요약**이다(텍스트 템플릿 200자 · 갈래마다 한 통, 하루 세 통 안쪽). 줄마다 원문 주소는 못 싣는다 — 링크는 카카오 앱에 등록한 웹 도메인(ERP)만 걸 수 있어서, **«전체 보기» 단추가 정부사업신청 «📮 오늘의 요약»을 연다**(줄마다 원문 링크·까닭·새/마감 임박 표시).
- 카카오가 길이로 거절하면 더 짧은 글로 한 번 더 보낸다.
- 이 글은 «알림»이다 — 지원 여부는 원문을 보고 정한다(틀릴 수 있다).

## 모드 — `gov_digest_cfg/mode` (서버 전용 자리, 화면에서 못 고침)
| 모드 | 하는 일 |
|---|---|
| `off` | 아무것도 안 한다 |
| `dry` (기본) | 요약만 `gov_digest/last` 에 쓴다(전체 보기용). 카카오는 한 번도 안 부른다 |
| `live` | 보낸다. **카카오 연결을 처음 마치면 자동으로 live** (이미 정해 둔 모드는 안 건드린다) |

끄려면 `gov_digest_cfg/mode` 를 `off` 로(Claude 에게 «카톡 요약 꺼 줘»), 카카오 쪽에서는 카카오계정 › 연결된 서비스에서 앱을 끊으면 토큰이 죽는다.

## 대표가 한 번 하실 일 (연결)
1. **카카오 개발자 콘솔**(developers.kakao.com › 내 애플리케이션 › «푸른토탈서비스») 세 곳:
   - **제품 설정 › 카카오 로그인 › 동의항목** → «카카오톡 메시지 전송(talk_message)» 을 **선택 동의**로 켠다.
   - **제품 설정 › 카카오 로그인 › Redirect URI** 에 `https://asia-northeast3-pureun-erp.cloudfunctions.net/kakaoMemoCallback` 을 **글자 그대로** 더한다.
   - **앱 › 플랫폼 키/제품 링크 관리 › 웹 도메인**에 `https://erp.pureunlabor.co.kr` 가 있는지 본다(카톡 단추 링크가 이 도메인이어야 한다).
2. 서버에 함수가 올라간 뒤(`kakaoMemoStart`) 아래 주소를 브라우저에서 연다 → 카카오 로그인 → «카카오톡 메시지 전송» 동의 → «✅ 연결됐습니다» 화면과 함께 카톡 «나와의 채팅»에 확인 글 한 통이 온다.
   `https://asia-northeast3-pureun-erp.cloudfunctions.net/kakaoMemoStart`
3. 그 뒤 매일 아침 8시 30분에 새 공고·모집이 있으면 알려 준다.

연결은 **ERP 에 연결된 총괄 관리자(대표) 카카오**만 된다 — 다른 카카오로 동의하면 토큰을 저장하지 않는다.

## 안 올 때 — `gov_digest/status` 의 코드(요약 팝업 맨 위에도 쉬운 말로 뜬다)
| 코드 | 뜻 | 할 일 |
|---|---|---|
| `not-connected` | 카카오 연결이 아직 안 됐다 | 위 «연결» 2번 |
| `reconnect-needed` | 동의가 풀리거나 토큰(60일)이 죽었다 | 연결 주소를 다시 연다 |
| `refresh-failed` | 토큰 갱신이 막혔다(일시 오류일 수 있음) | 다음 날 자동 재시도, 계속되면 다시 연결 |
| `send-failed` | 카카오가 메시지를 안 받았다(`httpStatus`·`kakaoCode`) | 웹 도메인·동의항목 설정 확인 |
| `no-data` | 서버가 모은 공고가 없다 | 07:40 공고 모으기(`govFeedCollect`) 확인 |

## 서버 자료 자리
| 자리 | 누가 읽나 | 내용 |
|---|---|---|
| `gov_digest/last`·`status` | 재직 직원(읽기만) | 오늘의 요약(공개 공고 정보뿐)·돌린 결과 |
| `gov_digest_secret/kakao` | **서버만** | 카카오 토큰 — 보안규칙에 없어 화면에서 닫힘, 로그·상태에 안 남김 |
| `gov_digest_state/sent·lock` | **서버만** | 보낸 기록(120일)·잠금 |
| `gov_digest_cfg/mode` | **서버만** | 모드 |

## PC 미리보기 `main.js` (정식 길 아님)
`node scripts/gov-digest/main.js` 는 서버 자료로 오늘 보낼 글을 화면에 보여 준다(읽기만, 기록 안 남김). `--send` 의 «PC 카톡 자동 입력» 길은 **정식 길이 아니다** —
창 제목만으로는 «진짜 나와의 채팅»을 가릴 수 없고 카카오 약관상 위험도 있어서(2026-11-22 보안 검토) 공식 방식으로 바꿨다. 코드는 남겨 두되 쓰지 않는다.

## 알아 둘 것
- 카카오 «나에게 보내기»의 하루 한도(발신자·pair 단위)가 문서에 분명하지 않다 — 하루 세 통 안쪽으로 보낸다.
- 리프레시 토큰은 60일이고, 남은 기간이 한 달 아래일 때 갱신하면 새로 받는다 — 매일 돌기 때문에 저절로 이어진다. 서버가 두 달 넘게 멈추면 다시 연결해야 한다.
- 서버 코드를 고치면 함수도 다시 올려야 반영된다(`govDigestKakao`·`kakaoMemoStart`·`kakaoMemoCallback`). 공용 모듈(`js/gov-*.js`)을 고치면 `functions/vendor/` 사본도 같이(검사가 바이트까지 맞대 본다).
- 지킴: `tests/gov-digest.test.js`(규칙) · `functions/gov-digest-kakao.test.js`(보내기·토큰·연결) · `tests/gov-digest-view.test.js`(요약 팝업)
